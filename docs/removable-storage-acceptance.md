# 可卸载存储：四波合并真机验收

测试程序：`C:\rb-target\raybend\debug\raybend-desktop.exe`；同目录保留 `raybend-raw-worker.exe`。使用正常 Windows debug 版本，不需要逐波更换程序。

以下是真机验收步骤。单元测试、编译及合成冒烟由 Agent 完成；实际拔插、盘符、照片库、视觉、DPI 与性能体感由崔总确认。

| 场景 | 操作 | 应当看到 |
| --- | --- | --- |
| 离线仍能设置 | 卸下库所在移动盘，打开该库的齿轮 | 齿轮保留；库设置仍能打开，登记位置可管理。需要连接的模版/重建操作禁用；普通离线用中性提示 |
| 盘符改变 | Windows 将原 D: 改分配到 G:，离线库设置中点「定位此库」，选 G: 上原库根 | 核对 catalog ID 后登记新位置。连接后使用新根；原位置仍保留且可移除。无须改回旧盘符 |
| 错库拒绝 | 定位时选另一个库根，或把另一个盘放在旧盘符上 | 拒绝冒认；现有库登记与文件不被改写，设置入口仍可用 |
| 来源拔插 | 展开来源、勾选目录并选择图片，拔盘再插回 | 展开与勾选意图保留；卷、最近、勾选来源状态更新。原路径回来后树和图片重新读盘，旧扫描结果不覆盖新状态 |
| 一个来源等待 | 从两个来源导入，复制中拔下其中一个来源盘 | 保留已成功项；该来源等待，其它来源继续。原设备恢复后从文件安全点继续；不把拔盘计为大量文件失败 |
| 目标等待与取消 | 导入中拔下库盘，观察等待，再取消；另一次重新接回原盘 | 目标断开使整批等待；等待期间取消能结束，已落地文件保留。原库恢复时取得新健康连接后续跑。相同路径的不同库/同 ID 副本不接替旧任务 |
| 重启后的部分成功 | 导入中中断应用，重新连接原库，再用相同来源发起导入 | 已登记的成功项不重复导入，即使关闭「避免重复导入」；未登记的 pending 成品经过内容核对才接纳，大小相同但内容不同不会冒认；已有文件不覆盖 |
| 导出等待 | 导出时拔下源库盘或输出盘；同时保留另一库的队列任务 | 等待项让出执行槽，其它可用任务继续；设备恢复后核对库身份和捕获定稿再继续。停止的预设不会自动开启；移除/重置的等待项不会回来 |
| 同 ID 多副本 | 注册两个独立复制的同 ID 库，重启应用使连接重新解析；在库设置点「使用此位置…」并确认 | 解析发现多个实体时需要明确选择；添加位置不会切走健康会话。选中实体缺席时不会自动切到其它副本；本库还有未完成导入/导出时，位置切换被拒绝，需先取消/移除 |
| 主动释放 | 运行本库任务后点「释放此库」并确认，也可从 Ctrl+K/文件菜单进入 | 先显示正在释放，拒绝新任务与发布；等待本库任务、观察器、数据库连接退出。最终显示已释放，照片与登记保留；回焦点、卷变化、进入目录不会自动接回，明确点重新连接才恢复 |

身份读不到或不能证明原设备已恢复时，任务保持等待；可以取消后重新发起。重新检查不会跳过身份核对。

释放控制本应用对库的使用，未实现操作系统弹出设备，也不关闭其它应用持有的文件。释放状态持续本次应用会话，重启按正常连接规则。

导出队列仍是进程内队列；应用重启后不宣称恢复尚未持久化的导出队列。NAS 预留的是定位分类、连接状态、探测预算、扫描/文件操作/恢复适配接口；实际协议、认证、远程 catalog 与多机写入仍属后续范围。catalog 当前继续要求本地磁盘。
