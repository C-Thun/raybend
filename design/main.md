### 1.2 派生纪律（踩过坑，必须遵守）

```text
主稿（rJRpX）  ──Copy──▶  变体（只改本变体，不动主稿）
```

1. **主稿是唯一真相源**。所有改动**先改主稿**，再重新派生变体；
   **不要在变体上原地修改**。
2. **不要跳过中间步骤直接改变体** —— 曾经把浅色稿**原地改成宽松**，后果是：
   浅色稿变成了一个**孤立的、无法重生成的手改产物**，主稿后续的更新（`按时间` 按钮、
   `批量排除`、导入计数）**一个都没同步过去**，两边严重不一致。
3. **变体必须自洽**：换密度档时，**标题栏里的密度开关必须同步选到那档** ——
   否则写「宽松」的稿子里开关选的是「紧凑」，是自相矛盾的误导。
   同理，换主题时标题栏的主题按钮也应体现当前主题。
4. 变体的尺寸不是「主稿 × 系数」得来 —— 两档密度是**两套独立设计值**（见 `DESIGN.md` §8.3），
   且**容器尺寸要跟着内容重算**（例：面板加宽→中列变窄→照片列数要减）。

### 1.1 为什么先放在一个文件里

`AGENTS.md` §5.1 的纪律是 `design/<模块>-<视图>.pen` 分开。但实测**Pencil MCP 只能操作已在编辑器中打开的 `.pen`**，
且 Agent 无法自行新建文件（见 §6.1）。所以当前先把内容集中在一个文件里推进；
后续要拆分时，由人在 Pencil 里建好文件后，我再迁移内容并配套 `.md`。

**建议的拆分方案**（待用户确认）：
`design/components.pen`（16 个基础组件）／`design/shell.pen`（三行外壳）／`design/import.pen`（导入三列）。

### 2.1 `titlebar`（应用标题行）— 节点名 `TitleBar` `hrAhp`

**形态**：沉浸式，**没有系统级程序标题行**，窗口拖动由应用内接管。
高度 `40`（紧凑）/ `48`（宽松）—— 令牌 `--bar-title-h`（原稿的 `32` 已上调）。

| 位置 | 内容 | 节点 |
| --- | --- | --- |
| 左 | 应用图标：**真 logo**（`logo-small.png`，20×20 —— 只有徽章、没有字的那版；带字的版本在 20px 下糊成一团） | `AppIcon`（**画布上是占位符**，见 §9 的定案） |
| 左 | 应用名「光伴」`--fs-3`（15px）`600` | `AppName` |
| 左 | 菜单「帮助」 | `MenuItem / 帮助 / hover` |
| 中 | **空白拖拽区**（`fill_container`，无内容） | `DragArea` |
| 右 | 主题切换（单开关，**不跟随系统**） | `IconButton / 主题切换` |
| 右 | 密度切换：横向多选 `紧凑` / `宽松` | `SegmentedControl / 密度` |
| 最右 | 最小化 / 最大化-还原 / 关闭 | `WindowControls`（**`52×40`** 紧凑 / `62×48` 宽松；宽 `--win-ctl-w`、高随 `--bar-title-h`） |

**设计思路（界面表达不出来的部分）**：

1. **菜单只在鼠标指向标题行时才显示**（类似 VSCode 现在的行为）。设计稿里画的是**显示态**
   （`MenuItem / 帮助 / hover` 带 `$state-hover` 底），因为静态稿无法表达悬停触发。
   隐藏态＝这一行整体不存在，拖拽区向左扩展。
2. 标题栏菜单为文件 / 编辑 / 视图 / 窗口 / 帮助；任一菜单已经打开时，鼠标悬浮其它菜单标题会直接切换，
   不要求每个标题再次单击。
3. **主题切换是「只有一个开关」**，不做「跟随系统」这个第三态（用户明确要求）。
   图标显示当前模式的语义（深色时显示 `moon`）。
4. **窗口三键的悬停态已实现**（2026-09-15）：关闭键悬停变红 —— Windows 平台惯例。
   已补令牌 `--danger = #BF4E30` 与 `--fg-on-danger = #F6F8F4`（`DESIGN.md` §9.2），
   两主题共用同一个值，靠色相/饱和度差异跳出条带面。**画布未体现**（见 §9）。
5. **不在 Tauri 里、或窗口带系统标题栏时，三键整组不渲染**（浏览器降级）：
   判定问的是**运行时** `isDecorated()` 而不是配置 —— 这样 WSL 开发期的 Linux 配置
   与产品配置不会漂移；读取失败时按「沉浸式」处理（宁可多画按钮，不可让窗口关不掉）。
6. **菜单要「钉住」**（实现中发现的必要行为）：菜单渲染在 portal 里，鼠标移进菜单会触发
   标题行的 `pointerleave`，若不钉住就会「菜单刚要点就消失」。做法是 `Menu` 的 `onOpenChange`
   把标题行钉住。**这条约束改版时必须保留**。

### 2.2 `flowbar`（工作流行）— 节点名 `FlowBar` `uVSjs`

**形态**：高度 `52`（紧凑）/ `68`（宽松），令牌 `--bar-flow-h`（原稿的 `44` 已上调）。
**这一行的风格刻意与界面其他地方不同 —— 更圆润**（轨道与选中块都是胶囊形）。

| 位置 | 内容 | 节点 |
| --- | --- | --- |
| 左 | 工作流切换：`导入` `浏览` `编辑` `导出`（图标 + 文字） | **`FlowSwitcher`**（独立组件，见下） |
| 中 | 空白弹性区 | `SpacerFlex` |
| 右 | 图片信息区（Exif） | `ExifStrip` |
| 最右 | 全屏看图按钮（跟随图片信息一起出现；没选中照片时整个不出现） | `IconButton / 全屏` |

**工作流切换器是独立组件 `FlowSwitcher`（设计纪律，别合并）**：

| | 工作流切换 `FlowSwitcher` | 密度开关 `SegmentedControl` |
| --- | --- | --- |
| 语义 | 流水线位置（有序、互斥、每段不同图标） | 偏好设置（两档外观） |
| 尺寸 | `--flow-chip-h: 34px`、`--flow-chip-pad-x: 18px` | `--seg-chip-h: 30px`、`--seg-chip-pad-x: 14px` |
| 文字 | `--fs-3`（正文基准） | `--fs-2`（控件文字） |

> **为什么强调**：两者外观相似（都是胶囊轨道 + 选中块），最容易「顺手合并成一个组件」。
> 但它们的语义、尺寸、文字档都不一样，合并后一定会被参数塞满并开始互相妥协 ——
> **保持两个组件**是明确决定（`implementations/2026-09-15_M1-4_shell.md`）。
> 另注：Ark UI 的指示块只给 `--left/--top/--width/--height` 变量，**消费方必须自己接上**
> `h-[var(--height)] w-[var(--width)] top-[var(--top)] left-[var(--left)]`，
> 否则选中块会「全黑/铺满」—— 实测踩过。
> **动画只允许一个背景块**：目标 item 自己不预先铺主色底；Indicator 直接按 Ark 每次测得的
> left/top/width/height 从原项滑到目标项。这样没有“目标先亮、旧背景随后滑来”的双底错觉，
> 也不靠累计位移，反复切换不会积累像素误差。

**工作流切换的方向性**：`导入 → 浏览 → 编辑 → 导出` 是一条**有明确先后顺序的流水线**
（类似 DaVinci 的页面切换），不是并列的多选项。这决定了：

- 顺序**从左到右固定**，不因「最近使用」而重排；
- 当前项用品牌主色实色胶囊（`导 入`），其余为次要色 —— 视觉上一眼看出「我在流水线的哪一段」。

**图片信息区（Exif）的分组**：分组是**内容本身的结构**，不是视觉随意切分。
鼠标划过时同组边框一起亮起，用户能看出哪些信息是一组（`easy copy`，见 §4.1）。

| 组 | 内容 | 设计稿示例 |
| --- | --- | --- |
| 组 1 | 机型 + 镜头 | `DC-G9` · `LEICA DG 12-60mm F2.8-4.0` |
| 组 2 | 焦段 + 光圈 + 快门 + 感光度 | `12mm · ƒ/2.8 · 1/125s · ISO 200` |
| 组 3 | 尺寸 + 像素数 + 格式 | `5184 × 3888 · 20.2 MP · RAW` |

- **色彩空间信息刻意省略**（用户指定）。
- 排版采用「**值 + 间隔点**」而不是「标签 + 值」，因为这一行高度有限且值本身有强可识别性
  （`DC-G9` 一眼就是机型）。语义靠 `easy copy` 的分组框与 Tooltip 补足。
- 机型用正文色（`$fg-1`）、其余用次要色（`$fg-2`）：机型是这张照片最关键的识别信息。
- **两条实现纪律**（`src/features/exif-strip/grouping.ts`）：
  1. **空组整个不渲染** —— 不出现「只有边框、里面什么都没有」的气泡；
  2. **`easy copy` 复制的是整组，且带字段名**（`焦距 12mm · 光圈 ƒ/2.8`）——
     只复制值的话，粘到别处没人知道那串数字是什么。
- **窄容器下的行为**（实测修过一个 bug）：窗口变窄时三组曾经**互相重叠**。
  现行做法是**每组 `shrink-0`（不被压缩）+ 容器裁切**：宁可把最右侧截断，
  也不能让文字叠在一起。做响应式设计时要保留这个取舍。
- **设计稿里组 1 带 `$state-selected` 底** —— 这是为了在静态稿里示意 `easy copy` 的悬停分组框；
  实际交互中该底色**不出现**，只有 `easy copy` 的细边框（见 §4.1）。

**关于最右端**：磁铁开关（吸附）已于 2026-09-23 撤销（人类定：暂时不做吸附），
换成**全屏看图**按钮 —— 它**跟随图片信息一起出现**（`ExifStrip` 有内容才有它；
没选中照片时整个不出现，不是灰着占位），因为「只有选中了照片才谈得上全屏看它」。
点击**另开一扇无边框窗口**、按主窗口所在屏幕全屏（沉浸式无 UI，实现见
`src/features/fullscreen/`，命令 `viewer.fullscreen`，默认键 `F`）。

**历史形态（保留作组件参考）**：原磁铁开关是**类似 Affinity 的磁铁方块图标**
（`ToggleBlock / 吸附` `twdoH`），其形态规范由仍在使用的 `ToggleBlock` 继承
（「按时间」「筛选」等同款）：

| 状态 | 表现 | 节点 |
| --- | --- | --- |
| **未开启** | 方块**无底色**（与 `flowbar` 同色，即「平的」），磁铁图标用次级色 | `ToggleBlock / 吸附 / 未开启` |
| **已开启** | 方块填**主色实色底**，磁铁图标用 `fg-on-brand` | `ToggleBlock / 已开启 On`（见 `States / 状态速查`） |

- 方块 **`32×32`**（令牌 `--toggle-block`），圆角 4，图标 `16px`（**磁铁 `magnet`**）。
- 它同时是 §4.5 全局反馈规则的一个实例：指向→辅色底；按下后→**主色底**。
- 「未开启时是平的」意味着**没有边框** —— 在无边线体系里天然成立，不需要额外处理。

### 2.4 启动闪屏（2026-09-17 新增）

**它不在 `main.pen` 画布上** —— 闪屏的「设计」就是那张图本身（1086×814 ≈ 4:3 的透明 PNG/WebP，
不规则边缘），画布反而表达不了「窗口是透明的、没有边框」。

| 项 | 口径 |
| --- | --- |
| **窗口** | **800×600**（4:3）；`transparent: true` + `decorations: false` + `shadow: false`，**无边框、无按钮、无阴影** |
| **行为** | 置顶、居中、不进任务栏、**不抢焦点**；它只是一个「图」，用户不需要在这里做任何决定 |
| **图片** | `public/splash/splash-cn.webp` / `splash-en.webp` —— **每次启动随机抽一张**（`Math.random()`），在首次绘制前决定（`public/splash.html`） |
| **出现** | 应用能控制的最早点（`setup()` 里 `show()`）；**主窗口此时是藏着的** —— 不让人看到它在下面一行行渲染 |
| **停留** | **至少 3 秒**（人类 2026-09-17 定）—— 准备好了也要等满，一闪而过反而像卡了一下 |
| **消失** | 闪屏露满 3 秒**且**前端首屏（含字体）已就绪（`ui_ready`）→ 关闪屏 + 显示主窗口；前端一直不就绪则 **4 秒兜底**放行（前端挂了也不会把闪屏留成墓碑） |
| **开发模式** | **不弹**（`tauri::is_dev()`），而且主窗口立刻可见 —— 起 dev 不该多等 3 秒 |

**为什么值得单独说**：它顺手是「Windows 上 webview 能不能真透明」这条风险项
（`AGENTS.md` §6.1 / §8）的**真机最小验证** —— 透明窗口一旦不工作，闪屏会立刻变成一片黑底/白底。

> **定案（2026-09-17）：`main.pen` 里的 `AppIcon` 是占位符，以实际图片为准。**
> 画布上它是一个品牌色圆角方块 + aperture 图标，**不代表最终外观**；
> 实现里用的是 `src/assets/branding/logo-small.png`（20×20，只有徽章那版）。
> 为什么不让画布显示真图：实测 Pencil **不认本地图片路径** —— `fill: {type:"image", url:…}`
> 相对路径与绝对路径都渲染成断图，它只吃拖进画布的素材或远程 URL。
> 真实观感一律以**跑起来的应用**为准（人类在执行包里目视核对标题栏左上角）。
> 闪屏不进画布（理由见上）。

## 3. 工作区 `workspace`（导入）

**三列布局**，完全跟着工作流走。左、右列用 `$surface-main`，**中列用 `$surface-bar`**
（浅色主题下中列更深、深色主题下中列更浅）→ 两种模式下中央都形成聚焦。

> **结构红线（人类 2026-09-20 定，适用于所有工作流）**：
> workspace 里**只有纵向分列，没有跨列行**；每一条列都**自己到底**。
> 任何“在三列下面再铺一条全宽的东西”的布局都不允许 —— 底部信息条一律住在
> **它所属的那一列里面**（看图状态栏就在中列最底，见 `DESIGN.md` §8.7、`AGENTS.md` §11.1）。

| 列 | 节点 | 宽度 | 面 |
| --- | --- | --- | --- |

| 中：图片区 | `Panel / ImageGrid 中列` `OJtmE` | 弹性 | `$surface-bar` |

#### 3.1.1 `Recent`（最近）— `PanelBody / 最近` `F8HPE`

- **不需要用户自己添加收藏**：每次导入的目录自动记录，**记录最近 50 条**，

- **两个独立的状态，不要混用**：

  | 状态 | 表达 | 含义 |
  | --- | --- | --- |
  | **勾选** | 左侧**圆形主色勾选框** | 这条目录**加入待导入**（出现在下方「已选目录」区） |
  | **选中** | 整行背景 **`$state-selected`（主色底）** | 中间图片区**正在浏览**这条目录 |
  | 移除 | 行**最右**的**禁行图标**（悬停才出现） | 从最近列表移除 |

#### 3.1.2 `Source`（来源树）— `PanelBody / 来源` `fdym0`

- **树形结构，按操作系统适配**（当前只做 Windows，但结构上预留）。
- Windows 第一层依次列出**所有驱动器**。**不能只标盘符** —— 前方必须有**来源类型图标**，

  两条，用来确认「不同类型来源靠图标可辨」。
- **只显示目录，不显示文件**；可逐级展开（`chevron`）。
- 每条左边是**与 Recent 同款式的圆形勾选框**；勾选与选中语义同 §3.1.1。
- **注意**：树里点击某目录后，中间图片区列出的是**该目录直属的图片（仅可识别图片类型），不下钻子目录**。

#### 3.1.3 `已选目录`（可伸缩）— `PanelBody / 已选目录` `VBx6T`

> **已修订（2026-09-15）**：原设计是自动换行的 tile 流，用户反馈「感觉不太行」，
> 改为**横向一条一条的结构**（类似右列库卡片），因为它能给路径留出足够长度。

- **默认不显示**；每勾选一个待导入目录就出现一条。
- **每条是一个横向长条**（`SelectedBar / ...`，`300×56`，圆角 4，面 `$surface-track`）

```text
┌───────────────────────────────────────────────────┐
│  📁   D:\Photos\2024\Vacation\Japan\Kyoto    ⊘   │  ← 图标 + 路径（占满中间） + 右上角移除
│                                        包含子目录 ●─│  ← 右下角：包含子目录开关
└───────────────────────────────────────────────────┘
```

| 位置 | 内容 | 节点 |
| --- | --- | --- |
| 左 | **文件夹图标** `20px` | `BarIcon / folder` |
| 中 | **完整路径或 `shortpath`**，`textGrowth: fixed-width` + `fill_container` → **占满中间全部剩余宽度** | `BarPath / ...` |
| **右上角** | **移除**（禁行图标，`--remove-hit: 24px` 点击区 / 图标 18px） | `BarRemove / hover` |
| **右下角** | **「包含子目录」开关**（默认 **关**） | `Switch / 包含子目录 / (on·off)` |

- **为什么从 tile 改成横条**：用户实测后反馈 tile 放不下目录长度；横条能把路径横向铺开，且与右列库卡片风格统一。
- **为什么移除在右上、开关在右下**：两者职责不同 —— 移除是对这一条的**整体操作**，开关是这一条的**局部属性**。
  分居上下两角，鼠标不会误点。
- **点击区尺寸**：移除按钮不小于 **`24×24`**（令牌 `--remove-hit`；用户反馈原先 `16×16` 太小，
  随后又从 `22` 上调到 `24`）。宽松档 `30×30`。
- 这是 `easy destroy` 范式的一个应用点 —— **是「移除」不是破坏性删除，所以用禁行图标而不是叉**。

### 3.2.1 tile 排版口径（2026-09-16 重做，实现已按此落地）

人类反馈的原样：*「图片只吃上边的圆角……图片和文件名间距还太小……也不支持紧凑与宽松两种，
明显做一个排版只做了一半」*。当晚进一步定案为**正方外框 + 保比例照片 + 覆盖式信息条**（人类提的方案），
口径如下（**结构层面**，尺寸仍以实现 + `tokens.css` 为准）：

```text
┌──────────────────────────────┐  ← 外框：**正方**，边长 = 尺寸档（--tile-cell，17 档）；四周 --tile-pad
│  ╭────────────────────────╮  │
│  │        照片            │  │  ← 照片**保自己的比例居中**（短边贴边），四角 --tile-radius；
│  │              [动作槽]  │  │     超过 3:1 / 1:3 的由**后端**居中截取（看图档不截）
│  ╰────────────────────────╯  │
│ ▒ P1000156            ORF ▒  │  ← 底部信息条：**覆盖在照片上**（不占高度、不缩图），默认隐藏；
└──────────────────────────────┘     锦在**外框**边缘、被外框圆角裁到；指向/选中时出现
```

| 项 | 口径 |
| --- | --- |
| **形状** | **正方外框**（边长 = 尺寸档）。为什么不跟着照片比例走：行高必须恒定 —— 否则拖动尺寸/左列宽度时界面会扭成迪斯科舞厅；附带好处是**元信息迟到不重排网格**（照片只在自己的框里长大/缩小） |
| **照片** | 保比例、短边贴边、居中、四周 `--tile-pad`、四角 `--tile-radius`（**6px**，与外框共用；2026-09-16 从 3px 加大 —— 原来基本看不出倒角）；超出 3:1 / 1:3 的由后端居中截取（真值常量前后端一致） |
| **信息条** | **底部**：文件名（**去后缀**）+ 扩展名标签 +（库内）加锁位；**顶部**（**库内**才有）：星标 / 颜色点 / 旗标。都是**覆盖层**，锦在外框上下边缘（不是照片边缘 —— 否则比例一变就上下跳） |
| **信息条底纹** | 两层叠加 = 外框状态底纹 + `--tile-bar-scrim`（主题中性蒙层）；浓度与实测对比度、为什么不用「同色改浓度」见 `DESIGN.md` §12.9 |
| **状态** | 默认无底纹；库内颜色标记 → 该色低浓底纹；指向 → 辅色底纹 + 信息浮出（辅色 = §4.5 全局规则）；选中 → 主色底 + 信息**常亮**；**排除** → 照片变透明（`opacity .35`）+ **照片正中**一个中性的禁行图标（`fg-2`，不是红黄 —— 图标本身已经说清，颜色要克制；`AGENTS.md` §11.3） |
| **间距** | 四周 `--tile-pad` + 信息条高 `--tile-bar-h` —— **两档密度不同**（紧凑 `3/18`、宽松 `4/22`）。旧的「图 + 字幕条」方案（`--tile-gap` / `--caption-h`）已废弃：信息条不再占高度 |
| **扩展位** | ① 照片右上角 = 动作槽（排除等）；② 顶部条 = 星标/颜色/旗标；③ 底部条右端 = 加锁位。三处先在实现里留好，加功能时不必再试位置 |

**行高 = 外框边长**（不再叠加字幕条）—— 信息条是覆盖层，这是行高能这么简单的前提。

> 倒角：`--tile-radius` **6px**（外框与照片共用）—— 2026-09-16 从 3px 加大，当时「基本看不出倒角」。
>
> **画布待同步**（`main.pen` 里该块仍是旧的「图 + 下方字幕条」）：编辑器侧当前不可达，
> 见 `ASSISTANCE.md`；本表与 `DESIGN.md` §12.9 就是同步时的口径依据。

### 4.3 `shortpath` — 本稿中的实例

```text
盘符 + 中间各级目录的首字母 + 最后一级目录的全名
```

| 完整路径 | shortpath（设计稿中显示） |
| --- | --- |
| `D:\Photos\2024\Vacation\Japan\Kyoto` | `D:\P\2\V\J\Kyoto` |
| `D:\Photos\2022\Wedding-Studio` | `D:\P\2\Wedding-Studio` |

- Linux / macOS 下**第一级与最后一级写全**，中间同样取首字母。
- **两层算法**（必须如此）：① 只缩中间各级，保留首尾；② 仍超长则**放弃 ① 的结果整体重缩**。
  不能直接在 ① 的结果上继续截断 —— 若首级或末级本身很长，已生成的 `...` 会在某一侧「戳出来」。
- 生成组件要支持**传入长度上限**。

### 4.4 `Tile` 流换行

见 `DESIGN.md` §12.6。

> **适用范围已收窄**：该算法**不再是「已选目录」的布局**（那里已改为横条，见 §3.1.3），
> 而是**照片网格（`GridBody`）的布局**。本稿 `GridRow / 1` 放 6 张、`GridRow / 2` 放 4 张，
> 用来示意「**除最后一行外每行列数相同**」这一约束。
> **算法**（`DESIGN.md` §12.6）：列数 `N = floor((可用宽 + gap) / (tile 宽 + gap))`，
> 余量 `L` 全部作为右边距 —— 保证「除最后一行外每行列数相同」。
>
> 画布上的示意用的是**其中一档尺寸**（tile `150` 宽、gap `8`、中列内容宽 `960` →
> `N = 6`、`L = 20`）。**实现里 tile 是正方外框、边长 17 档可变**（默认 `--tile-cell: 260px`），
> 所以这个算式是**示例**而不是常量 —— 换档时 N 与 L 都要重算（由 JS 负责，见 `DESIGN.md` §12.6）。

### 4.5 全局反馈规则（新增，2026-09-15 用户指定）

```text
鼠标指向          →  辅色底
切实被点击后      →  主色底
已有主色底时指向  →  保持不变（不回落成辅色底）
```

**这是跨模块的全局规则**，适用于任何可交互元素（列表行、树行、卡片、图标按钮、分段控件、磁铁方块…）。
完整定义与色值见 `DESIGN.md` §5。

**要点（界面表达不出来）**：

1. **指向与点击用不同色相**（辅色黄 vs 主色绿）。这比单纯改深浅强得多 —— 用户一眼能分辨
   「我只是划过」与「我已经选定」。
2. **`DESIGN.md` 原本还有一条「hover 用极淡前景色」的旧定义，已被本规则取代。**
3. 本规则与旧稿的冲突点：原 §3.1.1 的「选中行用辅色淡底」已作废 —— **辅色底现在专用于 hover**。

### 4.6 选中状态的跨面板同步与树的展开策略

**完整规则见 `DESIGN.md` §12.4 / §12.4.1**，这里只强调两条容易实现错的：

1. **`最近` 与 `来源树` 的「选中」是同一个状态**。选中 `D:\Photos` 后，若「最近」里也有这条，
   它必须一并显示选中；「最近」里**其他条目不得**有任何选中态（不要让人误以为多选）。
2. **不要为了显示选中而强制展开树**。展开与否**只跟用户操作有关**：
   树没展开到那一层时那些行根本不存在，自然不会显示选中态；用户展开后再如实上色。

### 4.8 按时间分组与批量排除（2026-09-15 新增）

完整规格见 `DESIGN.md` §12.7。演示版面：`Demo / 按时间分组 + 批量排除`（`omXCA`）。

#### 4.8.1 `按时间` 按钮

位于 `GridControlBar` 里、**缩放滑块左边**。形态与吸附磁铁一致（**可按下式，不是左右切换的圆点开关**）：
未按下时与背景同色（平的），按下后**主色底**。

#### 4.8.2 两级分组规则

```text
一级：按拍摄日期分组（本地日期）  → 一天一组
二级：该天内按拍摄时间升序，相邻两张间隔 > 1 小时 → 断为新片
```

- **「1 小时」必须是配置项**，不要写死在代码里。
- **拍摄时间缺失**的照片：归入「未知时间」组放在最后，**不参与时间片切分**。

#### 4.8.3 为什么要做时间片

一次导入往往包含「同一场活动的多段拍摄」（上午出门、下午回来、晚上又拍）。
只按「天」分组太粗（一天可能上千张），只按「张」又太细。**时间片正好对应「一次连续拍摄」**，
也就是用户心里天然的分段 —— 所以它应该是**可一键选中的单位**。

#### 4.8.4 批量排除（取代 tile 上的单张排除）

**操作流程变成：先选择 → 再按顶部排除**。

| 选择方式 | 用途 |
| --- | --- |
| 单张点选 / `Shift` 区间 / `Ctrl` 增减 | 常规 |
| **点日组标题的「全选当天」** | 一整天不要 |
| **点时间片标题的「全选此段」** | 只要剔掉某一段（如当天最后一波） |

选中后，顶部 `toolsbar` 的按钮（**内容居中**）—— **只有一个按钮，没有独立的「反排除」**：

```text
批量排除 = 反转操作
  对当前选中的照片：未排除 → 排除；已排除 → 取消排除
```

| 状态 | 表现 |
| --- | --- |
| 有选中 | `批量排除`（普通态，可点） |
| 无选中 | **禁用态**（前景降到次级色） |

> 曾经把它设计成「选中项已排除时按钮文字变成『反排除』」，**用户否定了这个做法**。
> 它就是一个语义固定的**反转**动作，文字也恒定。

**为什么把排除从 tile 移到 `toolsbar`**：排除真正有用的场景是**批量**的（「这一天的都不要」），
而不是一张一张点。移到顶部后可以一键完成「把选中的未排除项排除、已排除项恢复」，
而且不再需要在每张缩略图上挂一个小按钮 —— 缩略图也变干净了。

`toolsbar` 原有的「筛选」占位按钮**已移除**（用户要求），换成批量排除。

## 6. 实测的工具约束（影响后续设计方式）

### 6.1 Pencil MCP 的操作约束

| 约束 | 说明 |
| --- | --- |
| **`.pen` 必须已在编辑器中打开** | 否则报 `A file needs to be open in the editor`。**Agent 无法自行新建 `.pen`** |
| 编辑器无打开文件 | 连 `pencil_get_app_state` 都失败（`Failed to access file "undefined"`） |
| `TakeScreenshot` 与写入**不能同调用** | 同一次 `execute` 里 `Insert` 后立刻截图会返回**空白**（渲染管线未更新）。必须拆成两次调用 |
| `Get(document, …)` 必须带 visitor | 否则被拒：「Reading the whole document without a visitor would return everything」 |
| execute 失败时**不要重发整段** | 用失败消息里的 `editId` + `edits:[{find,replace}]` 打补丁重跑 |
| 全局变量**不跨调用保留** | 每次 `execute` 独立作用域，跨调用只能用字面量节点 id |
| **`Insert` 的新子节点不会被已有容器的布局引擎摆位** | 实测：往 `RepoCard` 这类**已有且带 flexbox 布局**的容器里 `Insert` 新节点，子节点会停在容器外（`ctx.problems` 报 `fully clipped`，截图为空）。**用过 `Copy` 现成节点再改属性**就正常 —— 这也是技能文档「优先复制已有内容」的真实理由 |
| **flexbox 容器里 `x` / `y` 被忽略** | 手工定位没用（工具会明确提示 `x/y is ignored … inside a flexbox layout`）。要改位置只能靠布局（顺序、间距、填充）或把父级改成非布局容器 |
| **`bounds` / `problems` 可能是布局前的陈旧值** | 同一轮 `Insert` 后立刻读，几何数字与「被裁」判断都不可信；**结论以截图为准**，必要时下一轮再读 |
| 新变量**当场可用** | `SetVariables` 加的色值在同一次会话里立刻能渲染（实测未出现「要重开编辑器」） |
| **变量必须先于节点创建** | 实测踩坑：节点创建时若变量还不存在，`$surface-main` 这类引用会被**烤成 `#000000`**（不是报错、是静默变黑）。补救＝变量建好后再 `Update(id, {fill: "$..."})` 重挂一次（本轮一次性重挂了 162 处）。**新画布的固定顺序：先 `SetVariables` → 再画节点** |
| **画布没有 Tabler 图标集** | 画布只支持 `lucide` / `feather` / `Material Symbols Outlined·Rounded·Sharp` / `phosphor` —— 而**实现用的是 Tabler**。做法：**画布上用 lucide 当替身**（同为 24px/2px 描边，风格最接近），并在设计文档里写出**到 Tabler 的名字映射**，避免误导实现。另：Tabler 有 `-filled` 变体，画布上的 lucide 没有，点亮态只能靠颜色表达 |
| **帧可以用 `theme` 属性挂主题轴** | `theme: {mode: "dark", density: "compact"}` 是合法节点属性（schema `Entity.theme`），子树继承。但**它只解决「解析哪一个变体」，不能救被烤死的引用**（见上一条） |

### 6.2 令牌的两个限制（重要）

1. **`width` / `height` 不接受变量引用** —— 传 `"$bar-title-h"` 会被**静默丢弃**（不报错，但值不生效，
   实测读回 `undefined`）。`cornerRadius` / `padding` / `gap` / `fill` 等**可以**用变量。
   → **结论：密度轴（尺寸）在 Pencil 里无法用变量表达**，只能用字面量。
   因此设计稿的尺寸是**按紧凑档硬写的**，「宽松」档需要另出一版。
2. **主题可按节点设置** ✅ —— 给 frame 加 `theme:{mode:"light",density:"loose"}` 即可让整棵子树按该主题解析，
   并且**子树自动继承**。这正是同一张画布能同时渲染深浅两主题的原因（浅色版是 `Copy` + 覆盖 `theme` 得到的，
   **不是另画一遍**）。

> **对 `DESIGN.md` 的修正**：§8.2 末尾说「密度档位在 Pencil 里用主题轴实现」—— 对**颜色**成立，对**尺寸**
> 不成立（限制 1）。实现侧不受影响（`tokens.css` 里 `[data-density]` 照样能切换所有尺寸令牌）。
>
> **2026-09-16 升级为约定（`DESIGN.md` §8.4）**：既然尺寸在画布里只能硬写，
> 那就**以 `tokens.css` 的实现为准** —— 两档尺寸不再逐项同步回画布。
> 本 `.pen` 的职责收敛为：**结构 / 区域划分 / 控件放置 / 状态与交互**。
> 也就是说，画布与实现之间出现**纯尺寸**差异时不算偏离设计；
> 但**结构、状态、交互**的偏离仍然要先改 `.pen` 再改代码（`AGENTS.md` §5.1）。
