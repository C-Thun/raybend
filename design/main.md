## 2. 外壳（从上到下三行）

### 2.1 `titlebar`（应用标题行）— 节点名 `TitleBar` `hrAhp`

**形态**：沉浸式，**没有系统级程序标题行**，窗口拖动由应用内接管。高度 `32`（紧凑）。

| 位置 | 内容 | 节点 |
| --- | --- | --- |
| 左 | 应用图标（**占位**，20×20 品牌色圆角块 + `aperture` 图标） | `AppIcon` / `Glyph / aperture` |
| 左 | 应用名「光伴」13px `600` | `AppName` |
| 左 | 菜单「帮助」 | `MenuItem / 帮助 / hover` |
| 中 | **空白拖拽区**（`fill_container`，无内容） | `DragArea` |
| 右 | 主题切换（单开关，**不跟随系统**） | `IconButton / 主题切换` |
| 右 | 密度切换：横向多选 `紧凑` / `宽松` | `SegmentedControl / 密度` |
| 最右 | 最小化 / 最大化-还原 / 关闭 | `WindowControls`（3×46×32） |

**设计思路（界面表达不出来的部分）**：

1. **菜单只在鼠标指向标题行时才显示**（类似 VSCode 现在的行为）。设计稿里画的是**显示态**
   （`MenuItem / 帮助 / hover` 带 `$state-hover` 底），因为静态稿无法表达悬停触发。
   隐藏态＝这一行整体不存在，拖拽区向左扩展。
2. **帮助菜单点开后只有一个选项「关于」** —— 界面上没有画下拉，因为只有一个选项没有分层价值。
3. **主题切换是「只有一个开关」**，不做「跟随系统」这个第三态（用户明确要求）。
   图标显示当前模式的语义（深色时显示 `moon`）。
4. **窗口三键的悬停态**（关闭键变红）属于 Windows 平台惯例，未在此稿体现；若要保留需在 `DESIGN.md` 补一个
   `danger` 令牌，不能硬编码色值。

### 2.2 `flowbar`（工作流行）— 节点名 `FlowBar` `uVSjs`

**形态**：高度 `44`（紧凑），**这一行的风格刻意与界面其他地方不同 —— 更圆润**（轨道与选中块都是胶囊形）。

| 位置 | 内容 | 节点 |
| --- | --- | --- |
| 左 | 工作流切换：`导入` `浏览` `编辑` `导出`（图标 + 文字） | `SegmentedControl / 工作流` |
| 中 | 空白弹性区 | `SpacerFlex` |
| 右 | 图片信息区（Exif） | `ExifStrip` |
| 最右 | 开关组（当前只有 `吸附`） | `Switch / 吸附` |

**工作流切换的方向性**：`导入 → 浏览 → 编辑 → 导出` 是一条**有明确先后顺序的流水线**
（类似 DaVinci 的页面切换），不是并列的多选项。这决定了：

- 顺序**从左到右固定**，不因「最近使用」而重排；
- 当前项用品牌主色实色胶囊（`导 入`），其余为次要色 —— 视觉上一眼看出「我在流水线的哪一段」。

**图片信息区（Exif）的分组**：分组是**内容本身的结构**，不是视觉随意切分。
鼠标划过时同组边框一起亮起，用户能看出哪些信息是一组（`easy copy`，见 §4.1）。

| 组 | 内容 | 设计稿示例 |
| --- | --- | --- |
| 组 1 | 机型 + 镜头 | `DC-G9` · `LEICA DG 12-60mm F2.8-4.0` |
| 组 2 | 焦段 + 光圈 + 快门 + 感光度 | `12mm · ƒ/2.8 · 1/125s · ISO 200` |
| 组 3 | 尺寸 + 像素数 + 格式 | `5184 × 3888 · 20.2 MP · RAW` |

- **色彩空间信息刻意省略**（用户指定）。
- 排版采用「**值 + 间隔点**」而不是「标签 + 值」，因为这一行高度有限且值本身有强可识别性
  （`DC-G9` 一眼就是机型）。语义靠 `easy copy` 的分组框与 Tooltip 补足。
- 机型用正文色（`$fg-1`）、其余用次要色（`$fg-2`）：机型是这张照片最关键的识别信息。
- **设计稿里组 1 带 `$state-selected` 底** —— 这是为了在静态稿里示意 `easy copy` 的悬停分组框；
  实际交互中该底色**不出现**，只有 `easy copy` 的细边框（见 §4.1）。

**关于开关组**：当前只放 `吸附` 一个，作为「以后会加」的位置占位。开关轨道用品牌主色表示开启。

### 2.3 `toolsbar`（工具菜单行）— 节点名 `ToolsBar` `U6cvt`

**形态**：高度 `32`（紧凑），与 `flowbar` 同面（`$surface-main`）→ 视觉上连成一体。

- **有内容时显示，无内容时整行隐藏**；内容**跟着工作流走**。
- 当前在 `导入` 下放了一个**占位按钮**「筛选」（`list-filter` 图标 + 文字）。

## 3. 工作区 `workspace`（导入）

**三列布局**，完全跟着工作流走。左、右列用 `$surface-main`，**中列用 `$surface-bar`**
（浅色主题下中列更深、深色主题下中列更浅）→ 两种模式下中央都形成聚焦。

| 列 | 节点 | 宽度 | 面 |
| --- | --- | --- | --- |
| 左：Source | `Panel / Source 左列` `xuAqM` | `320` | `$surface-main` |
| 中：图片区 | `Panel / ImageGrid 中列` `OJtmE` | 弹性 | `$surface-bar` |
| 右：库 | `Panel / Repositories 右列` `eUtf2` | `300` | `$surface-main` |

### 3.1 左列：Source（上中下三段，可拖拽）

三段顺序：`最近` → `来源` → `已选目录`。
**段与段之间是 `SplitHandle`（一排 `...` 三点的细空白区，高 11px）**，这就是拖拽区 ——
位置刻意放在「上接内容区、下接块标题行」之间。

#### 3.1.1 `Recent`（最近）— `PanelBody / 最近` `F8HPE`

- **不需要用户自己添加收藏**：每次导入的目录自动记录，**记录最近 50 条**，
  每条背后存**完整路径**。
- 显示的是 **`shortpath`**（见 §4.3），完整路径由 Tooltip 在悬停时给出。
- **两个独立的状态，不要混用**：

  | 状态 | 表达 | 含义 |
  | --- | --- | --- |
  | **勾选** | 左侧**圆形主色勾选框** | 这条目录**加入待导入**（出现在下方「已选目录」区） |
  | **选中** | 整行背景**辅色淡底**（`#EECC5526`） | 中间图片区**正在浏览**这条目录 |
  | 移除 | 行**最右**的**禁行图标**（悬停才出现） | 从最近列表移除 |

- 点击某条 = 选中 + 中间图片列表显示**该目录下的图片**（不显示其他文件）。
- **勾选可多选；选中全局同时只有一个**（因为中间只能展示一个目录）。Recent 与 Source 树的选中状态**必须同步**。

#### 3.1.2 `Source`（来源树）— `PanelBody / 来源` `fdym0`

- **树形结构，按操作系统适配**（当前只做 Windows，但结构上预留）。
- Windows 第一层依次列出**所有驱动器**。**不能只标盘符** —— 前方必须有**来源类型图标**，
  因为未来会扩展到 NAS、云盘等不同来源。设计稿里特意画了 `server`（群晖 NAS）与 `cloud`（OneDrive）
  两条，用来确认「不同类型来源靠图标可辨」。
- **只显示目录，不显示文件**；可逐级展开（`chevron`）。
- 每条左边是**与 Recent 同款式的圆形勾选框**；勾选与选中语义同 §3.1.1。
- **注意**：树里点击某目录后，中间图片区列出的是**该目录直属的图片（仅可识别图片类型），不下钻子目录**。

#### 3.1.3 `已选目录`（可伸缩）— `PanelBody / 已选目录` `VBx6T`

- **默认不显示**；每勾选一个待导入目录就出现一个 tile。
- **自动换行的 tile 流**（`TileRow / 1` `UOns4`、`TileRow / 2` `yH0zx`）。
  换行算法见 `DESIGN.md` §12.6：列数 `N = floor((W+gap)/(cellW+gap))`，
  **剩余空间 `L` 全部作为右边距**，不做居中、不做拉伸。
  设计稿参数：tile `94×96`、gap `8`、容器内容宽 `320−2×10=300` →
  `N = floor((300+8)/(94+8)) = 3`，`L = 300 − (3×94 + 2×8) = 2`。
- 每个 tile：**文件夹图标** + **`shortpath`** + **「包含子目录」勾选框**（**默认不勾**）。
- **移除**：鼠标指向 tile 时，**右上角浮现禁行图标**（`TileRemoveBadge / hover`）。
  这是 `easy destroy` 范式的一个应用点 —— **是「移除」不是破坏性删除，所以用禁行图标而不是叉**。

### 3.2 中列：图片展示区 — `Panel / ImageGrid 中列` `OJtmE`

- **只展示图片，不包含目录**。这是**精简版**：图片 + 文件名（+ 文件类型）。
  **不含标色、星标、评级** —— 那些统放到顶部 `toolsbar` 里做。
- 组件本身要做成**通用组件**（`PhotoGrid`），浏览模块会复用。
- 底部 `GridControlBar`（`q1fSV`）**放在列底部**，目前至少包含：**计数**（`1 248 张`）与 **tile 尺寸缩放**滑块。
- 每张图 tile 右上角有**排除**按钮（`ExcludeBadge / hover`，悬停浮现，同样是禁行图标）。

**图片展示区的交互（界面表达不出来，必须文字记录）**：

| 操作 | 行为 |
| --- | --- |
| 双击 / 选中后回车 | 切到**图片查看** |
| `Esc` / 再按一次回车 | 返回 tiles 列表 |
| 鼠标双击 | 在**适合屏幕**与**放大到 100%** 之间切换 |
| 滚轮 | **平滑缩放** |
| 鼠标移到**左上角区域** | 浮出**返回按钮**，作用同退回 tiles 列表 |
| 本区域 | 与编辑模块不同，**只要有简单的缩放拖动即可** |

**排除操作的区间语义（重要，容易实现错）**：

- 点击某张图的排除按钮 → 排除该图。
- **点击第一张的排除后，按住 `Shift` 再点另一张的排除** →
  **这两张之间的所有文件都被排除**；
  而**这两张之间原本已被排除的，则被反选（取消排除）** —— 这是一个「区间反转」，不是「区间全选」。

> 注：浏览模块下，图片查看会在**下方显示胶片界面**（横向摆放的当前目录照片列表），上方才是图片查看，
> 且支持 `Ctrl` 点击多张**直接对比** —— 这部分以后再说，本稿不体现。

### 3.3 右列：库 `repositories`

- **这里不是文件树，而是所有库**。以**高度较高的横向组件**（卡片）表示。
  - `RepoCard / Kowloon Studio` `sivH3`、`RepoCard / 个人相册` `PQcw4`
  - 卡片内容：库图标 + 库名 + 库路径 + 照片数量
  - **选中的库**用 `$state-selected` 底 + 品牌色图标块 —— 同屏只有一个库被选中
- **没有库就无法导入**：必须先建库。
- **建库入口**暂时放在库列表**最下面**，做成「一个 `+` 号库」的样子（`CreateRepoCard` `P2PiT`）。
  以后支持多种库时，点击创建 → 先选类型 → 再按类型弹不同窗口（当前不走这套）。
- **最下面是导入按钮**（`ImportButton / 可点` `MC0Gt`）：
  - **必须左边（已选目录）与右边（库）都选中后才亮起可点**；
  - 同处有一个**默认勾上**的「避免重复导入」勾选项（`AvoidDupRow`）。

## 4. 通用交互范式在本稿中的落点

### 4.1 `easy copy` — Exif 信息区

| 阶段 | 表现 |
| --- | --- |
| 悬停某个信息组 | 该组加**一圈淡淡的细边框**（固定用**品牌主色**，约 40% 透明度），同时内容**上方紧挨着**弹出 `点击复制` 标签式小窗（窄 padding） |
| 弹出动画 | **由下向上**弹出（`translateY` + 淡入） |
| 点击 | 复制**整组**内容到剪贴板；`点击复制` 小窗**再向上弹**，紧接着下方**又弹出一个** `已复制` |
| 离开 | 边框与提示淡出 |

**「同组边框一起亮起」是核心**：用户因此能看出哪些信息是一组。
实现参考 `/home/andares/repos/zzd/vue-admin/src/components/project2/P2CopyText.vue`
（Vue 的 `P2Tip` + `flip()`；本项目是 Solid，需自行实现等价物）。

> **设计稿要不要做演示？** 本稿**只在组 1 上加了 `$state-selected` 底**作为静态示意，
> **没有**画出 `点击复制` / `已复制` 气泡与细边框。
> 理由：这两个元素是**浮层 + 动效**，静帧画出来反而容易被误读为「常驻元素」，
> 且它们应当做成 `Tooltip` 基础组件的一部分（见 `DESIGN.md` §10.1 #7）。
> **建议**：等基础组件画完后，单独出一张 `easy copy 状态演示` 的小画板，把 4 个阶段并排画出来。
> 若你认为没必要，可以跳过 —— 我在 `DESIGN.md` §12.1 已把行为写全，实现时不会歧义。

### 4.2 `easy destroy` — 三个应用点

**默认弹窗确认；按住 `Shift` 点击则跳过确认。**

| 应用点 | 节点 |
| --- | --- |
| Recent 条目移除 | `RemoveBtn / hover` `R8LDk` |
| 已选目录 tile 移除 | `TileRemoveBadge / hover` `ouRlb` |
| 图片排除 | `ExcludeBadge / hover` `y9C92a` |

**统一用「填充圆 + 一条横杠」的禁行图标**（`Material Symbols Rounded` 的 `do_not_disturb_on`），
**不是叉号** —— 因为它们都只是「移除出当前集合」，不做磁盘操作。

### 4.3 `shortpath` — 本稿中的实例

```text
盘符 + 中间各级目录的首字母 + 最后一级目录的全名
```

| 完整路径 | shortpath（设计稿中显示） |
| --- | --- |
| `D:\Photos\2024\Vacation\Japan\Kyoto` | `D:\P\2\V\J\Kyoto` |
| `D:\Photos\2022\Wedding-Studio` | `D:\P\2\Wedding-Studio` |

- Linux / macOS 下**第一级与最后一级写全**，中间同样取首字母。
- **两层算法**（必须如此）：① 只缩中间各级，保留首尾；② 仍超长则**放弃 ① 的结果整体重缩**。
  不能直接在 ① 的结果上继续截断 —— 若首级或末级本身很长，已生成的 `...` 会在某一侧「戳出来」。
- 生成组件要支持**传入长度上限**。

### 4.4 `Tile` 流换行

见 §3.1.3 与 `DESIGN.md` §12.6。设计稿中 `TileRow / 1` 放 3 个、`TileRow / 2` 放 2 个，
用来示意「**除最后一行外每行列数相同**」这一约束。

## 6. 实测的工具约束（影响后续设计方式）

### 6.1 Pencil MCP 的操作约束

| 约束 | 说明 |
| --- | --- |
| **`.pen` 必须已在编辑器中打开** | 否则报 `A file needs to be open in the editor`。**Agent 无法自行新建 `.pen`** |
| 编辑器无打开文件 | 连 `pencil_get_app_state` 都失败（`Failed to access file "undefined"`） |
| `TakeScreenshot` 与写入**不能同调用** | 同一次 `execute` 里 `Insert` 后立刻截图会返回**空白**（渲染管线未更新）。必须拆成两次调用 |
| `Get(document, …)` 必须带 visitor | 否则被拒：「Reading the whole document without a visitor would return everything」 |
| execute 失败时**不要重发整段** | 用失败消息里的 `editId` + `edits:[{find,replace}]` 打补丁重跑 |
| 全局变量**不跨调用保留** | 每次 `execute` 独立作用域，跨调用只能用字面量节点 id |

### 6.2 令牌的两个限制（重要）

1. **`width` / `height` 不接受变量引用** —— 传 `"$bar-title-h"` 会被**静默丢弃**（不报错，但值不生效，
   实测读回 `undefined`）。`cornerRadius` / `padding` / `gap` / `fill` 等**可以**用变量。
   → **结论：密度轴（尺寸）在 Pencil 里无法用变量表达**，只能用字面量。
   因此设计稿的尺寸是**按紧凑档硬写的**，「宽松」档需要另出一版。
2. **主题可按节点设置** ✅ —— 给 frame 加 `theme:{mode:"light",density:"loose"}` 即可让整棵子树按该主题解析，
   并且**子树自动继承**。这正是同一张画布能同时渲染深浅两主题的原因（浅色版是 `Copy` + 覆盖 `theme` 得到的，
   **不是另画一遍**）。

> **对 `DESIGN.md` 的修正**：§8.2 末尾说「密度档位在 Pencil 里用主题轴实现」—— 对**颜色**成立，对**尺寸**
> 不成立（限制 1）。实现侧不受影响（`tokens.css` 里 `[data-density]` 照样能切换所有尺寸令牌）。
