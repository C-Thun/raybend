# design/editor.pen 说明书

RGB 软打样增加输出选择与目标色域警告，默认关闭，复用输出 ICC 库；相对色度且经 LCMS 双向参考验证的矩阵/TRC 目标才可启用。关闭、准备失败与设备恢复均不污染照片状态。新增统一命令：打开色彩管理、恢复自动输入、切换打样、切换色域警告；默认热键留空（专业低频，避免占编辑键）。预设保存新增色彩管理组，默认不选，仅高精度照片可保存；记录自动/指定输入策略和处理版本，不复制某张原片的内嵌配置、屏幕或打样。应用整份预设先在后台解析输入，失败不改其它组。

## 2026-10-04 色彩管理输入操作闭环

沿用第 3 组色彩页签和共享 ProfileSelect，新增“应用输入 / 恢复自动”。选择先为草稿，应用时 Rust 后台检查 RGB/RAW 相容性、透明通道、ICC 可用性，再固化输入并提交现有撤销历史；失败保留当前画面和历史，提示原因。原命名定稿不重写。无照片/锁定/准备中禁用操作，准备中状态明确。原片内嵌优先；恢复自动是本次重新解析并固化，不依赖将来的全局默认。屏幕状态只读，不进入定稿。高精度版本高质量降噪已接入同一可取消后台任务；准备中显示状态，拖动继续使用快速结果，不等待高质量任务。软打样仍有独立能力闸门。

采用现有主/辅反馈、密度与 Ark/原生选择器，无新控件风格。输入选择是照片上下文属性，无独立默认热键，配置资源入口复用全局设置命令。

### 3.1 workspace left —— 上：LUT / 定稿 面板（`prompts/editor.pd`；2026-10-12 改版）

#### 3.1.A LUT 面板（默认开）

- **占据整个 left、不可调宽**（没有拖拽把手），画布取 **280px**（紧凑档）。
- **默认打开**（人类 2026-09-23 定），且**开关状态要持久化**（设备级偏好：版本化 key + 一次性迁移，
  照 `AGENTS.md` §2.16 的口径，不要每次启动重置）；v3 起偏好存的是**左列面板意图**
  （`lut` / `issues` / `null`），v1 的 LUT 分类只读取一次。
- **一个 `LUT` 标题行**：进度为「新建分类」+「导入 LUT」两个图标按钮（都在行尾）。
- 下面是**一级分类**列表，每个分类一行标题（chevron + 名称 + 数量），点标题展开 / 收起；
  展开时**其他分类自动收起**；再点同一个标题可以全部收起。
- 展开后是 **一行 2 个 LUT tile**：上面是**该 LUT 的封面图**（口径见 §3.1.1），下面是 LUT 名。
  **当前底层（点选出来的那一支）**用 1px 主色内描边表示；**是否在应用层里**由右上角圆圈表达（见下）。
- 标题下方有独立的 **应用 LUT** 开关（整条链的总开关）；选中的链与开关一起写入 latest。关闭开关保留整条链，重新开启即恢复。
- **应用层列表（2026-10-31 新增）**：夹在「应用 LUT」开关行与分类列表之间，**空态整块不存在**。
  每行 = 缩略图（4:3，占满两层高）+ 右侧上层（名称 + 单层开关）+ 右侧下层（强度拉杆 + 留空的删除位），
  自上而下 = 逐层处理顺序。详见 §3.1.3。
- **点 tile = 把它换到第 1 层**（不是「选中并替换唯一一支」）：它在链里就移到第 1 层，不在就替换当前第 1 层。
  封面本身不参与当前照片的实时计算。导入失败或应用内 LUT 文件丢失时，显示明确的不可用状态，不静默套用另一支 LUT。图库移除只隐藏条目，保留文件，已有编辑引用继续生效。
- tile 的封面固定 **4:3**，名称行显示导入文件名；同名文件导入后以内部唯一 ID 存储，不靠文件名定位。

#### 3.1.2 导入 LUT 的进度（2026-10-30 新增，崔总口述）

原问题：导入窗口里**只有分类选择，没有任何进度**；目录里 LUT 一多，复制那几秒界面像死了一样。

口径（与 `Dialog / 导入进度` 共用同一套进度语言，`design/main.md` §3.5）：

| 阶段 | 能知道什么 | 界面 |
| --- | --- | --- |
| **扫描** | 还不知道总数 | 说明行「正在扫描目录…」+ **不确定态进度条**（一道来回跑的亮条，不编百分比） |

- 分类选择在导入期间**禁用**（这一批已经定了往哪儿放，中途换分类只会让人以为会改）。

#### 3.1.3 应用层（多层 LUT）—— 2026-10-31 崔总口述

**画稿**：主稿 `P1JiB` 的左列 + `Components / Editor / LUT 应用层`（`pj0oo`）。
**位置**：`应用 LUT` 开关行与分类列表之间；**空态不占位**（与改动前完全一致）。

##### 两条选择通道（不要混用）

| 手势 | 含义 | 视觉 |
| --- | --- | --- |
| 点 tile 本体 | **把它换到第 1 层**（底层）；已在链里则**移到第 1 层**，不出现重复 | 该 tile 的封面 **1px 主色内描边** |
| 点 tile 右上角圆圈 | **加入 / 移出**应用链（不动第 1 层） | 圆圈：空（悬停出现）/ 实心主色 + 勾（在链中，**常显**） |

- 只有**指向 tile** 时才出现「空圆圈」；已经在链里的那一支，圆圈**始终显示**（否则又要滑一遍才能找到谁在用）。
- 勾选与选中是两件事（`AGENTS.md` §11.2）：一支 LUT 可以「在链里但不是第 1 层」。

##### 应用层每一行（高 54，紧凑档）

```text
┌────────┬────────────────────────────────┐
│        │ Kodak 2383              [开关] │  ← 上层：名称 + 单层开关
│ 缩略图 │ ──────●────── 100%        [⨂] │  ← 下层：强度拉杆 + 数值 + 删除（指向才显）
└────────┴────────────────────────────────┘
```

- **缩略图**：56×42（4:3），左、上下贴行内边距，占满两层高（与分类里的封面同一个 `LUTPreview` 取图口径）。
- **上层**：名称（超出右缘渐隐）+ **单层开关**（关 = 旁路该层，不删）。
- **下层**：**强度拉杆**（与曝光/反差同一套 `Track / TrackBase / TrackFill / Handle`，默认 **100% 且在最右**）+ 数值（tabular）+ **删除位**。
  - 删除位**每行都占位**（14×14）—— 只在指向时才画出禁行图标；不占位的话数值列会在悬停时左右跳。
  - 双击拉杆 = 回到默认 100%。
  - 删除 = 从链里移除（不是删除文件）；与非链场景一样使用禁行图标（§11.3）。
  - **强度写入即定开关**（2026-10-31 崔总定，2026-11-01 改成「写入即定」）：拉到 **0% = 关掉该层**
    （开关同步变灰）；该层关着时把拉杆拖到 **>0% = 自动打开该层**。只动这一层，
    **与顶部总开关无关**。判定放在数值写入的同一步，不依赖手势收尾 —— 手势收尾只是
    多记一个撤销节点（`lib/slider-gesture.ts`，不用 Zag 的 `onValueChangeEnd`）。
  - **反向也补同一条**（2026-11-01 崔总定）：**不存在「开关开着但强度 0%」的层** ——
    把 0% 的那层点开关打开时，强度**直接给回 100%**（否则得到的是「开着却什么都没发生」的层）。
    总开关关着时这条联动照常生效，但整条链照旧不参与渲染。
- **拖动整行排序**：松手才落库（撤销的一个节点）。拖动时**整行本体变成跟随光标的幽灵**
  （`surface-layer` + 主色细描边，`position: fixed`），**落点槽位**画一块 `state-selected` 占位块，
  其它行用 140ms 过渡上下让位；指针到滚动区上下 24px 内自动滚。
- 行与行间隔 6，行容器 `surface-track` + 圆角 4（比面板的 `surface-main` 低一级，与「卡片进凹槽」的既有口径一致）。

##### 语义与边界

- **总开关**（顶部 `应用 LUT`）只控制整条链是否参与渲染：关闭**不清空**链（与现状「关闭开关保留选择」同口径）。
- **空链** = 与改动前完全一样：没有这一块、没有额外空白。
- **单层开关全关 + 总开关开** = 等同无 LUT；不弹提示、不自动关总开关。
- **删掉第 1 行**：下一层顶上成为新的底层（不在 UI 层特判，由有序表自然得出）。
- **替换底层**（点一个新 tile）：新底层用默认 `开 + 100%`，不继承旧底层的强度/开关（避免「换了支 LUT 却只剩 30%」）。
- **缺文件**：某层 LUT 文件丢失时该层置为不可用（行上显示不可用态），不整链失败；其余层照常渲染。
- **顺序敏感**：链的顺序、每层开关与强度都要进 profile hash（否则重排不失效缓存 → 串图），并随 issue / preset / XMP `rb:profileJson` 一起存。

##### 待崔总定的点（画稿已按括号里的倾向画）

1. 替换底层时强度/开关**重置为默认**（倾向）还是继承旧的？
2. 删除第 1 行：**下一层顶上**（倾向）还是清空整链？
3. 同一支 LUT 允许在链里出现两次吗？（倾向不允许：点同一支 = 移到第 1 层）
4. 链长上限（倾向 8 层；GPU 每层一次 3D 采样，8 层仍可实时）。
5. 行内强度拉杆要不要显示「强度」标签？（按 §2.20 不显示：那是无变量的固定说明文字。）

#### 3.1.1 LUT 封面（效果图）—— 人类 2026-09-25 定

**封面在导入时烘焙并存储，读取有效缓存时不重新处理照片。**
编码版本升级或缓存丢失时，首次读取自动重建一次；伴生原图随 LUT 复制留存。
理由：tile 渲染零成本；LUT 原文件被移动 / 删除后封面仍然可显示。

> 这一条**取代**了原先设想的「用当前照片的 SOOC 缩略图实时套 LUT」。

**两种来源**（优先级自上而下）：

1. **LUT 自带的演示图** —— 导入目录里与 `.cube` **主文件名同名**的图片，
   按 `jpg` → `jpeg` → `png` → `tif` → `tiff` → `avif` → `webp` 的优先级取第一张。
   这类图是 **LUT 作者已经套好效果的展示图**，我们**只做几何处理，不再套 LUT**。
2. **回落：内置固定样片**（`lut-sample`）—— 没有自带图时，用固定图**套上该 LUT**再烘焙。
   固定图由人类提供，规格 **768×576（4:3）**。

**几何**：自带演示图按原图尺寸分两档，判据如下。
内置固定样片生成的效果封面固定 **384×288**：先在完整样片应用 LUT，再缩图。

| 原图条件 | 目标尺寸 |
| --- | --- |
| `w ≥ 768` 且 `h ≥ 576` | **768×576** |
| 否则（小图 / 竖图 / 超宽图） | **384×288** |

算法一律 **cover**：`scale = max(target_w / w, target_h / h)` → 按 `scale` 缩放 → **居中裁切**目标尺寸。

> **判据等价性**：`w ≥ 768 && h >= 576` 与「cover 缩放比 ≤ 1（不需要放大）」完全等价。
>
> **为什么是 cover 而不是「先缩到宽 768 再截中间 768×576」**：后者对 16:9 这类图不成立
> —— 1920×1080 缩到宽 768 只有 432 高，裁不出 576。cover 对 4:3 的原图与上述描述结果一致，
> 对其它比例也能给出正确结果。

**编码**：一律 **WebP 质量 80**（官方 libwebp 编码器）。下采样用 Lanczos3。
封面缓存版本与原图来源记录在 LUT 私有目录的 `cover-meta.json`；不是业务配置，不改 DB schema。
旧版本未记录来源且外部源目录已经丢失时保留旧封面，避免把作者自带的演示图替换为统一样片。

### 3.4 三个工具（`toolsbar center`，互斥，同一时刻只有一个控制块）

**共同线型**（人类指定）：**中间 2px 浅色线，两侧各 1px 深色线** —— 保证压在任意照片内容上都清楚。
画布上落在两个新变量 `$overlay-line`（浅）与 `$overlay-halo`（深）上（**两主题同一值**，
因为它们压在**照片**上、不压界面面；见 `memory/DESIGN.md` §9.2 的新条目）。

| 工具 | 框线 | 把手 | 右栏控制块 | 退出方式 |
| --- | --- | --- | --- | --- |
| **裁切** | 4px「深-浅-深」线 + **井字主色线** | **四角 + 四边中点**都有加粗外框线 | 比例下拉（自由/原始比例/1:1/3:2/2:3/4:3/16:9/自定义…）+ 反转比例 + 取消比例限制 + 横/纵两个输入 + 取消/确认 | ① 控制块「取消」② 再点一次 toolsbar 上的裁切 ③ `Esc` |
| **旋转** | 同上但**井字线改用辅色**、**没有加粗把手**（一眼区分「这是旋转不是裁切」） | 无 | 角度拉杆（默认把手在正中，左逆右顺，最大 ±360）+ 重置 + 提示「在画面中拖一条水平线可自动摆正」+ 取消/确认 | 同上 |

**几何边界（都不可越界）**：
- 裁切框最大只能在图像范围内（画布上画的是一张 3:2 照片里缩进后的框；真实默认是**撑满**）；
- **对比左侧来源**：状态栏同一个下拉中选择 SOOC、RAW 或本照片的命名定稿；定稿行显示名称和 RAW/SOOC 基准，选择后异步读取该定稿独立的 1920 预览。快速改选或换照片时只接受最新选择，旧预览不得覆盖；SOOC 不存在时标出实际的 RAW 参考帧。展开态见 `Components / Editor / 对比来源菜单`。
- **水平工具框坐标**：裁切框、旋转框、拉直线和对比分线由 Rust 用现有视口坐标计算，在照片的同一个 GPU render pass 中绘制；不再依赖 250ms 状态轮询绘制 DOM 线。未来图像像素锚定的 DOM 覆盖物仍复用 `ViewportOverlay` 的矩阵。前端不算视口变换。
- **旋转之后再进裁切**（人类 2026-09-23 补）：打开裁切时显示的是**被旋转过的原图画布**
  （不是水平化之后的），裁切框**只能在“有像素”的范围内拖** —— 即边界是旋转后画布的边缘，
  而**不是**那个水平展示框。
  > 画布上 `States / Editor / 裁切` 画的是**未旋转**的简单情形（好读）；
  > 「旋转后再裁切」是同一个工具在另一个几何下的表现，本版没有单独画帧。
- 旋转时**展示框保持水平**、且随角度增大而**按原画幅比例缩小**，保证框内不出现空白 —
  **框就是成片边界**（画布上：斜着的画布铺满视口 → 水平内接框 → 框外压暗）。
  ⚠️ 这条 2026-09-23 被人类纠正过一次：**框不能小于画布**，
  早期的画法（斜照片浮在视口里、框再套在里面）是错的。

**对比的 statusbar**（人类指定）：左边显示 **`SOOC`（主色按钮状，点开可换其他 issue，
未来完善）**，右边显示**当前结果**。画布对比帧里这一条已经这么画了。

## 8. 画布操作约束（本轮实测，接着 `browse.md` §4 补）

| 约束 | 说明 |
| --- | --- |
| **跨文件 `Copy` 不可用** | `Copy("PRpZa", …)` 在 `editor.pen` 里报 `Can't find node` —— **画布之间互不可见**，外壳只能在本文件重搭（结构可从 `browse.pen` 读出来照抄） |
| **`Get(id)` 拿到的是纯 schema 数据** | 可以直接 read → 手工改 → 重新 `Insert`，但**不能跨 execute 调用保存变量**（下面那条） |
| **变量不跨调用** | `myId = Insert(...)` 里的 `myId` **下一次 `execute` 就没了**（与官方 skill 描述不符），要么写死 id、要么重新按名字找 |
| **`Update(id,{fill:undefined})` 清不掉属性** | 要把「曾经的主色底」清成无底，得显式 `fill:"$surface-track"`（与凹槽同色 = 看上去没有底）。本轮踩过：页签改文案后旧的主色底留在别的项上 |
| **`TakeScreenshot` 不可靠** | 同一批改动里截图常常拿到**空白**；换到「只读 + 截图」的独立调用里稳定得多 |
| **`Export` 比截图可靠** | `Export([id],"png","/tmp/pen-shots")` 落盘后用图片查看器看，清晰度也更高（2x） |
| **渲染有高度上限** | 节点在 `y ≳ 1900` 之后截图/导出会**整块空白**（疑似渲染纹理高度限制）。画布已按此把帧排进 `y ∈ [0,1870]` |
| **图标库** | 画布只有 lucide / feather / Material Symbols / phosphor；**没有 Tabler**。实现用 Tabler，映射见 `design/browse.md` §3。LUT 用 `palette`（实现建议 `color-filter`） |

### 3.8 W6c：定稿、切换与缓存（2026-09-26；**latest 写入时机 2026-10-27 崔总修订**）

- **「最近编辑」行可点选**（2026-10-27）：点它读库里那份 latest 回切；高亮由后端返回的 `selection` 判。
- **「最近编辑」只在当前栈与所有定稿指纹都不同时出现**（2026-10-31）：刚定完稿那一刻它与那条定稿是同一份画面，
  整行不画；再改一格参数就回来。判据 `IssueLibrary.latestMatchesIssue`（后端算），前端只负责显示。
- 定稿按钮（2026-10-12 起在左栏底部，整宽主按钮）只在配置与所有命名定稿及 SOOC/RAW 原始源均不相同时可点；与自动保存的 latest 一致不影响定稿。按下打开命名弹窗，默认名由影调与色彩形容词组合，再附两位起的 36 进制序号；可手改名称。同名在当前照片内逐次自增。保存后右栏滚回顶部并切到“定稿”。

## 2026-10-09 定稿行的两行结构（崔总口述）

```text
┌──────┬─────────────────────────────────┬────┐
│ 缩略图 │ 名称（单行；超长右端渐隐，不撑行宽）    │ ✎  │ ← 对齐第一行
│      │ RAW · 2026-10-09                 │ 🗑 │ ← 对齐第二行
└──────┴─────────────────────────────────┴────┘
```

* 文字区恒为**两行**：第一行名称（`fs-2`），第二行基准 + 日期（`fs-0`）；两行同 `leading-5`（20px），
  合计 40px = 缩略图高，三块都在同一条 40px 的水平带上（行仍 `min-h-12`）。
* **第一行宽度受限、超出渐隐**：宽度由文字列给足，超出部分用 `styles/fade.css` 的 mask 淡出
  （不加省略号：省略号与渐隐叠在一起会糊）。没超出时渐隐区是空白 —— 看不出来。
  整名仍可在悬停提示（title）里读到。
* **第二行宽度受列约束**（超长才截断，带省略号）—— 基准与日期永远只占一行，不把行拉高。
* **动作列纵向排列**：上=改名、下=删除，与两行文字一一对齐（各 20px 高、`w-6` 热区），
  仍是悬停出现；中间文字区因此横向更宽。
* 生成中的占位行照同一结构（无动作列，预览位是转圈）。
* 废弃的做法（别回去）：第一行 `truncate` 省略号；两个图标横排；说明小字行。

## 2026-10-10 过渡帧口径（进编辑 / 切图先出图）

**过渡帧**=换照片时先画上去的「已经存在的图」（毫秒级），真帧（解码 + 管线，秒级）随后替换。
`specs/editor-session-pipeline.md` W1 把它从「有图先给」收敛成**契约**，三条：

1. **同版本（分三层）**：
   * **L1** 编辑栈非空 + `latest-<base>` 快照在 → 只用它；
   * **L2** 编辑栈为空（未编辑）→ 允许基准图（SOOC 位图 / RAW 内嵌预览）——真帧就是它的中性显影；
   * **L3** 编辑栈非空但快照不在 → **不出帧**，界面停在「载入中」。
   ❗ 废除了「有编辑栈却回退到 SOOC/RAW」的旧行为（那会先闪一张相机白平衡、无裁切、无 LUT 的图）。
2. **同画幅**：过渡帧的逻辑尺寸 = `geometry.output_size(原图尺寸)`（真帧将报的同一个值），
   `original_image` 单独报原图尺寸。裁切过的照片首帧不再被拉伸，真帧到达也不 refit 跳变。
3. **投递可靠**：过渡帧不受「最新任务号」支配（解码期间拖了拉杆不会被丢掉）；

## 2026-10-10 过渡帧的有意软化（崔总口述）

**背景**：过渡帧通常是 1920 预览；在高分屏 / 大窗口下它会被**放大**显示，而渲染侧的放大
采样是最近邻（1:1 档要看像素）——1920 被放大就成了马赛克。崔总：可以故意做个适当模糊，
「至少比空屏好」。

**口径**（两件事一起做）：

1. **过渡帧放大走线性采样**：`GpuContext::set_soft_preview(true)` 让下一次换图用线性放大的
   采样器；真帧到达置回 `false`（1:1 看像素不变）。只影响过渡帧，不动真帧。
2. **按放大倍率有意软化**：`transition_soften = clamp((倍率 − 1) × 0.75, 0, 1)`，
   倍率取 `Viewport::zoom_for_fit()`（Fit / Fill / 1:1 / Free 同一份数学）；
   软化核 = 3×3 可分离 `[w, 1−2w, w]`，`w = 0.25 × amount`，边缘复制不引黑边。
   倍率 ≤ 1（缩小或 1:1）不软；倍率越大越软，3× 以上封顶。

视觉上仍然**没有新控件**：软化只发生在「过渡帧」这一张临时图上，真帧一到即恢复清晰。
