## 2. 关键设计点（界面表达不出来的）

### 2.1 三行外壳

与 `design/main.md` §2 一致（titlebar 40 / flowbar 52 / toolsbar 40，紧凑档）。
`toolsbar` 在**浏览模式**下装配（`BROWSE.md` §3）：

```text
[筛选 可按下开关]  [旗标][移除所有旗标][★3/5][●色标×6][喜欢]  |  [标签]  [锁]
```

- **筛选**开关：形态与「吸附」一致（关=平的，开=主色底）；打开后它**后面所有控件**变成筛选语义；
- **标星**：示例是 3 星（前 3 颗主色、后 2 颗 `$fg-3`）；
- **标色**：5 个实心色点 + 1 个**空心圈**（无色）；点亮的那颗内嵌 `check`；
- 组与组之间只用间距（20px）分隔，**不加竖线** —— 平面布局、线条极少是既定风格。

### 2.2 左列：库目录选择器（`BROWSE.md` §4）

- **搜索条** → **紧缩库列表** → **库内目录树**，三段纵向；
- **库列表（**2026-09-18 人类逐条重述，实现已按此改**）**：
  - **≤3 个库**：只有缩起态，卡片区**高度只够内容**，**不画「查看所有库」**；
  - **>3 个库**：前 3 张 + 第 4 位**伪卡片**（与真卡同宽同高、同圆角同面，只有一行 `查看所有库`
    **靠卡片顶部**、上方留 8px），容器高度钉在 **3.5 张卡**上、`clip` 切掉下半截；
  - **展开态**：显示全部、可滚；**下面的目录树不是消失而是缩到最小值**（画布上就是底那一条
    `DirTree / 缩到最小`：一行提示 + 两行树行，实际实现为 `TREE_MIN_HEIGHT_PX = 88`）；
  - **移顶只在展开态**（点卡片本身才算，点齿轮不算）；收起靠三件事触发：
    **15 秒没再点库 / 在 browse mid 点了一下 / 切 flow**。
- **3.5 截断**：三个库卡片（60）+ 一条**半截条**（30），半截条里只写「查看所有库」；
- **库卡片**：图标块 / 库名 + 路径 / 数量 / **齿轮**；选中卡 = `$state-selected` 底 + 主色图标块；
- **目录树**：选中行主色底 + 主色文件夹图标；左侧 chevron 表展开态（**点名字=选中，点箭头=展开**，两个动作）；
  行尾 `⋯` 是「删除空目录 / 创建子目录」入口。
  **没有「整个库」入口** —— 点库不铺图，要点到某个目录才出图（口径见 §5.01）。

### 2.3 中列：tiles 与控制条

- tile = 图区（150×112）+ 字幕条（26）两行；tile 上可出现的标记：**左上角色标点**、**右上角锁**、字幕右侧星；
- **锚点环**：最后一幅被点中的图，在「选中底」之外再加 **1px 主色内描边**（`$brand`，inner）——
  回答「选了一堆，现在右栏看的是谁」（`BROWSE.md` §5.10）；
- **控制条与导入模式逐项对齐**（32 高）：`计数` — 弹性 — `当前目录 + 文件名` — 弹性 — `按时间`（时钟图标 + 文字，
  80×28 按下式方块）— `缩放图标`（14px）— `缩放滑块`（**96×14 外框、内部 2px 轨道**，已选段填主色）。
  当前目录写作 `库名 / 最后一级目录 · 文件名`（**不放完整路径**；文件名用更亮的 `$fg-2`）。

### 2.3.1 底面用法（2026-09-15 用户纠正，**重要**）

**背景只用「深色 / 浅深」两档来回换**（外加选中/悬停等状态色），**不要引入第三档黑**：

| 面 | 用在哪 | 不用在哪 |
| --- | --- | --- |
| `$surface-main`（深色 `#202226`） | 两侧栏、flowbar / toolsbar 条带；**照片占位区**（tile 图区 / 胶片带缩略 / 对比画幅） | — |
| ~~`$surface-track`~~ | —— | 建稿初期误把库卡片也用了 track，导致「库是黑的」；已全部改回 `$surface-bar` |
| `$surface-bar`（浅深 `#2A2D33`） | **工作区中央内容面**；面板内的插入块（搜索条 / 预览 / 直方图 / chip / 输入框） | — |
| `$surface-track`（`#17191C`） | **只做凹槽轨道**：分段控件底槽、缩放滑块轨道 | **不得**用于照片区、搜索框、缩略图、chip —— 本轮就是踩了这个 |
| `$surface-layer`（`#33373E`） | 菜单 / 弹窗 / 提示气泡 / **浮在照片上的小徽标**（如 tile 的锁） | — |

- ⚠️ 这条与现存的 `main.pen` **不一致**：那边 `PhotoThumb` 用的是 `$surface-track`（导入稿 18 个 tile）。
  需要同一轮把 `main.pen` 也改成 `$surface-main`，否则两稿观感不统一。
- **2026-09-18 本稿按实现改了一遍**（人类口径：已实现的部分以实现为准）：
  - 两个网格帧与选择态 tile 的 **`TilePhoto` → `$surface-main`**（原为 `$surface-track`，与这条规则相反）；
  - **搜索条 / chips / 预览底 / 直方图底 / 命令面板输入行 / 「查看所有库」半截条 → `$surface-bar`**（§2.3.1 已经写明，之前画错了）；
  - 状态栏的**锁徽标 → `$surface-layer`**（与 tile 上的锁同一个做法）；
  - `$surface-track` 现在只剩**凹槽轨道**：分段控件底槽（密度 / 工作流 / 与或）、缩放滑块轨道、以及「取消」次级按钮（实现里 `Button variant="secondary"` 就是 `bg-surface-track`）。
- 相关的选择态：tile 被选中时，**整块（含图区）铺 `$state-selected`**，不只是字幕条。

### 2.4 右列：信息栏（`BROWSE.md` §6）

- **tiles 模式**：EXIF（可滚动）→ 标签 → 文件（含可编辑的作者/描述）→ 地理（5 行，均可编辑）；
- **看图模式**：**预览**（全图缩略图 + **当前视野框**，1px 主色描边）+ **直方图**（24 根柱）→ 其余同上（EXIF 让位给预览+直方图）；
- **排版纪律（用户 2026-09-15 强调）**：平面布局、线条极少 ⇒ **识别度靠排版**：
  段落间距 `20`、段内行距 `6`、段标题 `15px / $fg-2 / 600`、字段名 `12px / $fg-3`、字段值 `14px / $fg-1`。

### 2.5 看图与对比

- 看图：中列 = 照片区（上）+ **胶片带**（下，104 高，缩略 96×80）；
- **底部状态栏与 tiles 不同**：**左侧**文件名 + 紧跟其后的**锁徽标**；**右侧**该图标记（星 / 色标 / 旗标 / 喜欢）；
- 对比：两图等宽并排；**第一幅带主色内描边**（它是画幅基准，其余图按它的比例取中间区域同步位移）；
- 对比下胶片带：**只显示参与对比的图**，整条胶片带加 **1px 主色细边框**表示进入该状态（`BROWSE.md` §5.5）。
  （2026-09-18 修正：原来这一条胶片带画了 12 张缩略图，与「只显示对比图」矛盾，已改成 2 张；当前那张带主色内描边。）

### 2.6 浮层（`BROWSE.md` §8）

- **toast**：`titlebar` 正下方、右上角；**带边框**，边框色表状态（成功 `$brand` / 警告 `$danger`），
  底 `$surface-layer`；示例带一个「撤销」按钮；**不遮挡操作**；
- **中央模态**：`$scrim` 遮罩 + `$surface-layer` 卡片（本例 380 宽），标题 17px、字段 32 高、
  错误文案用 `$danger`、右下角「取消 / 创建」。

## 4. 画布操作约束（本轮实测，写下来免得下次再踩）

| 约束 | 说明 |
| --- | --- |
| **变量必须先于节点创建** | 节点先建、变量后建 ⇒ `$...` 引用被**静默烤成 `#000000`**（整屏全黑）。补救＝变量建好后再 `Update(id, {fill:"$..."})` 重挂 |
| **`Insert` 的新子节点会被布局引擎摆位** | 但它需要一次重算：**同一调用内读到的 `bounds` / `problems` 是陈旧的**，判断要以**截图**为准 |
| **flexbox 容器里 `x` / `y` 被忽略** | 位置只能靠顺序（`Move(id, parent, index)`）、间距、填充来控制 |
| **优先 `Copy` 现成节点** | 本轮 `View` / `Compare` / `Libs Expanded` 与库卡片都是复制后改的，比从零 `Insert` 更快也更不容易坏 |
| **画布没有 Tabler** | 见 §3 |
| **主题** | `theme: {mode:"dark", density:"compact"}` 是合法节点属性，子树继承；它只决定「解析哪个变体」，救不了被烤死的引用 |
| **`alignItems` 只有 `start/center/end`** | 没有 `stretch`（写了会直接报错并回滚整批） |
| **`filePath` 只对当前打开的文件生效** | 不能跨文件读写（`main.pen` 与 `browse.pen` 互不可见） |

### 5.0 tile 两态对照（`Components / Tile 两态对照`，2026-09-17 新增，M2 阶段 0.3）

**这张画框解决的是「同一张 tile 在库内 / 库外到底差什么」** —— 差异只有两处，
都是「这张照片有没有库内属性」造成的：

| | 库内 | 库外（导入正在扫的外部目录） |
| --- | --- | --- |
| 顶部标记条（星标 / 色标 / 旗标） | **有** | **整个不渲染**（不是渲染成空条） |
| 底部条右端的锁位 | **有** | **不渲染** |
| 底部信息条（文件名 + 类型） | 有 | 有 |
| 正方外框 / 照片保比例居中 / RAW 角标 | 有 | 有 |

画框里刻意把两张都设成 **RAW 且带角标**，让「上下文」成为唯一变量 ——
否则一左一右既换了上下文又换了格式，看的人分不清差异是谁带来的。

实现依据（不是设计稿拍的）：`Tile.tsx` 里顶部条与锁位都包在 `<Show when={inLibrary()}>` 里，
`inLibrary()` 由 `context` prop 决定（`"library"` / `"source"`）。

### 5.3 与实现冲突时的判据（人类 2026-09-18 定，**长期有效**）

> 原话：*「pencil 中的设计与实际是会有少许差异的，对于已经实现的部分，优先以已经实现的为主。」*

- 画布与**已经实现**的部分冲突 → **以实现为准，反向同步画布**（本轮就是这么做的：面用法、tile 外形、状态格）；
- 只有「实现尚未做、画布已画」的地方 → 才是实现去跟画布对齐；
- **结构与状态**的偏离仍按 `AGENTS.md` §5.1：先改 `.pen` 再改代码；**纯尺寸**的差异不算偏离（`DESIGN.md` §8.4）。

**尺寸口径不变**：画布上的具体像素只作**结构**示意，实际以 `tokens.css` 与实现为准（`DESIGN.md` §8.4）。
