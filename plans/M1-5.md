## 1. Context —— 为什么现在做这个

M1 的前四个单元已交付：设计系统（M1-1）、数据底座（M1-2）、扫描+EXIF+缩略图管线（M1-3）、
外壳三行（M1-4）。**M1-5 是把它们接起来的那一步**：让用户能挑目录、看见照片、建库、按下导入。

三个交付面（`design/main.md` §3）：

```text
┌────────────┬──────────────────────────────┬──────────────┐
│ 左列 320   │ 中列（弹性）                 │ 右列 300     │
│ 最近       │ 照片网格（Tile 流 + 虚拟化） │ 库列表       │
│ ─ Split ─  │ + 按时间分组                 │ + 新建库     │
│ 来源树     │ 底部 GridControlBar          │ 导入按钮     │
│ ─ Split ─  │                              │ + 避免重复   │
│ 已选目录   │                              │              │
└────────────┴──────────────────────────────┴──────────────┘
```

**现状**：`src/App.tsx` 的三列还是占位（`照片区（M1-5）`），`ToolsBar` 的「批量排除」恒为禁用态，
`FlowBar` 的 EXIF 区恒为空态，前端**没有任何与 Rust 数据层通话的代码**（只有窗口控制）。

**完成定义**（本单元交付时能演示）：

1. 左列能列出驱动器与子目录、能勾选目录（多选）、能在「最近 / 来源」之间同步选中；
2. 中列能列出选中目录的图片、显示**真实缩略图**、按时间分组、区间反转批量排除；
3. 右列能列出已有库（含在线/离线徽标）、能在任意目录新建库；导入按钮的可用性由左右两侧共同决定；
4. 上述一切都走**真实的 Rust 数据层**（sqlite + 文件系统 + 缩略图缓存），不是前端假数据；
5. 选中一张照片时 `flowbar` 的 EXIF 区显示它的真实信息。

## 3. Approach

### 3.1 数据桥（`src/api/` ←→ `src-tauri/src/`）

> **已定（Q3）**：**手写 TS 镜像 + 「形状冒烟」测试**，本单元不引入 `tauri-specta`。
> `src/api/types.ts` 与 Rust 的 serde 结构逐字段对应（`serde(rename_all = "camelCase")`）；
> 漂移由「命令返回的 JSON key 集合」测试 + 本文件的字段表 + review 兜住。
> 若到 M1-6 结束时命令总数显著超出预期（>25 条），再回头评估 specta（登记 `FUTURE.md`）。

`ARCHITECTURE.md` §1.1 规定 **`src/api/` 是唯一 `import { invoke }` 的地方**，
且"未来的 `raybend-ipc` 契约与之逐条对应"（`AGENTS.md` §4：M1 出现真实契约时再拆 crate，
**本次不拆**，先把命令放在 `src-tauri/src/` 的独立模块里）。

新增命令（按面板分组，全部 `async` —— 同步命令会跑在主线程上，**会卡住窗口**）：

| 命令 | 面板 | 做什么 | 实现的 Rust 侧 |
| --- | --- | --- | --- |
| `recent_dirs_list` | 左 | 最近导入过的目录（≤50，按时间倒序） | app.db 新表 `recent_dirs`（迁移 v3） |
| `recent_dir_remember` / `recent_dir_forget` | 左 | 记住 / 移除一条 | 同上 |
| `volumes_list` | 左 | 驱动器 + 来源类型（本地/网络/可移动/云） | Windows `GetDriveTypeW`；Linux 读 `/proc/mounts`（`store::location` 已有半边） |
| `dir_list` | 左 | 某目录的**直接子目录**（排序、跳过隐藏/垃圾） | `media::scan`（只取目录层，`max_depth=1`） |
| `source_scan` | 中 | 某目录的**直接图片**（+ 名称/大小/mtime/`taken_at`） | `media::scan` + `media::exif`（并行取时间） |
| `thumb_get` | 中 | 一张源文件的缩略图字节（命中缓存即返回） | `thumbnail::{cache,render}`，缓存目录 `cache/_sources/` |
| `file_exif` | 中/上 | 选中照片的 EXIF（喂 `flowbar`） | `media::exif::read_file` |
| `repositories_list` | 右 | 库列表（名称/路径/在线状态/照片数/模版） | `store::repository` + `store::assets::counts` |
| `repository_create` | 右 | 按 `REPOSITORY.md` §2.4 的两个分支建库/登记 | `CatalogDb::create` + `AppDb::register_repository` |
| `repository_remount` | 右 | 离线库重挂载探测（对所有登记路径找一遍） | `store::repository::resolve_repository` |
| `repository_counts` | 右 | 刷新某库照片数 | `store::assets::counts` |

**缩略图通道**：`thumb_get` 返回 `tauri::ipc::Response`（**原始字节，不走 JSON/base64** ——
已核实 `tauri-2.11.5/src/ipc/mod.rs:190` 有 `pub struct Response`），
前端拿 `ArrayBuffer` → `Blob` → `URL.createObjectURL`，按 `路径+档位` 缓存在内存 Map 里，
卸载时 `revokeObjectURL`。渲染跑在 `spawn_blocking` + 并发信号量（4）里，避免滚动时同时解码几十张。
缓存落 `<app data>/cache/_sources/thumbs.db`（源文件还没入库；键仍是文件身份，与库内缩略图不冲突）。
**RAW → 占位图**（M1-3 的既定取舍，本单元沿用）。

**EXIF 时间分两步**（避免首次进目录就等 2 秒）：`source_scan` 先快速列出文件
（`taken_at` 用「文件名 → mtime」的兜底值，并标明来源），网格立刻出图；
用户按下 `按时间` 时再调 `source_times(paths)` 并行读真实 EXIF（4 线程）并就地更新，
分组随数据到位自动重排。

### 3.2 左列（`src/features/{recent,source-tree,selected-dirs}/`）

- **三段可拖拽**：用 Ark UI `Splitter`。已核实 `@ark-ui/solid@5.39.2` 带 `splitter` 组件，
  且现有 `SplitHandle` 的文档注释写明「供 Ark `Splitter.ResizeTrigger` 内部复用」——两者本就是对着做的。
  若实测发现 Solid 端行为不对（拖拽不跟手 / 不能限制最小高度），立即退回手写 pointer 拖拽并在实施记录里记一笔。
- **最近**：每行 = `RadioCircle`（勾选）+ `PathText`（`shortpath` + Tooltip 全路径）+ 行尾禁行图标
  （`EasyDestroyButton`，默认确认、`Shift` 跳过）。**选中态 = 主色底**（§12.4），勾选与选中互不影响。
- **来源**：驱动器 → 子目录逐级懒加载（`dir_list`），只显示目录；每条左侧同款勾选框。
  展开集合存在 `source-tree` 模块内部，**选中绝不触发展开**（§12.4.1）。
- **已选目录**：横条（文件夹图标 + 路径 + 右上移除 + 右下「包含子目录」`Switch`，默认关）。
  空时整段隐藏。
- **「最近 / 来源」的选中是同一个状态**（`store` 里的 `selectedDir`），比较一律走 `lib/tree.ts` 的 `pathKey`。

### 3.3 中列（`src/features/photo-grid/` + `src/components/ui/VirtualGrid.tsx`）

- **虚拟化（已定 Q1：自研）**：`src/lib/virtual-window.ts` 纯函数（可见行窗口 / overscan / 总高 / 边界与退化输入）
  - `src/components/ui/VirtualGrid.tsx` 只做窗口渲染；**零新增依赖**，与 `PLAN.md` M0-6 的既定方向一致。
  行高由 `tile-flow.ts` 的档位与 `tileTotalHeight()` 给出，列数沿用 `computeTileFlow()`。
- **按时间分组**：纯函数 `src/lib/time-group.ts`（日组 + 天内间隔 > 阈值断片），阈值从设置读（默认 60 分钟）；
  日组标题「全选当天」、片标题「全选此段」；缺时间的归「未知时间」组且不参与切分。
- **选择与排除**：点选 / `Shift` 区间 / `Ctrl` 增减（纯函数 `src/lib/selection.ts` + 单测）；
  `toolsbar` 的「批量排除」= **反转**选中项（同一个文件里的集合反转函数）。
- **底部控制条**：计数 · 弹性 · `ToggleBlock/按时间` · 当前目录 · 弹性 · 缩放滑块（Ark UI `Slider`，9 档）。
- **双击 / 回车（已定 Q2：留到 M2）**：M1-5 **只做选中**；放大查看留给 M2-W3 的 wgpu 查看器。
  顺手登记 `FUTURE.md`，写明「M1-5 评估过 DOM 版简易查看、决定不做」，免得 M2 重新纠结一遍。

### 3.4 右列（`src/features/repositories/`）

- 库卡片：图标 + 名称 + 路径（`PathText`）+ 照片数 + **在线/离线徽标**。
  多路径时显示当前在线那条；离线时显示上次已知路径 + 徽标，**点徽标 = 重挂载探测**。
  （**齿轮本单元不渲染** —— 它与模版弹窗绑定，属 M1-6，见 §3.6）
- **新建库**：库列表最下方「`+` 卡片」→ 弹窗（名称 + 库根目录）。目录选择要**新增依赖**
  （见 §8「新增依赖」）：`tauri-plugin-dialog`（官方插件：1 个 npm 包 + 1 个 crate + 一条 capability 权限）。
  同弹窗内保留「手填路径」输入框作退路（WSLg 下原生对话框异常时不必返工）。
- **建库分支照 `REPOSITORY.md` §2.4，但收窄到 M1 够用的形态**：
  目录里**已有 `catalog.db`** → 读出库身份：`app.db` 里已有该 ID = 登记一条新路径（同库多路径）；
  没登记过 = 整个库登记进来；目录里**没有 `catalog.db`** → 直接新建（不覆盖）。
  「把这条路径登记到某个已知库」的入口放在**已选中库卡片**上（一个菜单项），不在新建弹窗里绕。
- 底部：**选中统计文案** + **导入按钮**（左右都选中才可点）+ **避免重复导入**（默认勾选）。
  导入按钮在 M1-5 只做「可点性 + 点击后的事件」（真正执行在 M1-6）。

### 3.5 状态归属与分层（`ARCHITECTURE.md` §3）

- `src/workspaces/import/store.ts`：`createImportStore()` —— 跨 feature 的共享状态
  （`selectedDir` / `checkedDirs` / `selectedRepositoryId` / 照片选择 / 排除集 / tile 档位 / 按时间）。
  由 **`App.tsx` 创建**（组装层可以 import `workspaces/`），再以 props 下发：
  工作区拿全量，`ToolsBar` 只拿 `hasSelection` + `onBatchExclude`（替换现在的 `hasSelection={false}` 占位）。

- 浏览器里（`pnpm dev` / `smoke:ui`）没有 Tauri：`src/api/` 的每个封装都要**优雅降级**
  （返回空列表 + 空态文案），窗口三键那套 `isTauriRuntime()` 判定继续用。

## 7. Risks

| 风险 | 应对 |
| --- | --- |
| Ark UI `Splitter` 在 Solid 端有问题 | 第一批就验证；退路是手写拖拽（`SplitHandle` 已就位） |
| 缩略图渲染 174ms/张，滚动时同时解码导致卡顿 | 并发信号量 + 持久缓存 + 占位骨架；先量再调 |
| 大目录（数千文件）EXIF 并行取时间造成首屏延迟 | 分批并行 + 先出网格后补时间；必要时降级为「先按 mtime，后按 EXIF」 |
| 9p（`/mnt/c`）在 WSL 下极慢，性能数字失真 | 性能数字只作上界参考；真实基线在 Windows 侧或 WSL ext4 上取 |
| Blob URL 未回收导致内存增长 | 卸载/换目录时统一 `revokeObjectURL`；上限告警 |
| `tauri-plugin-dialog` 在 WSLg 下不可用 | 退路：手输路径输入框（同弹窗内切换） |
