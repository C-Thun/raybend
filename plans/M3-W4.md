## 1. 关键调研结论（技术底稿，避免下一个人重查）

### 1.1 降噪 / 锐化：**没有现成可用的库**，路线是「复用本仓算子 + 参考实现移植」

| 候选 | 是什么 | 结论 |
| --- | --- | --- |
| `bm3d_core`（crates.io） | 纯 Rust BM3D，**为断层成像（sinogram）的条纹 / 环状伪影设计** | ✗ 领域不对（不是自然图像去噪），带多尺度与条带专用逻辑 |
| `imageproc::bilateral_filter` | 通用双边滤波，**只吃 8bit**，naive 实现 | △ 能跑但不为摄影设计；我们是 u16 线性，要来回转换；性能一般 |
| `opencv` crate（`xphoto::bm3d_denoising`） | OpenCV 的 BM3D | ✗ 引入 C++ OpenCV 巨型依赖，与「纯 Rust + Windows 交付」相冲 |
| RapidRAW 的 BM3D（`src-tauri/src/denoising.rs`，AGPL-3.0） | ~1000 行纯 Rust CPU 实现，rayon 并行，**烘焙式**（一次处理整张 + 进度条） | △ 许可允许（同 AGPL-3.0，可移植），但它是「处理一次落盘」的形态，**不是实时管线**；移植 + 适配成本高 |
| darktable / RawTherapee 的小波 / NLM（GPL-3.0） | `denoise (profiled)` = 小波或 NLM；RawTherapee = 小波 + DCT 分块 | △ 参考价值高，要自己写 |
| `ort` + AI 模型（RapidRAW 的 AI 去噪） | ONNX Runtime 动态加载 + 外置模型 | ✗ 本轮不做（`FUTURE.md` E1：模型分发 / 体积 / 首次启动体验） |

**本仓已有的底子（这就是不用引库的理由）**：`develop/filters.rs` 有 **O(N) 箱式滤波 + 快速引导滤波**；
`develop/local_tone.rs` 有**多尺度保边分解 + 四道门控 + 软限幅**，而且它**已经是「分析 / 应用分离」的形态**
（分解与强度无关、可缓存，拖动只跑便宜的那一段）——降噪要做的分解与它是同一套算子。

**定案路线（人类 2026-09-25 拍板：两档都做，先保底再移植）**：

* **「快速」档（默认，实时跟手）**
  * **亮度降噪**：多尺度保边分解（引导滤波）→ 逐尺度按「幅度 / 噪声水平」软阈值收缩 → 重组。
    即 darktable 小波路线的简化版，但算子复用本仓的 `GuidedModel` / `box_blur`，**零新依赖**；
  * **色度降噪**：色度单独一支（半径更大、更狠、只动色度）。参考 RapidRAW
    `image_processing.rs::remove_raw_artifacts_and_enhance` 的**很轻的做法**（YCbCr + 稀疏采样 + 亮度差加权 +
    保持色度幅值），用我们自己的算子实现；
* **「高质量」档（BM3D，后台任务）**：移植 RapidRAW `src-tauri/src/denoising.rs` 的 BM3D
  （**AGPL-3.0 ⇒ 与本项目许可一致，可移植**，逐文件确认文件头许可标注并保留署名与来源）。
  **只搬算法核心**（分组 / 协同滤波 / 聚合）；并行照本仓风格用 `std::thread::scope` ——
  若移植成本明显更高，可直接用 `rayon`：它**已经在依赖树里**（`image` 的 `rayon` feature），
  不新增编译成本与许可；
* **锐化**：显示域 unsharp（base 用引导滤波 / 箱式模糊，detail 增益 + **软限幅防 halo**）。
  参考 RapidRAW 的 `shaders/shader.wgsl::apply_sharpen`（亮度域 + 边缘加权 + 软限幅）**思路**，
  实现在我们的 CPU 管线里（本仓显影是 CPU 管线，GPU 只负责显示静态纹理）。
* **AI 去噪不在本波**（`FUTURE.md` E1：模型分发 / 体积 / 首次启动体验）。

### 1.2 镜头校正：**有公共数据库**（lensfun），且已有**纯 Rust** 可直接用

* **数据库**：[lensfun](https://lensfun.github.io/) 的 XML 校准库（56 个文件，未压缩 ~5 MB / gzip 后 ~574 KB），
  覆盖主流机身与镜头，含**畸变 / 横向色差（TCA）/ 暗角**三组系数。
  **许可**：数据 **CC BY-SA 3.0**（署名 + 相同方式共享；我们**原样分发、不修改**）、
  代码 LGPL-3.0（可经 GPL-3.0 路径与 AGPL-3.0 组合 —— 与 rawler 同一套论证）。
* **Rust 侧**：`lensfun` crate **0.7.0**（https://crates.io/crates/lensfun ，
  源码 https://github.com/vdavid/lensfun-rs ）——**纯 Rust 移植，无 C 依赖**（只用 `flate2` / `regex` /
  `roxmltree` / `thiserror`，其中 flate2 本仓已在用）：
  * `Database::load_bundled()` 把 DB（gzip）**嵌进二进制**，无需分发资源文件；`load_dir()` 也可从磁盘加载；
  * 与上游 C++ 做过 **1,640 组 A/B 对照**（最大差 `4.9e-4` 像素，比上游回归容差还小约 2000 倍）；
  * `Modifier`：`enable_distortion_correction` / `enable_tca_correction` /
    `enable_vignetting_correction(lens, aperture, distance)` +
    `apply_geometry_distortion` / `apply_subpixel_distortion` / `apply_color_vignetting_u16`
    —— **逐行矩形**接口，正好配我们的按行分块并行。
  * **分层纪律照抄 RAW 后端**：`develop` 只认**我们自己的**校正模型（纯数据 + 纯数学），
    lensfun 只在「取系数」那一层出现；万一 Windows 构建出问题，换实现不碰管线。
* **备选与不选**：C 库 liblensfun（FFI，Windows 要带 DLL、交叉编译麻烦）→ 不选；
  自己解析 XML + 自己写数学（RapidRAW 就是这条）→ 重复造轮子，模糊匹配与焦距插值是 bug 温床 → 不选。
* **RapidRAW 对照价值**（`src-tauri/src/lens_correction.rs`）：它把 lensfun 的 XML 当 Tauri resource 分发
  （`lensfun_db/`，5.1 MB / 56 文件）、自己 serde 解析、自己写数学。它的**规则**值得抄：
  焦距在两档之间**线性插值**、超出范围取**最近档**、TCA 用 `vr`/`vb` 比值、暗角用 `pa` 模型。
* **匹配所需的元数据**（catalog 里都有）：`camera_make` / `camera_model` / `lens` / `focal_mm` / `f_number`；
  **拍摄距离没有** → 暗角按默认（无穷远）。
* **启动代价**：`load_bundled()` 要解压 ~5 MB XML 再解析（预计数百毫秒）——
  **不许放在窗口启动路径上**：惰性 + 后台线程 + `OnceLock`，面板先显示「配置文件加载中」；
  实测数字写进实施记录。

### 1.3 像素阶段的顺序（本波定案，改顺序 = 改画质）

```text
线性 u16（现有源）
  → ① 镜头几何校正（畸变 + TCA）+ 暗角增益     ← 空间，u16 → u16（不启用则整趟跳过）
  → ② 降噪（亮度 / 色度）                       ← 空间，u16 → u16（0 则整趟跳过）
  → ③ 现有链（WB → 曝光 → 反差 → 高光 → 黑区 → 显示变换 → 曲线 → 色度 → 局部色调）  ← 逐像素（LUT）
  → ④ 锐化（显示域，**量化之前**）              ← 空间，0 则整趟跳过
  → 8bit
```

* 几何校正**放在最前**：后面所有算子（降噪、锐化）都在校正后的几何上工作；
* 暗角是**线性域乘性增益**，与几何同一套半径，折进①同一趟；
* 锐化放在**量化之前**（8bit 之后再锐化会把量化噪声一起放大）；
* 每趟都是「按行分块 + `std::thread::scope`」（与既有并行风格一致），不引新依赖；
* 三处 `0 值` 都必须**逐位恒等**（与 `local_tone` 同一条纪律，单测钉住）——
  「没开这个功能」不能悄悄改变画面。

### 1.4 参数 → 算法的映射（写下来，免得实现时各写各的）

| 参数 | 范围 | 映射 |
| --- | --- | --- |
| `lumaNr` | 0..100 | 收缩强度 0..1（0 = 不动） |
| `colorNr` | 0..100 | 色度支路强度 0..1 |
| `sharpenAmount` | 0..100 | 增益 0..~1.5（0 = 不动） |
| `sharpenRadius` | 0..100 | 半径 `1.0 + v/100 × 3.0` px ⇒ **默认 0 = 1.0 px**（不改成中间值：契约不动、`只存非默认值` 的语义不动） |
| `distortion` | −100..100 | 手动径向项 `k1 = v/100 × 0.15`，叠加在配置文件之上（0 = 只按配置文件） |
| `vignette` | −100..100 | 手动暗角增益量，同上 |
| `chromatic` | −100..100 | 手动 TCA 缩放量（约 ±0.2%），同上 |

## 2. 已定案的四件事（人类 2026-09-25 拍板，**不要再翻案**）

| # | 决策 | 含义 |
| --- | --- | --- |
| 1 | **降噪两档都做：先保底、再移植 BM3D** | 「快速」= 本仓算子的多尺度保边分解（默认、实时跟手）；「高质量」= 移植 RapidRAW 的 BM3D。两档都是**编辑栈的一级**，随时可切回 |
| 2 | **镜头三根拉杆 = 手动微调，叠加在配置文件之上** | 配置文件负责自动校正；拉杆 0 = 只按配置文件。「启用校正」开关**只管配置文件那部分**，手动拉杆照常生效（与 Lightroom 的 Lens Corrections 面板一致） |
| 3 | **畸变校正后自动放大裁掉空边** | 画布尺寸不变 ⇒ 1:1、W5 裁切、逻辑尺寸的语义都不用动；代价是画幅略微缩小（Lightroom 默认行为） |
| 4 | **引入 `lensfun` crate**（纯 Rust 移植、DB 内嵌） | 数据 **CC BY-SA 3.0**（原样分发 + 署名）、代码 **LGPL-3.0-or-later**（经 GPL-3.0 路径与 AGPL-3.0 组合，与 rawler 同一套论证）；登记进 `THIRD-PARTY-NOTICES.md` |

### 2.1 「两档降噪」带来的三件事（决策 1 的直接后果，**别漏**）

1. **界面多一个「降噪方式」选择**（快速 / 高质量）——`design/editor.md` §3 的清晰度页签要同步，
   `.pen` 需人类在 VS Code 里打开补画（§7）；
2. **它是编辑的一部分**（同一张照片选不同方式 ⇒ 画面不同）⇒ 存进编辑栈
   （`develop_stacks.nr_method`，与镜头那两列同一支迁移）、**进 `DevelopStack::signature()`** ——
   否则缩略图缓存会拿旧方式的结果（毒缓存）；
3. **BM3D 不能在拖动路径上跑**（24 MP 是秒级）：它是**后台任务**，结果按
   `(照片, 档位, 降噪强度)` 缓存进显影线程；算完之前**先显示快速档的结果**（过渡态 + 状态提示），
   算完再换上 —— 与 W3 的「先出过渡帧、再出真帧」同一套体验。
   **这不违反 W3 定案 #1**（「不做 1:1 拖动先看糊图」）：档位不降级，只是高质量结果**晚一点到**。

## 3. 施工顺序（每步都能单独冒烟；**前五步不碰 Cargo**）

1. **校正模型与数学（自有类型，无新依赖）**：`crates/raybend/src/develop/lens.rs` ——
   `LensCorrection`（畸变系数 / TCA 比值 / 暗角系数 / 自动缩放比）+ 径向映射与增益的**纯函数**；
   单测用**外部给定**向量钉住（不是自证）。
2. **几何校正的像素实现（warp 趟）**：线性 u16 → 线性 u16，双线性采样，按行分块并行；
   **暗角增益折进同一趟**；不启用时**整趟跳过**（零代价）。
   单测：恒等映射逐位一致、中心不动、边界夹取、坐标数学对着外部向量。
3. **降噪（亮度 / 色度两支）**：复用 `filters.rs`；`0` 逐位恒等；单测含「边缘保持」的合成图断言。
4. **锐化**：显示域、量化前、软限幅防 halo；`0` 逐位恒等。
5. **管线接线（唯一入口）+ 性能测量**：多趟顺序按 §1.3；`render_rgb8_*` 家族收敛成「一个入口 + 可选阶段」
   （**逐像素数学仍然只有一份**，LUT 快路径不许出现第二份）；
   `tier_for_params` 的 `interactive` 语义照旧（拖动只算预览档）；
   `cargo run -q -p raybend --example develop-probe` 扩一组带全部新阶段的数字。
   **这一步末尾才把四条清晰度参数翻 `wired: true`**（契约 + 两侧断言 + 界面解除禁用同批）。
6. **镜头数据层（需要新依赖，排到另一个会话提交之后）**：`crates/raybend/src/lens/` ——
   惰性 `load_bundled` + 后台线程、`auto_match(EXIF)`、下拉候选、`resolve(...) -> LensCorrection`；
   单测：无匹配 / 焦距在两档之间（插值）/ 超范围（取最近档）/ 缺光圈与距离（退回默认）/
   **非矩形投影（fisheye 等）标记为不支持而不是硬算**；
   冒烟：拿真样本（`/mnt/c/src/tmp/pic/P1000096.RW2`）跑一次匹配，把结果写进实施记录。
   同时把 `distortion` / `vignette` / `chromatic` 翻 `wired: true`。
7. **降噪「高质量」档：BM3D 移植**（算法核心，先不接 UI）：
   移植 RapidRAW 的分组 / 协同滤波 / 聚合；单测用**合成图**（加已知噪声）断言
   「噪声方差下降 + 边缘不被抹平 + 强度 0 时逐位恒等」；性能数字进实施记录。
8. **高质量档的接线**：显影线程的后台任务 + `(照片, 档位, 降噪强度)` 缓存 +
   过渡态（先快速档结果）+ 状态上报（「高质量降噪中…」）——**不许阻塞拖动**。
9. **持久化（迁移 v6）**：`catalog_0006_lens.sql` —— `develop_stacks` 加
   `lens_profile TEXT`（NULL = 没动过 ⇒ 自动识别；`'none'` = 用户显式关掉自动匹配）+
   `lens_enabled INTEGER`（NULL = 默认开）+ `nr_method TEXT`（NULL = 快速档）；
   `DevelopStack` 加字段、**`signature()` 必须含它们**（否则改 profile / 降噪方式缩略图不重渲染 —— 毒缓存）；
   迁移测试（v5 → v6 不丢数据）。
10. **IPC + 前端 + 命令注册表**：`lens_profiles`（自动识别结果 / 候选列表 / 当前选择）、
   配置文件下拉接真数据（现在是写死的「未选择」）、启用开关接真状态、**降噪方式选择**、
   七条参数解除禁用、i18n 双语；**命令注册表**：新增「重置镜头校正」「重置清晰度」等条目，
   每条**要么给 `defaultKey`、要么写明为什么留空**（`AGENTS.md` §2.15，别再事后打地鼠）。
11. **编辑后直方图（W3 遗留）**：渲染线程把当前帧 RGB8 过
    `display::histogram::histogram_of_rgb8`（**唯一计数实现**）→ 随状态给前端；
    编辑流改用它，非编辑流照旧走 `image_histogram`。
12. **对比数据侧**：渲染线程能同时产出「当前结果」与**参考帧**（SOOC / RAW 基准、不带编辑参数、
    同档位同几何）+ 渲染器持有第二张纹理 + 状态上报；**对分线显示与交互留 W5**。
13. **收口**：`PIPELINE_VERSION` 6 → 7（**同批**改 `render_sig` 字面量）、缓存签名、
    六条质量门 + 离屏像素证据、Windows 构建 + `pnpm check:win`、实施记录、
    `FUTURE.md` D3 定案 + `THIRD-PARTY-NOTICES.md` 登记 lensfun、真机清单。

## 5. 纪律提醒

* **一套实现**：逐像素数学只有 `develop/pipeline.rs` 一份；新阶段是**纯函数**，不许在渲染线程里再写一份；
* `0 值逐位恒等`：降噪 / 锐化 / 镜头三处都要单测钉住（「没开」不能悄悄改画面）；
* **`PIPELINE_VERSION` 与渲染行为同批抬**（`render.rs` 里已经三次毒缓存事故）；
* 镜头 profile 与降噪方式都进 `DevelopStack::signature()` —— 它们与参数一样会改变像素；
