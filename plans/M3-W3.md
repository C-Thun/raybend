## 0. 结束时可看到

右栏 `影调` / `色彩` / `曲线` 的拉杆与曲线**真的改变画面**（RAW 与 JPG 同一套管线），
可撤销、可重置、可持久；编辑结果在缩略图与看图里也生效；issue 用 `latest` 单一存储位
（外加 `SOOC` / `RAW` 两个虚拟 issue 做对比）。

## 1. 四个已定案的口径（人类 2026-09-24 定，**不要再翻案**）

| # | 决策 | 含义 |
| --- | --- | --- |
| 1 | **管线结果 = 一张静态图，GPU 视口只显示静态结果** | 不做「1:1 拖动先看糊图、松手才变清」的妥协。参数一变就在当前档位上重算（全尺寸也重算），靠 LUT + 并行把耗时压住；视口的平移/缩放永远只是画一张静态纹理 |
| 2 | **这一波就上完整解码 + 去马赛克** | RAW 走 rawler 的 `RawDevelop`（PPG 去马赛克 + WB + 色彩矩阵），**去掉 `SRgb` 步** ⇒ 线性 sRGB f32（scene-referred 输入）。JPG / RAW 内嵌预览走 sRGB→linear 线性化（诚实标注为准线性） |
| 3 | **issue：本轮只有一个存储位 `latest`** | `latest` 与 `SOOC` / `RAW` 一样是**固定 issue，不可改名/不可多建**；`SOOC` 仅当该资产有 JPG 文件时才存在，`RAW` 仅当有 RAW 文件时才存在；三者之间只能互相比较。CUBE / 多 issue 等 W4（方案待人类给） |
| 4 | **色温 = 绝对 K 语义** | 标尺范围不变（2500–10000K）；**载入照片时标尺移到该照片的 as-shot 色温**；拖动按绝对 K 调。RAW 走真绝对（相机 wb_coeffs + 色彩矩阵反算 CCT，再用目标 K 的增益比），JPG 本质是相对（以 as-shot 或 6250K 兜底为基准），但表面同一套刻度 |

## 2. 施工顺序（每步都能单独冒烟）

1. **参数契约（唯一数字真相）**：`src/api/develop-params.json` 存 id/min/max/step/default/origin；
   `params.ts` 与 Rust 侧都从它取数 + **两侧一致性断言**（照 `dto-contract` 的做法）。
2. **显影管线数学**（`crates/raybend/src/develop/`）：线性化 → WB（绝对 K 两套）→ 曝光 → 高光/黑区 → 反差
   → 饱和/自然饱和 → 显示变换 → 曲线（RGB/R/G/B，单调三次）。**参考实现 f32 + LUT 快路径**，
   两者用同一组**外部给定**测试向量钉住；并行用 `std::thread::scope`（不引新依赖）。
3. **RAW 线性解码**：worker 协议加 `linear` 模式（u16 线性 sRGB + as-shot CCT 等元数据）；
   `rawler_backend` 的 `LINEAR_STEPS`；用真机样本（`/mnt/c/src/tmp/pic/P1000019.RW2`）验证。
4. **渲染线程接入**：源像素常驻（线性）+ 参数应用 + `set_image`（复用唯一入口）；
   前端帧合并意图（复用 `lib/editor-intent.ts` 的合并 + 尾样本）+ 松手落库。
5. **编辑栈落库**：`catalog_0005_develop.sql`（`develop_stacks` / `develop_params` / `develop_curves`，
   含 `masks` 预留字段）+ `store/develop.rs` + 迁移测试（v4 升上来不丢数据）。
6. **撤销 / 重置**：`marking::Op` 加 `DevelopParam`（值用 f64 位模式保 `Eq`），复用既有 `ChangeSet`/`UndoStack`；
   单项重置与全部重置；undo/redo 后编辑器重载参数。
7. **色温基线**：载入时读元数据 → 标尺归位；DB 只存与基线不同的值。
8. **曲线编辑器 UI**（唯一自研控件，`design/editor.md` §3.7）：SVG + 指针事件 + 通道 + 控制点。

   **人类 2026-09-24 的补充口径（照这个做，别自作主张）**：

   * **通道选择不复用功能块的 tab/分段控件** —— 那样根本分不出主次。要**小一号**、
     集成在曲线组件内部（通道靠左、重置靠右同排）；
   * 曲线区**必须是正方形**，并占满 workspace right 内容区的宽；
   * 通道选择样式**参考直方图那一套**（只是多一个 RGB 全色通道）；
   * 曲线背景显示**当前通道的直方图**（同一时刻只显示单通道）：
     颜色用直方图的 3 个单色 + 1 个全色，**50% 半透明**浅浅印在底纹上；
     ❗ 直方图里的**等分格子仍然要有**，并且**压在峰值图上**（与直方图组件里「格子在下」相反）；
   * 功能：点线上（附近）加点 / 拖动控制点 / **双击移除控制点** /
     拖**两个端点（画成正方形点）**左右平衡最亮最暗基点（丢弃明度范围选择）/ 重置当前通道；
   * 通道按钮**有调整时给辅色底纹**（示意这个通道动过）。
9. **缩略图 / 看图反映编辑**：`EditSpec` 变成真参数；缓存签名含参数哈希（GC 改前缀匹配）；
   grid / strip / screen 三档都生效。
10. **视口覆盖层抽象**（人类 2026-09-24 要求：为 W5 的裁切/旋转/对比与将来的蒙版打地基，
    **不许上来就硬写**）：Rust 暴露「图像像素 → CSS 视口」的**同一个仿射矩阵**
    （含 zoom / pan / rotation / DPR / 洞口原点），前端只有一个 `ViewportOverlay` 宿主 +
    `lib/editor-overlay.ts`（纯函数）；所有覆盖层子元素一律**用图像像素坐标书写**，
    由那一层统一变换。禁止任何覆盖层自己推导对齐（`AGENTS.md` §6.1 红线 2）。
11. **收口**：i18n 双语、命令注册表（重置参数等，含默认热键决定）、`REPOSITORY.md` 的 XMP 契约、
    `FUTURE.md` D2 定案、实施记录、六条质量门 + 离屏像素证据 + Windows 构建 + 真机清单。

## 4. 纪律提醒

* `PIPELINE_VERSION` 与渲染行为**同批**抬（`render.rs` 里三次毒缓存事故）；
* 同一个能力只允许一套实现：管线数学只有一份（LUT 是它的快速求值，必须有等价性测试）；
* 换纹理只走 `GpuContext::set_image`；视口数学全在 Rust；
* 参数范围/默认值的真相只有 `develop-params.json` 一处，两侧都要有断言；
* 遇难题先绕过、记录、继续走；绕不过去再统一报告（`AGENTS.md` §2.11）。
