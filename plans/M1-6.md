## 1. Context —— 为什么现在做这个

M1-5 交付了导入工作区的三列：能选库、能勾目录、能看到照片网格、**导入按钮的可用性已经算好**，
但按钮按下只显示一句「导入中…（M1-6 实现）」。M1-6 就是把这句话兑现 —— 也是 M1 完成定义
（`PLAN.md` §M1 DoD）里「把照片真的导进库、重启后状态完整」那一条的主体。

这一单元结束时应当能做到：

```text
勾 3 个目录 → 选一个库 → 按「导入」→ 进度弹窗逐阶段推进 → 完成后这些照片
在库里的 photos/ 下按模版就位（RAW 在同级 _RAW/），catalog.db 里有 assets/asset_files 行，
缩略图任务已入队，重启应用后它们还在
```

## 3. Approach

### 3.1 模版求值（`crates/raybend/src/import/template.rs`）

纯函数，**本单元最该被钉死的一块**（`REPOSITORY.md` §3.2–§3.5）：

```rust
pub struct Template { parts: Vec<Part> }          // Part = Literal(String) | Var(Var) | Seq(usize)
pub enum Var { CYear, CMonth, CDay, CWeek, FileName, Brand, Model }

pub fn parse(src: &str) -> Result<Template, TemplateError>;      // 语法 + 非法字符 + 末尾 '/' + 空
pub fn validate(src: &str) -> Vec<Warning>;                       // 未知变量（不致命，给即时反馈）
pub fn render(&t: &Template, ctx: &RenderCtx) -> String;          // 目录部分 + 文件名部分
```

三条容易做错、必须写进测试的规则：

1. **最长前缀匹配**：`:FILENAMEGO` → `FILENAME` + 字面量 `GO`（**不是**未知变量）。
   已知变量名集合排序后按前缀匹配；`:` 后不匹配任何变量名时按字面量输出 + 一条警告。
2. **序号宽度即身份**：`:SEQ000` 与 `:SEQ0000` 在**同一目录**下是两个独立计数器（键 = 目录 + 宽度）。
3. **变量来自「每张照片自己」**：同一批里不同日期 → 不同目标根目录（`REPOSITORY.md` §4.2 的表格）。

### 3.2 目标路径规划（`import/plan.rs`）—— 本单元的核心，纯逻辑 + 可注入 FS

输入：扫描结果（源根、每个文件的相对路径、身份、拍摄时间） + 模版 + 选项（含子目录 / 避免重复）。
输出：`Vec<PlannedItem>`（源路径、目标相对路径、角色 bitmap/raw、状态 skip/fail/plan）。

```rust
pub trait FsProbe {                       // 真实实现查盘；单测用内存实现（不碰真文件）
  fn dir_exists(&self, rel: &str) -> bool;
  fn file_exists(&self, rel: &str) -> bool;
  fn free_bytes(&self) -> Option<u64>;
}
pub fn plan(files: &[SourceFile], tpl: &Template, opts: &PlanOptions, fs: &dyn FsProbe,
            known: &KnownIdentities, seq: &mut SeqAllocator) -> PlanResult;
```

按 `REPOSITORY.md` §4.1/§4.2 实现，顺序不能换：

```text
① 目录透传：源子树的每个目录，只有「含可导入图片」才保留（空目录/只含文档不建、不复制）
② 模版求值出「该文件的 target 根」：模版的目录部分只在这里求值一次
③ 把文件相对源根的目录层级原样搬到 target 根之下（几层搬几层，不逐层套模版）
```

三条纪律写进测试：**同一个 target 根下才共享序号**；**位图/RAW 同名成组**（两者都有 → RAW 进
同级 `_RAW/`；只有 RAW → 正常进目标目录）；**重名加 `_01`…`_99` → `_100`**（主序号不因此后退，
追加位置在扩展名之前）。

> **规格里那个「先摸一遍子树」的第①步自动成立，不用真的摸一遍**：目标目录是**从文件反推**出来的
> （每张照片算出自己的 target 根 + 相对层级），所以「只含文档的目录不建、空目录不建、目录只在真的有
> 文件落地时才创建」全都是这一条的自然结果。行为与 `REPOSITORY.md` §4.2 完全一致，只是少了一遍目录枚举。
> 配对用的 `stem_folded` 由扫描给出（`media/scan.rs`），不用自己折。

### 3.3 执行器（`import/runner.rs`）—— 后台线程 + 原子标志 + 事件节流

- **不占主线程**：`std::thread::spawn` 一个导入线程（不是 `spawn_blocking`，它要活几分钟）。
- **暂停 / 取消**：`Arc<AtomicU8>` 表示 `Running | Pausing | Paused | Cancelling`；
  检查点是**每个文件之间**（复制中途不打断，半截文件比慢更糟）。
- **每个文件的顺序（不能反）**：

  ```text
  ① import_items 先插一行 status='pending'（target_rel 已确定）
  ② 复制文件（.part 临时名 → 复制完 rename 就位；避免半截文件被当成成品）
  ③ 读副本身份（FileId::try_read），登记 assets / asset_files
  ④ 补写「来源列」（source_path/_folded + 源身份）；更新 status='imported'
  ```

  **状态词表沿用 schema 的 `imported / skipped / failed`，只新增一个 `pending`**
  （原来草案里的 `copied/done` 砍掉：`.part` + rename 已经排除了「半截文件」这一整类问题，
  `copied` 与 `imported` 之间没有真正需要区分的时刻）。

  这样任何时刻被杀，重开都能凭 `target_rel` + `import_items.status` 判断该文件到底落没落
  （M1-7 的崩溃演练就查这个）：

  - `pending` + 目标文件在、大小相符 → **视为已复制**：直接登记，不重拷、也不加 `_01` 后缀；
  - `pending` + 目标不在 → 重拷；
  - `imported` → 跳过（连身份判重都不用查）。

- **登记复用 `apply_diff`**（`store/assets.rs`）：把本批已复制的文件构造成
  `Vec<DiskFile>` + `DiffPlan { new_files: 全部 }`，一次事务交给它 —— 位图/RAW 配对、
  资产合并、唯一索引冲突都在那份**已被 M1-3 测过**的代码里。
- **缩略图入队走注入的回调**：核心 crate 不该认识 `app.db`（它的单写者归外壳持有）。
  所以 runner 拿到的是一组 `Hooks { on_progress, enqueue_thumbs }`，外壳侧的实现
  去写 `jobs` 表（`thumbnail::worker::enqueue_many`）。核心侧单测用假回调断言「入队了 N 张」。
- **续跑 = 用同一批源再导一次**：不搞复杂的断点续传账本。靠源身份判重自动跳过已完成的，
  靠 `pending` 行把「复制了但没登记」的那几张补齐。启动时若发现 `state='running'` 的旧 run，
  前端提示一句「上次导入被中断」并给出继续入口。
- **批量事务**：每 200 个文件或每 500ms 提交一次（进度显示要跟得上，事务也不能太碎）。
- **单文件失败不打断整批**：`status='failed'` + `reason`，继续下一个（`REPOSITORY.md` §4.5）。
- **磁盘预检**：开始前查目标卷可用空间，小于「源总字节 × 1.05」→ **先提示再决定**
  （本机 `C:` 只剩 ~58GB，这不是理论风险）。
- **进度事件**：内部维护快照，**节流到 ≥100ms 一条**（阶段切换、暂停、结束立刻发），
  避免「每文件一事件」把 WebView 打爆。

阶段机（`REPOSITORY.md` §4.4 的四个阶段）：

```text
扫描(scan) → 规划(plan) → 导入(import：复制+登记同拍推进) → 缩略图(thumbs)
```

> **一处刻意的偏差**：规格把「复制」与「登记」写成两个阶段，实现里它们是**同一拍**推进的
> （每批事务提交时一起前进）。理由：分成两遍会让中断后的续跑判断变复杂（可能复制了没登记），
> 而 §3.3 的「先 `pending` 后 `imported`」已经把这件事表达清楚了。界面上仍然是两条独立计数。

#### 迁移 v3：源身份列（`catalog_0003_source_identity.sql`）

`asset_files` 的 `(volume_serial, file_id)` 是**库内那个文件**的身份 —— M1-3 的差分、改名识别、
缺失检测全靠它，**不能被源身份占用**。而 §4.3 的「避免重复导入」判的又是**源文件**的身份。
一个列对服务不了两件事，所以加两列（不加就退化成「按源路径 + 大小 + mtime 判重」，源文件一改名就判不出）：

```sql
ALTER TABLE asset_files ADD COLUMN source_volume_serial INTEGER;
ALTER TABLE asset_files ADD COLUMN source_file_id BLOB;
CREATE INDEX idx_asset_files_source_identity
  ON asset_files(source_volume_serial, source_file_id)
  WHERE source_volume_serial IS NOT NULL;
```

判重时**先在内存里装一遍**（`known: KnownIdentities`，把库里已记录的源身份 + 源路径折叠 + 大小 + mtime
一次读进 HashSet），逐文件查内存；身份读不到的文件退化为「源路径折叠 + 大小 + mtime」三项比对。
不走逐文件 SQL 查询（5000 个文件 × 全表扫描会很难看）。

> 迁移框架已有（版本闸门 + 迁移前 `VACUUM INTO` 快照），加一条 `CATALOG_MIGRATIONS` 条目即可；
> 同时补一条「v2 → v3 迁移后旧行不被破坏」的单测（照现有迁移测试的写法）。

### 3.4 命令与事件（`src-tauri/src/import.rs`）

**一次导入 = 一个 batch = 每个源目录一个 run**（你选定的模型）：

```text
import_runs（每行一个源目录；source_root 语义保持干净）
  run#1  D:\Trip\Japan   imported 412  skipped 3
  run#2  D:\Trip\Korea   running  ··
  run#3  E:\2019          done（`import_runs.state`）
```

| 命令 | 语义 |
| --- | --- |
| `import_start(repositoryId, sourceDirs, opts)` | 每个源目录建一行 `import_runs` + 起一个线程；返回 `{ batchId, runs: [{ runId, sourceRoot }] }` |
| `import_pause(batchId)` / `import_resume(batchId)` | 作用到**整批**（用户按的是弹窗上的一个按钮，不该让他按 N 次）；暂停生效点在文件之间 |
| `import_cancel(batchId)` | 同上；**已导入的部分保留**（快照里带上「已保留 N 张」） |
| `import_status(batchId)` | **聚合快照**（总计 + 每个 run 的明细）—— 聚合在 Rust 侧算，前端只认一个 batchId |
| `import_errors_export(batchId, path)` | 把错误清单写成 JSON（路径由前端用 `tauri-plugin-dialog` 的 `save` 选） |

事件名 `import://progress`：载荷 = 聚合快照（含 `runs[]` 明细），**节流后的事件 + 阶段切换 + 结束**。

> `batchId` 是**进程内**的（内存表：batchId → runIds → 控制句柄）—— 重启后没有活线程，自然不该有 batch；
> 那时靠 `import_runs.state='running'` 的旧行提示「上次导入被中断」（见 §3.3 的续跑语义）。

两条不要踩的细节：

- **`CatalogDb` 要 move 进导入线程**（它 `Send`：`ReadPool` 是 `Mutex<..>`、`Writer` 是 `Sender + Mutex<Option<JoinHandle>>`），
  实现时用 `fn _assert_send<T: Send>() {}` 钉一下 —— 不合格会直接编译报错，不用猜。
  导入线程**自己开一个** `CatalogDb`（在 `spawn_blocking` 里算好路径后 move 进去），不共用外壳命令期的句柄。
- **事件不需要改能力文件**：`core:default` 已含 `core:event:default`（`listen`/`unlisten`）。
  要动的只是 `src-tauri/src/lib.rs` 的命令注册表。

### 3.5 前端（`src/api/import.ts` + `src/features/import/`）

- `api/import.ts`：命令封装 + `onImportProgress(handler)` 事件订阅（返回取消订阅函数）；
  **浏览器降级**：命令返回「不在 Tauri 里」的空结果、事件订阅返回空函数（照 M1-5 的惯例）。
- `features/import/store.ts`：吃事件流 → 派生 UI 状态（阶段、百分比、**三类计数**（已导入/跳过/失败）、当前项、错误列表、状态）。
  单测喂**假事件流**：阶段推进 / 暂停 / 单文件失败 / 取消 / 结束摘要。
- `features/import/ImportProgressDialog.tsx`（新画布帧）：
  阶段条 + 百分比 + `已导入 / 跳过 / 失败` 计数 + 当前项（文件名 + 库内目标路径）
  - **多目录时多一行 `[2/3] 目录名`**（一次导入可含多个源目录）
  - 错误清单（可展开、可导出）+ 暂停/继续/取消 + 结束摘要（含「在库中查看这些照片」**按钮**）。
  两条文案纪律：**取消要说清「已导入的保留」**；关闭弹窗 = 取消（要二次确认）。
- **完成后不自动跳工作流**（你选定的）：结束摘要给一个「在库中查看这些照片」按钮，
  点了才切到浏览并选中这批照片；不点就停原地（用户很可能接着导下一批）。
- 导入完成后：右列的库卡片刷新张数、中列网格刷新（复用 M1-5 的 store 动作）。

## 7. Risks

| # | 风险 | 处理 |
| --- | --- | --- |
| 1 | **半截文件被当成成品**（复制中途崩溃） | 复制到 `.part` 再 rename；`import_items` 先 `pending` 后 `imported` |
| 2 | 序号并发/回绕撞名 | 主序号不后退，一律靠 `_01…` 后缀兜底（已定）；计数器走单写者 |
| 3 | 事件把 WebView 打爆（大目录每文件一条） | 节流 ≥100ms + 阶段切换立即发；快照里只带**错误清单尾部**；多 run 时按 `batchId` 聚合成一条事件 |
| 4 | 取消后用户以为「回滚了」 | 弹窗文案写清「已导入的保留在库中」，取消要二次确认 |
| 5 | 磁盘写满（C: 只剩 ~58GB） | 开始前预检可用空间；失败项记入错误清单并继续 |
| 6 | 9p/WSL 的复制速度不代表真机 | 性能只记**形态与算法结论**，吞吐数字标注环境，不下结论 |
| 7 | 透传把 source 的目录层级搬错（多套一层/丢一层） | `REPOSITORY.md` §4.2 的五种情形逐条写成单测，`error!` 不放过 |
| 8 | 模版把非法字符写进目标名 | `validate` 在 Rust 侧统一判（库设置弹窗与导入前都走它） |
| 9 | **把源身份写进 `asset_files` 现有的身份列** → 库内差分（M1-3）会把每个文件当成「被替换过」 | 源身份单独放 `source_volume_serial` / `source_file_id`（迁移 v3），现有列只放**副本**身份 |
| 10 | 「复制了但没登记」在续跑时被当成新文件 → 多出一份 `_01` 副本 | `import_items` 先落 `pending`；续跑时 `pending` + 目标存在且大小相符 → 视为已复制，直接登记 |

## 8. 默认值（如不同意请在评审时直接说）

| 项 | 默认 |
| --- | --- |
| 复制 vs 移动 | **复制**（第一阶段不做移动；照片的原始来源保持不动） |
| 「避免重复导入」 | **它就是开关，不再另设按钮**（你指出的）：勾着=按源身份判重并跳过；**取消勾选=不判重**，撞名走 `_01` 后缀（绝不覆盖）。M1-5 已把它落进设置，M1-6 负责让它真的生效 |
| 取消后的处置 | **保留已导入的部分**，不做事后回滚（文件已落盘） |
| 缩略图阶段 | 导入完成后**入队即算这一阶段完成**，生成是后台任务，不阻塞「导入完成」 |
| 错误导出格式 | JSON（结构稳定，便于将来喂给诊断）；用 `tauri-plugin-dialog` 的 `save()` 选路径 |
| 并行度 | 复制**串行**（HDD 友好，且错误顺序可读）；缩略图并行度沿用现成的 worker |
| 多源目录 | **每个目录一个 run**，一个 `batchId` 聚合（§3.4） |
| `import_items.status` | 沿用 `imported / skipped / failed`，**新增 `pending`**（复制中途崩溃的痕迹）；不加 `copied/done` |
| 判重键 | **源身份优先，源路径 + 大小 + mtime 兜底**（`REPOSITORY.md` §4.3）—— 需要迁移 v3 的两个源身份列 |
| 新增依赖 | **无**（事件用已在依赖里的 `@tauri-apps/api`，选路径用已装的 `tauri-plugin-dialog`） |
