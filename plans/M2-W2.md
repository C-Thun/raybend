### 1.1 导入：库的物理结构

库（repository）就是用户指定的**一个目录**，它是这个库的根。库根下的结构**由 raybend 管理**：
根下直接放两份东西 —— `catalog.db`（库数据库）与 `photos/`（导入落地目录）。
`catalog.db` **直接在库根**、不藏在 `.raybend/` 子目录里，这是您明确要求的；
`photos/` 是模版求值后照片的落脚点；库根下除此之外**不放别的由我们创建的东西**。
`index.db`（派生索引：缩略图索引、人脸、相似度）**暂时不建** —— 等真的需要「可删可重建」的索引时再加，
位置仍是库根，不进 `photos/`。

`_RAW/` 是一个**保留目录名**：它与照片**同级**，放**同名**的 RAW。
注意它**出现在每一层落地目录下**（例如 `photos/2026-08-15/_RAW/`），不是全局只有一个。
库**不强制**目录里只有位图 —— 用户可以自己往库里放东西，目录里「有啥就是啥」，
raybend 不因此报错，只是**登记到库里的**是它自己导入的那些。

### 1.2 导入：库身份、多路径与在线 / 离线

这里有两件看似矛盾、但您明确要求都要支持的事：
**同路径不同库**（同一个目录下换过 `catalog.db`）与**同库多路径**
（同一个库出现在多个目录，例如同一块盘的不同挂载点、或库被复制、或 U 盘换了盘符）。

真相源是**两处记录**：中央 `app.db` 记录**所有已登记库**（库唯一 ID、名称、导入模版缓存、
**该库登记过的每一个路径**及其最近状态）；每个 `catalog.db` 记录**自己的唯一 ID**
（`repository_meta.repository_id`）。于是「某个路径现在挂的是哪个库」不靠路径字符串判断，
而是**读该路径下 `catalog.db` 里的 ID**、再与 `app.db` 的登记比对得出 —— 这正是「同路径不同库」
能成立的机制。

所有对库的操作都要过**一层统一的状态解析**（`resolve_repository`），只有三种结果：
**在线**（某个已登记路径下确实有这个 ID 的 `catalog.db`）、**离线**（登记过的路径都不含该 ID 的库）、
**未落地**（新建但还没落地）。判定顺序是「先查上次已知在线的路径（快），再遍历其它路径」，
结果**带失效时间地缓存**。任何读列表、导入、缩略图、写元数据的操作都先走这一层；
**解析失败一律转为离线而不是报错** —— 界面显示离线徽标，操作给出可读提示。

离线库的重新挂载流程：库显示离线（比如移动硬盘没插）→ 用户插入驱动器 → **点击离线图标** →
对该库**所有已登记路径**做一次查找（找 `catalog.db` 且 ID 匹配）→ 找到就记下「当前挂在哪个目录」
并转在线；找不到仍是离线，并给出「未找到该库」的提示。

添加库分**两个分支**：选中的目录下**已有** `catalog.db` 时，读出其中的 ID —— `app.db` 里已有这个 ID
就**不是新建而是登记一条新路径**（同库多路径）；`app.db` 里没有就**把该库整体登记进来**
（连同它已有的资产）。目录下**没有** `catalog.db` 时，要问用户是「新建库」还是「该目录属于某个已知库」——
新建就生成新 ID、建库、登记路径；「已知库」则把这条路径登记到那个库名下（用于离线库换挂载点）。
「一个路径被标记了但没有 `catalog.db`」时，该库显示离线，并允许在同一路径下**补建**库。
**同一路径允许登记给多个库**（唯一约束是 `(path_folded, repository_id)`，不是路径唯一）。

库唯一 ID 已定案（M1-2 已实现）：**可排序的 16 位 base62**——`[时间刻度（10µs 一格，自 SINGULARITY） | 随机 40 bit]`
编码成 base62、左补 `0` 到 16 位。字母表按 ASCII 升序 + 定宽，所以**字典序 = 数值序 = 时间序**，
「按 ID 排序就是按创建时间排序」；比 UUID 短一半、无横线、可直接进文件名与路径；
40 bit 随机段足以保证「一台机器上几十个库」不撞。不保留原方案里的 `shard` 段（那是分布式分库用的）。

### 1.3 导入：导入模版、序号与重名

默认模版是 `:CYEAR-:CMONTH-:CDAY/MY:FILENAME`。模版里的 `/` 是**目录分隔符**，
落地起点是 `<库根>/photos/`，模版描述的是 `photos/` **之内**的相对路径；模版是**库级设置**，
存在该库的 `catalog.db` 里（可随库迁移），同时缓存在 `app.db` 里供离线显示。

变量表（`:` 前缀）：`:CYEAR`（4 位年）、`:CMONTH`（2 位月）、`:CDAY`（**2 位**日）、
`:CWEEK`（**2 位**周）、`:FILENAME`（文件主名，**不含扩展名**，扩展名原样透传）、
`:BRAND`、`:MODEL`、`:SEQ000` / `:SEQ0000` / `:SEQ00000`（3/4/5 位序号）。
**解析规则按已知变量名做前缀匹配，其后一律是字面量** —— 例如 `:FILENAMEGO` 是
「`FILENAME` + 字面量 `GO`」，不是把 `FILENAMEGO` 当成变量名；未匹配的 `:` 当字面量并给校验警告。

序号（`:SEQnnn`）在**最终落地目录**范围内计数，计数存在该库的 `catalog.db` 里；
**不同宽度各自独立计数**（同目录下 `SEQ000` 与 `SEQ0000` 互不干扰）；**从 1 开始**；
**写满后回绕到开头**（您明说「不纠结」）。

重名处理已定稿：模版算出的目标文件名已存在时，**在扩展名之前追加 `_01`**，仍在就依次 `_02`、`_03`…
两位用满（`_99` 也被占）就继续涨位数（`_100`、`_101`…）。**主序号不因此往后挪** —— :SEQ 的值由模版算，
撞名不改它的推进逻辑，解决冲突的一律是后缀，所以同一目录里可能出现 `MY0001.jpg` 与 `MY0001_01.jpg` 并存。
模版校验要**给即时反馈**：变量名不认识 → 警告并列出可用变量；结果路径含非法字符（Windows 的 `<>:"|?*` 等）
→ 报错并指出位置；模版末尾为 `/` 或为空 → 报错；两个同宽度的序号变量 → 允许但提示。

### 1.4 导入：位图与 RAW 的分流

对**同一张照片**（同名不同扩展名，如 `P0001.png` + `P0001.ORF`）分三种情况：
只有位图 → 位图进目标目录；**只有 RAW → RAW 正常进目标目录**（不是进 `_RAW/`）；
**两者都有 → 位图进目标目录，RAW 进同级的 `_RAW/`，且 RAW 也按同一模版改名**（同名，只差目录）。
`catalog.db` 里**可以**关联这两者（便于「编辑位图时自动找同名 RAW」）但**不强制** ——
用户可以自由移动/改名文件，`_RAW/<同名>` 只是一种**约定**；编辑位图时默认尝试载入 `_RAW/` 下的同名 RAW，
用户可切换为「仅编辑位图」。

### 1.5 导入：目录透传（同步子目录）

算法**三步、顺序不能换**：① **摸一遍 source 的子树**（任意层级），判断每个子目录里**有没有可导入的图片**
（M1 只认图片：RAW + 位图）—— **只有「含可导入图片」的子目录才透传**，空目录、只含文档/视频/其它文件的目录
**不建、不复制**；② **模版求值出 target 根** —— 按每张照片自己的变量（`:CYEAR`/`:CMONTH`/`:CDAY`…）
算出它落哪一级目录，这个目录就是该文件的 target 根，**模版的目录部分只在这里求值一次**；
③ **把 source 的相对路径层级原样搬到 target 根之下** —— 文件相对于 source 根有几个层级就搬几层，
一层不丢；直接躺在 source 根里的文件就落在 target 根下（不额外套目录）。

四条纪律：**模版不逐层套用**（`Japan/Kyoto` 不会被再套一遍日期模版，绝不会出现
`photos/2026-08-15/Japan/2026-08-15/Kyoto/`）；**目录只在真的有文件落地时才创建**（不留空目录）；
**序号在每个最终目标目录内独立计数**（`Japan/Kyoto` 与 `Japan/Tokyo` 各有各的 `MY0001`）；
**关闭「包含子目录」时不透传** —— 只导入 source 根那一层的图片，子目录整体跳过。

### 1.6 导入：避免重复、进度与反馈

避免重复导入**默认勾选**。判据是**文件身份**（`(volume_serial, file_id128)`）＋ 内容大小/mtime 兜底；
导入后身份记在 `catalog.db` 的 `asset_files` 上。已在库中的文件**默认跳过**；若要强制再导入，
界面提供显式开关（M1 可先不做）。

导入是**真正建立数据**的一步（写 `assets`/`asset_files`/序号计数、把文件复制进库、排缩略图任务），
所以必须有**独立的进度弹窗**（不是角落里的一行字）：形态是**模态**，导入进行中不可被误关，
关掉＝取消（要二次确认）；要显示**当前阶段 / 总阶段**（扫描 → 复制 → 登记 → 缩略图）＋总进度条与百分比；
**计数**（已导入 / 跳过 / 失败）实时更新；**当前项**（文件名 + 库内目标路径）让人知道它没卡住；
**错误清单**可展开看原因（权限、磁盘满、格式不支持…）并可导出；**暂停 / 继续 / 取消**，
取消后已导入的部分**保留**且界面上要说清这一点；**结束态**是完成摘要（成功/跳过/失败）
＋「在库中查看这些照片」的跳转，失败项给重试入口。单个文件失败记入清单、**继续导入其余文件**；
缩略图生成是导入**之后**的后台任务，在弹窗里只体现为最后一个阶段（不阻塞导入完成）。

### 1.7 导入：界面（导入工作区与库列表）

（工作流切换 + 图片信息区 + 开关组）→ `toolsbar`（工具按钮，内容居中，随工作流变，无内容时整行隐藏）。

导入工作区是三列：**左列 Source（320 / 宽松 360，`surface-main`）**、**中列图片区（弹性，`surface-bar`）**、
**右列库（300 / 宽松 340，`surface-main`）**。左列上中下三段：`最近` → `来源` → `已选目录`，
段与段之间是可拖拽的 `SplitHandle`。`最近` 自动记录最近 50 个导入目录（不需要用户收藏），
显示 `shortpath`、悬停出完整路径；**勾选**（左侧圆形主色勾选框 = 加入待导入）与**选中**
（整行主色底 = 中间正在浏览它）是**两个独立状态**，跨面板（最近 ↔ 来源）的选中必须同步；
`来源` 是树（Windows 第一层是所有驱动器，**不只标盘符、前方要有来源类型图标**，为将来 NAS/云盘留位），
只显示目录不显示文件，点某目录后中间列出的**是该目录直属图片、不下钻子目录**；

中列**只展示图片、不含目录**，是精简版（图片 + 文件名/类型，**不含标色、星标、评级** —— 那些放 `toolsbar`）。
底部 `GridControlBar`：**计数** — 弹性 — **按时间按钮** — **当前选中目录** — 弹性 — **tile 尺寸缩放**（9 档）。

**正方外框 + 保比例照片居中 + 覆盖式信息条**（外框边长为尺寸档，行高恒定因此不重排；
照片短边贴边、四角 6px 圆角、超过 3:1/1:3 由后端居中截取；信息条**覆盖**在照片上、
锚在外框上下边缘，底部是文件名（去后缀）+ 扩展名标签 +（库内）锁位，顶部是（库内才有）
星标/颜色/旗标；默认无底纹，库内颜色标记给低浓色底，指向 → 辅色底 + 信息浮出，选中 → 主色底 + 信息常亮，
排除 → 照片变透明 + 正中一个中性的禁行图标）。tile 的排版纪律来自 `DESIGN.md` §12.6/§12.9。

按时间分组是**两级**：一级按拍摄日期（本地日期）一天一组；二级在该天内按拍摄时间升序，
**相邻两张间隔 > 1 小时就断为新片**（「1 小时」必须是**配置项**）。拍摄时间缺失的照片归入

选中后顶部就**只有一个恒定文字的按钮**，语义是**反转**（未排除 → 排除，已排除 → 取消排除），
无选中时禁用。排除入口从 tile 移到 `toolsbar` 后，缩略图干净了，`toolsbar` 原先的「筛选」占位按钮已移除。

右列是**所有库**（不是文件树），用横向卡片：库图标 + 库名 + 路径 + 照片数量，选中卡主色底 + 品牌色图标块。
卡片右侧那一格**一律图标化、不写「离线」二字**：**在线 = 齿轮**（开库设置，M1 只有「改导入模版」一项，
含变量提示与实时预览）、**离线 = 离线图标**（点它 = 对所有登记路径重新查找一次）。
还要体现**多路径**（列表显示当前在线的那条；离线时显示上次已知路径 + 标记）。
列表最下面是「一个 `+` 号库」的建库入口，再下面是动作区：**选中统计文案**（`已选择 3 个目录 · 1 248 张照片`）
→ **导入按钮**（**左边已选目录与右边库都选中才亮起**）→ **「避免重复导入」勾选项**（默认勾上）。

### 1.8 浏览：定位与三列

浏览模式是**看片、挑片、打标**的主战场：左边选库与目录，中间看图，右边看信息。
它与导入模式的根本区别是：导入模式「把照片弄进库」，浏览模式「对库里的照片做评估与组织」。
结构仍是三列 —— **左：库目录选择器**（搜索条 + 紧缩库列表 + 库内目录树）、
**中：照片 tiles / 看图 / 对比**、**右：信息栏**；三条横带不变，`toolsbar` 换成浏览专用的四组能力。

### 1.9 浏览：toolsbar 的四组能力与「筛选模式」

浏览模式的 `toolsbar` 承载四组能力，**全部只在浏览模式下出现**：**筛选开关**（一个可按下式开关）、
**标记系列**（旗标 / 清空旗标 / 标星 / 标色 / 喜欢）、**设置标签**（打开标签弹窗）、**设置锁**（两级锁）。

**筛选状态是本模块最独特的机制**：开关**关 = 平、开 = 主色底**（形态与「按时间」「吸附」一致）；
**开关打开后，后面的标记系列、标签、锁全部从「设置」变成「筛选」** —— 它们不再是「给选中图片设置值」，
而是「**对当前 tiles / 胶片带做筛选**」。影响范围**只限当前的 tiles 或胶片带内容**，不改库、不改目录；
**不影响看图** —— 看图模式下开筛选**不影响当前正在看的那张图**，哪怕它不在筛选范围内，
也只是**在胶片带里选不到它**，看图状态本身不变。您点名的「很爽」用法是：选中一张或多张图片时，
上面的标记/标签/锁显示成**这些图片的状态**；此时打开筛选 → **直接筛出同类图片**
（例如选一张 3 星红标图 → 开筛选 → 所有 3 星或红标图留下）。多选状态下开筛选时
**多个条件之间是「或」还是「与」**，您当时的口述读起来像「或」（此点已在 M2-W1 定为：
引擎两种都支持、**UI 默认「或」**）。

### 1.10 浏览：标记、标签、锁

标记系列里：**旗标**只有开/关两态，**不持久化、只在内存中**，**跨库、跨目录**都有效
（用来临时标记一堆要处理的东西，一定程度上替代未来规划的 bucket）；**清空旗标**清空内存中的
**所有**旗标（效果类似关掉软件重开），**点击要确认**（`easy destroy` 范式）。
**标星** 0–5 星、持久化，在已选中且为 1 星时**再点一次 → 扣成 0 星**。
**标色**红/黄/绿/蓝/紫/无共 6 态、持久化。**喜欢**喜欢/不喜欢/取消三态、持久化。

所有标记共同遵循**三态规则**：未选图片时全部处于**无状态**（默认态，没有值被点亮）；
选中单张时显示该图真实状态且**可以直接调整**；选中多张且取值不一致时显示**混合态**
（既不是有值也不是无值的中性形态），方便批量改，改完统一后恢复正常显示。
混合态必须与无值态**视觉可区分**（已定案：无值＝全暗 `fg-3`；取值一致＝显示该值；
**混合＝半亮 `fg-2` ＋ 一个短横**；硬要求是混合**不能**看着像无值，否则点一下会清掉一批已打标的照片）。

**设置标签**：单张时弹窗内**可增也可删**，标签以 **flex 横向瀑布流**列出、
**每个标签右边带一个叉**（点叉移除）；**批量时只能添加**（不能移除），添加时**自动去重**。
标签输入组件对标 Element 的「带查询的 select input」：一边输入一边搜索、**0.6 秒防抖**；
搜索出结果后可用**上下键**或鼠标选中；**输入完成后即使已有匹配结果，只要不选而直接回车 → 创建为新标签**。

**设置锁**：**一级锁 = 不能删除**，**二级锁 = 不能编辑**（更严，显然也不可删）；支持批量，
批量时遵循三态规则；锁状态在**图片上要有明确显示**（tiles 上、看图时、胶片带上都要能看出来）；
看图模式下**文件名右边紧挨着的就是锁状态**。

### 1.11 浏览：左列（搜索条 / 紧缩库列表 / 目录树）

左列从上到下三段。**搜索条**：本期是简单版、**只搜库名/目录名**，后续扩展到照片信息
（标签/注释/文件名/日期/EXIF 品牌…）；**结果的作用是「过滤」而不是「跳转」**——
界面内的库、库下目录、右侧照片 tiles 都只显示符合条件的内容；多层级目录命中时，
**该目录的整条树分支链路都要显示**（否则用户看不出它在哪）。

**紧缩库列表**是纵向排列的长条形库列表（组件与导入模式几乎一样，含离线徽标、齿轮、点离线检查在线）。
截断规则必须照做：**可见高度 = 最多 3.5 个库卡片** —— ≤3 个库时正常全部显示、区域随内容撑开
（用户感知不到有限制）；>3 个库时**第 4 个只显示「半个」**，而那半个里**不是库信息**，
只在**被看见的那半部分**显示「**查看所有库**」；用户点击 → 库列表展开到「除搜索条外的全部空间」，
并**完全吃掉**下方库内目录树的显示区域。展开态**支持滚动**、显示所有库、**每次点击的库都排到最顶部**、
**进入浏览模式时默认进入最顶部那个库**；**导入模式下每次导入照片，也会把该库在浏览界面移到顶部**
（这样「最常用的库 / 最近导入的库」自然浮在顶部）。**移顶规则的例外**（您特别强调）：
**展开态**点中的库移至顶部并选中、同时列表**收缩**、下方显示该库的目录树；
**收缩态**在**顶部三个库之间来回切换不会移动位置**（避免日常切换时列表乱跳）；
**导入行为**不管库在哪、列表什么状态，**都强制把该库移顶**。展开/收缩**要有弹性动画**。

**库内目录树**：选中库后库列表**收缩**并把选中的库放到**顶部并选中**，下方显示该库的目录树；
**选中会自动展开**；右边有展开/收起的图标；**点选（选中）与展开/收起必须是两个不同的动作**
（点名字=选中、点图标=展开），不要合并成一个。行尾 `⋯` 菜单有两项：
**删除空目录**（选项**一直在**，目录不为空时**暗掉不可点**；支持**同步删除其下所有空子目录**，
所以点开时要**做一次深度检索**判断「是否真的没有文件」）与**创建子目录**
（弹**中央模态窗**输入子目录名，**创建时检查重名**，重名要提示）。

### 1.12 浏览：选择逻辑与「当前文件」

选择逻辑**所有工作流通用**（tiles 与胶片带一致）：**点击** = 移除原有选中 + 选中当前这张；
**Shift + 点击** = **区间翻转**（严格语义见下）；**Ctrl + 点击** = 自由多选（**含反选**：
已选中的再点一下取消）；**按日期模式下**可直接点时间范围内的选中（点时间片/日组即选中该范围内全部）；
**无修饰键的点击任何时候**都是「移除原有选中 + 选中当前」；**Esc** 取消所有选中。

Shift 区间翻转的严格语义（用户逐字描述，必须照做）：`ABCDE` 五张连续图片，
① 点 A（A 选中、A 成为「上一次的图」）；② 按住 Shift 点 C → **A..C 之间（B 和 C）**的选中状态**翻转**，
**不包括**上一次的图（A）、**包括**这一次点的图（C），然后 C 成为新的「上一次的图」；
③ 按住 Shift 点 E → 从 C 开始计，**D 和 E** 翻转；④ 按住 Shift 再点 A → **A B C D 全部翻转**。
这样做的理由是**逻辑简单、无需保存复杂状态、操作又灵活**；**Ctrl / Shift 的所有选中操作都是「翻转」**，
不是单纯的「置为选中」。**暂不支持跨目录选择** —— 未来用**图片筒（picture bucket）**实现跨目录批量操作。

**「当前文件」（anchor）**回答「多选时右栏和状态栏显示谁」：单击某张就是它；
`Shift` 区间翻转后**本次点中的那张**成为新锚点；`Ctrl` 加选时**新加的那张**成为锚点；
取消锚点本身时回退到**最早选中的**那张；全部取消则右栏显示空态；看图/对比模式里
看图就是它、对比模式是**点击的那张**。**视觉**：锚点在「选中底」之外再加 **1px 主色内描边**，
一眼看出「选了一堆，但当前看的是这张」。**底部状态栏**中间显示
`库名 / 最后一级目录名 · 文件名`（**不放完整路径**），库名与目录名用 `$fg-3`、文件名用 `$fg-2`
（文件名是这块最要紧的信息）。

### 1.13 浏览：进入看图 / 胶片带 / 对比

**双击图片或回车**进入**看图**（不再是「放到全屏观看」）；看图模式下**下方形成胶片带**
（横向滚动选图）、上方显示照片；**Esc 或回车**退回 tiles；**选中多张时按回车**进入**图片对比模式**。
看图有三种显示状态、由 **`Tab` 循环**：① 默认（左边的库目录选择器 + 右边信息栏都在）；
② 关闭左右（只有中间看图部分最大化，**包括**下面的胶片带；**顶部区域不受影响**）；
③ 关闭胶片带（只关胶片带）—— ②③ 是并列循环还是叠加，**这条到现在仍未定**（`BROWSE.md` §10 问题 3）。
**按回车切回 tiles 时，左右栏都会回来**；**tiles 状态不做「tiles 区最大化」**（最大化只在看图模式存在）。

**胶片带**横向滚动选图，**选择逻辑与 tiles 完全一致**（点击 / Shift / Ctrl / Esc 全部适用）；
胶片带中多选 → **自然进入多图对比**；反选图片 → **自然从对比中移除**。
**对比模式下的特殊状态**：只要胶片带开启，**再按一次回车** → 胶片带**只显示当前对比的图片**，
此时胶片带区域显示**一个主色细边框**表示进入这种状态；在此状态下**即使不按 Ctrl**，
点击胶片带中的图也是「带 Ctrl 的效果」而不是简单选中 ⇒ **点什么图就把什么图移出对比**；
直到**只剩一幅图**时退出此状态、胶片带恢复显示全部图片，并**定位到这最后一张图的位置**。

**看图操作**：滚轮缩放；双击在 **100% 与适合窗口**之间切换；`←` / `→` 左右切图
（**所有界面通用**，不限于浏览模式）。**对比模式**：缩放**比例同步**（所有对比图一起缩放）；
位移**同步且按百分比换算**（不是按像素）；**画幅比例不一致时以第一幅图的画幅比例为准**，
对后面的图**扣等比例区域**做位移同步（例：第一张 4:3、后面是 3:2 → 只能对比「3:2 区域中间抽出来的 4:3」那部分）；
**点击哪张图**就是**当前实际选中的图**，决定右侧信息栏显示谁的内容。

**底部状态栏**在看图模式与 tiles 不同：tiles 同导入模式（计数/当前目录/视图控制等）；
**看图**时**左边**是文件名、**紧挨着文件名右边**是**锁状态**，**右边**是当前图片的**标记**（星/色/旗/喜欢）。
**全工作流通用**的操作还有：**`Delete`** 删除文件、**有确认**、支持批量；**`Shift + Delete`**
删除文件、**无确认**、支持批量；`←` / `→` 看图时左右切图。
（⚠️ `Shift+Delete` 这条与 `AGENTS.md` §11.3 在 M2-W1 阶段 4 的定案有冲突 —— 见 §5 待定夺。）

### 1.14 浏览：右列信息栏、标签体系与两个浮层

**右列内容随中间状态不同**：**tiles 模式**是 **Exif 详细信息**（要**支持滚动**，内容可能很长）；
**看图模式**是 ① **全图缩略图**（放大时要显示**当前看的那块区域的框**）② **直方图**。
**两种模式下都显示（通用）**：**标签信息**（该图的所有标签，点击/右键可增删）、
**文件基础信息**（文件名 / 创建日期 / 所在路径 / 所属库 / **作者**（可编辑）/ **Description**（可编辑））、
**地理信息**（GPS 经纬 / Country / Province-State / City / Sublocation，**均可编辑**）。
作者字段的附注：**将来支持「某库导入时自动设置 author」**（按库配置）。

**标签体系**：用过的标签存进 `app.db`（**全局标签词典，跨库可用**），标签**附到图片上**
（关联记在每库的 `catalog.db` 里）以便搜索。**标签库的管理界面本期不做**（改名、合并、批量删除等）。

**两个新的通用浮层**：① **中央模态** —— 原则上遮挡后面所有界面，用于创建库、导入进度、创建目录等；
② **右上角 toast（非遮挡提示）** —— 位置在 **`titlebar` 正下方、右上角**；形态是**一个清晰的框、
可以带边框**；**边框颜色表状态**（成功 = `$brand` 主色、警告/错误 = `$danger`）；底色走
`$surface-bar` / `$surface-layer` 那一档；**约 5 秒自动消失**；**除了自身显示，不阻挡界面上任何操作**；
占位大致是「图片信息 / 磁吸控制」那块（可能稍微压到 `toolsbar` 一点点，但 `toolsbar` 是居中的所以影响很小）。
放右上角的理由：① 不挡操作（右上角是空白拖拽区）；② 将来可以在 `titlebar` 右侧放「消息中心」，
把消息作为列表塞进去。

### 2.1 统一取图口（人类 2026-09-18 定，两条消息；**本波只做基础框架**）

第一段（初版要求）：

> 「只有 editor 上 GPU，DOM 查看照片的在 view；关键是统一渲染工作流 —— 预留两个工作流，
> 一个针对位图、一个针对 RAW……对外部调用来说，可能就是一个能用于显示的图片地址。」

第二段（**更正**，以它为准）：

> 「上面那段重点还是在 **view** 而不是 editor —— editor 涉及实时编辑、变化，
> 肯定不可能操作一次生成一次图片到磁盘上。所以这块的取图**主要用于 view**
> （**也可以用于生成 tiles 里小图的 cache**），而这个生图接口内的一部分逻辑，
> 多少会引用一部分 editor 中一直要调到的模块。可以这么理解：
> **这个接口是对 editor 中实际往 GPU 渲染图片的一次封装**，
> 以专门服务于 view / 生缩略图这一场景下的统一接口。」

所以约定变成：

| 项 | 约定 |
| --- | --- |
| **服务对象** | **view（DOM 看图）+ tiles 小图缓存**；**不是** editor 的实时路径（那条路直接进 GPU，不落盘、也不经这个口） |
| **本质** | **对「editor 里真正把图片渲染出来」那条链路的封装** —— 两边共用同一份渲染模块（解码 / 色彩 / 编辑栈应用），只是这个口把结果落成**能给 `<img>` 用的东西** |
| **两个口** | 位图 / RAW 各一个后端；调用方只给「资产 + 用途」，**不需要知道它是哪种** |
| 位图 | 没编辑过（导入阶段、SOOC）→ **直接给原图**；编辑过 → 套编辑逻辑生成一张再看 |
| RAW | 现在由 rawler 出图；封完后由**渲染器按修改设置**渲染成位图再给显示 |
| 临时图 | **能不落盘最好**；做不到、或实时生成会卡，就落临时图 + **定时清理机制**（属后一波） |
| 本轮范围 | **只实现基础框架**：两个后端 + 统一入口 + 复用缩略图那套缓存键（`render_signature` 已有），编辑栈接入留到编辑里程碑 |
