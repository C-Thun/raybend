> **这份表是给崔总的**（`AGENTS.md` §2.8：涉及真实 GPU、DPI、多显示器、体感的验证只能由人在真机上做）。
> Agent 侧已经把**能程序算的都算完了** —— 适配器、后端、表面格式与 alpha 模式、dpr、显示器、

## 1. 逐项检查表

每一项都按 **怎么做 → 看什么 → 填什么** 写。程序能答的已经在窗口左栏显示出来了，
你只需要把「填什么」那一列抄进报告（右栏的输入框）。

### 1.1 透明挖洞成立（无黑底、无白边）

| | |
| --- | --- |
| **怎么做** | 把 spike 窗口拖到另一个窗口（比如资源管理器）上面，让中间那块透明区**盖住**它 |
| **看什么** | 透明区里应当看到**下层窗口的内容**，而不是黑色/白色/灰色底；拖动窗口时不应闪烁 |
| **填什么** | 右栏勾「透明区是透明的」；如果不是，写清是「黑底」还是「白边」还是「闪」 |

- [ ] 透明成立，无闪烁
- [ ] 左栏 `alpha` 那一行记的是什么（`PreMultiplied` / `PostMultiplied` / `Opaque`）→ 抄进报告

### 1.2 1:1 档位下的像素锐利度

| | |
| --- | --- |
| **怎么做** | 点右栏「1:1」；把鼠标移到图像正中心（那个小十字上） |
| **看什么** | 中心应当是一个**方方正正的小白块**（一个图像像素＝一个屏幕像素），不糊、不发虚 |
| **填什么** | 右栏勾「1:1 档位下白块像素级锐利」 |

- [ ] 1:1 下白块是方的、锐的
- [ ] 顺手看一眼：左上/右上/右下/左下四个角应当是**红 / 绿 / 蓝 / 黄**（顺序不能错，错了就是镜像或翻转）

### 1.3 坐标同步（「图会不会跟不上鼠标」）

| | |
| --- | --- |
| **怎么做** | ① 把鼠标放在图像中心那个白块上，看左栏「命中测试」；② 然后**快速**来回滚轮缩放十几下，再放回中心点 |
| **看什么** | ① 放中心时左栏应当显示 **✅ 命中图像中心**；② 快速缩放之后，鼠标下的那一块图像**不能漂走**（这就是 RapidRAW 踩过的「差 1 像素图就跟不上鼠标」） |
| **填什么** | ① 数字（图像坐标）与是否出现 ✅；② 有没有漂移 |

- [ ] 中心处出现 ✅，图像坐标接近 `3000.0, 2000.0`
- [ ] 快速缩放十几下后没有可见漂移
- [ ] 左栏「程序化往返最大偏差」那一行是多少 → 抄进报告（应当是很小的数）

### 1.4 DPI 缩放（100% / 125% / 150%）

| | |
| --- | --- |
| **怎么做** | 关掉 spike 窗口（右栏或窗口关闭键都行）→ 系统设置把缩放改成 **125%** → 重跑 `RAYBEND_SPIKE=1` 直接开窗（见下面的命令）→ 对 150% 再来一次 |
| **看什么** | 每档都要：① 窗口内容不模糊、不留黑边；② 左栏 `dpr` 与 `显示器` 缩放两个数**一致**（125% → 1.25）；③ 再把鼠标放中心点，仍然 ✅ |
| **填什么** | 三档各填一行：dpr、是否 ✅、有没有异常 |

```bash
# 只想重开窗口、不重新构建：
RAYBEND_SPIKE=1 /mnt/c/rb-target/raybend/debug/raybend-desktop.exe
```

| 系统缩放 | dpr（左栏） | 中心 ✅ | 异常 |
| --- | --- | --- | --- |
| 100% | | | |
| 125% | | | |
| 150% | | | |

### 1.5 多显示器（有几台就做，只有一台就跳过）

| | |
| --- | --- |
| **怎么做** | 把 spike 窗口从主屏拖到另一台显示器上（两台缩放比例**不同**最好，比如 100% 与 150%） |
| **看什么** | 拖过去之后：① 图像仍然正确填满洞口、不模糊不变形；② 左栏 `dpr` 与 `显示器` 跟着变；③ 没有错位/闪烁 |
| **填什么** | 右栏勾「跨显示器拖动无错位/闪烁」；写清两台屏的缩放各是多少 |

- [ ] 跨屏后 dpr 跟着变，画面正确

### 1.6 窗口状态（resize / 最大化 / 全屏 / 最小化恢复）

| | |
| --- | --- |
| **怎么做** | 依次：拖边框改尺寸 → 最大化 → 还原 → 最小化 → 从任务栏恢复 → 全屏（F11 或最大化按钮看有没有）→ 还原 |
| **看什么** | 每一步之后图像都要**立刻正确**（不拉伸、不错位、不留白条）；最小化恢复后仍然正常（最小化时不该崩） |
| **填什么** | 有问题的步骤写出来；全都没问题就勾「四项都正常」 |

- [ ] resize 正常
- [ ] 最大化/还原正常
- [ ] 最小化→恢复正常（恢复后仍然出图）
- [ ] 全屏正常

### 1.7 命中测试（透明区吃不吃鼠标）

| | |
| --- | --- |
| **怎么做** | 在洞口（透明区）里：按住左键拖动 → 滚轮缩放 → 点击；再在洞口**外面**的面板上点几下按钮 |
| **看什么** | 洞口的拖动/滚轮都要**有效**（这是产品架构：指针事件由界面接住再转成意图）；面板按钮也要正常响应 |
| **填什么** | 有没有哪一处「点了没反应」或者「误触发」 |

- [ ] 洞口拖动有效
- [ ] 洞口滚轮缩放有效
- [ ] 面板按钮正常

### 1.8 后端回退（三个后端各跑一次）

| | |
| --- | --- |
| **怎么做** | 依次跑下面三条命令（每条都会重建+开窗；只改后端时要重建 exe 吗？不用，`RAYBEND_SPIKE=1` 直接开窗即可，但改了环境变量要重开进程） |


| **填什么** | 三个后端各填：起来了没有、后端名、有没有异常 |

| 后端 | 起来了吗 | 左栏显示 | 备注 |

| gl | | | |

### 1.10 性能基线（6000×4000 纹理 + 平移缩放）

| | |
| --- | --- |
| **怎么做** | ① 点「脚本平移 3s」；② 点「脚本缩放 3s」；③ 点「开始采集（手操）」，然后自己拖 + 滚轮折腾 5 秒，点「结束采集」 |
| **看什么** | 右栏表格里每个场景的 p50 / p95 / fps / CPU 两列 |
| **填什么** | 四个场景的 p50、p95、fps、CPU p50 抄进报告（表格会自动进报告，这里只是让你心里有数） |

- [ ] 平移 p50 ≈ 16.7ms（60Hz 上锁 vsync，正常）
- [ ] 缩放 p50 同上
- [ ] 手操时**跟手**（主观判断，勾右栏的「主观帧率」）
- [ ] CPU 那一列有没有接近帧间隔的（接近就说明是 CPU 瓶颈而不是等 vsync）
