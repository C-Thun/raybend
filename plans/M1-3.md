# M1-3 实施计划：扫描与缩略图管线

> 本文件是 **M1-3 这一个工作单元**的计划（`AGENTS.md` §5.4）。
> 相关：`PLAN.md` 的 M1-W3 / M1-W4、`AGENTS.md` §6.5（缓存）、§7.4（内嵌预览优先）、
> `LIBRARY.md`（导入后的落地结构）、`plans/M1-2.md`（已完成的数据底座）。

---

## 1. Context —— 这个单元解决什么

M1-2 已经能安全地建库、开库、写库（`crates/raybend/src/store/`，160 个测试）。
但**库里现在是空的**：没有任何东西把磁盘上的照片变成库里的记录，也没有可看的图。

M1-3 就是把这条链路打通：

```text
磁盘目录 ──扫描──▶ asset_files / assets 记录 ──缩略图任务──▶ 可显示的缩略图
                    （文件身份、EXIF、缺失标记）              （缓存，可删可重建）
```

产物会被 M1-5（导入工作区：源目录网格 + 流畅滚动）和 M1-6（导入执行）直接消费。

**验收锚点**：拿用户的真实样本 `/mnt/c/src/tmp/pic`（301 文件 / 4.2 GB，159 JPG + 142 RW2）
扫一遍，能给出**每张可显示图片的缩略图**，并回答性能问题（见 §7 的吞吐测量）。

## 4. Approach —— 分两波

### 4.0 共同前提：缩略图缓存放哪（**与 M1-2 的一个决定有关**）

`AGENTS.md` §6.5 要求「删掉整个缓存目录后，功能降级但完全可用」，而 `LIBRARY.md` §1
要求库根只有 `catalog.db` 与 `photos/`。所以：

```text
<app data>/cache/<library_id>/thumbs.db     ← 缩略图缓存（独立 SQLite 文件）
<app data>/cache/<library_id>/…             ← 将来 SCREEN 级的分片目录
```

- 独立文件、独立连接池与写者（复用 `store::pool` / `store::writer`，零新代码）；
- **删掉它 = 只是要重新生成**，`catalog.db` 一个字节都不受影响；
- 缓存路径将来可由用户改到外接盘（`AGENTS.md` §6.4 已登记）。

缓存表的键（`AGENTS.md` §6.5 的 `render_signature` 思路）：

```sql
CREATE TABLE thumbs (
    cache_key     TEXT    NOT NULL,   -- 文件身份（volume_serial:file_id）或折叠路径兜底
    size_class    TEXT    NOT NULL,   -- 'grid'（M1 只有这一档）
    render_sig    TEXT    NOT NULL,   -- 算法版本 + 参数（含 pipeline_ver）
    source_size   INTEGER,            -- 源文件大小/mtime：便宜的一致性校验
    source_mtime  INTEGER,
    format        TEXT    NOT NULL,   -- 'jpeg'（见 §9 问题 3）
    width         INTEGER NOT NULL,
    height        INTEGER NOT NULL,
    bytes         BLOB    NOT NULL,
    created_at    INTEGER NOT NULL,
    PRIMARY KEY (cache_key, size_class, render_sig)
);
```

**关键点**：`cache_key` 用**文件身份**而不是「资产 id」—— 这样导入工作区里**还没有入库的源文件**
也能用同一套缓存（M1-5 要显示源目录的网格）。

### 4.1 第一波：扫描与变更追踪（M1-W3）

#### A. 目录扫描（可中断、对 HDD 友好）

```rust
pub struct ScanOptions {
    pub recursive: bool,          // 是否下钻子目录（LIBRARY.md §4.2 的透传相关）
    pub follow_symlinks: bool,    // 默认 false（避免环）
    pub max_depth: Option<usize>,
    pub on_progress: Option<Box<dyn Fn(ScanProgress) + Send>>,   // 进度回调
    pub cancel: Option<Arc<AtomicBool>>,                          // 可中断
}

pub fn scan_dir(root: &Path, opts: &ScanOptions) -> Result<ScanOutcome>;
```

- **按目录批量、目录内按名字序**读取（HDD 上让磁头少跳），并发度可配（默认 `min(4, cores)`）；
- 每个候选文件产出 `ScannedFile { path, size, mtime_ms, file_id: Option<FileId>, kind: MediaKind }`；
- `MediaKind` 按扩展名判定（`media` 模块已有枚举）——**只认白名单**，其它一律忽略；
- 跳过明显的非照片（隐藏文件、`:Zone.Identifier`、`.tmp`、缩略图数据库自身）。

#### B. 增量与重命名识别（这是本单元最有价值的部分）

对库里已有记录做差异比对，**优先级从强到弱**：

```text
1. (volume_serial, file_id) 命中 → 同一文件：
   - 路径变了 ⇒ 判定为「重命名/移动」→ 更新 rel_path（保留资产的所有其它信息）
2. 身份拿不到（网络盘/FAT）→ 用 (size_bytes, mtime_ms) + 同目录文件名相似度兜底
3. 都没有 → 按 folded 路径匹配
4. 没匹配上 → 新文件（待导入 / 待入库）
5. 已有记录这次没扫到 → 标 missing_since（**绝不删记录**，AGENTS.md §6.4）
```

#### C. 缺失与离线卷

- `asset_files.missing_since` 置位；文件回来时清除；
- 整个卷不可用（库离线）→ 直接不扫描，由 M1-2 的 `resolve_library` 报离线。

### 4.2 第二波：元数据与缩略图管线（M1-W4）

#### A. EXIF 抽取 → 填 `assets`（拍摄时间、机型、镜头、ISO、快门、光圈、焦距、朝向）

- 新依赖 `kamadak-exif`（纯 Rust、MIT、只读、久经使用）——**待你确认，见 §9 问题 2**；
- 拍摄时间优先级：EXIF `DateTimeOriginal` → 文件名里的日期 → 文件 mtime；
  写入 `assets.taken_at` + `taken_at_source`（M1-2 已留这一列，就是为了这种透明性）；
- **RAW 的 EXIF**：M1 不解析（同名 JPG 对里，位图的 EXIF 与 RAW 等价）。

#### B. 缩略图生成

```text
读文件 → (RAW 或解码失败则走占位路径) → 解码 → 缩放（长边 N）→ 编码 → 写 thumbs 表
```

- 缩放档位：`grid` 长边 **384**（`AGENTS.md` §6.5 的 256–512 区间取中间）；
- 解码/缩放用 `image` crate（`jpeg` / `png` / `tiff` 特性），缩放先用 `image` 自带的
  `thumbnail()`（盒式滤波、只降采样、快）；若 §7 的吞吐测量不达标，再引
  `fast_image_resize`（SIMD）——**先不引**；
- 编码格式：**JPEG quality 82**（WebView 原生解码、体积极小、编解码都快）；
  备选 WebP（更小但编码慢、`image` 的编码支持有限），见 §9 问题 3；
- **RAW 与非图片**：生成一张**占位缩略图**（深色底 + 「RAW」/「?」字样，程序化绘制，
  不依赖字体文件），保证网格不留空洞；真正的 RAW 预览等 §9 问题 1 定了再说。

#### C. 任务队列与 worker（崩溃可续）

```text
扫描/导入 写 jobs 行（kind='thumb', payload={cache_key, source_path, ...}）
worker 池（默认 min(4, cores)）逐个领取 → 生成 → 写 thumbs → 标记 done
崩溃后重启：state='running' 的行重置为 pending（超过 attempts 上限则 failed）
```

- `jobs` 表在 M1-2 已建好，直接用；`state` 与 `attempts` 的语义沿用；
- **取消**：`cancel` 标志 + 每处理完一项检查一次；
- **进度**：`import_runs`（M1-6）与扫描进度各自统计，不做全局「任务中心」（M5 的事）。

## 7. Verification

#### Agent 能做的（冒烟 + 测量）

1. `cargo test -p raybend` —— 新增单测全部走**小规模合成数据**（几十 KB 的合成 JPEG/PNG，
   用 `image` 现场编码生成），保持**秒级**；真实照片一律进 `#[ignore]` 的手动基准
2. `cargo clippy --workspace --all-targets` 0 警告；`cargo check --workspace` 通过
3. **吞吐测量**（`cargo run --release --example thumb-bench -- /mnt/c/src/tmp/pic`）：
   报告 `文件/秒`、`MB/秒`、`平均缩略图字节数`、`P50/P95 单张耗时`。
   WSL 下 `/mnt/c` 走 9p，**会比 Windows 原生慢**，但足以回答「够不够用」和「要不要 SIMD 缩放」
4. **功能自测**（Rust 侧，不开界面）：
   - 扫描临时目录 → 断言记录数、身份、缺失标记、重命名识别（改名后仍是同一资产）
   - 同一文件重复扫描 → 不产生重复记录（幂等）
   - 缩略图：生成 → 读出 → 尺寸/格式正确；删掉 `thumbs.db` → 重新生成后结果一致
   - 取消：扫描与缩略图任务在中途取消后，已完成的项保留、未完成的不残留脏状态
   - 崩溃续跑：伪造 `state='running'` 的行 → 启动后被重置并跑完

#### 必须由人类确认的（`AGENTS.md` §2.8）

- 拿起真实样本看一眼：**RW2 配对里的 JPG 缩略图**、**无 RAW 的 JPG**、**RAW 占位图**
  三类的观感是否可接受；
- 性能体感（滚动流畅度）要等 M1-5 的网格出来才谈得上。

## 9. 待你定夺

1. **RAW 内嵌预览要不要放进 M1-3？**（这是本单元最大的范围问题）
   - (a) **先不做**（推荐）：M1 的 RAW 用**占位缩略图**；你的样本里 RAW 都配了同名 JPG，
     缩略图取 JPG，所以**实际观感几乎不受影响**；RAW 预览等 M1-7 之后单独做
   - (b) 现在就做：引入 `rawler`（LGPL-2.1）+ **独立 worker 进程**隔离（`AGENTS.md` §6.3 要求），
     能覆盖「只有 RAW 没有 JPG」的情况。代价：新依赖 + 进程间协议 + Windows 上 rawler
     未官方支持的风险 —— 这个风险不小，我倾向先做 (a)
   - (c) 折中：先做 (a)，但把 worker 进程的**接口与协议**先定下来（不引 rawler），
     等 M1-7 或编辑里程碑接后端时再填实现
2. **EXIF 解析依赖 `kamadak-exif`（MIT，纯 Rust）可以吗？** 另一个候选是 `rexif`（更小、维护弱）。
   我倾向 `kamadak-exif`。
3. **缩略图编码格式**：JPEG q82（推荐：WebView 原生解码、快）还是 WebP（更小、但编码慢、
   `image` 的 WebP 编码能力有限）？
4. **要不要现在就做实时目录监听（`notify`）？** 我建议**推到 M5**：
   导入流程（M1-6）稳定前做监听容易引发写入风暴，而 M1 用「按需扫描」已经够
   （导入后扫一次、库刷新时扫一次）。
5. **缩略图缓存放在 `<app data>/cache/<library_id>/thumbs.db`（推荐，库根保持干净）**
   还是放进库根（跟着库走，但会破坏 `LIBRARY.md` §1 的目录约定）？

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 真实照片上解码/缩放慢（尤其 WSL 的 9p） | §7 的吞吐测量先量化；不够再上 `fast_image_resize`（SIMD） |
| RAW 占位图被用户当成 bug | 占位图上直接写「RAW」字样；实施记录与 `ASSISTANCE.md` 里写明这是 M1 的有意取舍 |
| 扫描把用户目录读爆（符号链接环、超深目录） | 默认不跟随符号链接、限深度、可中断 |
| 缩略图任务与导入任务抢写 | 都走同一个单写者；缩略图任务**不持有**长事务（每张一个短事务） |
| `thumbs.db` 损坏 | 它是缓存：打不开就删掉重建（红线：删掉缓存目录后功能必须仍可用） |
| 依赖体积（`image` 不小） | 只开 `jpeg`/`png`/`tiff` 特性，不开 `avif`/`hdr` 等 |
