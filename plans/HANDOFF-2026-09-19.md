## 3. 未完成的三件（按优先级，含精确证据与下一步）

### ① 【阻塞冒烟】tile 的选中态不重绘

**现象**：冒烟里 `tiles 里 Ctrl 点两张应当有 2 张选中（实测 1）`，下游失败（多选→回车进对比、工具条按钮可用性）都是它引起的。

**已测量的事实**（都是打点实测，不是推测）：

```
store 选中集              : ["5","6"]      ✓ 点中了
适配器 selection()        : ["5","6"]      ✓ 一路读得到
Tile 内部 local.selected  : 六格全 false   ✗
同一组件的 label / src    : 正常跟随 ✓（说明格子是活的、item() 非 null）
「强制重建格子」实验      : 重建前=1 重建后=1  → 绑定**会**按当前 store 重算
```

**结论（重要）**：**不是"响应式不追踪"**（重建后结果一致），而是「两张选中的格子里只有一张渲染成选中」→ 是**逐格比较**的问题（某格的 `it.id` 与选中集内容没对上）。

**下一步（窄）**：在 `PhotoGrid.tsx` 的 `isSelected()` 里把 `{slot, it.id, [...ids], hit}` 打进一个 `globalThis` 数组（**保留数组尾部**，别只看开头——上次就是只看到开头 600 字符而误判），在冒烟点完两张之后读出来，看是哪一格、差在哪。

**注意踩过的坑**：清探针时**两次**误删了 `const tilesSelected = await send(` 这一行 → `node --check scripts/check-browse-boot.mjs` 必跑。

## 4. 这一个 session 踩过并已修的坑（下一个 session 不要再踩）

1. **TDZ**：`createMemo` 会立刻求值一次 —— 任何依赖后续声明的 memo 都必须排在依赖之后。
2. **传值 vs 传函数**：异步来的值（库根 `root`）必须传**取值函数**，传值等于把开工时的 `null` 闭包进去。
3. **行数组必须 `createMemo`**：`buildGridRows` 每次返回新对象，`<For>` 按引用去重 → 不 memo 会把整片行 DOM 重建（连点两张时第二下打在已被替换的节点上）。
4. **`Tile` 自己占着 `onDblClick`**（内部走 `onActivate`）：外面传 `onDblClick` 会被覆盖 —— 双击进看图要传 `onActivate`。
5. **看图件「谁建的谁渲染」**：网格传了外部 viewer 时**不要再自己渲染一份**（否则对比态出现两组返回控件）。
6. **分层路径**：`src/components/ui/tiles/x.ts` 里 import `lib/` 要写 `../../../lib/`（退三层）；`features/*` 不能互相 import。
7. **i18n / lens 的陈旧快照**：pi-lens 有时报「`itemId` 不在 store.ts 里」这类过期错误 —— 判据永远是 `tsc` 退出码。
