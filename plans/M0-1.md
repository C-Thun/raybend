## 2. 环境现状（实测，2026-09-15）

开发机是 **Windows + WSL2（Ubuntu 24.04）**，两端能力差异直接决定执行方式：

| 能力 | WSL2 Ubuntu 24.04 | Windows 侧 |
| --- | --- | --- |
| Rust | 1.91.1 → **仓库锁定 1.98.1** | 1.86.0 → **已升级 1.98.1 MSVC** |
| Node / pnpm | v26.5.0 / 12.3.4 | **刻意不装**（走「WSL 构建前端 + Windows 只跑 Rust」） |
| WebView 引擎 | webkit2gtk 4.1 + GTK3 | WebView2 运行时 `152.0.4191.66` |
| MSVC / Windows SDK | — | VS 2026 BuildTools + SDK `10.0.26100.0` |
| 磁盘 | `/` 剩 139G | `C:` 剩 78G（已用 92%） |

**两个硬结论：**

1. **WSLg 没有硬件 GPU**（`MESA: error: ZINK: failed to choose pdev`、`libEGL warning: egl: failed to create dri2 screen`）→ UI 骨架可在此验证，但 **GPU 渲染行为与性能数字只能在 Windows 上取**。
2. **agent 可以从 WSL 驱动 Windows 构建**：`cmd.exe` 互操作可用，`pushd` 到 UNC 仓库路径可用（会映射到 `Z:`）。

## 7. 踩坑记录（可复用的教训）

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| cmd `set` 尾随空格 | `set VAR=x & cmd` 把 `&` 前的空格算进值 → `failed to create directory 'C:\rb-target\raybend \debug'` | 不要用 cmd `set` |
| cmd 引号经 WSL 互操作丢失 | 改 `set "VAR=..." &&` 后变量**根本没生效** → 产物写进 WSL 仓库成为孤儿污染 | **用 `WSLENV` 从 bash 侧透传** |
| 9p 不支持 rustc 锁文件 | 增量编译在 `\\wsl.localhost` 上报 `could not create session directory lock file: 函数不正确 (os error -2147024895)` | 产物必须落 Windows 本地盘 |
| `mark_done` 会改写计划文件 | 勾选状态是真实写进 `plans/*.md` 的 | 计划文件的范围要小；不要一次性规划多个工作单元 |
