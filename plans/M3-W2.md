## 1. 目标与验收（DoD）

1. 切到「编辑」并选中一张照片后，洞口里出现**真实照片**（不是水印、不是占位块）；
2. 两条路都在：**RAW 内嵌预览**（快）与**完整解码**（1:1 档），状态里能看出用的是哪条；
3. 滚轮缩放**以光标为锚**（锚点下的图像像素不漂）、拖动平移、双击或 `0`/`1` 在**适合窗口 ↔ 1:1** 之间切；
4. 洞口之外**一个像素都不碰**（scissor），洞口内照片没盖住的部分是**界面底色**（不是桌面透出来）；
5. 渲染线程 **panic / 设备丢失都不许静默冻住**：捕获 → 重建 → 上报（状态里能看见重启次数与当前错误），
   恢复后错误横幅自动撤掉；
6. 窗口透明之后，**非编辑工作流的外观不变**（DOM 该画的地方一个像素不少）；
7. 六条质量门全绿：`typecheck` / `test` / `lint:colors` / `lint:arch` / `lint:i18n` / `build`，外加
   `cargo test -p raybend-desktop --lib` 与 `cargo test -p raybend`。

**明确不做**（留给后面波次，别当遗漏）：

- 编辑栈：拉杆改画面、落库、撤销（W3）；LUT 应用（W4）；裁切/旋转/对比的框线与手势（W5）；
- **位图 + RAW 配对时默认载入 `_RAW/` 同名 RAW**（`REPOSITORY.md` §4.1 第 257 行）——
  它是「编辑落在 RAW 上」的一部分，与编辑栈同时定（W3）；本波解码的是资产当前展示的那个文件；
- 缩略图金字塔 / mipmap（缩小时的抗锯齿质量）：本波用「预览档 ≤1920 长边 + 线性过滤」，
  真机目视若不可接受，W6 性能基线那一波处理；
- 色彩管理（第一阶段不做，`AGENTS.md` §6.1）。

## 2. 架构决定（写代码之前先定死）

### 2.1 谁画洞口底色：**wgpu 画**，DOM 那条链子在编辑态透明

透明挖洞的语义：webview 在 **DOM 没画东西的地方**是透明的，底下是我们画到窗口表面的内容。
所以「洞口」= DOM 让开的一块矩形。链条是（从上到下）：

```text
html / body（index.html 的行内底色）
  → #root → App 根节点（bg-surface-main）
    → 工作区外壳 → main（bg-surface-bar）
      → EditorViewport（bg-surface-bar）   ← 这一块要透明
```

三条规矩：

1. **只有编辑工作流、且「渲染器 ready 且已画出当前这张照片」时**这条链才透明（`holeActive`）——
   其余时刻一个像素都不动（浏览/导入/编辑空态的外观与今天完全一致）；
2. 透明时**洞口底色由 wgpu 画**（`LoadOp::Clear(backdrop)`，backdrop 由前端把
   `getComputedStyle(viewport).backgroundColor` 当**原始事实**报上来）——
   于是照片没盖住的部分是**界面底色**，不会透出桌面；
   顺带解决了主题：浅色主题下前端报的就是浅色令牌的值，Rust 不需要认识主题；
3. 空态（四态水印）**不依赖 GPU**：那时 `holeActive === false`，DOM 自己画底色 + 水印。
   渲染器起不来时同理 —— 洞口退化成一块普通 DOM 区域，**编辑工作区其余部分照常可用**。

> 为什么不让 DOM 画底色、wgpu 只画照片：DOM 在 GPU 之上，DOM 一画照片就看不见了。
> 这是「透明挖洞」的物理约束，不是取舍。

### 2.2 渲染线程：懒启动 + 一个监督器管三件事

```text
前端（编辑器挂载）           src-tauri/src/editor.rs                    crates/raybend/src/render/
  editor_bind_renderer  ──▶  EditorSession{ commands, shared }  ──▶  监督器（supervisor）
  editor_viewport_intent ──▶   命令通道（收发意图，不含坐标数学）      ├─ 建 GpuContext（挂主窗口 surface）
  editor_set_photo      ──▶   解码线程（一次一张，最新者优先）        ├─ 视口（Viewport，Rust 独有）
  editor_render_state   ◀──   RenderShared（快照）                  └─ 渲染循环
```

- **懒启动**：只有编辑器挂载时才有线程与 GPU 资源；离开编辑器 `editor_unbind_renderer` 停掉。
  没起编辑器时主窗口虽然透明，但 DOM 处处不透明 —— 与今天完全一样（退路仍成立）；
- **监督器**（`crates/raybend/src/render/supervisor.rs`）把三件事收成一个机制：
  ① 启动失败（窗口还没好 / 没有适配器）；② 渲染线程 panic；③ 设备丢失恢复失败。
  策略是纯函数（尝试次数 / 退避 / 终止态），循环体由它包住 —— 可单测；
- **线程内零窗口查询**（`AGENTS.md` §7.9）：窗口尺寸与 DPR 变化由**主线程**的窗口事件
  塞进暂存区（spike 的 `WindowFacts` 那套），渲染线程只取纯数据；
- **命令只是一堆状态更新**：线程每轮把通道里攒下的命令全部吃掉，再画**一帧**
  （不做「一条命令一帧」）；空闲时阻塞在 `recv_timeout`，CPU 占用为 0。

### 2.3 视口状态与命令面：前端只发意图

```text
editor_viewport_intent(intent)        # 只有意图，没有坐标数学
  zoomAt { x, y, factor }             # x,y = clientX/clientY（CSS 窗口坐标，**不**减洞口原点）
  pan    { dx, dy }                   # CSS 位移
  fit    { mode }                     # fit / fill / oneToOne / free
  reset                               # 复位：适合窗口 + 零旋转 + 零平移
  hitTest{ x, y }                     # → 写进状态的 lastHit（W5 的三个工具要用）
```

- CSS → 物理的换算**只在 Rust**（已有 `Viewport::{css_to_physical, pointer_to_image, zoom_at}`）；
- pan 用 `pan_by(物理位移)`；缩放用 `zoom_at(物理锚点, factor)`（锚点不漂是既有单测的职责）；
- 拖动与滚轮在**前端按帧合并**：滚轮复用 `components/ui/viewer/interaction.ts` 的
  `createWheelZoom`（同一份指数映射与尾样本语义，不造第二份手感）；拖动用同一套帧票号。

### 2.4 照片进纹理：两档 + 迟滞

| 档 | 何时用 | 怎么来 |
| --- | --- | --- |
| `preview` | 进编辑器、适合窗口、缩小 | `display::pixels(Screen)`：位图解码后缩到长边 ≤1920；RAW 走 worker 的**内嵌预览优先** |
| `full` | `zoom ≥ 1.0`（要看真实像素） | RAW：`DecodeRequest::full`（完整解码）；位图：原尺寸解码 |

- 迟滞：`preview → full` 在 `zoom ≥ 1.0` 触发；`full → preview` 要等 `zoom < 0.5`（避免在 1.0 附近反复解码）；
- **解码不在渲染线程上**：一条独立解码线程 + 世代号（generation），换照片/换档把新请求压进去，
  旧的世代回来直接丢；解码期间画面保持上一帧（不闪黑）；
- 纹理上传前把 RGB8 扩成 RGBA8（wgpu 的 `write_texture` 要求每行 256 字节对齐，
  RGB8 在 6000 宽下不满足）；超过设备 `max_texture_dimension_2d` 的图按上限降采样并在状态里说明。

### 2.5 复用：把「测试图渲染器」泛化成「照片渲染器」（**不造第二份 wgpu 上下文**）

`GpuContext` 现在写死一张 `scene::make_test_image(6000,4000)`。本波把它泛化：

- `render::image::RenderImage`（原 `scene::TestImage` 改名升级）：RGBA8 + 尺寸 + `from_rgb8` / `downscale_to_fit`；
- `GpuContext::new(handles, size, dpr, image, label_prefix)` + `set_image` / `clear_image`：
  **spike 与编辑器共用同一个 surface 渲染器**（`build_device_resources` 仍是唯一建资源入口）；
- `OffscreenRenderer::new_with_image(...)` + `set_image`：离屏那条路同样复用，
  于是「真实照片 → 纹理 → 视口 → 回读像素」可以在**没有窗口**的环境里断言（本仓的 WSL 就是这种环境）；
- `thumbnail/render.rs` 抽出 `decode_file(path, DecodeSpec) -> DecodedSource`，
  `render_file`（出 JPEG 字节）与 `display::pixels`（出像素）**共用同一份解码与方向逻辑**。

### 2.6 契约与轮询

- 新增 DTO 全部进 `src/api/dto-contract.json`，两侧（`src/api/dto-contract.test.ts` +
  `src-tauri/src/contract.rs`）对着同一份 JSON 断言（W1 已有的机制）；
- 前端在编辑器挂载期间**每 250ms** 读一次 `editor_render_state`：
  既是「渲染器起来了没有 / 画出来了没有」的握手，也是**监督器的上报通道**
  （重启次数、当前错误）；`lastError` 由后端在成功出图时清掉（spike 的「撤横幅」教训）。

### 2.7 命令体系接入（`AGENTS.md` §2.15）

- **不新增命令**：缩放 / 适合窗口 / 1:1 复用既有的 `viewer.zoomIn` / `viewer.zoomOut` /
  `viewer.fit` / `viewer.actual`（键 `=` `-` `0` `1`）—— 编辑器视口把自己注册进
  `components/ui/viewer/actions.ts` 的动作槽（那是**为这件事设计的扩展点**），
  并把编辑器接进 `App.tsx` 的 `activeWorkspaceActions()`（`viewing()` = 有照片）；
- 双击 = 适合窗口 ↔ 1:1（`DESIGN.md` §14.3 的看图口径）；
- 编辑器里 `Esc` **保持 W1 语义**（退出当前工具）—— 所以注册的 `close()` 是**空动作**
  （不去 browse：那是「回浏览」按钮/flowbar 的事，不该被 Esc 顺手触发）。

## 5. 风险与退路

| 风险 | 退路 |
| --- | --- |
| 主窗口透明后非编辑工作流外观变化（WebView2 透明会让文字失去次像素抗锯齿） | `holeActive` 只在编辑态为真；若真机目视不接受，退路是**只在编辑态**开透明（Tauri 运行时 `set_transparent`？v2 未必有）→ 备选：编辑视口改用独立子窗口（`FUTURE.md` 已登记 CEF 运行时那条更远的路） |
| WSLg / lavapipe 上建 surface 失败 | 前端把洞口退化回 DOM（`holeActive=false` + 一句说明），**编辑工作区其余部分照常可用**；Windows 真机才是判据 |
| 大图纹理超设备上限 / 内存尖峰（6000×4000 RGBA8 ≈ 96MB） | `max_texture_dimension_2d` 夹取 + `full` 档迟滞释放；真机内存体感记进 W6 |
| 全尺寸 RAW 解码阻塞缩略图（共用 `raw::worker`） | 解码线程串行、最新者优先；真机若明显卡顿，W6 给 worker 加优先级或独立进程 |
| `tauri.linux.conf.json` 是整份窗口配置的 merge patch，漏同步 | 本波只加 `main.transparent`，改完逐个字段对一遍；构建期 `pnpm lint:arch` 不查这个 —— 靠实施记录里的核对清单 |
