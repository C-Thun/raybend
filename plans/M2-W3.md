### 1.1 本轮追加（人类 2026-09-20 口述，**已先落地**）

> 「明显减小 tiles 放大的最大尺寸……放到 400 上下就够了，然后把这 9 级过渡改成 **17 级**过渡，
> 让尺寸变化变得更加细腻，方便适配不同的屏幕尺寸。」

* 阶梯：`128 … 400`（**512 封顶 → 400**），9 档 → **17 档**，级差约 ×1.074；
* 默认档从 256 挪到几何等价的 **260**（差 1.6%，为了阶梯均匀）；
* 存过的旧下标**按尺寸换算**（`migrateTileStepIndex` + 存储里的 `tileStepScale` 标记）——
  旧「最大档 512」不会静默变成中档，而是落到新上限 400；
* 落点：`lib/tile-flow.ts` / `lib/display-prefs.ts` + 两侧测试；
  实施记录见 `implementations/2026-09-20_tile-size-steps-17.md`。

## 2. 架构决定（写代码之前先定死）

### 2.1 一份注册表，三个消费者

```text
                 ┌───────────────────────────────┐
                 │  命令注册表 CommandSpec[]      │   ← 唯一事实来源
                 │  id / 文案 key / 分组 / 作用域  │
                 │  默认键 / 可用性 / run()       │
                 └───────┬───────────┬───────────┘
                         │           │
       ┌─────────────────┘           └──────────────────┐
       ▼                                                 ▼
┌──────────────┐   ┌────────────────┐   ┌──────────────────────────┐
│ 命令面板      │   │ 标题栏菜单      │   │ 快捷键分发器（唯一监听）   │
│ 模糊搜索/最近  │   │ 按 menu 分组    │   │ 匹配 → 执行 → 冲突检测     │
└──────────────┘   └────────────────┘   └──────────────────────────┘
```

**为什么必须是一份**：`AGENTS.md` §2.12。现在「同一个动作」在三个地方各写一遍（按钮 `onClick`、
keydown switch、将来的菜单项）—— 注册表把这三种入口压成同一份 `run()`。

### 2.2 分层落位（受 `lint:arch` 约束，`features/` 之间不许互相 import）

| 放哪 | 放什么 | 为什么 |
| --- | --- | --- |
| `src/lib/commands.ts` | `CommandSpec` / `CommandScope` / `CommandGroup` 类型；**纯**判定（`isApplicable`、`findConflicts`、`sanitizeShortcutFile`） | 纯逻辑 + 可测；`features/` 与 `shell/` 都能 import `lib/` |
| `src/lib/key-chords.ts` | 键位解析/格式化/匹配：`parseChord` / `formatChord` / `chordMatches(event)`；`Mod` 抽象（Win/Linux=Ctrl，macOS=Cmd） | 最容易写错、最需要单测的一块（修饰键、大小写、`+`/`=`、Backspace/Delete） |
| `src/lib/command-match.ts` | 模糊匹配打分（子序列 + 词首/前缀加权），不引第三方库 | 中文/英文/大小写/空格边界都要测 |
| `src/lib/shortcuts.ts` | 偏好存储（`localStorage["raybend.shortcuts.v1"]`）+ 覆盖表 + 最近使用 + 导入导出 JSON 形状 | 与 `display-prefs` / `layout-prefs` 同一套做法（设备级、首帧前可读、坏值回落） |
| `src/features/commands/` | `CommandPalette.tsx` / `ShortcutSettingsDialog.tsx` / `dispatcher.ts`（单一 keydown 监听）/ `registry.ts`（把各组命令拼起来） | 一级模块：自带视图与状态；**不认识任何别的 feature** |
| `src/features/<域>/commands.ts` | 每个域**自己**贡献命令（`createBrowseCommands(deps)` …），由组装层拼接 | 命令住在动作旁边；跨域只通过组装层 |
| `src/App.tsx` | 建 registry（把各 store 的动作传进去）、挂分发器、挂面板与设置弹窗 | 组装层唯一能 import 一切的地方 |

> **反面例子（明确禁止）**：在 `features/commands/` 里 `import { BrowseToolbar }` 或直接拿 `browseStore` ——
> 那会立刻违反分层检查（`features` 互不 import）。命令的 `run()` 一律由组装层注入。

### 2.3 快捷键存储（设备级，`localStorage`）

```jsonc
// localStorage["raybend.shortcuts.v1"]
{
  "version": 1,
  "overrides": { "browse.flag.pick": "Ctrl+Alt+P", "view.tiles.info": null }, // null = 显式解绑
  "recent": ["view.filter", "browse.open", "edit.undo"]                        // 最近使用（命令 id）
}
```

* 为什么不是 `app.db`：键盘布局是**设备级**的，而且要在**首次渲染前**读到（否则菜单上的键位提示会闪一下再变）；
  与主题 / 密度 / 布局 / 显示偏好同一条理由（`lib/display-prefs.ts` 的注释里写过）。
* 换机器靠**导入导出**（JSON 文件，走 `@tauri-apps/plugin-dialog` 的保存/打开）。
* 坏值一律回落默认（`sanitizeShortcuts`），**读取永不抛错**。

### 2.4 冲突检测判据（要能写进测试）

**作用域**（静态声明，是状态机里的「同一时刻只有一个成立」的互斥面）：

```ts
type CommandScope = "global" | "import" | "grid" | "viewer";
// global 与任何面同时成立；import / grid / viewer 三者互斥（同一时刻只有一个面在接键）
```

| 情形 | 判定 | 处理 |
| --- | --- | --- |
| 同一条键、**作用域相交**（含任一为 `global`） | **冲突** | 阻断保存 / 导入；提示「与『XXX』冲突」并给「解除绑定」入口 |
| 同一条键、作用域不相交（如 `grid` vs `viewer`） | 允许 | 列表里标一句「同一按键、不同上下文」；这也是现状（`0`/`1` 在网格=打星、在看图=缩放） |
| 保留键：`Alt+F4`、`Ctrl+Alt+Del`、`Ctrl+Shift+Esc`、`Win+*` | 不可绑定 | 输入时直接拒绝并说明（OS 级，抢不过来） |
| 开发期被 WebView2 抢的键（`F5` / `Ctrl+R` / `Ctrl+Shift+I`） | 可绑定但**警告** | 提示「开发期可能被 WebView2 吃掉；生产包不受影响」 |
| 把 `Delete` 绑给破坏性命令、或绑 `Esc`/`Enter`/`Tab`/`Space` 单键 | 允许但**警告** | 这些键有系统语义，误触代价大 |
| 只有修饰键（`Ctrl+Shift`）、未知键名、空 | **非法** | 拒绝并给原因 |

**运行时兜底**：万一两条命令同时匹配（导入的历史文件、外部改过存储），分发器**按注册表顺序取第一条**，
并把另一条打进 `console.warn`（不静默）。

### 2.5 分发器与「谁不归它管」

* **一个** `window` keydown 监听（挂在组装层），负责：文本输入/模态守卫（复用 `shouldHandleKey`，
  从 `features/browse/keys.ts` **挪到 `lib/keys.ts`** 供两边共用）→ 匹配 → `preventDefault` → `run()`。
* **不接管**（保持原地，登记成命令但标注 `builtin: true` 只显示不可改键）：
  * 文本输入框内的按键（搜索框、标签输入、可编辑字段）；
  * Ark 组件内部（菜单上下键、dialog 焦点陷阱、slider）；
  * 列表 roving focus（`Tab`/`Shift+Tab`、Tile 的 `Enter`/`Space` —— 那是**焦点行为**不是快捷键）；
  * `Escape` 关弹窗（Ark 自己处理）。
* **迁移顺序**（每一小步都跑冒烟）：
  1. 先接管 **`global` + `grid`** 面（browse/import workspace 的 window 级 handler → 命令，意图纯函数原样复用）；
  2. 再接管 **`viewer`** 面：把 CompareView 的缩放/适配动作收成一份
     `components/ui/viewer/actions.ts`（模块级单例，Viewer 与 CompareView 各自注册实现），
     命令的 `run()` 通过它取「当前生效的那一份」—— 这样 `0`/`1`/`+`/`-` 在两种看图形态下都是**同一条命令**；
  3. 最后才上**自定义 UI**（这时改键才是真的生效）。

### 2.6 菜单兜底（File / Edit / View / Window / Help）

* 标题栏左侧：五个菜单，**悬停标题栏才出现**（现状，`design/main.md` §2.1 的规矩不动），
  菜单打开期间钉住（`pinMenus`）。
* 菜单项**全部来自注册表**（`menu: "file" | "edit" | …`），所以「每个菜单项都是可搜索命令」是**结构保证**，
  不是靠人工同步。
* 每项右侧显示**当前键位**（`Menu` 组件加一个 `shortcut?: string` 位 + `kbd` 样式）；
  `enabled()` 为假时**暗着但可见**（`DESIGN.md` §12.11 第 3 条的口径：用户能看出能力存在）。
* 分组（第一版，够用即止）：

| 菜单 | 项 |
| --- | --- |
| File | 新建库… / 打开库（→浏览）/ 库设置… / 导入…（→导入）/ 退出 |
| Edit | 撤销 / 重做 / 全选 / 取消选择 / 标签… / 删除（回收站） |
| View | 四个工作流 / 主题 / 密度 / 筛选 / 按时间 / 信息档位 / 格子大小 / 排序 / 左右栏 / 胶片带 |
| Window | 最小化 / 最大化·还原 / 关闭 |
| Help | 命令面板 / 快捷键设置… / 语言 / 关于 |

## 9. 风险与退路

| 风险 | 退路 |
| --- | --- |
| 迁移 window 级键位时行为回归（W2 的键位表很密） | 阶段 2 拆成「先接管 global/grid、再删旧监听」，每小步跑冒烟；`browseKeyIntent` 一行不改 |
| CompareView 的本地缩放状态难以收口 | 只收「动作」不收状态（§2.5 步骤 2）；实在不行这两条命令标 `builtin` 只显示不可改 |
| 菜单变多后标题栏拥挤 | 菜单仍**悬停才出现**；`design/main.md` §2.1 的规矩不动 |
| 性能脚本在无头环境量不出 GPU 帧率 | 无头只报 JS 侧预算；60fps 归真机（脚本 + 人类目视） |
| 10 万条合成库拖慢冒烟 | 假后端**惰性生成**分页（不预建 10 万对象）；`perf:browse` 与 `check:browse` 分开跑 |
