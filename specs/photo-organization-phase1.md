# 相片整理上期：主要功能规划

> 2026-09-30，按崔总“上下两期分别规划并报告”的要求编写。**上期代码与 Agent 冒烟已完成，含跨库多选进入导出队列；Windows 真机交互和大库性能待人类验收。**
> 产品语义唯一正文：`photo-organization.md`。本文件只定义上期交付范围、依赖顺序、验证与交接，不另维护进度状态。

## 1. 完成后能够做什么

不安装 AI 也能完成“用标签找到照片或目录 → 跨库挑片 → 放入桶 → 用简单规则持续收片 → 继续评级/编辑/导出”的整理闭环。

| 范围 | 上期交付 |
| --- | --- |
| 左栏 | 库目录/相片桶/标签三个纯图标入口，整栏三选一，不能全关 |
| 照片标签 | 手动增删、文字规范化与去重、词典搜索、直接标签照片查询，接既有筛选/信息/导出 |
| 目录标签 | 只关联目录；标签树的第二级目录入口、正常目录导航、关联管理；绝不传播到照片 |
| 跨库查询 | 标签/桶照片均来自当前已挂载库，复合照片身份、统一 tiles 与批量路由；卸载不删记录 |
| 手动桶 | 新建/改名/删除、锁定置顶、选中或旗标加入、新建并加入、拖入、移出、成员幂等 |
| 自动桶 | 多组 OR、组内 AND、每类条件最多一次，指定库；初始补扫、增量收片、暂停/恢复、移出排除 |
| 规则弹窗 | 新建/编辑共用；完整显示、修改与新增条件链；从实际筛选复制草稿，目录范围不带入 |
| 可靠性 | 正式迁移、离线状态、崩溃重放、规则版本竞争与跨库部分失败反馈 |

自动桶是上期主功能，不能推到下期；下期只增加 AI 这个标签生产来源及纠错能力。

## 2. 明确不进上期

AI 模型/推理/安装下载、AI 批处理界面、照片遮罩操作入口、人脸识别、向量语义搜索、主体分割、目录标签继承、桶套桶、任意嵌套规则树、全局跨离线库标签改名/合并、手工成员排序。没有识别出来的类别也不能用假 AI 标签冒充已完成。

## 3. 上期的四个实施波次

| 波次 | 主要内容 | 出口与依赖 |
| --- | --- | --- |
| U1 交互稿与契约 | 在 `design/browse.pen` + 同名 `.md` 扩展三入口、标签树、桶卡片、加入桶选择器、共用规则弹窗；闭合空态/未挂载/错误态。确定文字关联迁移、照片跨库身份、规则结构与命令清单 | 界面实现以前稿件定案；契约区分已确认语义与尚待确定的默认值，不预建 AI 表 |
| U2 标签与统一照片来源 | 迁移照片标签文字真相；目录关联与设置入口；标签搜索/树/直接照片查询；将既有 browse 数据源一般化为目录、标签、桶可共用的来源适配；接多库身份、选择、分页、筛选、信息/导出标签 | 单靠标签就可找到直接标注照片与目录；目录打标对照片标签/自动规则无副作用；库目录原有行为回归通过 |
| U3 桶本体与规则编辑 | app.db 桶/成员存储，稳定卡片排序，选中/旗标加入、拖入和移出；新建/编辑同一条件链弹窗、筛选转换、范围选择、校验和真实查询预览 | 手动桶完整可用；规则能够保存及编辑，完整自动执行由 U4 收口，不提前宣称自动桶已完成 |
| U4 自动收片与整体验证 | 多组条件编译与复用；事件依赖、持久待处理与补扫、桶级排除、规则 revision；挂载/暂停/重启恢复；i18n/命令接入、性能检查、可重复 UI 回归脚本 | 上期全部功能形成一个闭环；Agent 冒烟与崔总 Windows 真机验收分开记录 |

顺序为 U1 → U2 → U3 → U4。每一波开工时再写必要的具体迁移/接口实施细节，避免在本次规划预分未来 schema 版本号或复制任务进度表。

## 4. 需要在 U1 固定的实现边界

- 标签文字键沿用现有规范化；catalog 自含文字与关联，app.db 只承担共享建议及全局桶。
- 目录关系直接按标签反查，不建立照片继承索引；移除一条目录关系不对整个目录的照片写库。
- 跨库照片身份需要在多库 tiles 前确定；优先评估上一轮持久照片 UID 建议，不能裸用不同库可能重复的 asset_id。
- 规则结构为字段对象和多组集合；库 ID 必填，值去重。允许显式“仅选库”的整库链，弹窗明确提示；最多 16 组，每组库范围和标签值各最多 64 个。
- 规则弹窗以草稿工作；新建/编辑/从筛选导入均共用，取消零写入，保存后才启用新 revision。库范围及所有条件必须显式可见。
- 筛选 AND 保留为一组，OR 转成多组；不复制目录/标签节点/桶的导航来源。临时 flag 或未知条件不能静默丢弃。
- UI 继续使用既有 TreeNode、按钮/菜单/选择器、PhotoViewingStage/PhotoGrid；筛选控件抽受控能力，禁止复制另一套规则控件和判断逻辑。

## 5. 下期必须能直接接入的预留

| 上期现在做到 | 下期再落地 |
| --- | --- |
| 手动来源有独立身份；来源写入不覆盖别的来源 | AI 生产者、模型/类别/输入版本与置信度 |
| 所有照片标签消费者经统一有效标签语义入口 | 在该入口统一加入 AI 和文字遮罩扣除 |
| 业务提交后变化记录与自动桶依赖通路可扩展 | AI 结果提交/遮罩改变发出同一种照片标签变化 |
| 统一复合照片引用与挂载会话校验 | 后台推理结果核对照片身份及输入版本 |
| 已有缩略图服务有明确源文件/版本契约可核对 | 本地 AI 读取有效 384px 缩略图，复用队列和缓存 |

预留不等于先安装推理运行时、创建无用表或给界面增加禁用的 AI 按钮；上期不被下期模型选型卡住。

## 6. 验证与完成判据

单元/合成冒烟必须覆盖：

- 中文、Unicode/NFC、大小写、空值/长度边界、同文字对照片和目录的关联独立、缺失旧标签名字安全保留。
- 目录打标签不改变照片标签结果；标签父节点不混入目录照片；目录子节点与原导航行为相同。
- 多库相同整数 asset_id 不串对象；挂载/卸载使查询重读且旧响应不能覆盖新范围。
- 标签/桶跨库多选进入导出后全部主定稿可入队；离线库或快照失败仅保留未成功照片待重试，不重复已入队项。
- AND/OR 筛选转换结果等价、每种字段仅一项、多值与多组去重、空白/非法规则拒绝、取消编辑无写入。
- 同照片命中多组只入桶一次，移出排除覆盖全部组；旧规则结果不能越过 revision；掉电重放不重复、不丢新变化。
- 不卸载重建 PhotoGrid；左栏模式无 none；新建/编辑共用表单，菜单/快捷键/拖入调用同一业务动作。

按改动运行 `cargo test` / `cargo check --workspace`、`pnpm typecheck`、`pnpm test`、颜色/架构/i18n 检查及 `pnpm build`。多库大数据、批量目录与自动桶负载实验单独手动运行，不拖慢默认单测。

UI 回归编写成可重复脚本；Agent 只做启动/日志/断言等冒烟。上期完成验证安排 `pnpm debug:win` 与产物核对，供崔总确认真实照片、窗口/DPI、拖拽与手感。规划阶段不构建；不跑 release，不顶版本号，不生成发布物。

验收场景：两个库给同名照片/目录独立打标 → 标签入口分别定位 → 跨库选片装普通桶 → 从筛选创建并修改两组自动链 → 新照片命中只入一次 → 移出不返 → 卸载后 tiles 移除、重新挂载恢复 → 评级/编辑/导出继续正常。

只有上述上期能力成立，才称“主要功能完成”；AI 未实现不影响上期完成定义。

## 7. 主要成本与风险

最大的改造是单库 BrowseStore/TilesSource 的多库适配及可靠自动写入，不是左栏三个按钮。文字词表迁移与既有全局数字 ID 兼容也需单独验证。目录标签改为目录颗粒度已删除最重的传播链路，不能在实现中偷偷加回来。

无新顶层框架或大型依赖；采用既有组件、Rust 查询/存储和任务机制。当前具体开工日期与工时未承诺，以 U1 定案与实际代码核对为准。
