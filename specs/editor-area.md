# 编辑区（area）系统 —— 规格

> **状态**：**规划完成，未实施**（2026-10-31 崔总口述并定案八条决策）。
> **开工门禁**：先出 `design/editor-area.pen` + 同名 `.md`（W0），人类定案后才动代码（`AGENTS.md` §5.1）。
> **粒度**：按 §5.4，本文件只把 **W0 / W1** 细化到可开工；W2–W6 保持路线级，开工前再展开。
> **关联**：`AGENTS.md` §2.26 / §11 / §13、`memory/PLAN.md` §4、`memory/FUTURE.md` §D4/D11/D12/D13、
> `docs/native-viewport-coordinate-guide.md` §4、`specs/xmp-sidecar.md` §5.1、`specs/issue-xmp-contract.md`。

## 0. 一句话

一张照片的编辑栈从「一份参数」变成「一叠层（`area`）」：每层有名字、上下顺序、启停开关，
层内装逐像素的影调 / 色彩 / 曲线调整；**控制点（`control point`）是层的一种类型**，用一处种子
加平滑权重把调整铺开，不用画蒙版。

## 1. 定位

* 编辑系统进入**层级时代**：一份照片 = 一叠 area，从底层向顶层依次求值。
* `全图`（full）是唯一必须存在的类型：可多份、可删，**删到最后一个不可再删**。
  它就是"没有点任何点的地方"的归属，也是全局阶段（LUT / 基础曲线）的隐式落点（§4.3）。
* 未来在同一个系统里加类型：**选区蒙版、智能蒙版**都作为 `AreaKind` 的新变体，不动骨架。
* **不做**（本轮及可见的将来）：层不透明度滑杆（崔总 2026-10-31：这毕竟不是绘图软件）。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| **`area`（编辑区）** | 编辑栈里的一层：带名字、顺序、启停的逐像素调整集合 |
| **`area panel`（编辑区面板）** | 左列顶部的层列表，与定稿 / LUT 面板同一套开关逻辑（toolsbar left 三选一） |
| **`全图`（full）** | 权重恒为 1 的层；每张照片至少一份 |
| **`control point`（控制点）** | 层的一种：一个种子点 + 一个范围 + 平滑权重 |
| **范围（`areaRadius`）** | 控制点的影响半径，归一化到源图短边 |
| **眼睛（`显示控制点`）** | toolsbar right 的开关，**只管控制点的圆点 / 引线 / 名字**是否显示 |

**命名固定为英文 `control point`**（崔总 2026-10-31 指定），代码与文档用 `control point` / `ControlPoint`，
不用 `u point` / `控制点标记`。中文界面文案用「控制点」。

## 3. 数据契约

### 3.1 形状

```rust
pub struct DevelopStack {
    // ── 全局（不进层）：与今天逐字段一致 ──
    color, source_base, as_shot_k,
    lens_profile, lens_enabled, base_curve_profile, base_curve_points,
    lut_id, lut_enabled, nr_method, geometry, auto_adjust,

    // ── 层：至少一条，areas[0] 恒为「全图」──
    #[serde(default, skip_serializing_if = "are_degenerate")]
    areas: Vec<Area>,
}

pub struct Area {
    id: u32,        // 稳定、单调递增、永不复用（撤销 / 引用 / 未来 XMP CorrectionSyncID）
    kind: AreaKind, // 带 tag 的联合体，不是 flag
    name: String,   // ≤30 字符，允许重名
    enabled: bool,  // 默认 true
    opacity: f32,   // 0..1，默认 1；**近期内无 UI**（预留，见 §10 D3）
    params: BTreeMap<String, f64>,
    curves: BTreeMap<String, Vec<[f32; 2]>>,
}

#[serde(tag = "type", rename_all = "camelCase")]
pub enum AreaKind {
    Full,
    Point { x: f32, y: f32, seed: [f32; 3], radius: f32 }, // 见 §3.3
}
```

### 3.2 参数表：新增 `target` 字段

`ParamSpec` 增加 `target: Tone | Chroma | Mask`（`develop-params.json` 同步，前端 `params.ts` 读同一份）：

* 管线只吃 `target != Mask`；掩膜求值只吃 `target == Mask`。
* 右栏参数区**只渲染 `Tone | Chroma`**（`Mask` 项不出现在参数区）。
* 预设侧一律不捕获 `Mask` 项（兑现"预设不存 area 信息"）。
* 新增四条 `Mask` 项：`areaRadius`（0..100，映射范围内半径）、`areaOpacity`（保留）、
  `areaChroma` / `areaLuma`（灵敏度，近期无 UI，固定 0.5）。

**为什么塞进 `PARAMS` 而不是另造结构**：撤销、校验、面板渲染、XMP 归类全部白拿（`AGENTS.md` §2.12）。

### 3.3 坐标与种子

* `x` / `y`：**源图归一化坐标**（方向已归正、裁切前）。绘制时经 Rust 变换矩阵换算（§7.9）。
* `seed: [luma, c1, c2]`：**创建时冻结的数值快照**，取样自「该层输入」（其下所有层与全局前置阶段的合成结果）。
* `radius`：归一化到源图**短边**，与缩放无关。
* 种子**从不实时重取**；界面在"该层输入已变"时给出提示与「重新取样」动作（§5.6）。

### 3.4 三条不变量（每条一张单测）

1. **退化不变**：没有额外层时，`serde_json::to_vec` / `profile_hash` / 侧车字节与改动前**逐字节相同**。
2. **阶段边界**：`Area.params` 出现非逐像素 id（镜头 / 降噪 / 锐化 / 局部色调 / LUT / 几何 / 基础曲线 / 色彩管理）
   → `validate()` 报错。比"界面禁用"硬。
3. **确定性**：同一份 stack 两次渲染逐字节相同；改下层不改上层 `seed`。

## 4. 求值与阶段边界

### 4.1 层内循环

```rust
for p in image {
    let mut val = base(p);              // 镜头 warp / 降噪之后
    for area in areas {                 // 底层 → 顶层
        let prev = val;                 // ← 本层输入
        let w = area.weight(p, prev) * area.opacity();
        if w <= 0.0 { continue; }
        val = lerp(prev, apply_tone_color(area, prev), w);
    }
    out[p] = val;                       // 之后才是锐化 / LUT / 显示变换
}
```

**红线：掩膜读本层输入 `prev`，绝不读本层输出 `val`。** 读输出 = 自我反馈（本层的调整改变选中范围 →
再改变调整），表现为拖动时选区缓慢爬行且不可复现。

**推论（重要）**：层内全是逐像素纯函数 ⇒ **合成不需要任何中间图**，一个像素里内循环走层即可。
`map_rows` 的行并行、单趟渲染、缓存签名全部不用动。一旦给层塞进邻域算子，就要引入 N 份 RGBA16
中间缓冲（20MP 一张 160MB），架构立刻崩 —— 见 `AGENTS.md` §2.26。

### 4.2 掩膜（U Point 五零件）

```text
d   = ‖(A(prev) − seed) · w‖₂          A = (luma, c1, c2)
α   = V(d)                             V 单调递减，V(0)=1；取 V(x)=0.5^(x/t)
weight = α                             Full 恒为 1
```

* `w` 由 `areaChroma` / `areaLuma` 映射（近期固定默认）。
* `radius` 通过把空间项折进 `A`（位置作为同一向量的一维）或对 `α` 乘一个径向衰减窗实现；
  **取"折进 A"**（与专利同构，也让"范围"就是那一维的权重），实施细节留给 W2。
* 原版多点"归一化竞争"（式 \[21\]）**不用于层间**，只留给将来"一个 area 里放多个控制点"。

### 4.3 全局阶段的锚点（**含一处待确认**）

**规则**：全局阶段（LUT、基础曲线/机型档案、色彩管理）不属层，但有隐式落点 ——
**自上而下第一个 `全图` area 的输出**。当前实现即如此隐式。

> ⚠ **待确认（唯一一处）**：LUT 现在挂在全局链末端（`render_develop16`：锐化 → LUT）。
> 若严格按"最高全图层输出处套用"，LUT 会跑到锐化**之前**，违反不变量 3.4-1（单层照片画面会变）。
> **建议**：v1 保持 LUT 在全局链末端，把"第一个全图 area"登记为**未来锚点**（LUT 并行改造时再用）。
> 基础曲线同理：不属层，全局，锚点语义与 LUT 一致。

### 4.4 层的求值方向

**底层先算、逐层向上**（上层叠在下层之上），符合"层"的直觉，也与 W2 的 `prev` 语义一致。

> 注：崔总 2026-10-31 第二轮口述出现「area 计算是从上向下计算」的表述，与第一轮「从最下方的往最上层去计算」
> 相反。本规格按**底层 → 顶层**定义（后者符合图层模型，也是 LUT 锚点那句"从上往下第一个全图"的自然读法：
> 那是**最后**一个被求值的全图层）。若本意相反，一句话即可纠正，改动只在 §4.1 的循环方向。

## 5. 交互规格

### 5.1 面板

* 位置：`toolsbar left` 第三组开关（定稿 / LUT / **编辑区**），三选一互斥，再点同一个 = 关整列。
* 结构：上＝层列表（可滚动）；下＝固定 `总览 / 信息`（与定稿 / LUT 面板完全一致）。
* 行内容：类型图标 · 名字 · 启停开关 · 删除图标（hover 出现）· 拖拽把手。
* 顶部右侧：「新建控制点」按钮（位置参考 LUT 面板）。
* **行内不放任何滑杆**（崔总 2026-10-31：范围控制走画布 handle，见 §5.4）。
* 重排：首版即支持拖动（复用 `DragPreview`，不写第二份）。

### 5.2 层名条（直方图下方）

* 位置：`HistogramPanel` 之下、`[data-editor-param-scroll]` 之外的**常驻**条（不随参数区滚动）。
* 内容：当前 area 的名字，**居中**；可视宽度左右两端均匀渐隐（`fade-x-end`，不用省略号，§2.22）。
* 顺带把 `HistogramPanel` 的外框/底部留白瘦身，腾出的高度给这一条。

### 5.3 画布上的控制点标记

* 形：实心小圆片（面积不随缩放变）+ 色环；外面一圈**明显白边**，白边外再包一圈**细黑线**（三者融为一体）。
* 引线：从圆片向**可用空间那一侧**水平引出，白线；线**上方**一行小字是 area 名字。
* 翻边判据：按**可用空间**（量标签宽度），不使用半平面；带死区，避免中线附近抖动。
* 尺寸：圆片 / 文字 / handle 都是**屏幕像素固定**（不随缩放变）。
* 点本身**不参与选中模型**（`AGENTS.md` §11.2 的"选中"），但**拖动它即把该 area 设为当前编辑层**
  —— 否则拖完位置，右栏还在改别的层，是最典型的错层事故。

### 5.4 范围 handle

* 位置：引线**远离圆片的那一端**一个小圆点。
* 拖动：横向拉伸即改 `areaRadius`；拖动时显示**范围圆**（几何提示，细线低透明度）。
* **引线长度固定**，不与半径挂钩。理由：
  1. 半径是图像空间量，引线若跟半径走，缩放到 400% 时 handle 会飞出视口；
  2. "图案不随缩放变化"只对圆片/文字成立，线长必须另定，固定长度最省事；
  3. 半径的真实反馈由**范围圆**给（它本来就该随缩放变）。
* handle 只在**该层为当前层**或 hover 时出现（100 个点时画布要能看）。
* 命中区 ≥ 8px；与拖动圆片（改位置）靠距离阈值区分。

> **注意区分**：范围圆是**几何**提示（半径多大），不是"实际受影响区域"。
> 控制点**不提供**渲染影响面（蒙版可视化）的功能（崔总 2026-10-31 明确）。

### 5.5 眼睛开关

* 位置：`toolsbar right`，重置按钮**左边**。图标 = 眼睛。
* 语义：**只控制"圆点 + 引线 + 名字"的显示**。不控制蒙版、不控制范围圆。
* 作用域：**纯视图偏好**，`localStorage` 版本化 key，**不进 profile / 不进哈希 / 不进撤销 / 不进 XMP**。
* 隐藏时必须**同时关闭抓取**，不允许"看不见但能拖"。
* 未来的蒙版显示是**另一套**：半透明**红区**（不是 PS 式黑白），独立开关，与本开关无关。

### 5.6 焦点与状态

* 换照片 → 当前层重置为 `areas[0]`（全图）。关掉面板再开 → 保留当前层。
* 删除当前层 → 选它的**下一层**（没有则上一层）。
* 新建控制点：按加号 → 待落点态（准星 + `Esc` 取消 + 面板一句带变量的提示）→ 点图落点 → 自动成为当前层。
* 该层输入已变（下层被改过）→ 层名条右侧出现「重新取样」小按钮（只在此时出现）。
* 裁切 / 旋转工具激活时：隐藏手柄并锁住拖动（不抢鼠标）。
* 层上限：**32**（超出时"新建控制点"变灰并给一句带上限数字的提示）。

### 5.7 默认命名

* `全图`（第一份）/ `全图 2` / `全图 3` …；`控制点 1` / `控制点 2` …
* 序号 = 该照片该类型的**最小未占用正整数**（删了再建不复用旧号也不撞名）。
* 名字在**创建时**按当时的界面语言生成并**冻结**（它是用户数据，不是界面文案；切语言不回改）。
* 用户可改名，≤30 字符，允许重名（引用一律靠 `id`）。

### 5.8 非全图层的禁用项

灰掉 + hover 小浮条 `当前编辑区域下不可用`（崔总 2026-10-31 指定文案口径）：

* 镜头（配置文件与三条手动杆）、色彩管理、LUT。
* 灰掉而非整块消失 —— 让用户看得见"这个功能存在，但这里不能用"。

**允许**：曲线（关键能力）、色温、饱和度、自然饱和度、影调四条、动态反差除外（见 §4.3 全局表）。
**不在层**：自动曲线 / 机型档案（全局；若有应用点，是自上而下第一个全图层）。

## 6. W0 设计稿清单（Pencil）

`design/editor-area.pen` + `design/editor-area.md` 成对，`.md` 须含视图用途 / 区域划分 / 控件 /

2. **层名条 + 直方图瘦身** —— 短名 / 超长左右渐隐 / 无层，并标出瘦身后的净高差。
3. **画布控制点标记** —— 点在左半 / 右半；hover；拖动中（含范围圆）；`enabled=false`；隐藏态。
4. **非全图层下的禁用表达** —— 灰掉 + 浮条。
5. **toolsbar 两处** —— left 三选一按下态；right 眼睛两态。
6. **两种空态** —— 待落点；最后一个全图层不可删。

| D1 | 层间合成代数 | **顺序累积**（底层→顶层，`lerp` 权重 = 蒙版 × opacity）；不采用归一化竞争 |
| D2 | 层序可否重排 | **首版就做**（LR 至今不支持，社区年年求） |
| D3 | 层不透明度 | **数据模型保留 `opacity`（默认 1）但无 UI**；近期不做透明度（不是绘图软件）。代价：重叠区叠加过头短期内没有总闸，只能调范围与参数 —— 已知取舍 |
| D4 | 种子语义 | **创建时冻结「该层输入」的合成结果** + 提供「重新取样」 |
| D5 | 首版类型 | **全图 + 控制点**两种；蒙版/智能蒙版是后续变体 |
| D6 | 层上限 | **32** |
| D7 | 眼睛的语义 | **只管控制点的圆点 / 引线 / 名字**；蒙版可视化是另一套（半透明红区），与本开关无关 |
| D8 | LUT 与层的关系 | LUT 是**独立层级、始终全局**，与 area 无关；隐式应用点是自上而下第一个全图 area（§4.3 有唯一一处待确认） |
| D9 | 层的复制 / 粘贴 | **不做**，登记 `memory/FUTURE.md` D12 并标注「有人给我钱了再做」 |
| D10 | 范围控制方式 | **画布上引线末端的 handle**（胜过层列表里的滑杆）；层行不放滑杆 |
| D11 | 引线翻边 | 按**可用空间**判据 + 死区，不按半平面 |
| D12 | 控制点的"显示影响面" | **不做**（控制点不做蒙版可视化） |

## 11. 风险

| # | 风险 | 处置 |
| --- | --- | --- |
| R1 | 层数 × 全图重渲导致拖动掉帧 | 复用现有"拖动中算预览档"（`beginParamDrag`）；上限 32 |
| R2 | 改下层后上层蒙版"看起来不对" | 层名条标「下层已改动」+「重新取样」（D4） |
| R3 | XMP 撒谎：把层合成后的扁平参数写进 `crs:`，外部软件存一次就丢层 | `crs:` **只写真正全局项**；层只进 `rb:profileJson`（自动跟随，§13.1-5） |
| R4 | 旧撤销历史里 `Op` 没有 `area_id` | 加 `Option<u32>`，`None` = `areas[0]`，旧栈仍可解析 |
| R5 | 裁切 / 旋转后控制点漂移 | 坐标定为源图归一化，绘制走 Rust 变换；进 `docs/native-viewport-coordinate-guide.md` §4 |
| R6 | 调错层（层系统头号事故） | 拖点即选中；层名条常驻；换照片回全图 |
| R7 | 裁切工具与控制点抢鼠标 | 工具激活时隐藏手柄并锁拖动 |
| R8 | `crs:MaskGroupBasedCorrections` 形态仍在变（LR 15.3 刚统一三种 legacy key） | 二期再议（`memory/FUTURE.md` D13），v1 不锁死 |

## 12. 明确不做

蒙版 / 智能蒙版 / 画笔、层的不透明度 UI、控制点的影响面可视化、每层直方图、层 solo/独显、
层的复制粘贴（D9）、三路色彩圆盘（`memory/FUTURE.md` D11）。
