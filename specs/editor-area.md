## 0. 一句话

一张照片的编辑栈从「一份参数」变成「一叠层（`area`）」：每层有名字、位置、启停，
层内装逐像素的影调 / 色彩 / 曲线；**默认层**同时是全局功能（LUT / 清晰度 / 镜头 / 色彩管理 / 局部色调）的宿主。

## 1. 三种层

| 类型 | 谁创建 | 数量 | 可删 | 能装什么 |
| --- | --- | --- | --- | --- |
| **`默认`**（default） | 系统 | **恰好 1** | ✗ | 逐像素参数 + 曲线 **+ 全局功能**（LUT / 局部色调 / 清晰度 / 镜头 / 色彩管理） |
| **`全图`**（full） | 用户 | 0..n | ✓ | 只有逐像素参数 + 曲线（权重恒为 1） |
| **`控制点`**（point） | 用户 | 0..n | ✓ | 同上，但按「种子 + 范围」铺开 |

* `默认` 的**效果就是全图编辑**（权重恒 1），但它是唯一能改全局功能的地方。
  「只有在默认层下，现有 editor 面板才是全功能的」——选中 `全图` / `控制点` 时，全局那几组灰掉（§5.8）。
* 新建照片 = `areas = [默认]`。用户加层一律**追加到末尾**（§4.4）。
* 未来：蒙版 / 智能蒙版作为 `AreaKind` 新变体；也许会有某类 area 的专属面板，现在不做。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| **`area`（编辑区）** | 编辑栈里的一层 |
| **`area panel`（编辑区面板）** | 左列顶部的层列表，与定稿 / LUT 面板同一套开关逻辑（toolsbar left 三选一） |
| **`默认`（default）** | 必须存在、不可删的系统层；全局功能的宿主 |
| **`全图`（full）** | 用户建的全幅调整层 |
| **`control point`（控制点）** | 一个冻结种子向量 + 一个**容差** + 平滑权重（**全图**匹配，**不是蒙版**） |
| **容差（`areaTolerance`）** | 控制点纳入多少「向量差」；同时决定强度渐变的宽度（与空间距离无关） |
| **眼睛（`显示控制点`）** | toolsbar right 的开关，只管控制点的圆点 / 引线 / 名字 |

**顺序术语**（`AGENTS.md` §11.5）：位置说「第 N 层」（第 1 层 = **基底**），先后说「先 / 后」；
**禁止**用「上层 / 下层」指计算顺序。

## 3. 数据契约

### 3.1 形状

> **实现时改过一次（2026-10-31，W1）**：默认层**不是** `areas[0]`，而是 `DevelopStack` 自己的
> `params` / `curves` + 那几个全局字段。理由：`params` / `curves` 在这份代码里被几十处引用，
> 把它们搬进 `Area` 等于全仓改名，W1 的「零行为变化」就守不住了。
> 代价是层列表要记一个 `default_index`；收益是**退化时序列化字节逐字不变**（`areas` 为空直接不写）。

```rust
pub struct DevelopStack {
    // ── 默认层本体（与今天逐字段一致）──
    color, source_base, params, curves, as_shot_k,
    lens_profile, lens_enabled, base_curve_profile, base_curve_points,
    lut_id, lut_enabled, nr_method, geometry, auto_adjust,

    // ── 默认层之外的层：顺序 = 计算顺序，新层追加在末尾 ──
    // 空 = 退化形状（只有默认层）⇒ 序列化里**不写**这两项，旧字节与旧哈希不变
    areas: Vec<Area>,
    default_index: Option<u8>,   // 默认层在层列表里的位置（0-based）
}

pub struct Area {
    id: u32,          // 稳定、单调递增、永不复用
    #[serde(flatten)] kind: AreaKind,
    name: String,     // ≤30 字符；空 = 显示类型默认名
    enabled: bool,
    opacity: f32,     // 0..=1；近期无 UI
    color: u8,        // **控制点色槽位 0..8**（`memory/DESIGN.md` §15.5），存下标不存色值
    params: BTreeMap<String, f64>,
    curves: BTreeMap<String, Vec<[f32; 2]>>,
}

#[serde(tag = "type", rename_all = "camelCase")]
pub enum AreaKind {
    Full,
    Point { x: f32, y: f32, seed: [f32; 3], radius: f32 }, // 见 §3.3
}
```

**颜色分配**（`DevelopStack::next_point_color`）：取已用次数最少的槽位，并列取下标最小；
只数 `Point` 层（全图层不画标记、不占颜色）。改色以后再做。

### 3.2 参数归属：`ParamSpec.target`

`ParamSpec` 增加 `target: Global | Layered`（`develop-params.json` 同步，前端 `params.ts` 读同一份）：

| target | 参数 | 能出现在哪 |
| --- | --- | --- |
| `Global` | `distortion` `vignette` `vignetteRange` `chromatic` `chromaticBlue`（镜头）、`lumaNr` `colorNr` `sharpenAmount` `sharpenRadius`（清晰度）、`dynamicContrast`（局部色调） | **只有 `默认`** |
| `Layered` | `exposure` `contrast` `highlights` `blacks` `temperature` `saturation` `vibrance` + 曲线 | 三种层都可以 |
| （不在参数表里） | LUT、色彩管理、基础曲线 / 机型档案、几何 | 绑定在 `默认` 上，走各自的结构字段 |

`validate()`：非 `默认` 层出现 `Global` 项 ⇒ 报错（比界面禁用更硬）。右栏按层类型过滤要显示的组。

### 3.3 坐标与种子

* `x` / `y`：**显示画幅归一化坐标**（0..1；方向已归正）。绘制时经 Rust 变换矩阵换算（§7.9）。
  * 2026-10-31 实现注：覆盖层与 `hitTest` 用的都是**显示画幅**（裁切 / 旋转之后的输出尺寸），
    所以落点也按它归一化；几何恒等（绝大多数照片）时它与「源图归一化」完全等价。
    几何非恒等时若按源图坐标存，画布绘制要反解一次几何，反而多一处可能错的换算。
* `seed: [luma, c1, c2]`：**创建时冻结的数值快照**，取样自「该层输入」（其下所有层与全局前置阶段的合成结果）。
* `tolerance`：归一化**向量距离**的尺度（`0..=1`），与空间距离 / 缩放都无关。
* 种子**从不实时重取**；界面在"该层输入已变"时给提示与「重新取样」。

**2026-10-31 实现注（取样）**：
* 取样走 `develop_area_seed` 命令：解 **1024 长边**的线性源 → 把当前栈（不含还在等落点的那一层）
  合成一遍 → 取落点周围 **7×7 小窗的逐通道中位数**，再算 `feature_vector`。一次点击几十毫秒，与全尺寸同一像素的颜色一致。
* **2026-11-02 修正（真实照片 bug）**：解码结果必须先按**文件头方向**摆正
  （`media::exif::raw_orientation`，与显示路径同一规则；worker 对 TIFF 家族报 1 不可靠），
  再取样。`MYP1000048.RW2`（EXIF 8）曾因漏掉这一步，点天空采到墙、点墙采到天空。
  旧照片用编辑区标题栏的刷新按钮按层序重新取样全部控制点（`EditorActions.resampleAreas`）。
* 镜头 / 降噪**不参与取样**（它们会移动像素；为一次点击跑全图重采样不划算）——已知近似，记在这里。
* `Ctrl`（macOS `⌘`）+ 左键拖圆片 = **移动采样位**（2026-10-31 崔总追加）。
  普通拖动**不接管**：圆片与视口平移是同一块手势区，不加修饰键会「想平移却拖走了点」。
  移动时**种子不重取** —— 「换位置」与「重新取样」是两件事（旧的）。
  ❗**2026-11-01 改口（崔总）**：移动采样位就是为了换地方取样 —— 松手后按**新位置**
  自动重取一次种子（`AreaMarkers.onResample` → `develop_area_seed` → `adoptAreaSeed`），
  位置与种子在同一次 `confirmEdit` 里落库（一步撤销）。
  理由：旧行为把点拖到别处画面一点不变，与「移动采样点」的直觉相悖。

### 3.4 三条不变量（每条一张单测）

1. **退化不变**：没有额外层时，`serde_json::to_vec` / `profile_hash` / `DevelopStack::signature()`
   / 侧车字节与改动前**逐字节相同**。
2. **阶段边界**：非 `默认` 层的 `params` 出现 `Global` id ⇒ `validate()` 报错（§3.2）。
3. **确定性**：同一份 stack 两次渲染逐字节相同；改下层不改上层 `seed`。

### 3.5 落地范式：照抄 `lut_chain` 已经验证过的那一套

| 坑 | LUT 链的做法 | area 照做 |
| --- | --- | --- |
| 旧数据兼容入口只能有一处 | `#[serde(from = "DevelopStackWire")]`，`From` 里把旧 `lut_id` 归一化成单层链 | `areas` 走**同一个** wire 入口（空 ⇒ 一个 `默认`），不许 DB / XMP / preset 各写一份迁移 |
| 退化形状不能破坏缓存 | `signature()` 里「单支 @100% / 空」**逐字照旧** | `areas` 退化成 `[默认(空)]` 时，`signature()` 与序列化字节保持今天的形状 |
| DB 只加列、不回填 | `catalog_0022_lut_chain.sql` | `areas TEXT` 同款；`prune_empty_stack` 判据一并加 `areas` |
| 改链只能有一个写入口 | `store.commitChain()` | `commitAreas()` 同款：截上限 + 结构校验 + `bumpDevelop` |

## 4. 求值

### 4.1 链循环

```rust
for p in image {
    let mut val = base(p);              // 解码 → 输入色彩 → 镜头 → 降噪之后，**线性 f32**
    for area in areas {                 // 列表自上而下 = 计算顺序（第 1 行最先算）
        let prev = val;                 // ← 本层输入
        let w = area.weight(p, prev) * area.opacity();
        if w <= 0.0 { continue; }
        val = lerp(prev, apply_area(area, prev), w);
    }
    out[p] = val;                       // 之后才是锐化 / 显示变换
}
```

**红线一：掩膜读本层输入 `prev`，绝不读本层输出 `val`。** 读输出 = 自我反馈（本层的调整改变选中范围 →
再改变调整），表现为拖动时选区缓慢爬行且不可复现。

**红线二：层内只允许逐像素操作**（`AGENTS.md` §2.27）。推论：**合成不需要任何中间图**，
一个像素里内循环走层即可，`map_rows` 的行并行与缓存签名都不用动。

### 4.2 控制点权重（**亮度 × 色相**，全图匹配，不是蒙版）

```text
seed = [Y′, Cb, Cr]                       感知域：先 sRGB 编码，再按 BT.709 求亮度 / 色差

ΔL = |Y′(p) − Y′(seed)|                   亮度轴
ΔC = ‖(Cb,Cr)(p) − (Cb,Cr)(seed)‖         色相轴（色度平面距离）

容差 u ∈ 100..1000（界面上的白线长度就是它的可视化）
t = (u − 100) / 900
band_L = (lerp(luma_core，t),   lerp(luma_end，t))
band_C = (lerp(chroma_core，t), lerp(chroma_end，t))

α = band(band_L, ΔL) × band(band_C, ΔC)   两个轴**各自**两段式，然后相乘
band(b, x) = 1                               x ≤ b.core
           = 1 − smoothstep((x−core)/(end−core))  core < x < end
           = 0                               x ≥ b.end
```

* **为什么要相乘（崔总 2026-11-01 真机拍板）**：旧模型把 `[luma, c1, c2]` 塞进**一个**
  欧氏距离、再比**一个**容差 —— 想把一件绿衣服的受光面与阴影都选上，就必须把容差放宽到
  0.27，而同亮度的红色此时距离 0.254、**也被拉进来**。这是「一个标量管两件事」的必然结果。
  换成两个轴各自两段式再相乘之后，亮度可以放得很宽，而色相闸门仍然收着：
  同一件衣服的受光面 `ΔC ≈ 0.05` 进得来，同亮度的红色 `ΔC ≈ 0.25` 进不来。
* **数值域**：`u ∈ 100..=1000`（`f32` 存储，连续无台阶）；新建时 **300**。它同时是白线的长度。
* **映射的八个数字**在 `crates/raybend/src/develop/areas.rs::POINT_WEIGHT_CONFIG`
  （`luma_core / luma_end / chroma_core / chroma_end`，每个都是 `[u=100, u=1000]` 两端、中间线性）。
  改手感**只动这八个数字**（开发期走调试面板，见 `implementations/2026-11-01_control-point-tolerance-and-ux.md`），
  改完必须抬 `PIPELINE_VERSION`。
* **感知域而非线性域**：线性 luma 在暗部挤在 0 附近，同一个容差在阴影里很宽、在高光里很窄 ——
  手感必然「一格一格」。sRGB 编码之后再量，容差在整条影调上近似等感
  （实现是 4097 项查表 + 插值，每像素 3 次，不碰 `powf`）。
* **色度平面而不是色相角**：近中性像素没有稳定的色相角（角度会跳变），平面距离天然把
  「很淡的颜色」放在原点附近 —— 中性种子只命中中性像素，彩色种子不会命中灰区。
* **没有任何空间项**：像素离采样位多远都一样算 —— 只要颜色相近就纳入（"全图扩展搜索"）。
  `x` / `y` 只用来（a）取种子、（b）画标记。
* **不是蒙版，也不是圆形蒙版**：没有边界、没有包围盒、没有"圈内圈外"。
* **SOOC（相机直出位图）基准下控制点不参与计算**：取样与掩膜都以「解码后的线性像素」为前提。
  此时新建按钮禁用、已有层在面板里置灰、画布标记半透明，载荷里发 `enabled: false`（权重 0），
  **层数据一个字不改**，切回 RAW 立刻恢复。
* **种子有版本**：`Area.seed_version`（`SEED_VERSION = 1` = 感知域）。旧定义（线性域）**没法换算**
  ——载入 latest 时按每个点的 `x/y` 逐点重新取样一次（位置 / 容差 / 参数都不动），然后落库。
* 原版多点"归一化竞争"（式 \[21\]）**不用于层间**，只留给将来"一个 area 里放多个控制点"。
* **独立设计声明（FTO，崔总 2026-10-31 要求记录）**：本权重由「位置无关特征 + 容差衰减」自行设计，**不参考任何厂商二进制实现**（无反编译、无移植）。形态上最接近的 Nik / Google『User definable image reference points』族（US 6,728,421 B2 及其 continuation 链，权利要求 1 就写着「each set having at least one characteristic that is location independent」）**已于 2022-10-24 到期**，当前不构成障碍；仍在有效的 Adobe『Local color range selection』族（US 11,223,744 B2 / CN 109 671 024 B）要求**空间掩膜与范围掩膜两个独立掩膜组合加权**，而本节成立的正是「**零空间项 + 单权重**」，不落入该结构。
* **专利边界同时是设计边界**：将来的蒙版**独立成层**（`AreaKind::Mask`），其权重图就是那一层的权重，与控制点**不相乘、不交叉** —— 不要为了「效果更准」把两个权重合成一个组合掩膜，那会同时破坏管线契约（§2.27）与上述边界。备忘：`implementations/2026-10-31_control-point-and-mask-patent-fto.md`。

### 4.3 `默认` 层 = 全局功能的宿主

`默认` 有两个身份：一个普通全图调整层 + **全局功能的归属地**。

| 全局项 | 实际执行位置 | 跟着 `默认` 层移动？ |
| --- | --- | --- |
| 输入色彩管理 | 链前（解码后立刻） | ✗（物理约束） |
| 镜头校正 / 变形 | 链前 | ✗ |
| 降噪 | 链前 | ✗ |
| 局部色调（`dynamicContrast`） | `默认` 层线性段之后（引导图按「源图 + 默认层线性参数」预计算） | ◐（近似：不含它上面的层） |
| 基础曲线 / 机型档案、用户曲线、色度 | `默认` 层的显示域段（§4.5 第 4 步） | ✓ |
| LUT 链 | `默认` 层段的末尾 | ✓ |
| 锐化 | 链后 | ✗ |

**"跑在默认这层下" = 归属，不等于全部在链里移动，也不等于界面要锁掉它。**
LUT 面板**恒可用**（崔总 2026-11-01）：选中控制点 / 全图层时拖 LUT 强度，改的仍然是**默认层那一段**的 LUT ——
不需要用户先切回默认层。右侧那些真正只属于默认层的组（镜头 / 清晰度 / 局部色调 / 色彩管理 / 基础曲线）
仍然灰掉 + 浮条 `当前编辑区域下不可用`。 物理上必须在前/在后的
（输入色彩、镜头、降噪、锐化）位置固定；能移动的是 `默认` 层的逐像素段、曲线、基础曲线、LUT、局部色调。

**`默认` 初始在列表第 1 位**（= 他上一轮"从上向下第一个全图 area"的口径：LUT 作为底层 look 先作用，
其后的局部调整都在它之上）。**它可移动** —— 这是「LUT 之前 / 之后」唯一的手段：拖到某个 `全图` / `控制点`
之后，LUT 就作用在它们之后。

### 4.4 求值方向与「新增追加在末尾」

**列表自上而下 = 计算顺序，新增追加在列表末尾。** 三条理由：

1. **与 LUT 链同一口径**（`specs/editor-lut-chain.md` §1：自上而下 = 逐层处理顺序）；两套东西在相邻面板里，
   顺序语义不能一边朝上一边朝下。
2. **新东西出现在末尾**：反过来（从末尾开始算）的话，新建的那一层必须在**最上面**才符合"最后算"，
   而用户对"新建"的直觉是"加到最后一行"（崔总 2026-10-31 原话）。
3. 推论：最后一行最后被应用 ⇒ 视觉上它盖在前面所有层之上。

> 历史：第一轮口述说过「从最下方的往最上层」，第二轮改为「从上向下」，以第二轮为准。

### 4.8 封闭控制点：**本期不做**

**决策**：只做**非封闭**（全图向量匹配，§4.2）。封闭控制点（区域生长、不跨过不相似的像素）
**本期不做**，方案整体存档在 `memory/FUTURE.md` D14 —— 做的时候照那份走，不要另起一套。

一句话理由：封闭点要邻域遍历 + 全图权重图，**不是逐像素算子**，进层就破了 `AGENTS.md` §2.27
（而那条红线正是"合成不需要中间图"的前提）。它的正确形态是**预计算掩膜层**（`AreaKind::Mask`），
不是 `Point` 的一个开关。

### 4.5 层内固定管线（一套，不许各层各写）

```text
输入：线性 f32（本层输入 prev）
  1. 白平衡增益 × 曝光增益（合并成一次乘：乘法律可交换）
  2. 反差（绕中灰 0.18 的幂）
  3. 高光 / 黑区（分段，两端固定 0 / 1）
     ── 若本层既无曲线也无色度 ⇒ 到此结束，**全程留在线性域，零往返**
  4. 转显示域（signed 可逆编码，**不夹取**）
     4a. 〔仅 `默认` 层〕基础曲线 / 机型档案
     4b. RGB 曲线 → 单通道曲线
     4c. 正向高光中性化（仅当 highlights > 0）
     4d. 饱和度 / 自然饱和度（绕亮度）
  5. 精确逆回线性
输出：线性 f32
```

**顺序的理由**：

* **白平衡在最前**：它是通道增益，晚做会把已有色偏一起放大；与曝光同为乘性、可合并。
* **反差不夹在影调两端中间**：反差定中段斜率，高光 / 黑区定端点行为；反了会互相打架。
* **曲线在色度之前**：曲线改的是亮度结构，色度要基于最终结构算（与今天 `map_pixel_exact_with` 一致）。
* **基础曲线只在 `默认` 层**：它是相机校准，**不能在每层重复应用**（重复 N 次就废了）；
  因为只在 `默认` 层，单层照片与今天**逐位一致**。
* 显示域段只在"本层真的有曲线/色度"时才进出（见 §4.6 的"按需跨域"）。

### 4.6 精度契约（多 area 不许伤色阶）

**承诺：层数不改变量化次数。**

| 位置 | 位深 | 说明 |
| --- | --- | --- |
| 入 | u16 线性 | rawler 解码（唯一不可避免的入量化） |
| 层间 | **f32 线性** | 不落地成图、不夹取、不转 8-bit |
| 出 | u16（显示再降 8-bit） | 只量化这一次 |

三个**真正的色阶杀手**与对策：

| 威胁 | 后果 | 对策 |
| --- | --- | --- |
| 层间写回 u16 / 8-bit 中间图 | 每层一个台阶（8-bit 更狠），32 层直接断层 | **单趟内循环**，运行值只在寄存器；永不物化中间图 |
| 每层 `clamp(0,1)` | 高光逐层被削 —— 这才是"伤色阶"的主犯 | 显示域段走 **signed 可逆编码**（LUT 路径已有 `signed_encode/decode` 与超域残差保留），**层间不夹**；只有最终输出 clamp |
| 每层查插值表 | 每层多 ~1 LSB 插值误差，逐层叠加 | **2026-10-31 实现取舍**：每层预建「线性半条链 / 显示半条链」两张表（与快路径同精度、同插值），层间只传 f32、跨域用 signed 编解码；实测单层与快路径**逐位一致到 1 个 16bit 级**（8bit 输出逐位相同）。纯 f32 标量写法在 24MP × 33 层时慢两个数量级，不能用在实时拖动上 |

**误差量级**：每层只有 f32 舍入（相对 ~1e-7），32 层累积仍在 u16 一个 LSB（1.5e-5）以内。

**性能对策**（不靠降低精度省时间）：

| 手段 | 收益 |
| --- | --- |
| 掩膜权重 ≈ 0 的层直接 `continue` | 控制点几乎免费（画面大多数像素权重为 0） |
| 纯影调层不进显示域（§4.5 的早退） | 省掉 6 次 OETF / 逆 OETF |
| **相邻、掩膜恒为 1、只含线性项**的 `全图` 层 ⇒ 可预折叠成一条 1D 复合表（每通道一张，按 u16 精确索引） | 把"N 层 = N 倍"压回常数；代价是参数变化时重建一次表 |
| 32 层上限（`memory/LIMITS.md`） | 兜底 |

> 折叠只在"中间没有控制点、没有需要跨域的层"时成立；被控制点隔开就分段各折一次。W2 实现时判据写死。

### 4.7 全局次序

```text
解码 → 输入色彩管理 → 镜头 → 降噪 → [area 链（默认层：线性段 → 局部色调 → 基础曲线/曲线/色度 → LUT）]
     → 锐化 → 显示变换（输出色彩管理）
```

**相对今天的画面变化（只有这两处，必须一起做）**：

1. **LUT 从"锐化之后"变成"锐化之前"**（因为 LUT 现在挂在 `默认` 层上，而锐化必须在链后）；
2. `默认` 层被移到第 1 位以外时，局部色调的引导图**不含它上面的层**（近似，记档）。

两条都要 `crates/raybend/src/thumbnail/render.rs::PIPELINE_VERSION` 加一，并在实施记录里写明
**是有意的画面变化，不是回归**。

除这两条外，单层照片与今天**语义一致**（对着 `map_pixel_exact` 这个参考实现对齐）。
注意措辞：W2 若把逐像素段从"查表"改成"直接 f32 数学"（§4.6 的对策），末位可能差 1 LSB ——
那是实现手段差异不是语义差异，但同样要走一次 `PIPELINE_VERSION`。

## 5. 交互规格

### 5.1 面板

* 位置：`toolsbar left` 第三组开关（定稿 / LUT / **编辑区**），三选一互斥，再点同一个 = 关整列。
* 结构：上＝层列表（可滚动）；下＝固定 `总览 / 信息`（与定稿 / LUT 面板完全一致）。
* 行内容：类型图标 · 名字 · 启停开关 · 删除图标（恒在；禁行图标）。**没有单独的拖拽把手**：
  整行可拖（行内的开关 / 删除 / 改名输入不参与拖动）。
* **双击行 = 就地改名**（2026-10-31 实现：行内输入框，`Enter` 提交、`Esc` 取消；
  最长 30 字符按**字符**截断）。没走弹窗：层名是短文本，弹窗要多一次确认与一次焦点跳转。
  `默认` 行的删除图标**不出现**、右侧是**锁**。
* 顶部右侧：「新建控制点」按钮 + 「新建全图」（追加到末尾）。
* **行内不放任何滑杆**：范围控制走画布 handle（§5.4）。
* 重排：首版即支持拖动（复用 `DragPreview`，不写第二份）。

### 5.2 层名条（直方图下方）

* 位置：`HistogramPanel` 之下、`[data-editor-param-scroll]` 之外的**常驻**条（不随参数区滚动）。
* **2026-11-01 平化（崔总定，以本条为准）**：**无边框、无底色**，不再是 `surface-track` 的一块；
  高 24，左右贴齐参数区（不再有 `px`），上下只留父级 `gap`（去掉原来的 `mb-1` 与直方图的 `!mb-1`）。
* 内容：左边一枚**主色**层类型记号（`AreaGlyph`：默认=滑杆 / 全图=方块 / 控制点=圆点），
  右边是当前 area 名字，13px **semibold**、`fg-1`；超长右缘渐隐（`fade-x-end`，不用省略号，§2.22）。
* **切层时名字上走一遍光条**（`ShimmerText` + `.rb-shimmer-mask` 的 800ms 单次动画，
  与导出「开始导出」处理中同一套原语）。首次挂载不走。

### 5.3 画布上的控制点标记

* 形：**三环同心**（不是白底 + 描边 + 贴一个色点）：外圈细黑线 1px、白圈 2.5px、内芯 12px，
  外面再没有别的描边；整体外框 20px（`design/editor.md` 2026-10-31 的 `RingBlack/RingWhite/Core`）。
* 引线（**就是容差白线**）：**水平**从圆片引出 —— 点在左半 ⇒ 向右，右半 ⇒ 向左；
  线是**白线 + 细黑勾边**（亮背景上也读得清）。
  **长度 = 容差**：`100..1000` 线性映射到 `lineMin..lineMax`（默认 **32..320** 屏幕像素，
  开发期可在调试面板里改）。所以「容差大 = 线长」，拉长拉短就是在调容差。
* 名字：**贴在圆片那一端**（采样点端）、线**上方**（`±(圆片半径+6)`、基线 −7），
  文字**永远从左往右写**（左半点在圆的右边用 `start`，右半点在圆的左边用 `end`）——
  于是**拖 handle 改容差时名字不动**，只有线的另一头在伸缩。
  名字**可以比线长**（不受线长约束）。
* 翻边判据：**图像中线**（`x >= 0.5` 走右侧）—— 2026-10-31 实现取这一条：
  设计稿只画了左 / 右两态，量标签宽度做动态翻边会让同一张照片在缩放时来回翻，反而抖。
  竖直方向只有一条**布局准则**：贴近洞顶（上方不足 26 CSS px）时名字翻到线下方（不量文字宽度）。
* 形：**非封闭 = 圆片**（现在只有这一种）；将来加**封闭**时用**朝上的正三角形**（§4.8）。
* 颜色来自**固定八色板**（`memory/DESIGN.md` §15.5，存的是槽位下标）；创建时取"已用得最少"的那个，
  并列取下标最小。与 browse 的图片色标刻意分家（那五个是中调灰、这八个是高饱和）。
* 圆片 / 文字 / handle 尺寸是**屏幕像素固定**；位置随图像变换。
* 点本身**不参与选中模型**，但**拖动它即把该 area 设为当前编辑层**（否则拖完位置右栏还在改别的层）。

### 5.4 容差 handle

* 位置：白线**远离圆片的那一端**一个小圆点；**横向**拖动改容差（往外 = 变大）。指针 `ew-resize`。
* **手柄 1:1 跟手**：拖动换算用的是**同一组端点** —— 拖 `lineMax − lineMin` 像素正好走完
  `100..1000`，所以线头永远在指针下面（不会「拖 10px 线只长 3px」）。
* 上下限：`u` 夹在 `100..=1000`（白线最短 / 最长）；再往内拖不动。
* 它控的是**容差**（差多少还算相近 + 渐变多宽），**不是空间半径** —— 所以**不画范围圆**：
  画一个圈等于宣称"圈外不算"，与 §4.2 直接矛盾。拖动时在名字下方显示一个带数字的小读数。
* 线**超出图像边界不管**（洞口本身可缩放平移），只在超出窗口时被裁。
* handle 命中区 ≥ 8px；与拖动圆片（改位置）靠距离阈值区分。

> 控制点**不提供**影响面可视化 —— 包括不画范围圆：容差是向量空间里的量，圈不出来。

### 5.5 眼睛开关

* 位置：`toolsbar right`，重置按钮左边。图标 = 眼睛。
* 语义：**只控制"圆点 + 引线 + 名字"的显示**。不控制范围圆、不控制蒙版。
* 作用域：**纯视图偏好**，`localStorage` 版本化 key，**不进 profile / 哈希 / 撤销 / XMP**。
* 隐藏时**同时关闭抓取**，不允许"看不见但能拖"。
* 未来的蒙版显示是**另一套**：半透明**红区**（不是 PS 式黑白），独立开关。

### 5.6 焦点与状态

* 换照片 → 当前层重置为 `默认`。关掉面板再开 → 保留当前层。
* 删除当前层 → 选它的**下一层**（没有则上一层）。`默认` 不可删。
* 新建控制点（**2026-11-01 改口径**）：按加号 → **只把按钮点亮（武装态）+ flowbar 提示一句
  「在图片中点击选取采样点」**（**不建层**，面板里不会多一行，也没有虚线幽灵行）→ 点图 →
  取样成功才创建那一层（追加末尾）→ 自动成为当前层。`Esc` / 再点一次加号 = 取消武装。
* **SOOC 基准下**新建按钮禁用；已有的控制点层照常显示（面板置灰、画布半透明），只是不参与计算。
* 该层输入已变（下层被改过）→ 层名条右侧出现「重新取样」小按钮（只在此时出现）。
* 裁切 / 旋转工具激活时：隐藏手柄并锁住拖动。
* 层数上限 **32**（不含 `默认`）；超出时新建按钮变灰 + 带上限数字的提示。

### 5.7 默认命名

**2026-10-31 实现定稿**（与 W0 画稿一致，替换原「按序号生成」的写法）：

* `默认` 名字固定、不可改。
* 新层 `name` 留**空串** ⇒ 面板按**类型默认名**显示（`全图` / `控制点`，走语言包、随界面语言变）；
  用户双击改名后写的是**用户数据**，从此不再翻译。
* 不自动编号：序号在「层名」这种短标签上没有信息量，反而让两层的名字看起来像一种编号系统。
* ≤30 字符（按字符，不按字节），允许重名。

### 5.8 非 `默认` 层的禁用项

灰掉 + hover 小浮条 `当前编辑区域下不可用`：**镜头、清晰度（降噪 / 锐化）、局部色调、色彩管理、LUT、基础曲线**。
灰掉而非整块消失（让用户看见"功能存在，这里不能用"）。

**允许**：曝光 / 反差 / 高光 / 黑区 / 色温 / 饱和度 / 自然饱和度 / 曲线。

### 5.9 与预设的关系

**预设不存 area**（崔总 2026-10-31）：不捕获名字 / 顺序 / 种子 / 范围；
套预设不会新建层、不会改层序、不会动任何控制点。

**2026-10-31 实现定稿：预设恒以「默认层」为作用对象**（不管当前在编哪一层）：

* 捕获与套用都走默认层的 `params` / `curves`（`store.presetSnapshot` / `applyPresetSnapshot`）；
* 于是 **Global 参数（镜头 / 清晰度 / 局部色调）与 LUT / 基础曲线 / 色彩管理永远与它们真正的宿主一致**，
  不会出现「名字叫 lens 的值被写进一个不能装 lens 的控制点层」；
* `Mask` 四条参数**不进预设**（`paramsInGroup` 已按 `target` 过滤）；
* 备选方案（按当前层捕获 / 套用）被否掉：预设里一半大类是全局项，套到控制点层时只能**静默丢弃**，
  等于同一份预设在不同层下语义不同 —— 比「只在默认层」更难解释。

**预设里的 LUT 走"追加"语义**（`specs/editor-lut-chain.md` §5）：贴到当前链**末尾**，按「第 1 层 → 最后一层」去重
（相同 LUT **保留最前面的那个**）；合并后超过 8 层的部分不加入并给一次提示；总开关从空链起步时听预设、
已有链时不会因为套预设被关掉；**预设里 LUT 大类为空 ⇒ 不动当前链**（预设整体是加法）。

## 10. 决策账本（崔总 2026-10-31）

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 层间合成代数 | **顺序累积**（第 1 层 → 最后一层，`lerp` 权重 = 掩膜 × opacity）；不采用归一化竞争 |
| D2 | 层序可否重排 | **首版就做** |
| D3 | 层不透明度 | 数据保留 `opacity`（默认 1）但**无 UI**；近期不做透明度。代价：重叠叠加过头没有总闸，只能调范围与参数 |
| D4 | 种子语义 | **创建时冻结「该层输入」的合成结果** + 「重新取样」 |
| D5 | 首版类型 | **`默认` / `全图` / `控制点`** 三种；蒙版是后续变体 |
| D6 | 层数上限 | **32**（不含 `默认`）。见 `memory/LIMITS.md` |
| D7 | 眼睛的语义 | **只管控制点的圆点 / 引线 / 名字**；蒙版可视化是另一套（半透明红区） |
| D8 | 全局功能归属 | 全部挂在 **`默认`** 层：LUT / 局部色调 / 清晰度 / 镜头 / 色彩管理 / 基础曲线。非 `默认` 层灰掉（§5.8） |
| D9 | 层的复制 / 粘贴 | **不做**，`memory/FUTURE.md` D12（「有人给我钱了再做」） |
| D10 | 范围控制方式 | **画布上引线末端的 handle**；层行不放滑杆 |
| D11 | 引线翻边 | 按**可用空间** + 死区 |
| D12 | 控制点的"显示影响面" | **不做** |
| D13 | 求值方向与新增位置 | **列表自上而下 = 计算顺序；新增追加在末尾**（与 LUT 链同一口径） |
| D14 | 预设里的 LUT | **追加到末尾 + 按序去重（保留最前面那个）**；超 8 层不加入并提示；**空链预设 = 不动** |
| D15 | 层内固定管线 | §4.5 那一套（WB×EV → 反差 → 高光/黑区 →〔按需跨域〕基础曲线 → 曲线 → 高光中性化 → 色度） |
| D16 | 精度契约 | **层间 f32 线性、不落地、不夹取**；量化只在入 / 出各一次（§4.6） |
| D17 | `默认` 是否可移动 | **可移动** —— 这是"LUT 之前 / 之后"唯一的手段（§4.3） |
| D18 | 顺序术语 | 位置说「第 N 层 / 基底」，先后说「先 / 后」；禁止「上 / 下」（`AGENTS.md` §11.5） |
| D19 | 控制点颜色 | **固定八色、按「已用得最少」自动分配**（并列取下标最小），版本内不做改色；层里存槽位下标（`memory/DESIGN.md` §15.5） |
| D20 | 控制点的本质 | **全图向量匹配，不是蒙版、不是圆形蒙版、没有空间项**；`x/y` 只用于取种子与画标记（§4.2） |
| D21 | handle 的语义 | 控**向量容差**（含强度渐变宽度），**不画范围圆**（画圈等于宣称空间边界） |
| D22 | 封闭控制点 | **本期不做**；以后按"蒙版层"实现（预计算权重图），不是 `Point` 的开关（§4.8） |
| D23 | 层改名 | **双击行 → 改名弹窗**（30 字符）；`默认` 层不可改名 |

## 11. 风险

| # | 风险 | 处置 |
| --- | --- | --- |
| R1 | 层数 × 全图重渲掉帧 | 掩膜为 0 跳过 + 纯影调层不跨域 + 相邻无掩膜全图层可折叠（§4.6）+ 上限 32 |
