# 可卸载存储 W3：长任务等待与续跑

接续已通过开发/冒烟的 W1、W2。复用现有 import runner、CatalogSink、RepoFs、export jobs Engine 与 catalog 租约，不新造任务框架。

恢复遵守固定身份：来源目录以平台 FileId（含卷身份）识别；目标以 catalog 唯一 ID 与实体 FileId 双重核对。不能拿到可靠实体身份时不静默自动续跑到路径上的未知设备。等待是非终态，已完成项保留，取消可在等待期间退出。来源等待只挂起该来源，继续其它来源；目标库等待暂停所有向该目标写入。恢复必须重新取得健康租约，不复活旧会话，也不自动转写同 ID 副本。

来源恢复从保存的文件安全点继续；扫描出错或中断的清单不得规划为完整结果。复制失败按设备状态区分等待与单文件错误；pending 目标须核对内容，大小相同不足以冒认复制完成。写入动作的重试保留待提交操作，不以失败提交丢掉登记意图。重启继续复用 import_runs/import_items 痕迹，并明确已成功、待登记和待重拷的区别；无需第二条迁移通道。

导出任务等待不消耗所有执行槽，也不被当终态失败；不同库任务可继续，恢复后仍验证捕获定稿与源身份。关闭队列/重置/取消等待不偷偷重启，发布文件前沿用 W1 会话闸门。导出队列仍是既定的进程内队列，不声称跨重启恢复未持久化的队列。

界面复用 `design/main.pen` 的 bJD0w 补充稿，崔总已批准补充稿，接入等待状态。进度、计数、阶段保留，使用中性说明；重新检查沿用继续动作但不可绕过身份验证。自动等待不是新命令；继续/重新检查和取消仅在进度模态内操作，不新增全局命令或默认热键（已有按钮承担此上下文操作，避免跨窗口误控批次）。

验收：

- [x] 来源与 catalog 身份在失联/恢复间得到核对，同路径换设备或同 ID 副本拒绝自动续跑。
- [x] 来源等待不阻塞其它来源，目标等待暂停整个目标批次，等待期间取消有效。
- [x] 中断扫描不规划半份清单，迟到结果不登记；pending 内容核验，部分成功不重复计数。
- [x] 导出等待让出执行槽，恢复保留队列意图并重新核对定稿；停止/重置可以终止等待。
- [x] 等待界面按批准画稿接入，双语 DTO 契约与命令体系决定同步。
- [x] Rust/前端单测、编译、合成冒烟与 Windows 成套产物核对通过。
