# app.db 启动等待与 catalog 升级遮罩

需求时间：2026-09-29。崔总确认本轮修正启动和现有遮罩流程；预置图生成等待具体需求。

## 行为与边界

- 产品启动先显示现有 splash，后台打开/迁移 app.db；迁移未返回时，首屏就绪和 4 秒兜底均不能提前关闭 splash。成功或失败都结束等待；失败保留既有明确错误，不无限等待。
- catalog 在验证已登记位置并建立会话时自动走现有 migration::apply。自动重连已走这条入口，无需另造迁移通道；升级成功前不交付会话。
- 复用现有 MigrationGate 的压暗遮罩、居中转圈和提示。catalog 标题明确为「库数据升级中」，说明完成后自动恢复；不显示 schema 版本作为操作提示。鼠标/键盘/滚轮被挡住，遮罩点击与 Esc 均不能结束升级。
- 按一次升级的唯一 ID 记账，而不是只按 app/catalog 种类；两个 catalog 同时升级时，一个结束不能撤掉另一个的遮罩。
- 外壳保存带递增 revision 的活动升级快照。前端先订阅再读快照，拒绝迟到旧快照；监听晚到/前端重新载入也能恢复正在升级的遮罩；清理订阅避免回写已卸载页面。事件订阅失败时只降级为每秒查询原生内存状态，查询单飞，销毁后停止。
- SQL schema 继续只走现有迁移执行器与 migrations/*.sql：版本闸门、迁移前快照、逐条事务、完整性检查、失败释放等待全部保留。

## 复用与设计

现有 store::migration、CatalogSessions、api/events.ts 与 MigrationGate 为唯一实现；本轮只修正时序、订阅与阻塞，不新增 UI 布局。崔总提供的标题及现有遮罩用于本轮实现。Pencil 连接当前 IPC 超时，无法同步 .pen；在 design/main.md 记录这次同布局文案修订及工具限制，不自行写入 .pen。

自动升级不作为可手动触发的独立命令，无默认热键；仍通过打开/重连库触发，既有 repository.reconnect 默认热键留空。

## 验收

- 原生测试：启动数据库未返回时，ui_ready/超时都不放行；正常/失败结束后恢复启动路径；迁移通知 ID 首尾一致、并发唯一。
- 升级注册测试：多 catalog 交错完成、快照可查询、revision 递增与溢出明确失败。
- 前端测试：晚订阅、快照与事件乱序、大整数 ID/revision、取消订阅及清理；并发升级只在最后一个结束后撤罩。
- 质量门：pnpm typecheck/test/lint:colors/lint:arch/lint:i18n/build；cargo check --workspace；相关 Rust 单测；已有 smoke:ui 遮罩冒烟按需修订。
- Windows splash 的实际可见性、真实旧库升级、GUI 阻塞与视觉由崔总验证；自动冒烟不代替真机确认。

## 预置图后续接入要求

SQL 结构迁移与图片生成分阶段；有必需生成任务时，升级范围应延伸到这些任务结束，不能在 SQL Done 时宣告全部完成。任务在 Rust/worker 生成，不能写进 SQL 长事务；以独立的版本化完成状态支持幂等、分批续做和失败重试。持久化字段仍用现有 SQL 迁移框架增加；普通可重建缓存是否需要全库阻塞随具体需求决定。

现有挂载探测等待上限 5 秒；长生成任务不可直接套进这段等待并当成拔盘/损坏。后续需把位置探测与已识别的升级任务等待分开，继续保留 I/O 单飞和预算。原图缺失、掉盘、磁盘满等策略随真实生成需求确定；本轮不声称已实现图片升级任务。需求原文保存在 todos/2026-09-29-catalog-preset-image-upgrade.md。
