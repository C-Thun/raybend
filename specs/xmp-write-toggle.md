# XMP 写出开关（验收增补单元）

**状态**：已批准实施（崔总 2026-10-09 问答拍板），本轮完成。
**关联**：`specs/xmp-sidecar.md`（主体规格；本文件修订其 §9「无设置开关」与 §11.6）、`specs/xmp-audit-tool.md`（验收工具）、`memory/REVIEW.md` R6-06。

---

## 1. 背景与决定（崔总 2026-10-09）

原规格 §9 定的是「无设置开关，编辑/标记时自动写」。崔总提出复核：是否给一个开关、默认关。
四问答拍板（本单元全部依据，不再二次征询）：

| 问题 | 决定 |
| --- | --- |
| 加不加开关、默认怎么定 | **加。默认开**（opt-out：默认写出，想不落文件的人自己关） |
| 开关存哪一级 | **设备级**（`app.db` settings KV，现成 `setting_get` / `setting_set`） |
| 打开时对历史照片 | **不补写**——只从之后的编辑/标记起写，不做后台扫描补写 |
| 读回（导入采纳） | **不受开关影响，永远读** |

默认取的「开」的理由（记档，避免下次重吵）：sidecar 在本项目里承担库内灾难恢复的半边
（`catalog.db` 丢了，`photos/` + sidecar 还能把编辑/定稿/评级/标签读回来）；sidecar 写在库内
（不是用户源目录）；行业两种先例都有（Lightroom 默认关、darktable/RawTherapee 默认写）。

## 2. 语义（唯一事实源）

### 2.1 键与默认值

* 键：**`xmp.write_sidecar`**（与前端 `SETTING_KEYS.xmpWrite` 同源，字符串 `"true"` / `"false"`）。
* 存储：`app.db` 的 `settings` KV（设备级；不进 catalog，**不需要数据库迁移**）。
* 读取：写出入口每次触发时现读（不缓存），所以改开关立即生效。
* 默认：键缺失、读取失败、值不是 `"false"`（大小写不敏感、去空白）→ **开**。取「保守向写」的一侧：读不懂的存储状态不改变默认行为。

### 2.2 关闭时的行为（判据清单）

| 场景 | 关闭时的行为 |
| --- | --- |
| 编辑提交 / 定稿增删改 / 标记（评级、色标、标签、文字） | **不写、不删**盘上文件；编辑照常落库，界面照常成功 |
| 内容清空到「全空」 | **不执行** §6.2 的删除（那是写出侧动作，关掉就别动盘上的文件） |
| 照片进回收站 | **照旧**把自家 `.xmp` 一起带走（`store/recycle.rs`，属清理不属生成） |
| 新资产导入 / 重扫重建 | **照旧采纳**自家 sidecar（读无副作用；关掉写的用户仍可能需要别人给的 sidecar） |
| 写失败日志 | 不再出现（根本没发起） |

### 2.3 打开时（含从关到开）

* 从**下一次触发**起写：不追溯、不补写、不扫库（§1 决定）。
* 已存在的（关期间未更新的）sidecar，按既有 §3.3 判据覆盖/备份/保留。
* 关期间全空但盘上仍有旧 sidecar 的资产，在下次触发时按 §6.2 删除。

## 3. 界面（`AGENTS.md` §2.15 / §2.20 合规）

* 落点：全局设置对话框新增一页 **「文件」**（`settings.files.title`），内一项开关
  「写入 XMP 文件」（zh）/ "Write XMP files"（en）。
* 说明**不占版面**：后果句（关闭后不再写入、已生成的文件不会被删除、重新打开从下次编辑起生效）
  放标题的**原生 tooltip**（与 `settings.editor.response.hint` 同一写法）。
* **不新增命令、不占默认热键**：设置项不是命令，经既有 `settings.open`（`Mod+,`）可达；
  本单元无用户可触发的新功能入口，故不进命令注册表。
* 前端读写走既有 `getSetting`/`setSetting`（浏览器降级自动落 localStorage）。

## 4. 工程接入

* 闸门位置：`src-tauri/src/sidecar.rs::sync_now` 入口（写出与删除的**唯一**通路）——
  关闭即整批跳过；`queue_sync` 保持原样（仍有队列语义）。
* 不做第二套开关实现：Rust 侧键常量一处（`sidecar::XMP_WRITE_KEY`），前端只在 `SETTING_KEYS` 里登记。
* 采纳路径（`adopt_new_assets`）不加闸门（§2.2）。
* 回收侧（`store/delete.rs`）不改（它本来就不认识设备级设置，语义如 §2.2）。

## 5. 测试

* Rust 闸门与会话层（`src-tauri/src/sidecar.rs::tests`）：开关值判定（缺失 / `true` / `false` / 大小写 / 空白 / 垃圾值，全部按 §2.1）。闸门本身是 `sync_now` 入口的一处短路（关闭 = 整批不动作），不单独造集成测试。
* Rust 核心（`crates/raybend/src/xmp/collect.rs::tests`）：真实（内存）catalog + 真实临时目录的
  `collect → compose → publish`（应写就写）与 `清空 → compose None → remove_if_ours`（应删就删）——
  闸门保护的正是这条通路。
* 前端：`src/lib/xmp-write.test.ts`（与 Rust 同一张值表）+ `SETTING_KEYS.xmpWrite` 登记在 `src/api/db.ts`。
* 不新增 cargo 集成测试通道；沿用既有单测。

## 6. 验收新增项（并入 `specs/xmp-sidecar.md` §10）

1. 关闭开关 → 编辑/标记一批照片 → 库内**不产生**新 `.xmp`；编辑全部照常保存；**已有** `.xmp` 内容不变（含「清空到全空」也不删）。
2. 重新打开 → 再编辑一张 → 该照片的 `.xmp` 出现；关期间编辑的那些仍没有（符合「不补写」）。
3. 关闭状态下导入一份带自家 sidecar 的照片（新资产）→ 编辑/定稿/评级**照旧读回**。
