# 相片整理下期：AI 增强规划

> 2026-09-30，按崔总“两期分别规划”的要求编写。**规划稿，未实施；依赖上期主要功能闭环。**
> 产品语义见 `photo-organization.md`；上期接口预留见 `photo-organization-phase1.md` §5。
> 本文件确定下期工作范围与验证次序；模型、推理运行时、阈值及资源预算在实测后选定，不提前虚构性能或新增依赖。

## 1. 完成后能够做什么

对照片的 384px 缩略图在本机识别少量大类，将结果作为 AI 来源的照片标签；可查看来源、纠正误判、禁止某个文字标签。既有标签导航、筛选和自动桶随标签变化工作，无需另一套“AI 相册”。

目录仍按目录标签导航，AI 不向目录自动打标签，不沿目录传播。

## 2. 下期范围

| 能力 | 交付 |
| --- | --- |
| 有限本地识别 | 少量可同时成立的大类，例：人、动物、鸟、风景、城市、室内、夜景；实际支持类别由样本效果决定 |
| 受控运行 | 对明确照片/目录/库范围启动识别、暂停/取消/重试、进度与失败说明；未挂载库不自动唤醒 |
| 来源合并 | 手动与 AI 同文字去重，分别保留来源，AI 重跑不能覆盖手动数据 |
| 文字遮罩 | 按照片＋规范化文字禁止，查看被禁止项、解除禁止；AI 重跑不能使禁词重新出现 |
| 纠错 | 保留为手动标签、禁止错误标签、重新识别；共用现有标签操作入口 |
| 自动桶联动 | AI 标签/遮罩变化复用上期依赖评估和持久队列，不引入第二个收片器 |
| 本地生命周期 | 模型不可用/加载失败/版本升级/输入失效/缓存清理均有确定行为，上期全部功能继续可用 |

不做：人脸身份识别/聚类、自然语言语义搜索、图像向量库、主体分割、云端图片上传、逐物体检测框、自动目录整理或自动修图。本次 AI 只服务大类标签。

## 3. 下期四个实施波次

| 波次 | 主要内容 | 出口与依赖 |
| --- | --- | --- |
| L1 可行性和类别校准 | 在本机用代表性 384px 输入对候选小模型做多标签效果、体积、加载、内存与耗时实验；核对运行时/模型许可、离线分发方式和 CPU 可运行性 | 形成具体候选及裁剪建议，登记 `memory/FUTURE.md` E；大型依赖在会话讨论后再引入。效果不足的类别直接裁剪 |
| L2 语义/UI 与存储 | 基于实测类别扩展 `design/browse.pen` + `.md`，定 AI 状态、来源详情、禁止/恢复、任务入口；正式迁移 AI 结果版本与文字遮罩 | 稿件定案后写 UI；来源/遮罩逻辑能用固定结果做确定性单测，未加载模型也不破坏手动标签 |
| L3 推理任务接入 | Rust 接有效缩略图、本地推理和可恢复任务，版本校验后原子替换 AI 集合；与导入/编辑队列协调资源、处理离线和失败 | 可对明确范围完成识别，暂停/取消/重试不写半份或过期结果；全程无需上传照片 |
| L4 联动、调优与验收 | AI 标签进入既有导航/筛选/自动桶，遮罩即时生效；校准误报、资源占用、模型切换与重启恢复；完整质量门与真机验收 | “识别 → 找片/装桶 → 纠错 → 重跑仍尊重纠错”闭环通过 |

顺序 L1 → L2 → L3 → L4。研究有结论后再锁具体迁移字段/模型接口，不将模型名称或某个运行时变成上期依赖。

## 4. 输入、结果与版本契约

建议识别照片原始内容而非 issue 版本：有相机直出用相应原始位图缩略图，RAW-only 用原始 RAW 的缩略图。必须先核对现有 384px 缓存是否随 latest 编辑变化，不能直接误用定稿封面。此输入选择在 L1 实测/L2 设计时定案。

- 推理只读取 384px 缩略图；必要的解码、缩放、模型预处理均在 Rust，前端只管任务和反馈。
- 缺缩略图走既有缩略图服务补建；不在 AI 模块重新实现 RAW 解码或借前端取像素。
- 结果关联照片身份、源内容版本、模型版本、类别映射版本与置信度。仅重建同一内容的缩略图缓存，不应触发无意义的全库重识别。
- 任务提交前比较捕获版本与当前版本；源已改变、模型/类别已切换、照片已移除时，旧结果不能落库。
- 成功后在 catalog 事务内整体替换该照片的 AI 来源并记录标签变化；失败不写部分集合，不碰手动来源与遮罩。
- 原结果输入仍有效而重跑失败，可保留原结果；输入已失效则原 AI 证据不参与有效标签，待新结果提交。
- 类别到 tag_key 的映射持久化并版本化；界面语言切换不自动翻译已经写入的标签，也不绕过文字遮罩。

## 5. 遮罩与纠错的闭合语义

有效照片标签仍为 `(manual ∪ ai) − masks`；目录关系不参与。

| 动作 | 结果 |
| --- | --- |
| 保留 AI 词为手动标签 | 新增 manual，解除同词禁止；AI 下次不再识别也仍保留 |
| 禁止某词 | 持久写 mask；所有照片来源的同文字都不显示，但证据保留 |
| 解除禁止 | 只移除 mask；仍有任意来源才出现 |
| 重跑 AI | 只替换 AI 来源，尊重 mask |
| 移除手动来源 | 有 AI 且未禁止时仍显示，来源详情解释清楚 |

未来 AI 禁止操作必须接入统一命令及撤销/反馈语义，不能只把标签 chip 在前端隐藏。新增动作的 defaultKey 默认留空，理由为低频且有明确上下文入口；继续走命令面板与快捷键设置，不能绕过上期动作接口。

**必须解释自动桶的累积性**：AI 误判曾把照片装入桶，之后禁止标签只改变今后的匹配，不自动移出已有成员。退出这个桶仍走上期“移出并排除”；本期不暗中把桶改成随规则动态增减的智能集合。

## 6. 任务和资源策略

优先做对明确范围的主动识别；可选的“仅新导入照片自动识别”在下期评估，默认不静默扫描全部历史库。

复用既有任务状态/挂载租约/取消与恢复方式，队列去重键包含照片与输入/模型版本。单个任务失败不影响其它照片，离线进入等待，不把离线记成“没有标签”。任务与 decode/导入争资源时主动限并发和批量，AI 不应让主要整理操作变迟钝。

模型加载与推理放在后台执行，评估独立进程隔离及现有 worker 接口的复用边界；不要把一套用途不同的任务硬塞进 RAW 协议，也不新造重复的通用任务系统。CPU 路径能工作是基线；硬件加速只有在具体测试证明值得时再接。

模型是否随包、首次可选下载或手动安装，需要在 L1 结合体积与许可明确，不默认新增在线服务、订阅或费用。模型安装与启用只作用 AI 增强；模型缺失时上期标签和桶保持完整可用。

## 7. 验证与完成判据

算法单测用固定推理结果，不加载真实模型进默认 `cargo test` / `pnpm test`。覆盖：多来源重叠、中文与规范化文字遮罩、解除禁止、手动提升、空结果、重复类别、非法置信度、结果版本过期、批次失败/取消、输入失效、规则重放和移出竞争。

模型质量实验分开进行：建立少量有人工类别标注的代表样本，校准和验证样本分开；逐类别报告误报/漏报、precision/recall，而不是只报整体“准确率”。门槛与阈值由实测确定；**优先少出错，低置信度宁可不写标签**。不具备可靠效果的类别从本期支持范围移除，不用提示词修补假装支持。

资源记录包括模型大小、冷/热启动、每张耗时分布、峰值内存、取消响应、同时浏览/导入时的影响。不能用 Node 内存数据库旧实验替代本地推理测量。

产品质量门沿用上期。Agent 交付固定样本冒烟、故障注入与可重复 UI 回归脚本；崔总在 Windows 上确认类别效果、误报纠错、真实照片与性能体感。真实模型测量与真机体验分开，Agent 不宣称已替代目视验收。

下期完成场景：照片识别出“鸟” → 标签导航可见且既有自动桶收片 → 禁止“鸟”后照片标签/筛选一致消失 → 重跑仍不出现 → 手动添加后恢复 → 卸载/重新挂载与重启不丢纠错；自动桶历史成员保留符合既定累积语义。

## 8. 与上期的交接检查

上期必须提供独立 source 写入、统一有效标签读取、稳定照片引用、可靠标签变化通知、可复用自动桶规则和缩略图服务。L1 可以先做独立模型实验；正式产品接线以上期这些契约稳定为前提。下期不得重新实现标签词典、照片选择、桶规则编辑器或自动收片引擎。
