## 1. 本期完成定义与边界

在本机对明确选择的照片、目录或库进行内容识别，可靠结果进入既有照片标签，支持来源查看、手动保留、按文字禁止与恢复。标签导航、筛选、导出和既有自动桶读取同一个有效标签集合。

- 首批重点：**人、鸟、车、山、海、森林、夜景**；一张图允许多个类别同时成立。其它类别只在质量验证通过后加入，首包上限 32 类。
- 识别的是照片本身。目录标签仍只生成目录入口，不传播到照片；AI 不自动给目录打标签。
- CPU 完整运行是交付基线，**产品不得依赖 CUDA、Python、PyTorch 或外部 AI 服务**。模型制作工具与终端产品运行依赖分开。
- 明确范围、主动启动；本期不做导入后静默自动识别、不后台扫描全部历史库。
- 不做：人脸身份/聚类、自然语言搜索/向量库、检测框、自动描述/OCR、编辑蒙版、自动修图、训练/微调、自定义任意识别词。
- 蒙版独立登记 `memory/FUTURE.md` D4/E2。标签“屏蔽”与图像“蒙版”是不同数据，不能混用。

允许为了效能限制并发和缩减自动化。本期保留七类，逐类披露实际效果：人物漏标、海类误标/漏标仍明显，不将校准目标等同真实图库保证，不删除难类后宣称原范围全部达标。

## 3. 模型与运行时决策

### 3.1 本期锁定 TinyCLIP

| 顺序 | 候选 | 用途与决定 |
| --- | --- | --- |
| 本期采用 | `wkcn/TinyCLIP-ViT-40M-32-Text-19M-LAION400M` | 固定revision，FP32图像编码器151.53 MiB；按崔总认可的准确率偏好完成校准与交付 |
| 远期考查 | `google/siglip2-base-patch16-224` | 本期不安装、不并跑；成本与原实验保留在 `memory/FUTURE.md` E1 |

原规划生产端只装**一个默认标签模型**，首版不做模型市场/多个识别模型并跑。不根据 ImageNet 总分或论文 GPU 吞吐直接选型。

模型资料：
- TinyCLIP：https://github.com/microsoft/Cream/tree/main/TinyCLIP
- 权重：https://huggingface.co/wkcn/TinyCLIP-ViT-40M-32-Text-19M-LAION400M
- SigLIP 2：https://huggingface.co/google/siglip2-base-patch16-224

许可登记必须覆盖实际采用的权重、导出修改、运行库与上游 NOTICE；不能只登记 crate 许可。

**2026-10-04 定案**：保留第一轮两个候选未通过原门槛的实验记录。崔总指定采用TinyCLIP并折中阈值；本期不切换检测器/场景分类，也不扩大候选。生产准入由固定模型/类别/校准结果组成可信包；包格式2的 `thresholds_calibrated` 只表明逐类阈值已校准和审阅，不承诺所有类别达到原门槛。

### 3.2 生产端部署

方向为 Rust `ort` + ONNX Runtime CPU，动态加载**应用自带、固定版本**的运行库。W1 验证后把 ort/ORT/opset/上游模型 revision 精确固定；不直接追 main，不把 rc 状态当稳定 API。

- `load-dynamic` 只是加载方式，**不等于免分发 ORT DLL**；Windows 私有运行库放应用资源目录，绝对路径加载，不要求使用者配 PATH。
- 首期只支持产品既有 Windows x64 基线；WSL 供开发冒烟。CPU Execution Provider 显式指定，运行时不得自动要求 CUDA。
- 前端只传动作/状态。像素、预处理、推理、评分都在 Rust。
- 固定候选类别的文字特征在模型制作阶段预计算，终端仅分发图像编码器、类别特征矩阵与配置；**本期不需要 tokenizers 或文本编码器运行依赖**。
- GPU/NPU 加速留未来；DirectML 已进入 sustained engineering，不能把它定为唯一长期接口。Windows ML 是后续候选，需单独核对 Windows 10 与 Windows 11 差异，不影响首期 CPU 路径。

官方依据：
- https://github.com/pykeio/ort
- https://onnxruntime.ai/docs/get-started/with-cpp.html
- https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html

### 3.3 高效多标签算法

1. 对每类准备少量固定英文描述，在制作阶段用同一 checkpoint 的文本编码器生成并归一化类别向量。
2. 每张图片只执行一次图像编码器，得到图像向量；归一化后与类别矩阵相乘，评分成本为 O(K × d)，K ≤ 32。
3. 每类独立阈值；只有实测证明有效时才加少量负例/易混淆类的差值判据。CLIP 类相似度、SigLIP 输出都不能未经校准直接显示成“正确概率”。
4. **不用整个词表的 softmax、不强制取 top-1/top-N、不把任意手动标签塞进识别词表**。模型可以返回零标签。
5. 首版不做多裁块、小目标搜索、标签层级推导或同义词图谱；例如识别出鸟不自动再添“动物/自然/风景”。
6. 类别配置包含稳定 concept key、文字映射、提示模板、阈值、预处理版本与模型摘要。修改这些配置产生新的识别配置版本。

中文/英文只是模型描述与 UI 的语言适配，标签真相仍是规范化文字。首次使用时为每个 catalog 固定一份 concept → 标签文字映射（按当时应用语言选择默认词表，复用已有同文字）；后续切 UI 语言不重命名、不生成第二套词、不绕过屏蔽。首期不提供词表改名/跨语言合并 UI。

## 4. 图像输入：原始内容与显示缩略图区分

已确认 `memory/FUNCTION-IMAGING.md` 定义小图随最新编辑变化。**不能直接读取“当前网格封面”来做内容识别。**

选择顺序：资产原始 SOOC/位图 → RAW 内嵌预览。RAW-only 无可用内嵌预览时，首期记录“缺少识别预览”并跳过，**不为了 AI 批量触发全尺寸 RAW 显影**。原始资源损坏/缺失不能当作成功空标签。

- 复用现有解码与色彩服务取得未编辑、已处理 EXIF 朝向的 sRGB 位图；不得写第二套 RAW/ICC 算法。
- 以长边 384px 原始预览作为首轮测试输入，再按模型要求预处理；384 是输入代理的初始选择，不是不可变规格。极端长宽比、边缘主体需在 W1 专项验证，必要时仅提高代理分辨率。
- TinyCLIP 官方裁切流程可能丢边缘，需对照“官方预处理/保留全图的预处理”；不得悄悄替换后仍套用原阈值。最终唯一方案写进模型包并校准。
- SigLIP 也按对应 processor 的实际 resize/normalization 校验，不凭模型名称猜预处理。
- 原始代理与 latest 缩略图使用不同的 source/render signature；复用同一缓存基础设施，禁止把 AI 原始代理写回网格 latest 槽位。
- 图像像素不用经 WebView/base64。缓存删掉可以重建，不能顺带删除标签、屏蔽和有效识别成果。

识别身份至少包含：repository_id、photo_uid、原始文件身份/版本、输入策略版本、模型权重摘要、类别/阈值/文字映射版本。只改路径、重编码同内容代理、调色、裁剪或新建 issue，不自动重新识别；原始内容/来源选择确实变了则失效。复用既有文件变更机制，调度和提交时重读源状态，不造“缓存几小时才算过期”的规则。

## 5. 标签、来源、纠错与算法一致性

`EffectivePhotoTags = (Manual ∪ ValidAI) − Masks`，目录标签独立。

| 动作 | 语义 |
| --- | --- |
| AI 识别成功 | 在 catalog 单事务中替换该照片 AI 集合及成功记录；manual/masks 不动 |
| AI 识别失败/取消 | 不提交半套结果；原输入仍有效时保留旧成功集合 |
| 原输入已改变 | 旧 AI 证据标失效，退出有效投影；manual/masks 保留 |
| 模型包升级/卸载 | 已提交且源未变的 AI 标签仍可用，标“旧版本/可更新”；不静默全库重跑或清空 |
| 保留为手动 | 增加 manual 并解除同文字 mask；以后 AI 不再命中也保留 |
| 禁止这个标签 | 保存规范化文字 mask，盖住所有照片来源；证据不删除 |
| 解除禁止 | 只移除 mask；仍有有效来源才重新出现 |
| 移除手动来源 | AI 仍有效且未禁止时继续显示，来源详情说明原因 |
| 新增手动同文字 | 沿用上期约定，解除 mask，再写 manual |

屏蔽匹配严格复用现有 `clean_name/fold_name` 的规范化，不新增另一套 trim/大小写/Unicode 规则。它是文字等价，不是模型推断的同义词等价；“鸟”不自动屏蔽“bird”。

存储职责（具体 DDL 与下一个可用迁移号在对应单元开工时定）：
- 现有 `asset_tag_sources`：唯一 manual/ai 关联；AI 不写入旧 `asset_tags` 冒充 manual。
- 新增 `asset_tag_masks`：照片 + tag_key 唯一。
- AI 成功/证据记录：输入和模型身份、生成时间、各类别原始分数与有效状态；失败尝试与上次成功分开，成功空集也要有完成记录。
- 作业记录：持久队列与冻结UID；完整准备后才运行，准备中断明确失败并重新选择范围，不恢复半份范围；复用已有 jobs/worker 能力，新增 AI 类型所需字段，不先造通用任务平台。

统一读入口可用索引支撑的 SQL view/共享谓词；标签筛选用 EXISTS，屏蔽用 NOT EXISTS，按 asset 去重。需复核 `query.rs` 的整数 tag_ids 和文字 tag_keys 两条路径，详情、导航、筛选、facet、导出、XMP、自动桶、标记快照必须一致。词典 UI 的数字 ID 是适配层，不能迫使 AI 关系变成 manual。catalog 内文字始终可恢复，app.db 词典同步失败可幂等补齐，不丢 AI 真相。

AI 替换、失效及屏蔽/恢复都产生同一既有组织事件；以事务前后有效集合差集限制无效刷新，批内按照片去重。正常处理不能逐张全库重算，也不实时为每个标签计算跨库精确数量。

**自动桶仍是累积集合**：AI 纠错只影响后续匹配，不自动弹出已收录的照片；已有成员走“移出并排除”。禁止和移出排除在并发重放中都不能被旧任务覆盖。

## 6. 任务、并发和恢复

- 明确入口范围：选中照片（支持跨库）、明确目录及其既有子树规则、明确库。不默认把当前标签/桶导航或筛选隐式变成识别条件。
- 开始时冻结范围成员：分页枚举并将稳定 UID 入既有持久任务队列，使用稳定游标而非 OFFSET；启动后新导入照片不自动混入。先处于“准备任务”，范围快照完成后再识别，避免结果修改自身的枚举范围。
- 去重键 = repo + photo_uid + 原始输入版本 + 识别配置摘要。默认跳过同版本成功项；“重新识别”显式生成新 attempt。
- 一个 AI 推理进程、一个常驻模型 session、同时一张图片；默认 ORT intra-op 线程上限 2、inter-op 1，作为 W1 待测初始值。预取最多一张，限制图像像素数和 IPC payload。
- 主进程调度/写库，AI worker 只收有界图像与固定包身份、返回有限结果；不持有 catalog 写连接。RAW 解码仍用既有隔离服务。通用启动/握手/超时能力优先从现有 worker 抽取，AI 不挤占同步 RAW 协议。
- 浏览交互、导入/显影等前台重任务优先；AI 在下一张边界让出，不要求中断半次矩阵计算。
- 每次提交检查 repo 挂载租约、photo_uid、输入版本、attempt/run 状态和固定模型包摘要。期间有更新/取消则丢弃；写事务尽可能短。
- 暂停：不再领下一张，当前张正常提交后暂停；取消：立即撤销提交资格，已完成项保留、当前结果丢弃。超时杀 worker，不挂死 UI。
- 进程崩溃重建；连续启动失败进入明确失败态，避免无限重启。重开应用将遗留 running 变待恢复，**默认暂停等待继续**，不启动即抢 CPU。
- 卸载库：等待挂载，不自动重挂、不算空结果；删除照片：跳过并清理相关待处理项；取消不会回滚已提交标签。
- 每个 catalog 的成功事务是幂等边界：catalog 成功而 app 作业确认前崩溃，重放识别到成功 key 后确认完成，不重复推理或装桶。

## 7. 模型包、安装与升级

普通安装包包含AI worker、固定CPU ORT运行库与TinyCLIP源包，设置中主动安装一份设备模型副本；**识别模型可选启用**，首次主动使用时说明大小、能力范围、许可与本地运行。

模型实现放设备级 `ai-models/<trusted-manifest-sha256>/`、`ready-v1.json` 原子指针，通过现有应用数据路径服务定位，不放可删的缩略图缓存；数据库仅保存模型标识，不随每个库复制模型。

模型包只装白名单数据：ONNX、类别特征矩阵、词表/阈值/预处理配置、manifest 与许可证。manifest 记录包格式、最小 app/ORT 版本、上游 revision、opset、输入输出 dtype/shape、各文件字节数/SHA-256、整体 pipeline 摘要。首版不支持运行任意用户模型或执行包内脚本。

- 应用自带安装和离线“导入模型包”走同一校验/安装流程；应用固定的可信清单记录摘要，不能只信包自带的 hash。正式镜像/发布地址由发布流程提供，不在源码虚构下载 URL。
- 安装复制到有界暂存目录，文件/摘要校验与实际图探测成功后原子切换 ready 指针；失败清理暂存并保留旧 ready。损坏同版本可重新安装。空间不足由实际复制错误报告并清理，真实满盘尚未测；提前空间提示、下载进度/重试留未来在线分发。活动任务禁止安装/卸载。
- 模型更新不自动重写标签；已启动任务固定包版本，新的任务才选新默认包。强制卸载正在使用的包须先取消/结束任务。
- 删除模型保留成功标签、manual 和 masks；未安装/网络失败只影响 AI，新旧手动整理功能照常可用。
- 分发制品必须包含权重来源、实际许可和可复现转换说明；发布/上传由崔总执行。Agent 可在临时目录作模型验证及 debug 冒烟，不运行 release。

W1 如需 Python/PyTorch 只是一次性上游导出验证工具，不进入项目包管理、产品构建或安装依赖；开发侧脚本仍由 pnpm/cargo 入口管理。若制作工具链当前不可用，先完成不依赖它的验证与数据单测，不为绕开限制给产品塞 Python。

## 8. XMP：同一次改动完成接线

**已实现标准有效关键词与 `rb:tagState` JSON格式1，复用现有writer/读回/sidecar队列，单元往返通过；Windows实际库尚未验收。** XMP 规格已更名为 `specs/xmp-sidecar.md`（旧名 xmp-w1.md）；只同步新增标签数据，不重开跨家导入、历史补写或其它已排除的 XMP 功能。 本期已读取最新 `specs/xmp-sidecar.md`、writer、读回、导出共享映射，以下契约已落实到原模块。

1. 标准 `dc:subject` 只写 EffectivePhotoTags 的去重文字；不写目录标签、不写被禁止词、不写失效 AI。
2. 自有 `rb:` 标签扩展需要保留 manual/ai 来源、按文字 masks 及最小可解释版本信息；具体序列化与版本闸门纳入 XMP 主线现有机制。成功分数/任务历史不要求全部塞进 XMP。
3. 自家导入优先恢复来源与禁止关系，**不能把自己导出的 AI 标签经 dc:subject 再添一份 manual**。没有自有来源扩展的旧 sidecar 继续按既有关键词兼容语义读回；更高未知版本不得误覆盖。
4. 自家恢复的 AI 来源明确标记“来自 sidecar/待校验”，不伪造本机推理成功记录；其源关联/有效性规则与 XMP 新建资产流程一起定案并测往返。不能因为 app.db 词典 ID 不同改变文字屏蔽。
5. AI 提交、有效性失效、手动提升、禁止/恢复后，通过**同一个** sidecar 触发机制更新；按照片合并事件。即使有效文字未变而来源改变，自有来源层仍需刷新。
6. DB 是真相；XMP 写失败不得回滚已经完成的标签纠错，须用届时已有的重试/错误反馈机制报告，不能吞掉。
7. 导出和 sidecar 使用同一关键词投影/转义实现。不新建另一套 writer、任务队列或私有目录命名。
