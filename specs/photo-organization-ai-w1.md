# 相片整理 AI-W1：CPU 标签识别可行性与模型定版

> 首次两候选实验、原门槛失败与Windows probe保留在 `docs/ai/2026-10-04/README.md`。崔总随后已定案本期TinyCLIP、阈值折中并偏向减少误标，SigLIP 2只留future；本单元按该定案收尾，不继续选型。
> 固定TinyCLIP v1矩阵/逐类阈值与回归证据见 `docs/ai/tinyclip-v1/README.md`。包格式2区分“阈值已校准”和“原指标达标”，后者没有改成true。人/海漏标及海类误标、场景负例不足如实披露。
> Windows完整应用资源与worker冒烟由AI-W3验收，GUI与真实库不由单元测试代替。
## 1. 要回答的问题

在 Windows x64、没有 CUDA/Python/PyTorch 的产品运行环境中，能否以可接受的 CPU 成本，为“人、鸟、车、山、海、森林、夜景”生成可靠的多标签结果？

输出必须足够具体，使下一单元可以直接接模型包与标签后端：唯一模型/权重 revision、运行库版本对、ONNX/opset/shape、Rust 预处理、类别阈值、输入来源、有限的资源配置及明确缺项。

## 2. 初次有界候选对照（历史实验，已结束）

1. 首测 TinyCLIP ViT-40M/32 Text-19M LAION400M，固定官方权重 revision；仅输出图像编码器（包含必要 projection）与预计算类别矩阵。
2. 使用 SigLIP 2 base patch16 224 做效果对照；TinyCLIP 质量不足时评估它是否能在 CPU 预算内替代。
3. 不再扩散成十几个模型的选型；两者都不满足时，交付失败证据/类别裁剪建议与明确的下一步，不带着未验证模型进入产品。
4. FP32 先验正确性，再测适合该图的 INT8 量化。INT8 不是无条件更快；若关键算子不受益或误报变多，保留 FP32。不将 CPU FP16 默认视作加速路径。
5. 模型代码、权重、转换工具和分发说明分别核对许可；MobileCLIP 的 research-only 权重不纳入。

官方链接见主题规格 §3。准备时记录上游 SHA、文件 hash 和下载地址，不使用会漂移的 main 作为制品身份。

## 3. 制作与运行隔离

- 验证阶段允许在隔离临时目录调用上游 PyTorch/Transformers 导出工具；这种一次性工具环境不进 RayBend 的安装包、构建必备项或项目包管理。
- 若工具链缺失，先检查现有工具/已验证导出物，保留可复现步骤；需要额外安装时在对话里说明实际缺项，不要求终端使用者安装 Python/CUDA。
- Rust probe 使用 cargo，复用仓内图像输入算法；实验依赖留非默认实验入口或临时 harness，不悄悄扩大产品默认依赖。
- 先用官方权重制作 ONNX，再用独立 ORT CPU 运行验证；不把 Python 能跑等同于 Rust 能跑，也不把 WSL CPU 等同于 Windows CPU。
- 产品最终只需 worker + ort 对应 CPU 运行库 + 模型数据，文本编码器/tokenizer 不分发。
- 记录 ort 精确版本、ORT 精确版本、MSRV、动态库布局、opset、所有 I/O 名称/dtype/shape；启动显式使用 CPUExecutionProvider。

## 4. 输入与数值一致性

先通过既有输入服务取得稳定原始预览：SOOC/原位图优先，RAW-only 用内嵌预览；无内嵌预览记录跳过，不新建全尺寸 RAW 解码支线。

对每个候选：
1. 用上游 processor 和 FP32 模型建立参考输出。
2. 对比相同输入的 ONNX 输出与 Rust 预处理，记录最大/均值误差与标签阈值两侧翻转；容差按实际模型确定，不只比较 top-1。
3. 验证长边 384 代理是否足够；包含横/竖/超宽图、EXIF 旋转、ICC 位图、RAW 内嵌预览、边缘人物/鸟、小主体与黑图。
4. TinyCLIP 对比官方中心裁切与全图保留方案，最多两种预处理；分别校准，不能套用同一阈值伪比较。保留全图仍不达标时允许只支持显著主体，报告漏检边界。
5. 量化后重新测阈值稳定性与每类效果，不能沿用 FP32 性能与质量报告。
6. 确认 latest 调色/裁剪不会改变 AI 原始输入；缓存重建不改变语义身份。
7. 损坏/超大尺寸/没有有效像素返回明确错误，不生成假的空标签。

预处理和评分只保留一个生产实现；probe、模型校准和正式 worker 通过它或同一份测试向量校验，不各写一套像素路径。

## 5. 类别校准与证据

- 先只做七个核心类别，标签定义写清，例如“夜景”是可见夜间场景，不推测 EXIF 拍摄时刻。
- 准备有授权的代表性照片及人工标签 manifest；路径只存本地，照片不上传。优先实际使用场景样本；公开样本记录来源/许可。
- 建议至少 400 张，按拍摄系列拆成校准/验证两组，避免连拍近重复同时进入两组。验证组每个核心类别目标至少 30 个正例、50 个负例；数量不足就报告证据不足。
- 必须有易混淆负例：雕像/海报中的人、玩具鸟、远处小鸟、湖与海、单棵树与森林、暗室与夜景、建筑与山。
- 每类独立阈值；多类可并存、允许全空。不得对七类做全局 softmax 后取最大值。
- 提示模板/阈值只在校准组调，验证集保持独立；验证失败后改算法需重新安排独立验证，不能反复调到验证集“全对”。
- 输出每类 precision、recall、TP/FP/FN、样本支持数、典型错误；仅输出真实相似度/分数，不写“99% 确定”这类概率文案。

**原拟定选择目标（历史对照）**：每类 precision ≥ 90%、recall ≥ 60%，优先保证误报少。小样本仅作筛选，不能证明真实图库达到相同比例。任何关键类失败都列出来；崔总接受缩范围后才缩最终承诺，不能以全空标签达成高 precision。

本期实际阈值规则：校准组precision目标85%、F0.5最大化、至少5个真阳性支持；每类独立，允许空结果。人/海增加固定易混淆负向量的半余弦差。只在校准组取阈值，旧验证集用于回归，不能称新盲测。原90%/60%字段仍保留为对照，不作为本期交付硬闸门。

默认不做层级推导、任意新词、多裁块、在线学习。模型配置上限 32 类，不为扩类抢先复杂化算法。

## 6. CPU 资源测量与选择规则

测试元数据必须含 Windows 版本、CPU、内存、ORT/模型版本、线程、输入数量与分辨率。统一 batch=1、intra-op 最多 2、inter-op=1 起测，再小范围调整。

分开记录：
- 模型数据与 ORT/worker 的实际文件大小；
- 冷加载、热推理 P50/P95、预览获取与预处理、落库模拟耗时；
- 峰值 RSS、空闲卸载后的内存、取消/超时和 worker 重启耗时；
- 编码结果重用/连续任务是否泄漏；
- 原始预览缺失率。

**初始预算目标（未实测）**：模型数据 ≤ 200 MiB、worker 峰值 RSS ≤ 1 GiB、热推理 P95 ≤ 1 秒/张、冷加载 ≤ 5 秒。基准机若未确定，报告设备和实测值，不能随意挑 GPU/高端机器“达标”。

决策：TinyCLIP 达到类别和资源目标就采用；若不达标而 SigLIP 2 达标则采用后者。两者各有得失时，报告多出的体积/内存/时间及逐类收益，由崔总评估真实取舍，不自行扩大产品硬件前提。不能因包小忽略质量，也不能因更准偷偷依赖 CUDA。

真实浏览/导入并发时的体感属于崔总真机验收；Agent 可做无 GUI 的竞争负载与资源日志冒烟，不把它替代 E2E。
