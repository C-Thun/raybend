## 1. 本波交付与边界

本波交付：**同一个已登记库断开后停止使用旧会话；原路径重新可用后重新开库；盘符变化后可从离线库的设置定位同库新位置并恢复；导入、浏览、编辑、导出与设置读取同一份可用状态；正常离线不再变成卡片下方的红色报错。**

覆盖库的探测、会话与写入闸门、跨工作流状态、已登记路径重连、手动定位与备用位置管理、轻量变化触发、共享卡片和命令入口。NAS 只留下本波真正使用的存储定位／探测接口，不接协议。

本波不增加新盘符自动搜库、主动释放库/系统弹出动作、完整离线照片索引、网络认证、远程 catalog、多机写入；任务掉线后自动等待与续跑属于 W3。**不过长任务不得继续使用已作废会话写入**，这项最低保护在本波，不能因为续跑后置而遗漏。

不改变库 ID、目录布局、RAW/XMP/issue 语义及迁移框架。本波优先不改 schema；观察时间、探测状态、连接代次属于运行态。确有持久化字段需求时先在本规格中补理由、兼容与迁移测试，再走既有迁移，不临时 ALTER。

## 3. 先锁定的行为契约

### 3.1 库可用状态

最小状态为 `unknown / checking / online / offline / unavailable`：

| 状态/原因 | 意义 | 行为 |
| --- | --- | --- |
| unknown / checking | 尚未确定／正在探测 | 不能据此认定库空、丢失或可写；保留上次展示资料 |
| offline | 登记位置不可达、设备未连接或库文件缺失 | 保留登记与最后成功计数；允许重新查找、打开设置与定位新位置 |
| unavailable + identity_mismatch | 此位置挂着别的库 | 不打开成目标库，不覆盖、不创建替代库 |
| unavailable + access_denied / read_only | 权限或写能力不足 | 给具体原因；禁止相应操作；不把它写成“设备未连接” |
| unavailable + catalog_invalid / schema_too_new / migration_failed | catalog 或版本问题 | 指明需要处理的原因，不循环当拔盘重试 |
| unavailable + timeout | 本次探测未按期返回 | 表示未知结果，不将迟到结果发布到新代次 |
| online | 身份和本次所需打开条件验证完成 | 操作仍经会话闸门；不能把卡片布尔当永久授权 |

错误码与参数由 Rust 给出，界面文案进中英语言包，原始诊断留日志。现有 `online` 如需过渡保留，必须由状态派生，不能再独立修改。`canRead/canWrite` 只报告实际支持的能力；本波不以“能读 repository_meta”冒充已经实现完整只读浏览。

状态快照含 repositoryId、当前验证位置、连接 generation、观察时间、原因。**连接 generation 与请求排序分开**：前者表示资源会话是否还有效，后者保证同代次的旧快照也不能覆盖新快照。采用运行期 revision/请求 ticket 时明确溢出与 JS 数字精度边界；u64 不直接当无限精度 JS number 传输。

### 3.2 会话的建立、作废与恢复

1. 获取操作会话时核对期望库 ID；实际打开后再核对，避免 resolve 与 open 之间换库。根路径从同一会话取得，不分别解析两次后拼成一次写操作。
2. 同库的浏览、设置、编辑和导入共享既有 CatalogDb 的写者，不再各起一个相互不知情的 catalog 写者。按实际活跃库持有会话，无使用者时释放，不无限缓存所有登记库。
3. 确认断开、底层连接失效或位置身份变化后：使 generation 作废，停止接受新任务、通知持有者，在锁外退场连接与 watcher。普通输入错误、单张照片损坏不应使整个库离线。
4. **已排队写入也要在执行点检查代次**；只检查发送请求的时刻不够。作废后尚未开始的写拒绝执行；已经进入 SQLite 事务的调用如实返回结果，不宣称能够撤销已提交写入。
5. `Writer::Drop/shutdown` 当前会排干队列并 join。实现必须处理这个真实语义：不能拿着全局状态锁等待磁盘，也不能在旧连接尚未退出时起一个新写者抢同一 catalog。若退场未完成，明确显示恢复中/暂不可用；不能报已恢复。
6. 原路径恢复也重新建立会话与必要监听。手动重新查找要能强制作废旧会话，不能因库 ID 和路径相同直接判“没有变化”。读池的 `PRAGMA user_version` 健康检查继续保留，但不替代该生命周期。
7. 活跃会话固定已验证位置；失联后不带着长任务静默切到另一个同 ID 副本继续写。多副本冲突选择的产品形态留 W4；本波安全失败并保留原任务上下文。

事件/轮询只是重新检查的触发器，实际打开和 I/O 结果才是事实。2 秒轮询不能保证捕获两拍之间的完整拔插；实现不得据此宣称绝无旧句柄问题。手动重连、操作失败以及真实会话重开必须各自成立，并以 Windows 真机测试补足边界。

### 3.3 锁、探测与位置策略

- app.db 短锁取登记路径 → 锁外探测 → 核对请求仍有效 → 短事务保存状态。任何目录扫描、网络 I/O、写线程 join 都不放在 app.db 写事务或全局会话锁内。
- 重连一个库只返回该库；库列表先返回已登记的资料，逐库更新状态。不得由一次状态查询顺带递归统计照片；计数走既有扫描链，成功后单独更新。
- 读失败保留最后成功计数。失联、部分扫描与空目录严格区分；复用 `rebuild` 的完整性与身份检查，不能造第二份宽松计数“真相”。
- 当前 `AGENTS.md` §6.4 禁止 catalog 放网络盘/云同步位置；`location.rs` 的历史“只警告”注释与之冲突，按现行红线收敛。复用分类器把入口策略接到创建、登记与打开；已登记的不删除，只报告不支持的位置。来源读取不受 catalog 位置策略牵连。
- 明确识别与启发式识别的限制，显示定位依据；不擅自扫描整机以识别全部云客户端。测试用临时本地目录，不拿 WSL 映射 Windows 盘冒充 Windows 本地盘策略测试。

### 3.4 触发与资源预算（本波拟定初值，可在执行前审阅）

| 项目 | 初值与约束 |
| --- | --- |
| 卷枚举 | 沿用 2 秒；应用级只有一处所有者，读盘符/类型，不取卷标、不扫 photos；App 清理时停止 |
| 合并触发 | 卷差量、focus、工作流进入同一库的触发合并 200ms；手动重查立即排队，不等去抖 |
| 探测并发 | 同库/同端点单飞；全局最多 4 个实际在途探测；超时仍未退出的调用继续占位，禁止补起无限线程 |
| 探测等待 | 每次库状态请求 5 秒软时限；返回已完成结果及超时状态；不承诺同步 OS I/O 已被取消 |
| 失败后的自动重试 | 同一受影响库最多在 1、3、10 秒各试一次；失败后等新事件、focus、进入或手动操作，不无限刷 |
| 正常操作 | 每次进入/展开/显式重读检查当前事实；不新增按分钟缓存的“在线 TTL” |

这些参数是调度预算，不是磁盘性能承诺；常量集中、时钟/定时器可注入。多个端点全部阻塞而耗尽预算时返回排队/暂不可用，不拖住本地 app.db 读写。若原生 I/O 无法回收，记录可复现证据再讨论独立探测进程，不能在本波默默引新守护服务。

### 3.5 全应用状态与界面

- `App` 持有唯一库事实 store。import 接收该实例；browse/export 移除自己的 repositories 信号和重连实现；editor、设置弹窗及命令判断订阅同一事实。导航选择按原工作流语义保留，不借此次重构合并两种选择行为。
- `load/upsert/remount/事件更新` 共用一个归并入口。逐库丢弃过期结果；同一库重复点击合并，不让慢库 A 阻止库 B；任何入口恢复在线都清过期提示。
- 先订阅事件，再取初始快照，或采用等价 revision 对账；测试事件先于快照到达的情况。组件销毁后不得写回，App 退出只清理自己创建的监听/定时器。
- 断开后保留库登记、路径、最后计数、选中和当前可展示内容，相关写命令禁用；不把陈旧图像冒充刚读成功。恢复后只重读当前库的必要查询、目录与预览，保留仍存在的选择/锚点/滚动；PhotoGrid 不卸载。
- 设置读取失败按结构化原因处理，不能把模板预览失败也标成整个库离线。写失败不显示保存成功；未保存编辑保留现有错误与草稿恢复能力，不偷偷改写成自动丢弃。

#### 3.5.1 永久设置入口与同库备用位置（2026-09-29 已采纳）

- 交互卡片的齿轮在 online/offline/checking/unavailable 下始终存在且能打开设置；连接状态移到库图标或路径旁独立表达。探测原位转圈，不占齿轮位置；点状态入口调用同一重新查找动作。两行卡片不增高。导入确认窗中的只展示卡片继续不装操作入口。
- 库设置最上方增加“库位置”，列出 app.db 中该库全部登记位置，标明当前使用位置与本次探测状态。尚未探测不能冒称未找到；完整路径可查看/复制。提供添加位置、重新查找、移除位置；移除只改本机登记，不删除磁盘文件，复用既有移除确认与 easy destroy 纪律。
- 离线时突出“定位此库…”：选择目标库根目录，先读 catalog 身份并核对期望库 ID，同时执行既有 catalog 位置策略。目标不是库、ID 不符、权限或策略失败分别说明，均不得新建替代 catalog、修改目标库或覆盖现有登记。
- 身份与位置策略通过后，以现有规范化规则幂等登记新位置，保留旧位置作为备用，再经统一探测/会话入口恢复。恢复 online 必须实际打开验证成功；添加登记本身不能冒充已恢复。迟到的选择/探测不得更新已关闭弹窗或另一个库。
- 在线时添加备用位置不切换正在使用的会话；定位恢复也不让失联的旧任务自动换根续跑。当前会话使用中的位置不能通过移除入口直接撤销，解释禁用原因；停止使用/释放后的处理留 W4。其它位置可独立移除，不连带移除库身份与最后成功资料。
- 设置页分开读取本机位置登记与 catalog 设置。位置区及整个弹窗不等待 catalog 成功才能显示；已知离线不为读模版先生成一段正常掉线报错。位置管理始终可用，模版保存、重建等需要 catalog 的操作按共享状态禁用，已有草稿保留。
- 此处“库位置/备用位置”只表示同一库的可替代挂载位置，同一时刻使用一个已验证位置，不表示照片同时分散在多个根目录。当前信息来源复用 RepositoryView.paths、repository_paths、PathForms 与 catalog ID 探测，不新增第二套路径登记或绕过身份验证的前端改盘符逻辑。

### 3.6 命令与 NAS 接缝

- 将现有“重新查找当前库”统一成 `repository.reconnect`（若开工时已有同义命令则复用，不并列）；scope=global、group/menu=file，目标由 App 按当前工作流注入。
- `defaultKey: undefined`，理由：低频库维护操作，保留 Ctrl+K 和文件菜单可达，不占照片操作键。没有目标库、库当前健康在线或同库已在探测时禁用；卡片和命令用同一动作。已失联库的重连必须等旧会话退场，不能借重连中断健康会话的活跃写任务。键位冲突/保留规则与本地化测试同时交付。
- “定位当前库”随本波接入统一命令；先检查是否已有同义入口，已有则一般化它，否则登记 `repository.locate`，scope=global、group/menu=file。复用当前工作流目标和同一定位动作，默认键明确 `undefined`（低频库维护，保留命令面板与文件菜单入口）；没有目标或同库正在定位时禁用，离线不能成为禁用条件。现有库设置命令同样保留离线可达。
- 自动探测不注册命令；添加/移除位置属于库设置内指定位置的操作，不另造全局命令；释放库的命令留 W4，不能先给空壳按钮。
- Rust 定义本波实际使用的 location/probe/session 数据，platform 卷变化为可替换适配器。保持 `VolumeKind` 与可用性分离；设备标识只作为可选发现提示，catalog ID 仍是最终身份。
- `Scanner/FileOps/ImportSink` 继续作为来源/执行注入边界。远程 provider、认证、本地暂存以及远程 catalog API 只在 `memory/FUTURE.md` 登记；不要为未选择的协议写空 trait 或无调用实现。
