批准依据：2026-09-26 崔总确认 M4 重排路线并指示「开干」。本工作单元覆盖整个 W1。
当前环境没有 plannotator / todos 工具；使用本文件记录进度，不冒称已运行其评审。

## 实施与验证

- [x] 一般化现有 rebuild/scan/diff/apply 链：局部范围为一个目录及其 `_RAW`；全库重建共用安全落库。读取失败、截断、离线不产生缺失；严格校验库内路径。
- [x] 文件身份补齐与替换更新；可信移动保持 asset/issue，局部扫描不会标记其他目录缺失；事务内读取现状和应用差分。元数据只刷新受影响资产，并刷新 FTS。
- [x] 接入已有 repository_sync_dir 和浏览取数链，先同步再查询；计数失败可重试、错误可见；统一失效源元数据、缩略图、编辑预览。
- [x] 引入 notify 小型基础设施依赖，复用平台实现；只监听正在访问的 photos 目录、其 `_RAW` 和父目录。事件只触发有界重扫，去抖、合并、单飞；退出/换库释放监听。回焦点与重新进入仍重读。
- [x] 边界单测（空目录、配对、中文、移动、替换、缺失回归、不完整扫描、并发变更、事件风暴）及前后端质量门；记录 Windows 冒烟可执行状态。真实 GUI / 照片库 / 颜色验收交崔总。
- [x] 更新 PLAN / 规格和实施记录，给出本波结果与真实环境验收点。

## 取舍与纪律

沿用 CatalogDb 单写者和现有目录计数存储，不新增 schema，不改变 issue/profile、选择或标记语义。
原生监听使用 notify 8.2.0（CC0-1.0）及 notify-types 2.1.0（MIT OR Apache-2.0），不分别硬编码 Windows 和 Linux 文件事件。
监听是提示，成功扫盘才是事实；不监听 cache/DB，不递归遍历整库以安装 watcher。
新增功能为既有刷新行为的实现，不新增独立用户命令或热键。
导出画稿与预设/渲染/队列属于后续波次，W1 不新增界面。
