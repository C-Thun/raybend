## 1. Context —— 为什么现在做

你要求「**titlebar 要处理掉**」，而 M1-4 正是这一单元：把设计稿里的外壳三行做成实物，

按 `specs/M1.md` 的依赖图，M1-4 只依赖 M1-1（设计系统，已完成），所以可以立刻开工；
它是你**最快能看到「像个真软件」**的一步，也是必须由你在真机目视确认的部分。

顺带把两件事落地：

1. `ARCHITECTURE.md` 里定义的 `src/shell/` 与 `src/features/` 的一级模块边界（先从 `exif-strip` 开始）
2. `scripts/check-architecture.mjs`（`pnpm lint:arch`）—— 让分层规则可执行

## 2. 前置事实（已核实，不猜）

| 事项 | 结论 | 证据 |
| --- | --- | --- |

| 拖拽区 | `data-tauri-drag-region`；直接执行 `startDragging`，**需 `core:window:allow-start-dragging`** | `tauri-2.11.5/src/window/scripts/drag.js` |

| 读取最大化状态 | **免权限**（`allow-is-maximized` 在 default 里） | 同上 |
| 监听窗口尺寸变化 | **免权限**（`core:event:default` 含 `allow-listen`） | `permissions/event/autogenerated/reference.md` |

`capabilities/default.json` 只有 `core:default`；前端没有 `@tauri-apps/api` 依赖。

## 3. Approach —— 推荐方案

### 3.1 代码结构（长在 `ARCHITECTURE.md` 的分层上）

```text
src/api/window.ts            窗口控制的前端封装（唯一碰 Tauri window API 的地方之一）
src/api/tauri-env.ts         运行环境判定（是不是在 Tauri 里跑）——纯函数，可单测
src/shell/flow.ts            工作流枚举 + 「该工作流下 toolsbar 有什么」的装配表（纯数据，可单测）
src/shell/store.ts           createShellStore()：当前工作流、菜单可见性
src/shell/TitleBar.tsx       应用图标 + 名称 + 帮助菜单 + 拖拽区 + 主题/密度 + 窗口三键
src/shell/FlowBar.tsx        工作流分段控件 + 空隙 + <ExifStrip/> + 吸附 ToggleBlock
src/shell/ToolsBar.tsx       内容居中；无内容时**整行不渲染**
src/features/exif-strip/     一级模块：EXIF 三组（easy copy 载体）+ 空态
src/shell/AboutDialog.tsx    「帮助 → 关于」的内容（版本、许可、仓库链接）
src/App.tsx                  组装：shell 三行 + workspace 占位（三列留给 M1-5）
```

`src/api/window.ts` **必须可注入**：它的单元测试不启动 Tauri，而是注入假的 window 对象，
断言「调用哪个方法、如何从 `isMaximized` 推出按钮语义」。

### 3.2 沉浸式标题栏

- `tauri.conf.json` → `app.windows[0].decorations: false`
- **拖拽区**：整个 titlebar 行加 `data-tauri-drag-region`，但**按钮上不加**（否则拖不动/点不动打架）。
  中间那段弹性空白就是设计稿里的 `DragArea`。
- **窗口三键**：自绘按钮（每个 `46×32`，方正无圆角），语义与图标如下。

| 按钮 | 图标 | 动作 | 权限 |
| --- | --- | --- | --- |
| 最小化 | `IconMinus` | `minimize()` | `allow-minimize` |
| 最大化 / 还原 | `IconSquare` / `IconArrowsMinimize`（按 `isMaximized` 切换） | `toggleMaximize()` | `allow-toggle-maximize` |
| 关闭 | `IconX` | `close()` | `allow-close` |

最大化状态通过 `onResized` + `isMaximized()` 同步（快捷键 Win+↑ 之类的最大化也要能反映出来）。

- **浏览器降级**：`pnpm dev` 在普通浏览器里跑时**没有** Tauri，窗口三键必须整组隐藏
  （否则点了就报错）。判定走 `src/api/tauri-env.ts`：`isTauri()`（Tauri 2 的公开助手）
  或退回检查 `globalThis.__TAURI_INTERNALS__`。**判定函数是纯函数，有单测**。
- **主题 / 密度**：复用已完成的 `src/lib/appearance.ts`（读写 + 落到 `<html data-theme data-density>`），
  titlebar 只负责把开关接上去；持久化沿用 `localStorage`（设备级偏好，见该文件注释）。
- **帮助菜单只在鼠标指向标题行时出现**（设计稿明确要求）：
  `onPointerEnter/Leave` 控制，另外 `focus-within` 也要能显出来 —— 否则键盘用户永远打不开菜单。

### 3.3 flowbar

- 工作流分段控件：复刻 `SegmentedControl`，四项顺序**固定** `导入 → 浏览 → 编辑 → 导出`（有序流水线，不按最近使用重排）。
- 右侧 `ExifStrip`（`src/features/exif-strip/`）：三组 `EasyCopy`（机型+镜头 / 曝光四件套 / 尺寸+像素+格式），
  排版是「值 + 间隔点」而不是「标签 + 值」（设计稿明确），机型用 `fg-1`、其余 `fg-2`。
  它现在**没有真实数据源**（扫描与 EXIF 抽取是 M1-3），所以：
  - 模块对外接一个 `ExifData | null`，`null` → 空态文案（`exif.empty` = 未选择照片）
  - 分组逻辑（哪几项属于哪一组）放在模块内的纯函数里并**有单测**，M1-3 接上真数据时不改这里
- 最右 `ToggleBlock / 吸附`：M1 **只做视觉开关**（设计稿也把它列为「以后会加」的占位），
  不做吸附行为；行为登记到 `FUTURE.md`。

### 3.4 toolsbar

- 装配表在 `src/shell/flow.ts`（纯数据 + 纯函数，可单测）：

  | 工作流 | toolsbar 内容 |
  | --- | --- |
  | 导入 | `批量排除`（`DESIGN.md` §12.2 的**反转**语义按钮；无选中时禁用） |
  | 浏览 / 编辑 / 导出 | 空 → **整行不渲染** |

- `flow.ts` 里的 `toolsFor(flow)` 只返回「有哪些按钮」，不碰状态；点击行为由 `workspace` 传入的回调处理。
  这样 M1-5 接上照片选择时不需要改 shell。

### 3.5 关于弹窗

`帮助 → 关于`：应用名、版本（构建期从 `package.json` 读入）、许可 `AGPL-3.0-only`、
仓库链接、以及「相片与目录都不会被改动」的一句实话（移除≠删除，`AGENTS.md` §11.3）。

### 关于 DPI（意见 3 的调研结论）

- Tauri 2 区分 **逻辑像素与物理像素**：Web 侧 API（`MouseEvent.clientX` 等）拿到的是逻辑像素，
  窗口尺寸/位置可用 `LogicalSize`/`PhysicalSize` 显式表达；`scaleFactor()` 与 `onScaleChanged()` 可读缩放比。
- 我们的外壳**全部用 CSS 逻辑像素写尺寸**（`--bar-title-h = 32px` 等），因此 WebView 自己会处理 DPR ——
  这也是不能用 `transform: scale()` 做密度的原因之一（会破坏命中测试与文字渲染）。
- ⚠️ 已知上游变更：窗口初始位置在 Windows 上自 Tauri 2.1 起按**物理**像素解释（issue #11718）。
  我们目前不设置初始位置，暂不受影响；将来做“记住窗口位置”时（`FUTURE.md` G9）必须处理。
- 待你目视确认：125% / 150% 缩放下标题栏三键、图标与 1px 描边是否仍然清晰对齐（§7 第 8 项）。
