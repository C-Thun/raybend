# 相片整理 AI-W3：任务与模型包接线

> 2026-10-04 崔总已定案TinyCLIP与准确率优先的折中阈值。原有任务/来源/XMP/获批界面接线继续复用，可信v1包进入默认CPU构建，模型随应用提供、主动安装；Windows产物核对与无窗口CPU worker冒烟见本轮实施记录，真实GUI/图库尚待验收。

复用 app.db jobs：photo_ai_run 为父任务，photo_ai_image 为冻结 UID 子任务；准备阶段分页写入，完成范围快照才领取。每页 ≤500，使用 asset_id keyset 和准备时冻结的上界；子任务唯一键为 run + repo + UID，同一范围重复页不会重复识别。暂停停止领取下一张、当前张可完成；取消使待处理/当前项失去完成资格；重开把活动父任务置 paused，当前子任务重排，默认不自动抢 CPU。损坏载荷显式失败，失败退避30秒且最多3次，离线 waiting 需明确唤醒，不无限循环。

模型制作物与生产安装隔离：实验 ort 精确锁 2.0.0-rc.13，CPU ORT 1.28.0（最小 API27），Rust1.88 满足现有工具链。核心 ai-runtime 特性启用ort，ai-probe是实验兼容别名；默认桌面构建启用photo-ai-runtime。模型包数据校验复用 fs_asset 有界读取/SHA与 fs_atomic：固定允许的文件名、外部可信 manifest 摘要、文件大小/摘要、ONNX固定I/O、预处理与词表、阈值及质量状态。包格式2要求逐类阈值已校准与应用外部可信摘要；它不承诺全部类别达到原门槛。未校准包只供probe；无虚构下载地址。

崔总2026-10-04确认 browse.pen hqlQz/xaQdZ 与 main.pen s1SP3g，界面已复用现有标签弹窗、全局设置、范围/任务弹窗和四个统一命令（defaultKey明确留空）。独立AI worker协议1复用RAW进程监督，CPU运行通过 `photo-ai-runtime` 条件特性接线；前台编辑/导入/实际导出阻止下一张领取，空闲30秒卸载，应用退出终止worker。每张读取和推理期间持有已有库任务租约，提交检查UID/磁盘版本/token/run，标签事件与XMP队列随有效变化更新。

为了保持有界恢复：范围每库单次WAL读快照、keyset500页，冻结上界与UID；跨库不是全局原子快照。**准备阶段中断不恢复半份范围**，重开明确失败并取消未完整子项，用户重新选择范围；完成准备的任务重开默认暂停。失败30秒退避、最多3次；缺原片/预览不是成功空标签；已识别/锁定计为跳过。预取为0，串行一张；离线等待需要明确继续，不循环扫描全部库。

模型安装完成可信包校验/暂存/原子切换与真实图加载probe，**首版从应用自带的TinyCLIP v1包安装**，并保留官方可信离线目录导入。模型与CPU ORT资源绑定固定摘要；大ONNX/DLL是忽略Git的构建输入，debug与人工release在构建前预检、check:win检查资源和exe可信摘要。损坏同版本可重新安装，损坏但受信的旧副本可卸载；安装/卸载均受活动任务与模型操作锁保护，卸载保留标签/屏蔽。生产包限定512维/≤256MiB，SigLIP 2只留远期对照，不进本期安装器。

本期没有HTTP下载依赖，离线安装闭合。在线分发优化留future，需崔总先发布固定模型制品；不把未发布的URL或不可用下载按钮留在首版界面。
