# 更新流程 v2：静默、可续、永不阻塞

> 崔总 2026-10-15 口述方案 + 本文件的评估与落地设计。**状态：已拍板（见 §6），实施中。**
> 现状实现见 `src-tauri/src/updates.rs`、`src/shell/UpdateDialog.tsx`、`src/lib/update-source.ts`。

## 0. 判据（崔总定的第一原则）

**对用户的打扰降到最低、不影响正常使用。** 推论：

- 更新**永不允许阻塞使用**（下载/校验都在后台，界面照常用）；
- **「不打扰」≠「藏起来」**（崔总 2026-10-16 澄清）：发现新版本**必须当场用阻挡式对话框问清楚**
  （下载 / 跳过），用户作答后这个版本才不再烦他；「不阻塞」指的是下载与校验不挡使用，
  不是把问题降级成轻提示让用户多走几层界面；
- 用户只有**两个决策点**，且**各只问一次**：`下载 / 跳过`、`安装 / 取消`；
- 面向普通用户：**不出现密钥、不出现"自定义源"**（面向程序员的配置留到源码/构建层）。

## 1. 目标行为（把口述拆成可测条目）

| # | 场景 | 行为 |
| --- | --- | --- |
| B1 | 启动后发现新版本（未跳过、未下载过） | 弹**一次**对话框：**下载（前进）** / **跳过（后退）** |
| B2 | 点「跳过」 | 记录该版本已跳过；**本版本不再自动提示**（手动「检查更新」仍可见、可下载） |
| B3 | 点「下载」 | 右上角出现**持久**提示（后台下载中 + 进度）；用户照常用软件 |
| B4 | 下载被进程中断（关机/退出） | 下次启动**自动继续下载**（断点续传） |
| B5 | 下载失败（网络/校验错误） | **不再提示该版本**（不弹窗、不自动重试）；保留已下载进度，手动可续 |
| B6 | 下载完成 | **不提示**。自由使用；启动时不再问下载 |
| B7 | 下载完成后的**下一次启动** | 弹**一次**「新版本可以安装：安装 / 取消」；问过即忘 |
| B8 | 点「安装」 | 走既有守卫（导入/导出/迁移进行中不许装）→ 启动安装器（应用退出） |
| B9 | 点「取消」 | 已下载文件**保留**；不再自动问安装；手动检查可安装 |
| B10 | 手动「检查更新」 | 始终显示真实状态：无更新 / 有更新（可下载）/ 下载中（可继续）/ 已下载（可安装）/ 失败原因 |
| B11 | 更新源 | 只有**稳定**（默认）与**预览**（灰掉占位、底层保留）；删除「关闭」与「自定义」 |
| B12 | 自动检查开关 | 保留（「启动时检查更新」，默认开）——这是用户唯一的"别联网"出口 |

状态机（phase 落盘，见 §3）：

```text
idle ──启动/手动检查──► checking
checking ─有更新且未跳过─► prompting(下载/跳过)
prompting ─跳过─► skipped ──(更高的新版本出现)──► prompting
prompting ─下载─► downloading ─完成─► ready ──下一次启动─► prompting-install(安装/取消)
downloading ─出错─► paused（不提示、可手动续）
downloading ─进程退出─► downloading（下次启动自动续）
ready ─取消安装─► ready-dismissed（不再自动问；手动可装）
```

## 2. 与现状的差距

| 能力 | 现状 | v2 |
| --- | --- | --- |
| 检查时机 | 启动后 8 s 静默检查，有新版本只弹 Toast | 检查后**弹决策对话框**（下载/跳过），跳过/失败按版本记账 |
| 下载 | `updates_download` 一次性下载进内存（`Vec<u8>`），中断即丢 | **落盘 + 断点续传**，跨启动保留 |
| 进度 | 无（回调未接） | 后台进度 + titlebar 持久指示器 |
| 安装时机 | 用户手动点「安装更新」 | 下载完成后的**下一次启动**弹一次 |
| 版本记账 | 无 | `skippedVersion` / `pausedVersion` / `readyVersion` / `installPromptedVersion` |
| 源选择 | 关闭 / 稳定 / 预览 / 自定义（含公钥输入） | 稳定 / 预览（灰）；自定义从 UI 移除 |
| 状态存放 | Rust 内存（`UpdateState`）+ localStorage 两条偏好 | Rust 落盘 `state.json`（单一事实源）+ localStorage 只留"自动检查"开关 |

## 3. 技术设计

### 3.1 断点续传：必须自研下载（已核实上游能力）

- `tauri-plugin-updater` 2.12.0 的 `Update::download(on_chunk, on_finish) -> Vec<u8>`：
  **一次性返回全部字节**，回调只给"已下载/总大小"，**不给数据** → 无法落盘、无法续传；
- 签名校验 `verify_signature()` 是**私有函数**（`updater.rs:1530`），不能复用。
- 结论：v2 自己下载（`reqwest` + `Range: bytes=<已下载>-`）+ 自己校验（`minisign-verify`，与插件同源、
  Tauri 官方维护的 MIT 小 crate，需登记 `THIRD-PARTY-NOTICES` 与 `AGENTS.md` §2.9 讨论——这也是本方案的
  **唯一新增依赖**），完成后仍走插件的 `Update::install(bytes)` 安装。
- 落盘布局（`%LOCALAPPDATA%\com.cthun.raybend\updates\`）：
  - `state.json`：`{ phase, version, totalBytes, doneBytes, url, signature, skipped, paused, ready, promptedInstall }`
  - `<version>.part`：下载中的临时文件（续传的字节基础）
  - `<version>.bin`：**校验通过**后的成品（安装时读它）
  - 只保留最新版本的文件；发现更高版本/校验失败 → 清旧。
- 续传的服务器前提：GitHub Releases 资产支持 Range（`Accept-Ranges: bytes`）✓；
  下载 URL 只从本次 `check()` 的结果取（不落盘 URL 供下次使用）——**启动续传时先 check 一次**，
  版本一致才续，不一致就清掉重来（安全且实现简单）。

### 3.2 校验与安装

- 下载完成 → `minisign-verify` 校验（公钥 = 构建期注入的 `RAYBEND_UPDATER_PUBLIC_KEY`）；
- 失败：删 `.part`/`.bin`，phase → `paused`（不提示，手动可重下）；
- 安装：读 `.bin` → `Update::install(bytes)`（沿用现守卫：导入/导出/迁移/外部编辑运行中禁止）；
  安装器接管后进程退出；下次启动若 `updates/` 里残留成品而版本已装 → 清理。

### 3.3 UI（三处）

1. **更新对话框**（`src/shell/UpdateDialog.tsx` 重写简化）：源 = 稳定 / 预览（disabled）；
   「启动时检查更新」开关；状态区（各 phase 的真实文案 + 进度条 + 重试/继续）；
   按钮按 phase 变（检查 / 下载 / 继续下载 / 立即安装）。
2. **决策对话框**（启动弹的那一次）：`新版本 vX.Y.Z` + 说明 + 「下载」/「跳过」；
   跳过即记账。**不阻塞**（非模态也行——但"只问一次"用模态更清楚，取模态）。
3. **titlebar 持久指示器**（下载中/已就绪）：小图标 + 进度环，点击打开更新对话框；
   Toast 只在"开始下载/下载完成"时各弹一条即走。**不占工作区**。

### 3.4 偏好迁移（AGENTS §2.16）

- localStorage `raybend.updates.v1`（源）→ 废弃；`raybend.updates.v2` = `{ autoCheck: boolean }`；
  一次性迁移：`v1.mode = off` → `autoCheck=false`；其余 → `autoCheck=true`；`custom` 一律归并到稳定。
- 原 `custom` 源能力**保留在源码层**（Rust `UpdateSource.mode` 与 `readUpdateSource` 不动，
  第三方构建按 AGPL 拿源码自己改端点/公钥）——满足"不强制只接受官方签名"的原有约束。

## 5. 风险与取舍

- **自研下载 + 校验是安全关键路径**（比复用插件多承担一段代码）：用 Range 边界、Content-Length、
  总字节数、minisign 四道校验钉住，并有单测（中断/脏数据/换版本/校验失败）。
- **续传 vs 简单落盘**：若想砍成本，可先只做"完成态落盘 + 失败重下"（省掉 Range 与校验自研的一半），
  代价是失败要重下 ~120 MB。**推荐一次做续传**（安装包只会更大）。
- 预览源灰掉期间，`beta.json` 的发布通路（docs/release.md §4）保留但停用，不删。
- 真机 E2E（安装、升级、断网、断电续传）归人类；单测覆盖状态机与下载器。

## 6. 拍板结果（崔总 2026-10-15）

1. **做真断点续传** ✓（自研 `reqwest` + Range 下载 + `minisign-verify` 校验）
2. **下载失败后：下次启动静默重试一次** ✓（不弹窗）——再失败就保持 `paused`、不再自动重试，
   避免反复联网；手动「检查更新」始终可继续
3. **取消安装后保留已下载文件** ✓（手动可装，不重下）
4. **下载中用 titlebar 持久指示器** ✓（Toast 只在开始下载 / 下载完成时各一条）
