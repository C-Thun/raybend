## 1. 目标与验收

**DoD（本波结束时成立）**

   且任意档位都能用鼠标把 LUT 面板开回来；import 同步为三档，**browse 四档不变**；

6. LUT 面板的**开关状态持久化**（版本化设备级偏好），分类可建、可折叠，同时只展开一个；
7. 右栏拉杆按 `DESIGN.md` §14.10 呈现（标签上行 / 值同行居右 / 轨道等宽 / 双极与单极填充 / `--slider-track` 半透）；
8. `pnpm typecheck` / `pnpm test` / `pnpm lint:colors` / `pnpm lint:arch` / `pnpm lint:i18n` / `pnpm build` 全绿。

## 2. 架构决定（写代码之前先定死）

### 2.1 中列：**复用** `PhotoViewingStage` 的既有件，但视口是编辑自己的

`AGENTS.md` §11.4 的红线说的是「import 与 browse 必须经过同一个 `PhotoViewingStage`」——
editor 不适用，因为它的 view 是 GPU 直绘、没有 tiles 模式。所以本波的装配是：

```text
中列 = EditorViewport（编辑专用：洞口上报 + 覆盖层 + 空态水印）
      + SplitHandle（三点，全项目唯一那份）
      + FilmStrip（**复用**，数据源 = browse store）
      + PhotoStatusBar（**复用**）
```

* 胶片带的「选中」回调写回 **browse store** 的 `select / setAnchor` —— 与设计稿的
  「编辑只能从浏览带照片过来、回网格要去浏览」一致，也避免第二份选择模型。
* 胶片带的尺寸档位**单独一份**（`settings` 的 `editorFilmStripStep`），与 import / browse 互不干扰
  —— 沿用已有的 `createFilmStripPreferenceStore`，只是多一个作用域名。

### 2.2 `Tab` 档位：抽成**带 flow 参数的纯函数**，不再写死四档

`src/lib/viewer-chrome.ts` 改成「档位 = 一组布尔（左 / 右 / 胶片带）」，每个 flow 自己的循环表：

| flow | 档位（从默认开始按 `Tab` 依次） |
| --- | --- |
| `browse` | `左中右+胶片带` → `中右+胶片带` → `仅胶片带` → `仅 view` → 回到第一档（**四档，保持现状不变**） |
| `import` | `左中右+胶片带` → `胶片带+view` → `仅 view`（**三档**，`prompts/editor.pd` 2026-09-23 要求） |
| `editor` | `左中右+胶片带+view` → `左右+view` → `仅 view`（**三档**，先藏胶片带） |

* `PhotoViewingController` 增加 `chromeMode` 依赖与 `showsLeft/showsRight/showsFilm` 三个读数，
  工作区不再自己拼 `chromeShowsX` 判断。
* `data-chrome` 属性保留（冒烟脚本在用），取值改为档位名。

### 2.3 editor 的「仅 view」与 LUT 面板：一个小的**纯状态机**

`prompts/editor.pd` 的口径：只有切到 `仅 view` 才动 LUT 面板，且要**记住**它原来的开关：

```text
进入 仅view：若 LUT 开着 → 关掉并记下「是我关的」；若本来关着 → 什么都不做
离开 仅view：若「是我关的」→ 开回来（开着的不动）
任意档位：点 toolsbar left 都能开 / 关 LUT 面板（用户操作永远优先）
```

抽成 `src/lib/editor-chrome.ts` 的纯 reducer（`toggleTab` / `toggleLut`），单测覆盖：
本来关着、本来开着、在 仅view 里手动开回来、来回切两轮状态不漂。

### 2.4 洞口契约：前端只报**原始事实**，Rust 只存不猜

```text
前端（EditorViewport）                         Rust（src-tauri/src/editor.rs）
  getBoundingClientRect()  →  x,y,w,h  ──┐
  window.devicePixelRatio               ├─→ editor_set_viewport(hole, dpr, viewportCss)
  window.innerWidth/innerHeight         ─┘        ↓
                                            EditorViewportState（会话级，Mutex）
                                                   ↓
                                        editor_viewport_state() ← 回读（诊断 / W2 渲染线程）
```

* **页面缩放 / 系统文字缩放都含在 DPR 里**（`AGENTS.md` §7.9 铁律 3）—— 前端不许自己乘系数，Rust 不许用
  `scale_factor()` 顶替；
* 上报要做**变化检测 + 尾样本**（`ResizeObserver` + `window.resize` + DPR 变化三处都报，最后一次一定发）；
* 非法值（NaN / 负数 / dpr ≤ 0）**直接报错**，不静默回退 —— §7.9 的教训就是「静默回退」比报错可怕。

### 2.5 右栏三组页签用 `Tabs`，拉杆用**新的 `SliderRow`**（不改造旧的 `Slider`）

* 旧的 `Slider` 是「图标 + 轨道」形态，网格尺寸档位在用；本波新增 `SliderRow`
  （标签上行 / 值同行居右 / 极值槽位 / 双极与单极填充），**两者用途不同，不是两份实现**：
  `SliderRow` 内部用 Ark `Slider` 做骨架（键盘 / 无障碍 / 指针捕获由 Ark 管），
  只负责 §14.10 的排版与填充方向。
* 参数表（`features/editor/params.ts`）是**纯数据**：标签 key / 范围 / 步长 / 默认值 / 是否双极 /
  极值显示 / 单位。右栏、命令、W3 的 IPC 都从它长出来。

### 2.6 依赖方向（`scripts/check-architecture.mjs`）

* `features/editor/**` 只 import `lib` / `i18n` / `api` / `components/ui`（**不** import 别的 feature）；
* 需要 browse 的数据时，由**工作区**（`workspaces/editor/**`，允许 import features）取值后当 props 传下去。

## 5. 风险与退路

| 风险 | 退路 |
| --- | --- |
| `toolsbar` 三段式改坏了 browse / import 的按钮位置 | 三段式对「只给中段」的调用方**表现与原来完全一致**（中段仍是整条居中）；`data-toolsbar` 属性与按钮文案不变，既有冒烟脚本照旧 |
| `Tab` 档位重构牵动 import 既有行为（人类已习惯四档） | browse 四档**逐档照抄**；import 三档是新口径（人类 2026-09-23 明确要求），实施记录里写清差异 |
| 右栏塞三组页签 + 拉杆后 255px 不够 | 本波按通用令牌 `--panel-w-right` 实现（`editor.md` 待决项 #2）；真机目视后要单独一档再说 —— 改宽度只需改令牌 |
| LUT 面板的「导入 / tile」还没有真实数据 | 面板显示空态 + 导入按钮**禁用并写明 W4 接入**，不放假数据、不做假交互 |
