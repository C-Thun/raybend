## 0. 规划原则

1. **先打通四大模块核心流程**。按 2026-09-21 已定路线，M3 先做编辑与 issue 地基，M4 形成「导入 → 浏览/评级/筛选 → 编辑 → 导出」闭环；高级组织检索与全面产品化后置。
2. **风险前置**：把可能推翻架构的事（渲染合成、RAW 解码、SQLite 并发、缩略图吞吐）全部放进 M0 验证，不允许带着未知直接开工产品代码。
3. **每个 milestone 都要能独立交付价值**，而不是「一次性铺完所有底层」。
4. **基础设施只做当前工作单元需要的部分**（例如缓存淘汰策略留到 M5，M1 只要有能跑的缓存即可），避免过度设计。
5. **一个 writer 原则**：人机协作期间，避免同一时段多路修改同一文件。

### 0.1 规划纪律（2026-09-15 修订）

- **一次规划只覆盖一个工作单元**（一个波次，或一个 milestone 里连续可交付的几波）。
- **本文件（memory/PLAN.md）只做路线级描述**：每个 milestone 含哪些波次、完成定义是什么。
- **具体实现方案在每个工作单元开工前单独规划**，写入 `specs/<milestone>-<单元>.md`（如 `specs/M0-1.md`），并提交 plannotator 评审。
- **不提前细化未开工的工作单元**：项目变大时前置规划必然失真，开工时按当时情况重新规划。
- **已归档的旧规划**放在本文件附录（如附录 A），**明确标注「仅供参考、不是待办清单」**。

## 4. M5 之后：三条主线（人类 2026-09-26 定，**这是发版后的工作重点**）

> **人类原话**：「后面最重要的就是 3 点，一个色彩管理，一个 XMP 方便导入迁移，一个强化相片集功能，
> 相片集功能我已经有了些创意想法，到时我们再讨论。」
>
> **定位**：M5 发版之后，**最重要的事只有这三件**。其余（多仓、缓存治理、数据安全、AI、跨平台、
> 打印/HDR……）仍留在 `memory/FUTURE.md`，**不进这条线**。
> **状态**：📝 已记录优先级，**均未排期**；每一条开工前先出方案。
> （背景：当时 M4-W3 在开发中、M5 未开工；同日已授权 M5 独立工程准备并行，状态见上表。）

| # | 主线 | 是什么 | 现状与落点 |
| --- | --- | --- | --- |
| 1 | **色彩管理** | 输入认得出（位图内嵌 ICC / 相机 profile）、工作空间装得下（线性广色域）、**显示器显示得准**、导出说得清 | 方案**已定稿**：`specs/color-management.md`（L1–L4 分级 + 验收判据 + 风险 + 7 项待拍板）。**待人类拍板工作空间选型**等诸项后才开第一波 |
| 2 | **XMP**（目的是**方便导入迁移**） | 让元数据能**跟着照片走**：把其它软件里已有的评标 / 标签 / 调整读进来，也让本库的成果能被别人读走。人类点明的重心是**迁移可用**——从 Lightroom / darktable 等迁到 raybend 时不该从零开始 | 契约已定：`specs/issue-xmp-contract.md`（issue 的 XMP 表达）；`memory/FUTURE.md` I 节有「DB 为真相源、XMP 为通道」的冲突规则。⚠️ **原登记偏「只写」**，本次人类的口径把**「读」（迁移进来）也纳入**——具体范围（哪些字段、哪些软件的方言）**待写规格时定** |
| 3 | **强化相片集** | 相片集（集合 / 智能集合这一层组织能力）要做强 | 引擎底座已在 M1/M2 落地（平面标签、FTS5 trigram、查询/分面、时间线），**缺的是产品形态与界面**。⚠️ **人类已有创意想法，方案待专门讨论** —— 本行只登记「它是三件最重要的事之一」，**不预设形态**（也许不等于现有 `memory/FUTURE.md` I 节的「集合与智能集合」，以讨论结果为准） |

### 三条主线的共同约束（沿用既有纪律，不另立规矩）

- **界面设计先行**：三条要么新增界面、要么改现有界面 ⇒ 按 `AGENTS.md` §5.1 先出 `.pen` + 同名 `.md`，
  人类定案后才写界面代码。
- **命令体系接入**：新增的用户可触发动作要登记进命令注册表，且在**同一次改动里**给出默认热键
  或写明留空理由（`AGENTS.md` §2.15）。
- **数据库变更走迁移框架**：相片集与 XMP 都会加表/加列，一律走 `store/migration.rs`（`AGENTS.md` §2.16），
  不许启动时临时 `ALTER`、不许另造迁移通道。
- **开工顺序**：每条开工前另写 `specs/<主线>-W<n>.md`（`AGENTS.md` §5.4），不提前细化未开工的波次。

> **第 3 条特别说明**：等人类把创意想法讲出来之后，**先写意图规格**（放 `specs/`）再谈界面与数据模型 ——
> 顺序不能反（先定「要它干什么」，再定「长什么样」）。
