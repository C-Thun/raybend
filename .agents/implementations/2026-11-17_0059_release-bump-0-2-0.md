# 2026-11-17T00:59+08:00 — 本版改按 minor 定档：0.1.4 → 0.2.0，并把定档口径写进发布手册

崔总质疑「这版改了很多，为什么只升 patch」，重新核算后改判 **minor（0.1.4 → 0.2.0）**。

## 判据（同一把尺子量两版）

| 对比项 | v0.1.3 → v0.1.4（上版走 patch） | v0.1.4 → HEAD（本版） |
| --- | --- | --- |
| 改动文件 | 200 | 862 |
| 行数 | +14 096 / −1 185 | +107 049 / −30 128 |
| `PROFILE_SCHEMA_VERSION` | 2 → 2（未变） | **2 → 3** |
| `store/migrations` | 33 → 33（未加） | **33 → 35**（`catalog_0022_lut_chain`、`catalog_0023_areas`） |
| 新子系统 | 无 | 编辑区/控制点、多层 LUT 链、离线地点库（`geo.rs` + `assets/geo/`）、目录搬移（`store/relocate.rs`）、窗口状态（`window_state.rs`） |

上版能走 patch 的关键是**没动持久化结构**；本版改了编辑栈格式并新增两条迁移，另有独立子系统落地 —— 按语义化版本应记 minor。

## 改了什么

1. `docs/release-notes/0.1.5.md` → **`0.2.0.md`**（文件名必须与版本一致，否则发布说明会退化成提交链接）。
2. `docs/release.md` §6.1 增补「版本号怎么定档」：patch / minor / major 的判据表（优先看「用户数据要不要跟着变」）+ 两条自查命令（`git diff --shortstat` 与对 `issues.rs`/迁移目录的定向 diff），此后不必再凭印象争论。
3. 本次发布说明正文不变（内容与版本号无关）。
