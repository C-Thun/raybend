## 2. 现场勘查发现的三件事（方案的前提，都是现状事实）

1. **今天一条有效日志都没有**：全仓无 `log` / `tracing` 依赖；`crates/` + `src-tauri/` 共 120+ 处裸 `println!`/`eprintln!`，而发布版 Windows GUI 无控制台 → 全部进虚空。
2. **worker 的 stderr 被丢弃**：`crates/raybend/src/worker_process.rs:119` 用 `stderr(Stdio::inherit())`，同文件注释已承认“继承来的句柄无效就静默失败” → RAW/AI 解码进程的 panic 与报错一条都留不下。
3. **release profile 是 `panic = "abort"` + `strip = true`**（仓库根 `Cargo.toml`）：
   - `catch_unwind` 在发布版**全部失效** —— `src-tauri/src/editor.rs`、`crates/raybend/src/render/upload.rs` 等处“接住 panic 并重启线程”的设计在用户手里是空操作；
   - panic 直接 abort，异步日志队列来不及落盘；
   - backtrace 只有地址、没有符号。

第 3 条是**发版前就该拍板**的事（它决定崩溃路径怎么实现），但按崔总口径本轮只登记、不动手；已写进规格的「开工前必须先定的两件事」。

## 3. 关键决策与理由（规格里的选择）

| 决策 | 理由 |
| --- | --- |
| 三层结构：运行日志 / 异常采集 / 报告包与提交 | 层间单向依赖，采集与提交只读日志产物，日志层不知道上层存在 |
| `log` + `flexi_logger` 落盘 | 需要**按大小**轮转的硬上限；`tracing-appender` 的按大小轮转至今未实现（tokio-rs/tracing#1940），排除 |
| 文本行（定宽前缀 + `k=v`），不用 JSONL | 日志首先给人看（用户会贴、崔总在手机上扫）；JSON 让两边都痛苦 |
| 容量：2 MiB × 10 = **20 MiB 硬上限**，按目录总容量删最旧 | 个数控制挡不住单文件膨胀 |
| 崩溃助手用**独立二进制**（`crash-handler` + `minidumper`），不 re-exec 主进程 | readest 的 re-exec 方案连续三次打死启动（commit c37d7eb），独立小二进制没有这个失败模式 |
| dump 档位：线程栈 + 模块表，**不含全量内存**；发送时**默认不带**、用户单独勾选 | 内存快照理论上可能含已解码像素片段 → 隐私优先 |
| 脱敏放**中心化 sink 层** + 盐化短哈希 + 发送前预览 + 金丝雀单测 | 120+ 已有调用点不可能逐个自觉；同一条路径在同一份报告里可对齐、跨报告不可关联 |
| 发送通道：T0 本地导出/邮件客户端（必做）→ T1 崔总 Azure VM 上的自建接收服务 | GitHub **没有**匿名附件上传接口（官方无 mutation，未公开端点必须带 token）；客户端内置 SMTP 凭据等于公开；服务端凭据可控且可限流 |
| 服务端：Caddy + axum，永不解包、永不经 HTTP 读回，令牌视为公开、真正闸门是限流/配额/容量 | 假定令牌必然可被逆向；报告只进不出 |
| 5 条命令**全部留空热键**并写明理由 | 低频动作，菜单 + 命令面板可达，不值当占全局热键（§2.15） |
| 隐私文案与发送功能**同批更新** | `docs/privacy.md` 现有承诺「没有…自动发送诊断的机制」必须与实现一致 |
