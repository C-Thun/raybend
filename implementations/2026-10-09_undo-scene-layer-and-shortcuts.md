# 撤销：修「清空选择」bug + 命令体系加**场景层** + 重做默认键改 Ctrl+Y

## 需求（崔总 2026-10-09）

> editor 中的撤销功能有问题……第一点撤销后撤销其实是成功的，但结果会取消当前编辑照片的选中，
> editor 画布一下子空了，还得重新进点来重新载入相片，要解决这个 bug 并且再检查一遍撤销时的处理逻辑
> 是不是足够优化，并评估成本与收益（用户无感知的优化不必做）。
> 然后就是 editor 中撤销重做快捷键丢了……对用户来说这就是一套操作而不是两套，我们要有场景概念……
> 对于功能，或者说快捷键入口（这套东西类似于系统的统一指令入口），要增加场景这一层级的转换，
> 入口只是入口，入口背后对应的业务逻辑要再根据场景做一次转换……补上这层并打通 browse 和 editor 下的
> 撤销重做操作快捷方式，同时把默认的重做快捷键改成 ctrl+y。

## 一、清空选择的 bug（根因与修复）

**根因**：`src/features/browse/store.ts` 的 `undo()` / `redo()` 用了 `await reload()`。
本文件自己的注释写着两者的分界：「**查询变了**用 `reload`（清空重来、选择作废）；**查询没变但数据可能变了**
用 `refresh`」—— 撤销改的是库里的**值**（标记/编辑栈），查询没变，却走了「选择作废」那条路：
编辑器里撤销一次 → 选择被清空 → 画布空 → 得重新点照片。**症状与崔总描述逐字对上。**

**修复**：`undo()` / `redo()` 改走 `await refresh()`（保留选择、只剔掉真的消失了的）。
顺带收益：不再重建列表头（少一次「清空重来」的闪烁），也就没有需要评估的额外优化成本
（`refresh` 路径本身就是为这条场景设计的）。`undoTick` 通知编辑器重读编辑栈的既有机制保持不变。

**回归测试**：`store.test.ts` 新增「undo / redo：撤销与重做都不清空选择」。

## 二、场景层（入口唯一，逻辑按场景转换）

**结构**（崔总要求的「入口 → 场景转换 → 业务逻辑」）：

* `CommandDeps.history`（`catalog.ts`）：`{ applies, canUndo, canRedo, undo, redo }` ——
  命令只认识这个「场景化后的动作」，命令本身**不含场景判定**；
* 组装层 `App.tsx` 的 `historyScene()` 做转换：`editor`（编辑工作区有可编辑照片）→ 编辑器场景；
  其余 → `tiles`（浏览网格 / 看图 / 组织视图）；`historyActions` 是两侧共用的实际句柄
  （后端就一个撤销栈：`BrowseState.undo` 每库一份，显影步骤与标记步骤都在里面 ——
  前端没必要造两份状态；差异在**判定**与**副作用**：编辑器靠 `undoTick()` 重读编辑栈并刷新预览）；
* 命令 `edit.undo` / `edit.redo`：
  * `scope` 由 `tiles` 改为 **`global`**（该键在浏览与编辑两面都要生效，静态归属就得覆盖两面；
    冲突检测因此会拦住别的命令占用这两个键 —— 这是正确的严格度）；
  * `when` 由 `inBrowse` 改为 `deps.history.applies()`（浏览器路径也更宽了一点：**浏览的看图态**
    以前按 `Mod+Z` 是失效的，现在可用）；
  * `run` 走 `deps.history.*`。
* **快捷键**：撤销 `Mod+Z`（不变）、重做 **`Mod+Y`**（崔总指定；`Mod+Shift+Z` 不再是默认键，
  用户在设置里自定义过的仍然生效）。`Mod+Y` 无冲突（全表复核过）。
* 编辑工具栏的撤销/重做按钮也改为复用同一份 `historyActions`（同一能力不许两套入口）。
