## 1. 控制点：撞的是哪族专利，以及它已经死了

### 1.1 我们的形态（`specs/editor-area.md` §4.1、§4.2）

```text
d = ‖(A(p) − seed) · w‖₂     A = (luma, c1, c2)，seed = 创建时冻结的向量
α = V(d / tolerance)         V 单调递减，V(0) = 1
weight = α                   全图层恒为 1
```

关键属性：**零空间项**（像素离采样位多远都一样算）、**单权重**（不是「掩膜 × 强度」）、**层内逐像素**（`AGENTS.md` §2.27）。

### 1.2 Nik 核心族：权利要求 1 本来正对着我们，但它过期了

Nik Software 的「User definable image reference points」族，权利要求 1 的要素是「确定若干**像素特征集合**，每集合**至少含一个与位置无关的特征**；为每个集合确定一个**图像处理滤镜**；提供一个**混合函数**，按此处理图像」——
这句话几乎逐字描述了 §4.2（位置无关的 `A`、逐层 `apply_area`、`V` 混合函数）。**唯一救命的点就是时间**。

| 专利 | 现权利人 | 状态 / 到期 |
| --- | --- | --- |
| US 6,728,421 B2（原始申请，priority 2001-10-24） | Google LLC | **Expired - Lifetime**，2022-10-24 |
| US 6,865,300 B2（division）、US 7,031,547 B2（continuation） | Google LLC | 同链，期限自 2002-10-24 起算 → 同日到期 |
| US 7,602,968 B2（同链 continuation，GUI 覆盖层）、US 7,602,991 B2、US 7,970,233 B2、US 8,582,877 B2、US 8,625,925 B2、US 8,900,420 B2、US 9,471,998 B2、US 9,786,031 B2 | Google LLC | 同链 continuation，同样 2022-10-24 到期 |
| US 8,064,725 B2（空间偏移形变族） | Google LLC | **Expired - Fee Related**（未缴维持费，提前失效） |
| US 10,140,682 B2（2017 年 continuation，形变） | Google LLC | 同链，2022-10-24 到期 |

出处：https://patents.google.com/patent/US6728421B2/en （页面明写 `2022-10-24 Anticipated expiration` → `Status Expired - Lifetime`，并在 assignment 链上列出上表全部 continuation）。

三点推论：

1. **到期专利不存在「将来侵权」**，过去的赔偿也只追 6 年 —— 而那时本项目还不存在。
2. 这族专利现在是**在先技术**：任何人都不可能再就「点一个位置、按颜色/亮度相似度铺开调整」这一基本概念拿到新授权。
3. 真正要担心的窗口已经过去了 —— 如果这个功能早做四年，风险不低。

### 1.3 还活着的近似专利：Adobe 的「范围蒙版」，结构不同

| 专利 | 权利人 | 状态 | 权利要求结构 |
| --- | --- | --- | --- |
| US 11,223,744 B2「Local color range selection」 | Adobe | **Active，2037-12-02** | 生成**两个独立掩膜**：`spatial mask`（圈区域）与 `range mask`（色彩/亮度范围），调整量按两者（通常乘积）加权 |
| CN 109 671 024 B（同族中国件，2025-07-11 授权） | Adobe | **Active，2038-08-15** | 同上 |

出处：https://patents.google.com/patent/US11223744B2/en 、https://patents.google.com/patent/CN109671024B/en

**我们为什么不落入**（逐条要素对照）：

| Adobe 权利要求 1 的要素 | 我们的实现 |
| --- | --- |
| 生成**空间掩膜**（圈出区域，逐像素 0/1 值） | **没有空间掩膜**：`x/y` 只用来取种子和画标记，不参与权重 |
| 生成**范围掩膜**（色彩/亮度范围） | 没有独立的「范围掩膜」对象，只有权重函数 `V` |
| 同一笔局部调整里**同时**用两者加权 | 每层只有**一个**权重 `α = V(...) × opacity`，不存在两掩膜组合 |
| 两掩膜可分别存储为 XML | 我们存的是 `seed` + `tolerance` + 层参数，不是掩膜位图 |

另外，**崔总 2026-10-31 追加的设计约束**进一步拉大了距离：**将来的蒙版是独立的一层（`AreaKind::Mask`），不与控制点交叉** ——
也就是说永远不会出现「控制点的色相似权重 × 蒙版的空间权重」这种乘积结构。这条约束已记进 `memory/FUTURE.md` §D4 与 `specs/editor-area.md` §4.2。

### 1.4 商标（比专利更现实的风险面）

- `U POINT` / `U-Point™` 是**注册商标**，现归 **DxO Labs**（加拿大注册号 TMA697401，有效期至 2032-09-27）。出处：https://ised-isde.canada.ca/cipo/trademark-search/1279244 ；DxO 仍在主推该技术：https://www.dxo.com/en/technology/u-point/
- 我们的做法：术语表 `AGENTS.md` §11.5 已把名字**定死为英文 `control point`**，规格、代码、文案都不用 `U Point`。**继续保持**。
- 同样避开 Nik / DxO 的其它产品名（`Viveza`、`Upright`、`Define`…），宣传文案不写「仿 U Point」「Nik 同款」。

### 1.5 为什么「实际被起诉」的概率比「法律上是否落入」更低

| 因素 | 影响 |
| --- | --- |
| 无赔偿基数 | 专利诉讼成本常达数百万美元；本项目是 AGPL 桌面软件，无营收、不上架商店 → 赔偿基数 ≈ 0 |
| 原告身份 | Google 不因开源修图软件起诉；Adobe 告的是同体量商业对手。NPE（专利蟑螂）只盯有收入的标的 |
| 代码来源 | 纯 Rust 独立实现，**没有**反编译 Snapseed / PhotoLab，也没有移植其二进制 → 也排除了著作权 / 商业秘密这条更常被用的路径 |
| 行业常态 | darktable 的按颜色/亮度相似度参数蒙版开源多年，业界普遍做法；核心专利到期后该做法进入公有领域 |

**前提条件**（破坏任一条，估计值就要往上修）：① 不用 `U Point` 类商标；② 不做界面像素级复刻（照抄 PhotoLab / Capture NX 的控制点外观与交互细节）；③ 保持「蒙版独立成层、不与控制点相乘」这条约束。

## 2. 智能蒙版：开源不等于免专利，但这次恰好拿到了专利授权

「库都开源了所以没专利」是**误解**，不过这一次的结论仍然乐观 —— 原因是**许可证类型**，不是「开源」本身。

### 2.1 Apache-2.0 第 3 条是明示的专利授权

Apache-2.0 不只有版权许可，还有一节专门的 **Grant of Patent License**：每个贡献者就其**必然被自己的贡献所侵犯**的权利要求，授予使用者「制造、使用、销售、进口」等**永久、全球、免费、不可撤销**的专利许可；仅当我们自己去起诉别人侵犯同一作品时才终止。
（原文：https://www.apache.org/licenses/LICENSE-2.0 ，第 3 节）

对比：MIT / BSD **没有**专利条款 —— 这类库「开源」确实不解决专利问题。这也是我们在 `memory/FUTURE.md` §E2 里特别标注权重许可的原因。

### 2.2 逐层核对许可（2026-10-31 复核）

| 对象 | 许可 | 对本项目的含义 |
| --- | --- | --- |
| SAM 代码（`facebookresearch/segment-anything`） | **Apache-2.0** | 含专利授权；https://github.com/facebookresearch/segment-anything/blob/main/LICENSE |
| SAM **模型权重** | **Apache-2.0**（官方 issue 明确答复） | 我们分发的是同源派生权重，授权覆盖 |
| **EfficientSAM** 代码 + 权重 | **Apache-2.0**（LICENSE 为 Apache-2.0 原文，无附加条款） | https://github.com/yformer/EfficientSAM/blob/main/LICENSE |
| **SA-1B 数据集** | **研究用途 Data License**（不是 Apache） | 只约束**数据集本身**的使用；我们不分发数据集、不重训，只跑已发布权重。属于「训练方」的风险，已在 `FUTURE.md` §E2 记录在案 |
| 派生的 ONNX 制品 | 继承上游 Apache-2.0 | 需在 `THIRD-PARTY-NOTICES.md` 记来源、许可、修改（转换脚本与模型摘要） |

### 2.3 专利面：没有找到针对「点选 → 掩码」的已授权有效权利要求

- Meta 在分割方向确有专利，但落在 **AR / 视频通话背景分割**（例：US 12,165,334 B2，2024-12-10 授权，Meta Platforms Technologies）与实时视频分割（US 2023/0222669 A1，申请公开）—— 场景与「静态照片里点一下取一个可编辑蒙版」不同。
- 「点击/勾画 → 分割」这条思路的**基础在先技术非常老**：GrabCut（SIGGRAPH 2004，Rother/Kolmogorov/Blake）及其微软同族（如 US 8,655,069 B2「Updating image segmentation following user input」，2014-02-18 授权，Google Patents 状态 **Expired - Fee Related** —— 未缴维持费而提前失效，名义到期日 2032-07-27；且其权利要求说的是「按用户笔刷重新加权前景/背景属性再跑图割」，与「神经网络一次前向出掩码」不是一回事），Magic Wand、Intelligent Scissors 等更早。基础思路不可专利化。
- SAM 时代（2023 起）的申请大多**仍在审查中**：未授权的申请不能维权；授权后往往被审查过程收窄。**近期风险 ≈ 0**。

### 2.4 真正的风险不在专利，在这三件事

1. **不要反向声明「自研分割模型」**：会同时踩虚假宣传与商标（Apache-2.0 第 6 条不授予商标权）。文案写「基于 EfficientSAM」即可。
2. **权重来源与派生记录**：模型摘要、转换脚本版本、修改说明进 `THIRD-PARTY-NOTICES.md`（`FUTURE.md` §E2 已要求）。
3. **界面不要照抄**：`Select Subject` / `Select Background` 这类 Adobe 的命名与图标组也不要用（商标 + 界面识别度，与专利无关）。
