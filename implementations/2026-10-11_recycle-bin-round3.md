## 一、回收站内目录点开是空的（**逻辑 bug**，根因明确）

**现象**：删除后照片进了回收站，展开回收站树、点里面的一级目录 → tiles 全空。
（崔总说「你可以查一下图片有没有被删丢」——**文件没丢**，是查询把它们滤掉了。）

**根因**：`BrowsePanels` 里点树行的逻辑是「在回收站里点行 ⇒ `openPhotosScope(path)`」，
而 `openPhotosScope` 的语义是**退出回收站**（`setRecycleMode(false)`）→ 查询变成
`visibility: Live`（只看 `deleted_at IS NULL`）→ **回收站里的资产全是 `deleted_at` 非空的，一张都匹配不上**。

**修法**：回收站区里的行**保持在回收站里**，只换范围：

```ts
if (isRecyclePath(row.relPath)) {
  if (!store.recycleMode()) store.enterRecycle();
  store.setScope(row.relPath);
} else if (store.recycleMode()) {
  store.openPhotosScope(row.relPath);   // 库内正式目录：退出回收站并切过去
} else {
  store.setScope(row.relPath);
}
```

## 二、删除后 tiles 整屏闪烁 → 改**局部移除**

**现象**：删除（按钮 / `Delete` / 拖动）之后整个网格闪一下重建。

**根因**：`removeSelected` / `removeIds` / `purgeIds` / `restoreSelected` / `purgeSelected`
删完都 `await reload()` —— 重查首屏 = 清空 + 重建（`resetForNewQuery` + 重新请求）。

**修法**：新增 `store.dropEntries(ids)` —— **就地摘掉，不重查**：
只动三样（时间线、条目表、总数），重排与「标记需重读的页」复用现成的 `retainPagesForTimeline`。
五个删除/真删/还原入口全部改用它。`exitRecycle()` 那条路不变（回 photos 侧本来就要重读）。

**测试**：`removeSelected` 的用例改成钉新语义 —— **页面请求数不变**、条目里不再有被删的两张、总数减 2。

**拖动「第一次没起效」**：给命中加了**兜底** —— 先按松手点算一次；若这一帧问不到（热区重绘/缩略图加载完重排），
回退到**拖动过程中最后算出的 target**（拖动时已经亮过的目标就是用户瞄准的那个）。
若真机仍能复现「第一次无效」，需要更精确的复现步骤（是特定照片、特定位置，还是每次冷启动后的第一次）。

## 三、回收站树结构（崔总 2026-10-11 的方案）

**改前**：回收站那行是个**目录行**（有展开箭头、会被选中），横线在它**下面**、回收站子目录在横线**之下**。

**改后**（按崔总的口径）：

- **回收站行不再是一个目录** —— 没有选中概念、**去掉最左边的展开箭头**、整行点击 = **展开/收起**回收站的一级目录
- **贴左显示**（`padding-left: 4px`，与库内目录同一档），**红色垃圾桶图标 + 数量**保留（点缀）
- **回收站的一级目录与库内正式目录同样左对齐、不缩进**（`walk(RECYCLE_DIR, 0)`；只有子目录才缩进）
- **横线移到回收站区之下**：回收站行 → 它的一级目录 → **横线** → 库内正式目录
  （树渲染拆成 `recycleRows` / `photosRows` 两段，横线夹在中间）
- 回收站里的目录**没有 ⋯ 菜单、不支持目录标签**（现状即如此，`row.relPath.startsWith(PHOTOS_DIR)` 才给菜单）

## 四、文案与配色

- **空态文案**：`browse.empty_lib` 「这个库里还没有照片」→ **「当前目录下无照片」**（en: `No photos in this folder`）。
  范围是**当前目录**、不是整个库，两回事。这是**通用**空态（不只回收站）。
- **拖动预览卡片底色**（跟随指针那一叠）：`bg-surface-layer` → **辅色 `bg-brand-2`**
  （浅色主题下纯白浮在照片上像界面外来的颜色；深色主题下与 tiles 同色分不清边缘）。
  数量角标改回**浮起档**（`bg-surface-layer` + `text-fg-1`）—— 卡片已经是辅色，角标要形成层次而不是撞色。

### 四之二、拖动**热区**底色（我改错了三次的对象）

崔总 2026-10-11 的红箭头指出：要改的是**左上角那个方块**（拖动时出现的落点，拖上去松手就删除/还原），
而前三次我改的都是**跟随指针的预览卡片** —— 两个东西，我认错了。

热区这一侧的正确改法：

- `--heat-surface`：`surface-layer` → **辅色 `var(--brand-2)`**（两个主题同一档）
- 图标：`text-fg-2` → **`text-fg-on-brand`**（辅色底上的前景色）
- 命中轮廓：原来是辅色 —— 底已经是辅色就看不出来了，改成 **`outline-fg-1`（深色）**；
  回收站里拖到它（真删）仍用 **`outline-danger` + `text-danger`**

### 四之三、查清楚：改的一直是**两个不同的东西**

崔总 2026-10-11 第三次指出后终于理清：

| 东西 | 位置 | 正确取值 |
| --- | --- | --- |
| **拖动预览卡片** | 跟随指针的那一叠 | `surface-layer` + `fg-3` 描边（**与 export 一致，不要动**） |
| **数量角标** | 卡片角上的那个数字 | **辅色**（`bg-brand-2` + `text-fg-on-brand`） |
| **拖动热区** | 左上角那个方块（落点） | **辅色**（`brand-2`，见 §四之二） |

前几轮的错：把「角标底色要辅色」理解成了「卡片底要辅色」，于是卡片一直改、角标一直没对
（它从「缩尺寸、去掉文字」那次起就是 `surface-layer` 的白 —— 而那是界面里不存在的颜色）。
现在：**卡片恢复原样，角标改辅色，热区保持辅色。**
