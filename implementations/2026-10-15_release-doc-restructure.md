## 一、文档重排（`docs/release.md`）

### 新骨架（正文线性可读，细节收进附录）

```text
§0  三层台阶一览（每层加什么 / 验收是什么）
§1  第一层：本地开发与调试      —— 需要什么（表）→ 一次性命令 → 验收 → 这层**不需要**什么
§2  第二层：本地 debug 包        —— 在第一层之上新增什么 → 验收 → 边界
§3  第三层：正式发布            —— 新增项（表，**每条带「不满足时的症状」**）→ 发布前自检
§4  指令 · 本地调试             —— 命令表 + 两条红线（workspace 测试门、前端必须先 build）
§5  指令 · 本地 debug 包        —— 命令表 + 常用参数 + 构建现场与锁
§6  指令 · 正式发版包           —— 一条命令 / 两条指令 / 参数速查 / 两条指令各自做了什么 / 重跑与中断语义
§7  变化与应急（按层）          —— 7.1 一 层 / 7.2 二层 / 7.3 三层 / 7.4 发布期纪律红线
§8  踩过的坑                    —— 13 条「症状 → 根因 → 做法」，全部来自真实事故
附录 A–J                        —— 原有细节，只重排编号与交叉引用
```

### 关键做法

1. **每层先「需要什么」，再「验收」**：第 ①/②/③ 层的清单表都带一列「本机现状」或
   「不满足时的症状」；第三层尤其如此（gh 令牌能不能触发 workflow、`github-pages`
   environment 是否放行 `v*`、crates.io 邮箱是否验证 —— 这些不满足时症状都写在表里）。
2. **命令同样分三层**，与文档前半一一对应；每节只讲这一层要敲什么。
3. **附录保留全部细节**（更新密钥变量语义与源码依据、证书与 SmartScreen 事实、crates.io
   首次发布、AI 外挂、手工 finalize、打包镜像与路径转换、真机验收、macOS/Linux、CI 评估、
   磁盘清理），正文只在需要时指过去 —— 避免同一件事两处表述。
4. **§8 是新增的事故账**：crashpad 漏同步、draft 端点 404、crates 上传 30 s 超时、
   `github-pages` 环境规则、构建期改工作树导致的 `AggregateError`、crates.io 邮箱未验证、
   签名变量互斥、漏 `pnpm build` / `--features custom-protocol`、只跑 `cargo test -p`、
   旧 `C:\rb-target` 17.9 G、beta 不能打 MSI、调试包被拉到正式版、更新下载不可续。

再统一修正交叉引用；`Export`/结构自检：代码围栏配平（48 个）、标题层级、引用指向存在的附录。
