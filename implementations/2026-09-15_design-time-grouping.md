## 一、按时间分组模式（新功能）

**入口**：`GridControlBar` 里、缩放滑块**左边**的 `按时间` 按钮（`R0J32`）。
形态与吸附磁铁一致（**可按下式，不是左右切换的圆点开关**）。

**两级分组规则**：

```text
一级：按拍摄日期分组（本地日期）→ 一天一组
二级：该天内按拍摄时间升序，相邻两张间隔 > 1 小时 → 断为新片
```

- **「1 小时」必须是配置项**，不写死在代码里。
- 时间缺失的照片归入「未知时间」组放最后，不参与切分。

**为什么做时间片**（这是本功能的真正价值）：一次导入往往包含「同一场活动的多段拍摄」
（上午出门、下午回来、晚上又拍）。只按天分组太粗（一天可能上千张），只按张又太细。
**时间片正好对应「一次连续拍摄」**，也就是用户心里天然的分段 —— 所以它应该是**可一键选中的单位**。

**片标题用「09:15 – 11:42」这种首尾时间范围**，不是张数也不是时长：
用户是在回忆「我那次拍的是什么」，时间范围是最强的记忆线索。

## 二、排除功能从 tile 搬到 `toolsbar`

| 改动 | 内容 |
| --- | --- |
| 图片 tile | **移除**右上角的排除徽标（缩略图变干净） |
| `toolsbar` | 内容改为**居中对齐**（原来靠右）；移除「筛选」占位按钮，换成**批量排除** |
| 新流程 | **先选择 → 再按顶部排除**。日组标题（全选当天）、片标题（全选此段）都可一键选中 |
| 按钮三态 | 可排除（普通）／已排除 → **反排除**（主色底）／无选中 → 禁用态 |

**为什么这样更好**：排除真正有用的场景是**批量**的（「这一天的都不要」），而不是一张一张点。
移到顶部后天然支持**反排除**，而且不再需要在每张缩略图上挂小按钮。

## 验证方式

```bash
# 布局体检（取实测 bounds 复核，不只看 problems）
Get(shell, (n,c) => Print(n.name, c.bounds.y, c.bounds.height))
```

**修掉的真实问题**：宽松档改尺寸后，**容器没跟着长大**导致内容被裁：

- `PanelBody / 最近` 150 → 200（5 行 × 32 = 160 > 150）
- `PanelBody / 已选目录` 210 → 268（3 × 68 + 间距 16 + 内边距 20 = 240 > 210）
- `BarTop` 24 → 28（移除按钮 26px 放不进 24）
- `BarBottom` 16 → 22（开关 18px 放不进 16）

> **这正是用户说的「不能用缩放系统整体缩放出来」的实证** —— 间距翻了 2×，
> 但承载它的容器高度如果按 1.5× 缩，就会裁切。两档密度必须是**两套独立设计值**，
> 不能由一套缩放得出。

**判定为误报的**：`GridRow / 1` 报 `partially clipped`，但实测
`GridBody` 高 822、两行在 y=16 与 y=158（各高 134，总到 292）—— 完全放得下。
与之前几次同类告警一致：**`ctx.problems` 在批量 Update 的同一调用内不可信**，需后续调用复查。

**未验证（诚实起见）**：全部是设计稿层面的验证，无任何前端实现代码；
