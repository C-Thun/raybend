## 关键决策与理由

### 1. `REVIEW.md` 定成「结论账本」，不是第二份规格

本仓的硬纪律是「同一个东西只允许一套实现 / 一种表达」（`AGENTS.md` §2.12）。
一份评审文档天然有变成"第二份规格"的倾向（同一件事在规格里和在评审里各写一遍，之后必然漂移）。
因此本文件**只记三样：判断、取舍、去向**；一经采纳，正式改动写回**拥有它的那份文件**，
评审文档那一项只更新到「已落地 + 落点」。这条写进了 `REVIEW.md` §0.1 与 `AGENTS.md` §5.6。

### 2. 不用 `- [ ]` 勾选框，状态写在表格「状态」列

`AGENTS.md` §5.4 明确：规划文件里的勾选项会被 plannotator 进度跟踪，且 `mark_done` 会真实改写文件。
那个机制只属于 `plans/*.md`。若 `REVIEW.md` 也用勾选框，就会与 `plans/` 的进度机制混淆、
出现两份都不可信的进度（`~/.pi/agent/AGENTS.md`「任务清单纪律」）。
故状态用 `待决 / 已采纳 / 已落地 / 不做 / 搁置` 五态写在表格列里。

### 3. 编号 `R<轮次>-<序号>`，每轮追加不覆盖

结论变了写新一节并注明取代了谁 —— 保留「当时为什么这么定」这件事本身有价值，
删掉它下一轮会把同一件事重新吵一遍。第 5 条规定了编号一经分配不再复用。

### 4. `AGENTS.md` §5.6 里加了一条权限边界

「Agent 可以把待决项、理由与证据写齐（并给出推荐），但**不得**把 `待决` 自行改成 `已采纳`」——
方向决策属于人类，与 §5.4 / §5.5 的既有分工一致。

### 5. 本轮 12 条建议**全部保持 `待决`**

包括三条 P0（R1-01 色彩管理进 DoD、R1-02 集合/智能集合排期、R1-08 出图质量基线）。
没有一条由 Agent 自行判定为"已采纳"，理由同第 4 点。

### 6. 证据级别的自我限定已写进文件

`REVIEW.md` §2 的元信息表里明确写了「**本轮没有任何来自真机的证据**」，
并在 §5 把它列为下一轮评审要补的输入之一 —— 与 `AGENTS.md` §2.8
「Agent 只做冒烟、E2E 归人类」「不得声称已验证」的口径一致。
