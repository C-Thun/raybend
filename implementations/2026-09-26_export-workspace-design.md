## 3. 关键设计决策（并说明理由）

1. **可选中单元 = issue，不是照片**：导出以 issue 为第一公民（`PLAN.md` M4-W2）。
   mid top 的网格单元因此是「照片 + 一行 issue 小片」；点照片本体 = 整组全选。
   这是 `prompts/exports.pd` 里「每张照片同时显示所有 issue」与「导出选中的 issue」两句话的交点。
2. **两个窗口各有自己的 statusbar**：上＝完整 tiles 状态栏（含按时间/排序/缩放/适合窗口），
   下＝精简（计数 + 预设名条 + 列表模式 + 缩放）。**不跨列、不横跨两个窗口**（`DESIGN.md` §8.7）。
3. **高度下限用算式表达**：`min_top(384) + min_bottom(384) + handle(8) = 776 ≤ 868`，
   还剩 92px 机动；实现时下限必须按当前工作区高度夹住（窗口变小要等比降），否则会出现「拖一边顶破另一边」。
4. **`新增` 主色 / `更新` 辅色**：直接采用人类口述的颜色分工，并天然用掉了 `$brand-2`（辅色）的语义。
5. **`送入队列` 的禁用态退为中性格**（而不是 `DESIGN.md` §2.8 的「面不变、前景降级」）：
   主色实底 + 次级前景看着仍然可点，绿底上也无法读。已登记为待确认项（导出 md §9 第 3 条）。
6. **队列顺序照人类口述画**：新入队在上、导出从下往上、导完留在队列里（对勾徽标 + 「已导出」）。
7. **流光带按「状态指示类」动效处理**：秒级慢循环，不套用 ≥150ms 的反馈类时长纪律（`DESIGN.md` §12.10）。
8. **不用重复实现的地方一律复用**：左列 = browse 的库/目录选择器（不新增能力）；
   分隔条 = film 胶片带那套三点细条；`按时间分组` = browse 的同一套组件（故不另画帧）；
   水印、toast、拉杆、弹窗按钮顺序全部照 `DESIGN.md` 既有条目。

## 4. ⚠️ 现场事故与处理：6 个 export 帧曾被写进 `editor.pen`

**现象**：本次绘制开始时 `pencil_get_app_state` 报的活动画布是 `export.pen`（空画板）；
中途以 `filePath=editor.pen` / `browse.pen` 读过节点后，**对 `editor.pen` 与 `export.pen`
两个 filePath 的读取开始返回同一批顶层帧**（而 `browse.pen` / `main.pen` 仍各回各的）。

**后果**：首版的 6 个 export 帧实际写进了**活动画布（当时是 `editor.pen`）**，并在 12:29
随一次保存落盘（`git diff --stat design/editor.pen`：+15157 行）；`design/export.pen` 一直是 315 字节的空画板。

**处理**：人类把活动画布切回 `export.pen` 后，**按同一套代码把 6 帧重建进 `design/export.pen`**
（本文件 §2.1 的 id 是重建后的新 id），并先用 `Get` 核对 `export.pen` 的顶层只有 `bi8Au` 才开始写、
写完后用截图与 `Get(bounds)` 复验。

**遗留（需人类拍板）**：`design/editor.pen` 里那份副本（6 个 `*/ Export /*` 帧，位置在 x ≈ 8200 起）
仍在文件里。清理方式二选一，**都需要人类点头**：
1. 我把画布切到 `editor.pen`、删掉这 6 帧（用名字精确匹配，不碰 editor 的任何原有帧），然后人类保存；
2. 人类自己在 Pencil 里删（它们集中在一处，很好框选）。

❗ **不要用 `git checkout design/editor.pen` 回滚**：editor.pen 在 12:29 的那次保存里
**同时**带上了人类新画的 `Components / Editor / 对比来源菜单`，回滚会把它一起丢掉。

**教训**（下次开工要先验）：动笔前先 `pencil_get_app_state` 确认活动画布，并且**每写完一帧就
读一次目标文件的顶层帧**核对归属；一发现「两个 filePath 返回同一批帧」立即停手问人。
