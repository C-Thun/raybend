## 关键决策与理由

1. **许可 = AGPL-3.0-only**（用户决定）。落地时同步做了一件事：**改写 RapidRAW 相关的纪律条目**——既然两边许可一致，其代码在保留声明与注明来源的前提下**可以**复用；原先「不要复制代码」的限制已不成立（需逐文件确认文件头标注）。
2. **rust-toolchain.toml 用命名工具链而非改全局默认**（对计划的偏离）：计划原文是 `rustup update stable && rustup default 1.98.1`。改为「安装 `1.98.1` 命名工具链 + 由 `rust-toolchain.toml` 锁定」，因为改全局默认会影响本机其他项目（如 `~/repos` 下的其他仓库）。效果相同，副作用更小。
3. **`crates/raybend-ipc` 不建**（计划已注明）：等 M1 真有 specta 契约时再拆，避免空壳 crate。
4. **前端加 router 但只挂一条兜底路由**（`path="*"`）：刻意避开桌面应用 URL 形态差异（`tauri://localhost` vs `http://localhost:1420`）导致的匹配失败；是否保留 URL 语义留给 UI 设计阶段定夺。
5. **`[profile.dev] opt-level = 2` + `[profile.dev.package."*"] opt-level = 3`**：图像类工作负载在 dev 下也需要性能，否则 M0-3/4/5 的基准数据会被优化级别扭曲。
6. **不预置未使用的依赖**：`crates/raybend` 目前只依赖 `thiserror`；`wgpu`/`rawler`/`rusqlite` 由各自波次引入。

## 关键发现（影响后续波次）

1. **WSLg 没有硬件 GPU**：`pnpm tauri dev` 日志出现 `libEGL warning: failed to get driver name for fd -1`、`MESA: error: ZINK: failed to choose pdev`、`libEGL warning: egl: failed to create dri2 screen`（共 4 条）。说明 WSL 侧是软件渲染回退。
   → **推论（对 M0-2 / M0-6 很重要）**：UI 骨架与逻辑可以在 WSL 验证，但**任何 GPU 渲染行为与性能数字都必须在 Windows 上取得**；M0-2 在 WSL 里跑不出有意义的结论，M0-6 的帧率同理。
2. **Windows 侧工具链仍缺 MSVC 与 Windows SDK**（`vswhere` 无 VS 实例、`Windows Kits\10` 无 Include/Lib），且 Windows Rust 为 1.86.0（低于 rawler 要求的 1.89）。M0-2/M0-6 的 Windows 验证依赖这一步。
3. `pnpm tauri dev` 首次完整构建耗时约 1m40s（429 个编译单元，含 webkit2gtk 绑定）；`cargo check` 约 2m37s（含下载）。
