# tile 信息条「有字没底」：`--tile-bar-scrim` 从来没人定义

完成时间：2026-09-16 23:06:04 CST

人类反馈：*「悬浮/选中图片 tile 时上下信息栏的背景条并没有出现，导致字直接压在图片上，
这在某些图片中会导致看不清字」*，并问「为什么这条漏了」。

## 一、根因（一句话）

`Tile.tsx` 写了 `bg-(--tile-bar-scrim)`，而**这个令牌从没进过 `tokens.css`** ——
`background-color: var(--未定义)` 在**计算值阶段静默失效**成 `transparent`：
没有编译错误、没有控制台警告、没有测试红。于是信息条只有字、没有底。

三处证据（都可复现）：

1. `git show a8013fa -- src/styles/tokens.css` —— 那次提交只加了 `--tile-radius` /
   `--tile-pad` / `--tile-bar-h`，**`--tile-bar-scrim` 漏了**。
2. 全库搜 `--tile-bar-scrim` 只有 4 处命中：`Tile.tsx` 两处引用 + 一处注释 + 计划/实现记录。
   **零处定义。**
3. 产出 CSS 里确实有 `.bg-\(--tile-bar-scrim\){background-color:var(--tile-bar-scrim)}` ——
   类生成了，值没有。

## 二、为什么没被发现（四个洞叠在一起）

| # | 洞 | 说明 |
| --- | --- | --- |
| 1 | **失效方式太安静** | `var()` 未定义是**计算值阶段**的事，不报错；不像拼错类名那样在 DevTools 里显眼 |
| 2 | **冒烟只量了 `opacity`** | 当时的断言是「指向/选中时信息条出现（opacity 0→1）」—— 这条**是真的**（字确实出现了），所以绿。**没有任何断言问过「它有没有底」** |
| 3 | **单测只管密度块成对** | `tokens.test.ts` 检查的是「紧凑/宽松两档定义同一批令牌」，不管「组件引用的令牌是否存在」 |
| 4 | **「文档里写了」被当成了「代码里有了」** | 计划 §4.1.1 连值都写了（`rgba(0,0,0,.55)` / `rgba(255,255,255,.72)`），步骤 6 也写了「两层叠加」，实施记录里又抄了一遍 —— 三层文档都有这个名字，代码里却没有值。同一次提交里还有第二例：记录写着「口径已写进 `design/main.md` §3.2.1」，而那里当时**还是旧的「图 + 下方字幕条」版本**（`design/main.md` 根本没在那次提交的文件清单里） |

一句话：**这条的验收标准是「看得见」，而当时的闸门全都在测「看不见的东西」（opacity 数值、
令牌成对关系）。** 照片上的文字对比度没人量过，就只能等人在真机上看见。

## 三、修法

### 3.1 补令牌（`src/styles/tokens.css`，主题层，不随密度变）

```text
--tile-bar-scrim  深色：color-mix(in oklab, var(--surface-track) 65%, transparent)
                  浅色：color-mix(in oklab, var(--surface-layer) 72%, transparent)
```

- 沿用 `--scrim` 的**派生**套路（`color-mix()` 合成，不新增字面色值 → 改主题色时自动跟着走）。
- 方向不同：它是铺在**照片**上的，所以深色**压暗**（取池内最深的 `surface-track`）、
  浅色**提亮**（取最亮的 `surface-layer`）。
- **主动偏离计划的一处**：计划写的是 55%，我改成 **65%**，并算出依据 ——
  最坏情况是「照片该处是纯白像素」，深色主题下 55% 只有 ≈3.7:1（**不过 AA**），
  65% 实测 **5.14:1**（过 AA 且留余量）。浅色的 72% 照计划，实测 8.03:1。

### 3.2 信息条上的次级文字改掉（`Tile.tsx`）

原来的扩展名标签与加锁图标用 `text-fg-2`。浓底上「分级」是好看的，但这里的底是**照片**，
压了蒙层也只能保证一档对比度：`fg-2` 在亮照片上是 **2.55:1**（深色主题）/ 2.75:1（浅色主题）。
→ 改成继承容器的 `fg-1`，**层级改由字号表达**（文件名 `--fs-1`、扩展名 `--fs-0`）。

### 3.3 顺手清掉同一批「写了但没用/没做」的残留

| 残留 | 情况 |
| --- | --- |
| `--tile-cell-w` / `--tile-cell-h` | 计划步骤 7 说「退役」，实施记录也说「已废除」，但**令牌本体一直留着**（还写着「3:2」）。删除；`--tile-cell`（正方边长）才是活的 |
| `--caption-h` | 「字幕条高」—— 字幕条方案已废弃（信息条是覆盖层、不占高度），全库只剩注释在引用。删除，两处引用它的注释改成 `--row-h` |
| `scripts/grid-bench.mjs` | 还在传 `cellWidth: 208, captionHeight: 26`，而行高接口早改成 `cellSize` → `tileRowHeight(undefined)` 返回 0，基准脚本一直在报「57 行总高 **266px**」（每行 4.7px）这种**看起来正常、其实是垃圾**的数。改成 `cellSize: 208`，现在报 10666px |

## 四、补闸门（两道，都验过「会红」）

### 4.1 单元：引用必定义（`src/styles/tokens.test.ts`）

扫 `src/**/*.{ts,tsx,css}` 里所有 `var(--x)` 与 Tailwind 的 `(--x)` 简写，逐个问
「`tokens.css` 里有定义吗」。两条豁免都写明理由：

- 运行时由 JS 赋值的（`--tile-cell`，`PhotoGrid` 写内联样式）；
- 别人给的：Ark 的分段指示块（`--left/--top/--width/--height`）、`index.css` 给 Ark Positioner 的 `--z-index`。

**踩到的坑**：不能「边扫边判」—— 豁免是**扫到赋值那一行**才登记的，而 `Tile.tsx` 排在
`PhotoGrid.tsx` 前面，于是 `--tile-cell` 白报一条。改成「先扫完所有文件、再判定」。

顺带补了一条「**两个主题块定义同一批令牌**」（与密度块那条对称）—— 同一类病换了个维度：
写进 `[data-theme="dark"]` 独占的块，浅色主题下就是空值。

**验证**：把 `tokens.css` 换回改动前的版本 → 测试精确报出
`--tile-bar-scrim ← components/ui/Tile.tsx`（复现原 bug）。

### 4.2 冒烟：真测对比度（`scripts/ui-smoke.mjs`）

新断言 = 「信息条的底纹必须存在（alpha > 0.5）**且**文字对最坏情况照片（纯白/纯黑像素）
的对比度 ≥ 4.5:1」，**两个主题各量一遍**（直接改 `data-theme` 量、量完还原）。

- 合成不解析颜色字符串：`color-mix()` 的结果被 `getComputedStyle` 序列化成
  `oklab(0.21256 ... / 0.65)`，手写解析只支持到一半；改成**用 canvas 真画一遍再读像素**
  （先铺纯白/纯黑，再叠蒙层），取色也走 canvas 的 `fillStyle` 规范化。
  —— 中途踩过一次：`rgb(32 34 38)`（空格分隔）被我按逗号拆成 `NaN`，而 `NaN` 经 JSON 变成
  `null`，看起来像「没测到」。
- **验证**：把令牌抽掉再跑 → 四条断言全红，实测正是人类看到的样子：
  `rgba(0, 0, 0, 0)`（全透明）、对比度 1.07:1 / 1.32:1。
