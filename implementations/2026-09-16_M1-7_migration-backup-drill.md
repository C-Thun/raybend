# M1-7 步骤 3：迁移 / 备份 / 故意损坏 演练

完成时间：2026-09-16 12:41:24 CST

## 做了什么

一条可重复执行的命令：

```bash
pnpm migrate:drill      # = bash scripts/migration-drill.sh [工作目录]
```

八段，全部在**真文件**上做：

| # | 做什么 | 断言 |
| --- | --- | --- |
| ① | 造一个有照片、有账的真库（12 张合成图） | 导入进来了照片、写下了期望值 |
| ② | 做一份快照（`VACUUM INTO`，与产品同一条机制） | 快照文件真的生成了 |
| ③ | **故意**把 `catalog.db` 头部 4 KB 写成垃圾 | 打开**必须报错**；文件大小与内容仍是坏的（**没有静默重建**） |
| ④ | 从快照恢复 | 能正常打开；`assets/files/imported` 三项与损坏前一致 |
| ⑤ | 手工造一个 **v1 schema** 的旧版库（复用真库的身份行 + 一条标记数据） | 造出来的是 v1 |
| ⑥ | 打开旧版库 | 自动迁移 `1 → 3`、`applied = [2,3]`、迁移前留快照、标记行与身份行都在、文件 `user_version` 前进到 3 |
| ⑦ | 快照轮转 | 同组只留 7 份、最旧的被删、**别的库的快照不被牵连** |
| ⑧ | 把 `user_version` 改成 99（未来版本） | 拒绝打开，且提示里说清「请升级 raybend 后再打开」 |

实测输出（关键几行）：

```text
迁移结果：Some(MigrationOutcome { from: 1, to: 3, applied: [2, 3], snapshot: Some("…/catalog_00LjJ2Ml_v1_20260916-044101Z.db") })
拒绝的理由：这个库是更新版本的 raybend 创建的（库版本 99，本程序支持到 3）。请升级 raybend 后再打开；若你确实要用旧版打开，请先备份这个库。
轮转前这组有 11 份，删掉 4 份；还剩 7 份
```

## 关键决策

- **旧版库怎么造**：不猜 `repository_meta` 的键，而是先建一个真库把身份行读出来，
  再用 `catalog_0001_init.sql`（`include_str!`）建 v1 全量 schema 后把这些行插回去。
  这样演练不会因为以后新增身份键而失效。
- **损坏用「写头部」而不是「删文件」**：要验的是「SQLite 能识别出这不是数据库」，
  删掉文件反而是另一回事（那该走「首次运行，建新库」的路径）。
- **轮转份数不写死**：backups 目录里可能还躺着前面步骤产生的真快照，
  所以断言写成「删掉的份数 = 原有的份数 − 7」。
