# M1 开工评估：外部资源依赖审计

完成时间：2026-09-15 15:43:15 CST

## 为什么要做这份审计

用户提出「网络不太好，要评估一下是否适合现在开始 M1」。因此把 M1（及其前置 spike）
**所有需要联网下载/安装的环节**逐个查清并量化，给出「哪些现在就能做、哪些该等」的结论。

## 一、实测数据（本次现场测量）

### 1.1 网络状况

| 目标 | 结果 |
| --- | --- |
| `registry.npmjs.org` | ✅ 200，**0.90 s** |
| `index.crates.io`（cargo 索引） | ✅ 200，**0.52 s** |
| npm tarball 实测吞吐 | **1.62 MB/s**（4.5 MB / 2.79 s） |
| 镜像配置 | **无** —— cargo 无 `~/.cargo/config.toml`，npm 用官方源 |

结论：**网络不是不通，是中等带宽**（≈13 Mbps）。慢但不致命。

### 1.2 本地缓存现状（这决定了要下多少）

| 缓存 | 现状 |
| --- | --- |
| `~/.cargo/registry/cache` | 共 **430 个 crate 包**，但 M1 需要的 **几乎都没缓存**：`rawler` ✗ `rusqlite` ✗ `libsqlite3-sys` ✗ `jxl-oxide` ✗ `image` ✗ `kamadak-exif` ✗ `notify` ✗ `qoi` ✗ `webp` ✗ `mozjpeg` ✗（仅 `walkdir` ✓ `zerocopy` ✓） |
| pnpm store（`~/.local/share/pnpm/store/v11`） | `ark-ui` ✗ `tabler` ✗ `tanstack` ✗ —— **全需下载** |
| 磁盘 | `/` 余 **137 GB** ✓ 充裕 |

### 1.3 关键依赖的体量

| 依赖 | 规模 |
| --- | --- |
| `@tabler/icons-solidjs` 3.46.0 | **解包 19.3 MB**（6000+ 图标，每个一个模块） |
| `@ark-ui/solid` 5.39.2 | 解包 1.51 MB，但**直接依赖 69 个**（其中 `@zag-js/*` 占 **68 个**）→ 连带体量远大于本体 |
| `rawler` 0.8.0 | **直接依赖 27 个**（含 `jxl-oxide`、`image`），传递依赖树更大 |

## 二、M1 各环节的外部依赖清单

| 环节 | 需要下载 | 估算体量 | 有无限定条件 |
| --- | --- | --- | --- |
| **M0-6 前端虚拟化 spike** | **零新增依赖** —— `DESIGN.md` §10 明确要求「手写最小虚拟化网格，**不引入任何组件库**」 | **0** | 无 |
| **M0-4 存储 spike** | `rusqlite`（`bundled` 特性）+ `libsqlite3-sys`（内含 SQLite C 合并源码） | **≈ 3 MB** | 无 |
| **M0-5 缩略图 spike** | `image` + 编码器（webp / jpeg / qoi） | ≈ 10–15 MB | 部分依赖 A3（要真实 RAW 才有意义，但可用合成图先跑通） |
| **M0-3 RAW spike** | `rawler` + 传递依赖树 | ≈ 30–60 MB（估） | ⛔ **硬阻塞：缺 RAW 样本（`ASSISTANCE.md` A3）** |
| **M1 UI 实现** | `@ark-ui/solid`（+68 个 `@zag-js/*`）、`@tabler/icons-solidjs`（19.3 MB）、TanStack Virtual、i18n | **≈ 35–45 MB** | 无（设计稿已定，实现期才需要） |
| 字体（Inter + Noto Sans SC） | 字体文件 | Noto Sans SC ≈ 10–20 MB | 无（可先只用系统字体） |

**合计**：若一次全下 ≈ **90–140 MB**，按实测 1.62 MB/s 约 **1–1.5 分钟**下载。
但**真正的成本不是下载，是首次编译**：rawler（含 `jxl-oxide`）+ SQLite C 源码的编译
在 WSL 侧预计 **5–15 分钟**（一次性）。

## 三、结论：**可以开始，但要分段下**

### 立即可做（下载量 < 5 MB，无外部样本依赖）

| 环节 | 说明 |
| --- | --- |
| **M0-6 前端虚拟化 spike** | **零新增依赖**，用现有 Solid + Tailwind 就能开工。这是 M1 与 M2 都要用的 `VirtualGrid`，价值高 |
| **M0-4 存储 spike** | 只需 `rusqlite`（≈3 MB）。这是 M1 的地基：表结构、FTS5 中文、并发、备份全在这里验证 |

**这两项做完，M1 的「数据底座 + 前端网格」两块就都验证过了。**

### 建议延后（等网络空闲时一次性做）

| 环节 | 为什么可以等 |
| --- | --- |
| **M0-3 RAW spike** | **本来就被 A3 卡住**（没有样本无法验证）。等样本到位时连带 `rawler` 一起下 |
| **M0-5 缩略图 spike** | 真正有价值的部分依赖真实 RAW；合成图只能验证编码格式与并发度 |
| **M1 UI 实现** | 设计稿已定，代码还没到写的时候；且这 35–45 MB 是 M1 实现期才需要 |

### 一个立即可做的动作（网络空闲时）

可以在后台先把 cargo 依赖拉下来而不编译：在项目里加好依赖后跑 `cargo fetch`（只下载不编译）。
这样等真要开工时，编译即可，不用边下边编。

  且它们的下载量加起来不到 5 MB —— **不受网络条件限制**
- 真正需要大流量的 M0-3 本来就被 A3 卡住，网络恰好不构成额外阻塞
