## 一、拿信息：实测与结论

| 做法 | 实测 |
| --- | --- |
| **只读文件头**（JPEG SOF + EXIF 方向） | ext4 **0.022 ms/张**（46,000 张/秒）；`/mnt/c` 9p 挂载 5.35 ms/张（**全是挂载开销**）；PNG（IHDR）0.12 ms/张 |
| 对照：完整解码 | ImageMagick `identify` **220 ms/张**；我们自己的缩略图管线 ≈53 ms/张 |
| **会话级内存缓存**（1000 条） | 冷路径 0.49 ms（含 1000 次读头）、**热路径 0.87 ms**（≈0.9 µs/条） |

**结论（采纳人类判断）**：读头比解码便宜 2–4 个数量级，**不值得为它落盘** →
做**进程内缓存**（不落盘、退出即丢），只解决「反复切目录时重复扫盘」。

* 实现：`crates/raybend/src/media/meta_cache.rs`（`MetaCache`）+ 命令 `dir_meta_ensure`。
* 复用条件两条：① 指纹相同（大小 + 修改时间）② **这条还没超龄**。
* 一处与计划原文的**主动偏离**：计划里「过期 ≠ 全量重扫」与「6 小时是防 100 年不关应用的保险阀」
  这两句互相矛盾（若逐条比对生效，TTL 就永远没有触发点）。我按**意图**实现成
  **逐条年龄**：指纹没变且没超龄 → 复用；超龄 → 即使指纹相同也重读一次。
  于是「反复切目录」仍是快路径，保险阀也真实存在。
* 容量：目录数 / 总条目双上限，按最近使用整目录淘汰（浏览几百个目录也不会无限涨）。

## 二、修掉的 bug（三个是测试自己抓到的）

1. **方向从来没被应用**（人类实测：所有竖拍图都躺下显示）——`render_file` 调
   `render_bytes(bytes, size, None)`，而 `apply_orientation` 早就写好了。
   修法：用**已经读进内存的字节**解析 EXIF（零额外 I/O）后传入；`render_sig` 升到 `v2`
   （像素会变，旧缓存必须失效），并把那条「改算法要升版本号」的守卫改成
   **签名串与 `PIPELINE_VERSION` 互相校验**（只改一处就红）。
2. **3:1 夹取的竖图分支把 `× max_aspect` 写成了 `/`** —— 被纯函数测试当场抓到。
3. **缓存里被复用的条目把 `read_at` 重置了** → TTL 永远不触发（保险阀形同虚设）—— 被测试抓到。
4. **元信息指纹的来源不一致**（读头 vs 目录列表）→ 改为**一律以目录列表为准**。
5. **前端按 `目录/文件名` 拼 key** → Windows 反斜杠下会静默查不到，改为**按顺序一一对应**
   （后端契约本就是「顺序与传入一致」）。

## 三、展示形态（按人类方案落地，含两条批注）

* **正方外框**：边长 = 尺寸档（96…512，9 档）；`Tile` **自己撑成正方形**（不靠调用方给尺寸 ——
  画廊里就因为没给而高矮不一过一次）。行高 = 边长，**信息条是覆盖层、不占高度**。
* **照片保比例居中**：`aspect-ratio` + 短边贴边，四周留 `--tile-pad`；四角圆角（`--tile-radius`，比控件圆角更小）。
* **底部信息条**：文件名（去后缀）+ 扩展名标签 +（库内）加锁位；**覆盖在照片上**，
  锚在**外框**底边、被外框圆角裁到；底纹 = **状态底纹 + 主题中性蒙层**（`--tile-bar-scrim`）。
* **顶部标记区（库内）**：星标（5 颗 / 窄格子退化成「一颗 + 数字」/ 0 星不显示）+ 颜色点 + 旗标。
* **状态**：默认无底纹；库内颜色标记 → 该色低浓底纹；指向 → 辅色底纹 + 两条信息浮出；
  选中 → 主色底 + 信息常亮。库外（导入）不渲染标记区与加锁位。
* **批注「加载中不要内框」已照做**：占位只是一个低存在感的形状，没有第二个圆角矩形。
* **3:1 / 1:3 夹取**：`grid` / `strip` 两档由后端居中裁取；`screen`（看图）**保持原比例** ——
  全景照片在查看器里必须看全。前后端同一个常量（3.0），前端有测试盯着。
