# 直方图改造：52 点 + 单调平滑曲线 + 色标六色显式分层 + 背景等分虚线

完成时间：2026-09-19 18:04:12 CST

## 人类的四条要求

> 1. 从采样加到 52 个点（51 格），即从 0 到 255 每隔亮度 5 取一个点
> 2. 找一个在点与点之间构建平滑曲线的组件来看看效果
> 3. 红黄绿青蓝紫正好与标记的色标颜色一致，使用这套色系；三色相交部分设计一个中间灰
>    （可以偏亮一点），dark 与 light 中都看得清，不要用纯白
> 4. 曲线背后加几条很浅的细密虚线，把背景纵向划成 4 等分、横向划成上下两等分；
>    组件要优化成方便后续编辑时实时调整的状态

## 一、52 个采样点

原先前端向 Rust 请求 **24** 桶（`getHistogram(path, bins = 24)`）。现在：

* `lib/histogram.ts` 新增 `HISTOGRAM_SAMPLES = 52`；
* `getHistogram` 默认值改成 52；看图右栏显式传 `HISTOGRAM_SAMPLES`；
* Rust 侧不用改：`histogram_of_image(image, bins)` 本来就按 `value * bins / 256` 分桶，
  52 桶正好是「每约 5 个亮度级一个点」——**前端仍然不碰像素**（`AGENTS.md` §6.1 的红线），
  只是把「要多少个采样点」说清楚。

## 二、平滑曲线：单调三次插值（Fritsch–Carlson）

人类说「找一个组件来看看效果」。评估结论：**不加依赖**（`AGENTS.md` §2.9 要求先讨论），
自己实现**单调三次插值**——它正是直方图这类数据该用的插值：

* 普通三次样条 / Catmull-Rom 会**过冲**：台阶形的数据会在两点之间冒出比两端都高的鼓包，
  在直方图上看就是「凭空多了一撮数据」，或者曲线掉到基线以下；
* 单调插值用 Fritsch–Carlson 限制器把切线夹住，保证**不越过相邻采样点的高度**，同时仍是 C¹ 连续。

新增的纯函数（都在 `lib/histogram.ts`）：

| 函数 | 干什么 |
| --- | --- |
| `monotoneSlopes` | 求每个采样点处的切线（内部） |
| `fitCurve` | 采样序列 → 三次贝塞尔段（内部，像素坐标） |
| `histogramPath` | 一条通道的**填充路径**（从基线闭合，画「三色重叠」那层用） |
| `histogramBandPath` | 一条**带形**路径（两边界之间，画两两重叠与单通道那两层用） |
| `monotoneSample` | 在同一条曲线上均匀取样（单测用它验证不过冲；将来编辑模块做交互也要用） |

## 三、颜色：色标六色 + 一个中间灰（显式分层，**不靠混合模式**）

原先三条路径用 `mix-blend-screen` 叠着画、通道色是纯 `#FF0000/#00FF00/#0000FF`。
换成色标色（都带灰度）之后，混合模式**混不出规定的黄/青/紫**。所以改成**显式分层**：

```text
每列按高度排序 → 切成三层
  ┌── 单通道（最高那条）            红 / 绿 / 蓝
  ├── 两两重叠（中间那条）          绿+红=黄、蓝+绿=青、红+蓝=紫
  └── 三色重叠（最低那条以下）      中间灰 --hist-triple
```

* 7 个区域**互不重叠**，每层填自己的颜色 ⇒ 颜色就是令牌里那个色，改色标只改令牌；
* 三色重叠的灰**按主题各一个值**：深色 `#A9AFA9`（对面板底 4.6:1）、浅色 `#7E847E`（3.0:1）——
  都是「中等偏亮的中性灰」，**不用纯白**（纯白在深色主题刺眼、在浅色主题与面板底分不开）；
* 单元测试钉住：分层不重叠、上边界不低于下边界、并列时按 r→g→b 固定顺序（可复现）、
  长度不齐按短的截断。

## 四、背景等分虚线

纵向 4 等分（3 根）+ 横向上下 2 等分（1 根），颜色 `--hist-grid`（很浅，从 `--fg-3` 派生的
`color-mix`），线型是「2px 线 + 3px 空」的**细密虚线**。

**用 DOM 而不是 SVG `stroke-dasharray`**：SVG 被 `preserveAspectRatio="none"` 拉伸，
虚线的段长会跟着变形（竖线拉长、横线压扁），DOM 的 CSS 渐变虚线始终是像素级的。

## 五、为「编辑时实时调整」做的结构

新组件 `src/components/ui/Histogram.tsx`：

* **只吃数据**：`bars`（`histogramBarHeights` 的产物，已归一化）；不碰 IPC、不碰 store；
* **没有内部状态**（没有信号、没有 effect）⇒ 每帧重画只是「传一份新 `bars`」，
  不需要重新挂载；
* 绘制数学全在 `lib/histogram.ts`（纯函数、有测），组件只负责把 7 个区域铺成 SVG。

数据获取仍留在看图右栏（`ViewerReadout`）：它把 DTO 归一化后交给组件 ——
将来编辑模块只要握着自己的采样，就能直接把组件挂上去。

## 七、过程记录

  组件保留短名字。
