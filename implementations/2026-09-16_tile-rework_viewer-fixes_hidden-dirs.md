## 一、tile 排版重做（人类：「这块你做一个精细化设计，重新来」）

先说清楚**病根**：一行 tile 的总高算的是 `画面高 + 字幕条`，而画面与容器边缘平齐 ——
于是「图片只有上两角是圆的、下缘是直角，字幕条又被下一行切掉」，看着就是「切开」的。
（这一版把行高公式也改成 `上内边距 + 画面高 + 图文间距 + 字幕条 + 下内边距`。）

按人类点名的四件事逐条落：

| 他问的 | 做法 |
| --- | --- |
| **边角和间距** | 容器四周 `--tile-pad`，图片自己也 `rounded-ui` → **四角一致**；图与字之间 `--tile-gap`；三者在两档密度下都不同（上一版写死 → 紧宽松一个样） |
| **图片信息** | 只显示**文件名（去后缀）** + **扩展名做成标签**（不再是第二行小字重复一遍后缀）。去后缀判据保守：只有「点后 1~5 位字母数字」才当后缀，`IMG.2024.raw` 只去最后一段 |
| **选中状态** | 容器主色底 + **画面外一圈主色细环**（照片是内容，只靠底色在图上分不出来） |
| **未来星标** | 三处扩展位先留好并写进 `design/main.md` §3.2.1：① 画面右上动作槽（排除等）② 文件名行右端（星标/旗标＝属性）③ 画面左下（评级、RAW 配对角标） |

## 二、看图三处（人类实测报的）

1. **左上角返回按钮点了没反应** —— 根因是拖动用的 `setPointerCapture` 把按钮的 `click` 抢走了。
   修法：`pointerdown` 落在 `button/a/input/[role=button]` 上时**不开始拖动**（缩放按钮同理受益）。
2. **看图时按回车应当返回**（设计稿 §3.2：进去用回车、出来也用回车，至少进胶片带之前是这样）。
3. **比例闪一个错数、有时卡住** —— 大图没到之前画面用的是网格小图（长边 384），
   以它为基准算出来的比例是个大数（1200px 视口 ≈ 312%），大图到了才正常；大图一直不到就一直卡着。
   修法：**适配状态只说「适配」**，大图（屏幕档）到位后再补上百分比；用户自己缩放时报的是
   「相对当前显示这张图」的比例，始终是真的。
4. **两个悬浮件改为靠近角落才出现**：返回按钮约 120px 内、缩放指示约 200px 内，
   离开即隐藏；键盘可 Tab 到（聚焦时也显示）。

## 三、隐藏目录不显示

`.git` 这类点前缀**本来就跳过了**；漏的是 **Windows 的隐藏属性**（在 Windows 上「隐藏」
多半靠属性而不是点前缀）。新增 `media::kind::is_hidden_name` / `has_hidden_attribute`，
目录树（`list_dirs`）与照片扫描（`scan_photos`，在没开 `include_hidden` 时）都用上；
属性判据只在 `cfg(windows)` 下花一次 `metadata()`，其它平台零成本。带单测。

## 四、tiles 里方向键移动选中

左右一格、上下**整行**（列数由换行算法给出），到头**停在原地**（不绕到另一端）。
几何算在纯函数 `lib/tile-flow.ts::nextIndexForArrow` 里并单测（含空列表/无效起点/列数为 0）。
不支持 `Ctrl`/`Shift` 组合（人类明确说可以先不支持）。移动走 `clickItem(.., "replace")`，
锚点跟着走 —— 这样随后按 `Shift` 的语义才对得上。
