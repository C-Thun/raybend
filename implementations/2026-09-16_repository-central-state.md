# 库的中央状态（一个地方变更，所有界面同步）+ 移除按钮不选中 + 滑块落盘时机

完成时间：2026-09-16 16:16:26 CST

## 一、中央状态（人类 2026-09-16 的诉求）

> 「像库这种明显数据量是有限的资源，一律进此状态库，这样可以实现一个地方变更了状态，
> 所有挂在这套数据上的界面都会同步变更，不然你一个一个地方盯怎么可能做得好。」

**现象**：把库目录改名模拟拔盘后，点库设置 → 设置窗口去读 `catalog.db` 失败、**它自己知道离线了**；
而外面那张库卡片**还写着在线** ✗ —— 因为库的状态被存了两份（工作区 store 一份、对话框自己取一份）。

**做法**：新增 `src/features/repositories/state.ts` —— 库的中央状态。

* **有限数据进这里**（库；以后的标签词典同理）；**照片列表这类无限增长的不进**（按目录走各自视图）。
* 所有改动只经由它：`load / patch / upsert / markOffline / remount / setTemplate`，
  界面只读它的信号 → 「一个地方变了，全都变」是**结构上成立**的，不靠自觉。
* `patch` 是**就地**的：只换那一行对象，别的行连引用都不动（避免白重渲染）。
* **关键那条**：库设置读 catalog 失败时会调 `onStale` → 外面转成 `markOffline` →
  **列表卡片立刻变离线**，与设置窗口里显示的是同一份状态。
* 工作区 store 不再自己存库列表，改为**转发**中央状态（对外 API 不变，所以调用方零改动）；
  新增 `markRepositoryOffline` / `applyRepositoryTemplate` 两个入口给界面用。

测试：新增 `src/features/repositories/state.test.ts` 11 条 —— 就地更新、别的行引用不变、
`markOffline` 立刻降级且保留「上次已知路径」、重挂载成功/找不到/报错三条路径、模版改了列表立刻同步。

## 二、移除按钮不该顺带选中（人类 2026-09-16）

「移除是移除，选中是选中，选中要点没有操作图标的部分。」

修在**原语**里：`RemoveButton` 自己 `stopPropagation`（不是每个调用点各加一次 ——
这类按钮出现在行内、卡片标题旁，漏一处就复发一次）。同时把它的 `onClick` 类型收窄成普通函数
（原生 `onClick` 的联合类型在包一层之后没法安全调用，而调用方传的都是函数）。

> 我顺手往浏览器冒烟里加了一条「点勾选圈不选中行」的断言，**试了两版都很脆**
> （演示里起始只有一行、且那一行本来就是选中的，测不出因果）→ **按止损原则撤掉**，
> 判据留在原语层。（教训记在下面第三节。）

## 三、尺寸滑块「非常卡」：时间盒内找到一处明显该改的

* **明显的浪费**：滑块每动一格都写一次设置 → 一拖就是**几百次 IPC + 几百次数据库写**。
  改成**拖拽结束才落盘一次**（`Slider` 暴露 `onValueCommit` ← Ark 的 `onValueChangeEnd`；
  store 拆成 `setTileStep`（只改状态）与 `commitTileStep`（落盘））。测试跟着改成
  「拖动中不写、commit 后写」。
* **剩下的成本如实登记**（`FUTURE.md` C5）：改尺寸会让 tile 流重新分组 → 可见行的行对象重建 →
  DOM 重建（图片命中缓存、不重新解码，但布局绘制是真的）。可能的做法与**不能简单替换**的原因
  （行种类混排，按键位复用会把标题行复用成 tile 行）都写在那里了。人类说了「没有明显可改的就先算了」。

## 四、踩到的坑（自记一笔）

* 冒烟脚本的**自检**（禁止注释里出现反引号，因为会截断 `evaluate` 的模板串）**抓到了我自己** ——
  我在块注释（`/* */`）里写了反引号 ✗。原来的自检只扫 `//` 开头的行，所以是个盲区；
  我试着把判据放宽到「缩进的注释行」（想覆盖块注释），结果把文件头那段说明也扫了进去 → 误报 21 处 ✗。
  **回退成原来的判据**，并在提示里补了一句「块注释同样会截断」。
  —— 教训：这道守卫已经够用，别为了「更聪明」把判据做肥。
* 我自己加的冒烟断言连续两版都很脆 → 撤掉，不在浏览器里验这条；判据落在原语层。
