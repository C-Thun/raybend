# 命令面板翻页/配色 + 直方图等分线（T1–T8 之后的追加反馈）

完成时间：2026-09-24 01:09:51 CST

> 崔总 2026-09-24 三条真机反馈（接在 T1–T8 之后）：
> ① `Ctrl+K` 除 ↑/↓ 外还要支持 `PageUp`/`PageDown`；
> ② `Ctrl+K` 列表配色：能用的要亮（高反差），不能用的别叠到看不清；
> ③ 直方图等分线：再细一点、要压在峰值图**背景**上、确认是四等分（看着左右不匀）。

## 1. 命令面板：PageUp / PageDown 翻页

* `features/commands/palette.ts` 新增纯函数 `pageStep({ listHeight, rowHeight, fallback })`：
  一页 = 列表可视高度 ÷ 光标那行的高度，**除不尽向下取整**（宁可少跳一行）；
  量不到高度（列表没挂上 / 高度为 0）退回保守值 10。
* `CommandPalette.tsx`：`move()` 放宽为任意步长；`PageDown`/`PageUp` 走 `pageSize()`；
  滚动跟随复用既有的 `scrollIntoView({ block: "nearest" })`。
* **接入评估（`AGENTS.md` §2.15）**：这是**面板内部键**（与 ↑/↓/`Enter`/`Esc` 同类，
  `DESIGN.md` §13.7 的「内建键位」）——**不进命令注册表、无默认热键**：
  它只在面板打开时成立，没有「改键」的语义。
* 验证：`palette.test.ts` 两条 `pageStep` 单测（含除不尽、量不到两种边界）；
  `check:browse` 新增「按 PageDown 至少前进一屏（>1 行）且选中行仍在可视区」断言。

## 2. 命令面板：行字色只分两档（按 DESIGN 标准档位）

* 旧实现：可用行 `fg-2`（次级）、不可用行 `fg-2 + opacity-50`（两级降下来低于可读线）——
  崔总原话：「根本看不清，能用的就亮出来不好吗」。
* 新实现（`DESIGN.md` §13.7 已补记这条口径）：
  * **能用** → `fg-1`（正文/标题级，高反差）；
  * **不能用** → `fg-2`（§5 的 disabled 规则「前景降为次级色，面不变」），
    原因文字同样用 `fg-2`（它是解释，不是装饰）；
  * **不许在行上叠 `opacity`**；指向/光标的区别由**底色**（`state-hover`）表达。
* 验证：`check:browse` 新增颜色断言（期望值从令牌现算，不写死 rgb）：
  可用行 = `--fg-1`、不可用行 = `--fg-2`、不可用行 `opacity === "1"`。

## 3. 直方图等分线：更细 + 在背景上 + 四等分对齐

三处修改（`components/ui/Histogram.tsx`）：

1. **更细**：虚线图案 `2px 亮 + 3px 空` → `1px 亮 + 2px 空`（平铺尺寸 5px → 3px），更细更密；
2. **在曲线下面**（崔总：「位置要在峰值图的背景上，不是盖在峰值图上」）：
   去掉网格层的 `z-10` —— 它在 DOM 里排在 SVG **前面**，同层级下后画的上，
   于是虚线只在曲线的透明处露出（背景纹理）；最上面的亮度指示线（`z-20`）不受影响；
3. **四等分对齐**：旧写法 `left: 25%` 是**左边缘**贴 25%，1px 线占 `[25%, 25%+1px]` →
   四格变成 `25% / 25%−1px / 25%−1px / 25%−1px`（左边那格天然宽一格，正是「左右看着不匀」的来源）。
   改用 `-translate-x-1/2` / `-translate-y-1/2` 把**中心**对到 25/50/75% 与 50%。

验证（`check:browse` 新增）：

* 等分线的 `backgroundSize` 必须含 `3px`（沿用「可平铺」那条判据）；
* 三根竖线的**中心**与 25/50/75% 的偏差 ≤1px；横线中心在高的 50%（±1px）；
* 网格层无 `z-index` 且排在 SVG 前面（DOM 顺序判据）。

## 4. 顺带记一笔：Vite dev server 转换缓存坏掉

改完 `Histogram.tsx` 后 `check:browse` 报
`does not provide an export named 'Histogram'`，而 `tsc` 干净、源文件导出正常 ——

下次遇到「源码没问题但浏览器说导出缺失」先 `curl` 那个模块看服务端给了什么。
