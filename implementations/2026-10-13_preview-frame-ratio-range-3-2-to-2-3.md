# 总览框比例范围重新约定：3:2（最矮）～2:3（最高）

**完成时间**：2026-10-13 12:32:27 CST（崔总 2026-10-13 重新约定；随后确认「就按你想法做」= 采用下面的信息态规则 A）
**位置**：`src/lib/preview-frame.ts`（唯一参数）为主；`src/features/editor/layout.ts` 为受牵动的唯一实现

## 一、需求（崔总原文要点）

* `PreviewFrame` 是**统一组件**：宽度受所在栏（browse 右栏 / editor 左列）约束，
  **只有高度**会被内部图片撑开 —— 所谓「比例变化」就是改高度。
* 比例范围重新约定：**高度最小 = 3:2，最高 = 2:3**（标准相机画幅必须完整落在低端之内）；
  超出范围的图**保持框高**，左右或上下留白。
* 栏宽可调不需要专门考虑（免测），但**设计上要支持**。

## 二、差距分析（除数值外）

| 问题 | 现状 | 结论 |
| --- | --- | --- |
| 宽度受栏宽约束、只有高度随图走 | `w-full` + `aspect-ratio: clamp(w/h)` → 高度 = 宽 / 比例 | ✅ 机制本来就一致 |
| 超出范围留白 | 外框按夹取后的比例定高；图用 `fitPreviewSize`（按**真实**比例）等比缩入、居中 | ✅ 一致 |
| 栏宽可调（设计支持） | 内容盒尺寸由 `ResizeObserver` 实时量，宽度一变高度跟着变 | ✅ 天然支持，无需改 |
| 比例上限 | 旧值 3:1 / 3:4 | ❌ **数值差**，本次改 |
| 编辑左列底部高度 | 旧公式按 3:4 上限写死（`宽/1.5 + 70`、信息态固定 472） | ❌ **唯一的实质耦合**：新范围下纵向图总览可达 `宽×1.5`，旧公式会让「切到信息反而变矮」 |

结论：**除数值外差距不大**，但有一处必须一起改（否则新范围会引出新的视觉 bug）。

**信息态规则 A**（崔总确认）：
`信息态高度 = max(总览态, min(总览态 × 1.8, 左列 60%))` —— 升高 80%，但最多占左列 60%（上面的列表留地方），
且绝不比总览矮（纵向照片的总览本身就可能很高）。
