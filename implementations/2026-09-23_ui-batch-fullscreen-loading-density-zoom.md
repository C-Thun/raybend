## 1. 全屏看图（`fullscreen`）

### 1.1 载入遮罩 + 载入期间封锁输入（人类：现在卡几秒什么提示都没有）

* **遮罩**：无边框毛玻璃（`backdrop-blur-md` + `bg-surface-layer/70`），中间浅色字 + 浅色动图 + 「载入中」（`fullscreen.loading`）。
  触发条件是 store 的 `imageStatus() === "loading"` —— `loadFor` 第一件事就置它，所以是**立即**出现，不是等超时。
* **封锁**：除 `Esc` / `Enter` 外一律不响应 —— 拖动、滚轮、`←/→`、`PgUp/PgDn` 的处理器全部先看 `busy()`。
  理由（人类原话）：「连按方向键时如果还继续换图，就是在还没看到上一张的情况下又发下一张的请求」。

### 1.2 进入速度（人类：一半黑 → 全黑 → 出图，还有白框闪）

三处改动，对应三个成因：

1. **建窗即带几何**：`position` / `inner_size` 在建窗时就给（用监视器自己的 `scale_factor` 把物理值换成逻辑值）——
   不先给尺寸的话，窗口会以默认尺寸出生在主屏、露一下再被挪过去并放大，那两下就是「一半黑 → 全黑」。
2. **窗口底色**：前端把 `--surface-track` 的计算值随 `fullscreen_open` 报给 Rust，设成窗口背景色 ——
   WebView 首帧是白的，不设就闪白框。
3. **`Esc` 只隐藏不销毁**（`hide()`）：销毁后下次要重新建窗 + 重新加载页面（几百毫秒），隐藏则下次 `show()` 是**瞬间**的
   （页面、图像缓存、清单都还在）。代价是一扇闲置 WebView 常驻内存 —— 换「秒开」值得，它不在任务栏里。
   `Alt+F4` / 系统方式关掉时窗口**真销毁**，下次打开走建窗那条路（两条路都处理了）。
   顺带解掉「按 `Esc` 后立刻再点全屏没反应」那类竞态（不再有「标签正在释放」的窗口）。
   页面侧补一条 `visibilitychange` 重读清单（隐藏期间 WebView 可能被挂起），版本号守卫保证重复应用无害。

### 1.3 邻图预载（人类：每浏览一幅图，后台对前后两张预载）

当前那张**就绪之后**才预载前后各一张（`store.ensureImage`，复用现有图像缓存）——
不抢当前这张的带宽/解码（RAW 解码在 Rust 侧是串行的）。全屏页的 `cacheLimit` 提到 6，
否则刚预载好的邻居会被挤出去，预载就白做了。

### 1.4 `F11` 热键 + `Ctrl+K`

* 命令 `viewer.fullscreen` 的默认键 **`F11`**（`normalizeKey` 原生支持 F1–F12；不是保留键）。
* `Ctrl+K` 面板直接吃命令注册表 —— 加了命令就自动收录，不用另登记（已确认 `CommandPalette` 的实现）。
* `keyLabel` 补了 F 键大写（`f11` → `F11`），否则快捷键面板里会显示小写。

### 1.5 术语与纪律（人类要求写进 AGENTS.md）

* §11 术语表新增 **`fullscreen`**（并注明与主窗口的 view / film / compare 是两回事）与 **`shortcut`**。
* §2.15 补强：**热键是「新增功能」这一步的必选项**，不是事后审计 —— 每条新命令必须在同一次改动里给出
  `defaultKey` 或**明确留空并写理由**；选键前过冲突/保留规则；键位文案走 `keyLabel` / `formatChord`。

## 2. 载入动画改成「流光」（途中追加）

**问题**：原实现是 `StateWatermark` 里一条半透明渐变**方块**从整块上扫过 —— 人类：「不是给文字和图案加一个渐变的方块背景，太丑了」。

**做法（内容画两遍）**：底下画一遍常态浓度，上面再画一遍**亮一档的同内容**，
用移动的 `mask-image`（`rb-shimmer-mask`，1.9s 线性循环）把上面那遍裁成一道扫过的光带 ——
变亮的是**字与图案自己的笔画**，不是盖在它们上面的渐变。

* ⚠️ 代价：`icon` 必须传**新造的 JSX**（内联写法），不能传存起来的元素对象（那样两遍会抢同一个 DOM 节点）。
  冒烟有断言盯着：流光层里**必须有图标**（`[data-watermark-shimmer] svg`）。
* 减少动态效果：流光层**整个去掉**（停住会变成「随机一块变亮」）。
* **browse 的读库载入**也用它，并加 **1500ms 保底**（人类建议的口径）：1.5 秒内出图就完全不显示水印；
  import 的目录扫描保持默认 120ms（它本来就快，慢的时候才值得看）。
* 陈列室新增「状态水印」示例（`delayMs={0}`），冒烟在那里断言（应用外壳页的 import 网格在浏览器里是**空态**水印，没有流光层）。

## 3. 直方图：回到「固定色」两套逻辑（人类：怎么会变成粉色和绿色）

**根因**：上一版我给的是 `lighten`（逐通道取最大值）→ 红+蓝 = **粉**、绿+蓝 = **青**。
人类指出原设计（GPT 那批）是**固定色**，我「只该改个色」。

**恢复并改良**（`289cd06` 删掉的那套 `histogramBands` 是切 7 块硬填，边界处有细缝 —— 那正是当年「覆盖区域出现空白」的原因）：

* 全通道（默认）→ **7 条从基线到自己包络的路径**，按 `r → g → b → rg → gb → rb → rgb` 顺序画（后画盖前画）：
  某一列某个高度上，**最后画到那儿的层**就是那一处的正确区域 —— 与「切 7 块」视觉等价，但**没有接缝**
  （相邻区域之间不存在两条各自抗锯齿的边界）。
* 颜色**全部来自令牌**（单通道/两两重叠用色标六色，三色重叠用恢复的 `--hist-triple`）→「改色只改令牌」。
* 点亮单通道 → 3 条通道 path **自然叠加**（选中在前、另两条 0.24），**同样不用混合模式**。
* 单测锁住语义：`histogramRegionAt`（7 种通道组合 × 若干高度，判出来的区域必须对）+ 绘制顺序常量。
* `check:browse` 更新为两套断言：全通道 = 7 块（7 个不同 fill、`mix-blend-mode` 全是 `normal`）；
  点亮单通道 = 3 条 `histogram-channel`（有 0.24 的半透明、也不许有混合模式）。

## 4. 密度（紧凑/宽松）统一 + 滚动条落进预留空间

### 4.1 密度

人类：「只有 import 右列在宽松下变了，browse / editor 都没变，这宽松了个啥」。根因：browse 的信息面板写死 `p-2`、editor 右列没有密度 padding。

* 三处右列的横向 padding 一律走**密度令牌**：`pl-panel-pad` + `py-panel-pad`；
* 新增 `--panel-pad-scroll`（= `--panel-pad` − 4px，紧凑 2 / 宽松 8）给**滚动侧**用。

### 4.2 滚动条（新增全局规则 DESIGN.md §8.9）

人类口径：滚动条必须**直接纳入预先设计的空余空间**，不能让它的出现改变内容区尺寸。

* 新类 `.scroll-y-reserved`（`overflow-y: auto` + `scrollbar-gutter: stable`），并写进共享的 `ScrollBox` ——
  一处生效，全应用受益。
* **实测证据**（Chromium，容器 308px + `padding-right: 8px`）：`stable` 下无滚动条与有滚动条的 `clientWidth`
  **完全相同**（293 / 293）；不用它是 **308 / 293** —— 那 15px 就是「跳一下」的来源。
* 滚动条画在 padding **之外**（贴外缘），所以 padding 就是「内容 ↔ 滚动条」那道空隙；
  滚动侧小一点（人类允许「有一点不平衡」）。
* 冒烟新增断言：右栏信息面板的 padding 在紧凑 / 宽松下必须**变大**、且**右侧更小**、容器带 `stable`
  （实测：紧凑 6/2 → 宽松 12/8 ✓）。

## 5. tiles / film 的 17 档重排（人类：最大档 −20%，过渡更平滑）

| | 旧 | 新 |
| --- | --- | --- |
| tiles（`TILE_SIZE_STEPS`） | 128–400，每级约 +7.4%，默认 260 | **128–320**，每级约 **+5.9%**，默认 **254** |
| film（`FILM_STRIP_TILE_HEIGHT_STEPS`） | 96–240，**等差** +9px，默认 132 | **96–192**，**等比 +4.4%**，默认 **130** |

* 两表都改成**等比阶梯**（与 tiles 原有的风格一致 = 一套阶梯语言）；旧表保留在 `LEGACY_TILE_SIZE_STEPS` 里，
  存过的档位下标仍按**尺寸最接近**换算（`migrateTileStepIndex`），老用户不会忽然变小。
* **自适应宽度夹上限**：算出来的格宽 > `MAX_TILE_SIZE`(320) 时，`canFitRow` 为假 →
  网格回填 `TilesFitChannel.available` → 状态条的「横向适合窗口」按钮**禁用**（`data-fit-available="no"`）。
  那时只有「少放几列」才铺得满，而列数不能为了铺满凭空改（网格会跳一次列）—— 老实禁用比「按了没反应」诚实。
  网格侧还有第二道闸（超过就什么都不做）。
* `check:browse` 里所有旧表硬编码期望（胶片带默认档/拖动/滚轮/落盘、直方图 path 数）都已按新规格更新；
  「点轨道还原档位」改成**拖回**（点轨道的 x→档位映射差零点几档，整数档下蒙对了、小数档下就露馅）。

## 归人类真机验收

1. **全屏**：一按就进（不该再有一半黑/白闪）；切图时遮罩立即出现且此时拖动/滚轮/方向键都不响应，只有 `Esc`/`Enter` 能退出；
   连续看图的第二张起应基本秒开（邻图预载）；`F11` 与 `Ctrl+K` 里的「全屏看图」都能进；多屏时落在主窗口那块屏。
2. **载入流光**：import 扫描慢时 / browse 读大库超过 1.5 秒时，看那道光是**在字与图案上**流过（不是一块渐变方块）。
3. **直方图**：全通道下交叠处只应是固定色（黄/青/紫/灰），**不该再出现粉色或绿色**；点亮单通道时才是三条自然叠加。
4. **密度**：切宽松档，browse / editor 右列的内容 padding 应当跟着变大（与 import 一致）；滚动条出现时内容不该跳。
5. **缩放**：tiles 与 film 的最大档都小了 20%；拖动滑块相邻档的跳跃感更小；
   窗口很宽 + 照片很少时，「横向适合窗口」按钮应当是**禁用**态（而不是按了没反应）。
