# M1-7 步骤 2：崩溃恢复演练（顺带修掉一个真 bug）

完成时间：2026-09-16 12:41:24 CST

## 做了什么

一条可重复执行的命令：

```bash
pnpm crash:drill        # = bash scripts/crash-drill.sh [工作目录] [张数] [杀在第几张]
```

它按顺序做四件事：

1. **造数据**：建库 + 造 600 张合成源文件（每张 24 KB，内容里写着自己的序号）；
2. **真导入 + 中途硬杀**：导入进程里起一个「杀手」线程盯着 `import_items` 里已提交的张数，
   到数就 `libc::_exit(137)` —— 与 SIGKILL 等价（不跑析构、不刷缓冲、不给 SQLite 收尾的机会）。
   用「盯进度」而不是「sleep 之后 kill」，是为了杀在**确定的**进度点上，可重复；
3. **崩溃现场检查**：库还能开吗？账与盘对得上吗？
4. **续跑同一批**：不重复、不覆盖、半成品续上。

跑完的状态：

```text
══ ③ 崩溃之后
  ✓ 崩溃之后库仍能打开
  ✓ PRAGMA integrity_check 通过（WAL 重放没留下坏账）
崩溃现场：未收尾批次 1 个 / imported 106 / pending 494
  ✓ 留下了「没收尾」的批次（state=running）—— 这是恢复的抓手
  ✓ 确实崩在中途（既有已入库的，也有没做完的）
  ✓ 库里标记为「已导入」的照片在磁盘上都在（没有只记账不落盘）
  ✓ 磁盘上没有库里不认识的孤儿文件
  ✓ 半成品能被 stale_pending 认出来
══ ④ 续跑
  ✓ 未收尾批次仍留着 running 标记（界面靠它提示「上次导入被中断」）
  ✓ 未收尾批次的 pending 行留着（这是续跑判「自己占的位置」的凭据）
  ✓ 续跑没有产生失败项
  ✓ 磁盘上没有任何一张照片出现两次（按内容核）
  ✓ 每张源照片在库里都恰好有一份（不丢也不多）
  ✓ 磁盘文件数与库里的目标路径数一致
  ✓ 磁盘上没有重复照片（每个目标只有一份）
  ✓ 磁盘与库里一一对应（既无孤儿也无缺账）
  ✓ assets / asset_files 与磁盘文件数对得上
```

## 演练抓到的真 bug（已修）

**症状**：崩在「文件已复制到目标名、但那一行还没提交」的瞬间时，重跑会**在库里多出一份**
——旧那份留在 `photos/` 里，库里却不认识它（成了孤儿），新那份才是登记过的。
提交是每 200 张/500 ms 一次，所以最坏情况下一次崩溃能留下上百个这种文件。

**根因**（两处，缺一不可）：

1. `runner.rs` 里判断「这条半成品是我们自己留下的」时，拿 `import_items.source_path`
   （**绝对路径**，`sink.rs` 写进去的）去比 `SourceFile.rel_path`（**相对**路径）——
   永远不相等，于是「续跑落回原名字」这段逻辑在真机上一直是**空转**的；
2. 就算比对了，规划器也只是「撞名时才复用」，而崩溃后计数器已经前进（本次演练里
   从 600 继续到 601），同一张照片自然会被编到**新名字**上。

**修法**：

- `runner.rs`：改比绝对路径；并把「上次真的把文件放到那儿了（大小相符）」的痕迹同时交给
  规划器一份（`plan::Adopt`：源文件 → 上次的目标）；
- `plan.rs`：组长渲染目标名时，若该源文件有 `Adopt` 记录就**直接沿用**（不再消耗序号）。
  runner 本来就有「目标在且大小相符 → 直接登记、不重拷」的分支，所以名字复用上之后，
  重复副本就不会产生。

**证据**：修复前 `磁盘 601 / 库里 600`（1 个孤儿）；修复后 `磁盘 600 / 库里 600`，
且「按内容核」的断言 —— **没有任何一张照片出现两次、每张源照片恰好一份** —— 全过。

## 测试

- 新增/改写的单元测试：`stale_pending_items_are_registered_without_copying_again`
  的夹具改成**绝对路径**（与真 sink 一致 —— 旧夹具用的是相对路径，正是它掩盖了 bug 1），
  并加断言「只允许 `MYa.jpg` 这一个名字，不许再编一个出来」；
- 该测试本来覆盖不到 bug 2（它没让计数器前进），所以真正守住这两点的是本演练。

## 关于「未收尾批次永远留着」

这是**有意设计**，不是缺陷：重启后界面靠 `import_runs.state='running'` 提示
「上次导入被中断」（见 `src-tauri/src/import.rs` 文件头），而它的 `pending` 行是
「这个位置是我们自己占的」的凭据 —— 续跑不加 `_01` 就靠它。
界面上的那个提示弹窗**还没做**（`importInterrupted` 命令已就绪，前端只包了 api 层），
属于后续界面工作；本次把这条**当作契约**断言下来，避免以后误当成 bug 删掉。
