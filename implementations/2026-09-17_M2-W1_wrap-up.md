## 一、一键脚本（7.6）

`pnpm spike:win` 四步，把人的操作压到「点几下 + 填两格」：

1. `pnpm build` —— **先重建 `dist`**（它是编译期嵌进 exe 的；忘了就让人拿着旧界面白测一轮，`AGENTS.md` §5.3 第 7 条的血教训）；
2. Windows 侧 `cargo build -p raybend-desktop -p raybend --features custom-protocol`
   （产物落 `C:\rb-target\raybend`；跨 WSL→Windows 的环境变量走 `WSLENV`；UNC 路径从 `WSL_DISTRO_NAME` 拼）；
3. `pnpm check:win` —— 既比时间也比内容，不合格**不许往下走**；
4. 带 `RAYBEND_SPIKE=1` 启动 exe（应用启动时自动开出 spike 窗口）。

另有 `--dry-run`：只做前三步、不开窗 —— 给自己验证这条路径用（免得为确认脚本没写错而在别人桌面上弹窗）。
失败时每条都打印**下一步怎么办**（而不是只报个错）。

## 七、这一批的教训（写下来）

1. **`git add -A` 在并行会话的仓库里是危险的**：这次把另一个会话正在做的 `website/`（软件主页）
   整目录扫进了提交。已 `git reset --soft` + `git restore --staged` 撤回，**对方文件一个字节没动**，
   重新提交时只按明确路径 add。以后一律按路径 add，并在提交前用 `git status --short` 核对暂存清单。
2. **离屏冒烟的价值在这两批里体现得很直接**：它抓到了「纹理绑定可见性漏了 VERTEX」与
   「WGSL `vec3` 的 16 字节对齐让 uniform 变成 96 字节」两个**只会在真跑时炸**的错 ——
   否则就是当着人的面白屏。
