# 三件事：最近目录的挂载检测、密度响应审计、基础看图

完成时间：2026-09-16 17:48:02 CST

人类出门前交代的三件（并说明「暂不进规划，等回来看是否开 M2 plan」）。

## 一、「最近」目录也可能未挂载（启动认一遍 + 每次选中再查一遍）

原话：*「recent 目录也有可能未挂载，要做处理，除了启动时要识别出哪些未挂载把颜色标灰以外，
每次重新选中时也要检测一遍有没有挂载」*。

* **后端**：`raybend::media::source::paths_are_dirs(&[String]) -> Vec<bool>` ——
  **一次问一批**（启动时几十条，一条一个 IPC 是浪费），判据很轻：`is_dir`，**不读目录内容**
  （网络盘掉线时立刻失败，不会像 `read_dir` 那样卡住）。新增 Tauri 命令 `source_paths_status`。
* **前端**：store 里存一份「找不到」的路径集合（大小写折叠，与 `samePath` 同口径）：
  * `hydratePreferences()` 时**整批查一遍**（启动即标灰）；
  * `selectDir(path)` 时**重查这一条** —— 盘可能刚插上，也可能刚拔掉；
  * 查不动（命令报错）**不打扰用户**，保持上次判断。
* **界面**：灰化 + **常显**的 `folder-off` 图标 + 悬停提示。
  一开始我把图标放进「悬停才出现」的区域里了 —— 那等于没标灰（人类要的是「标灰」），已改。
* 测试：crate 里两条（含**改名 = 拔盘**的往返）、store 里三条（启动识别 / 选中重查 /
  查不动不炸）。

## 二、密度响应审计：卡片 + 「有没有别的盒子也没响应」

人类原话：*「库卡片没有实现紧凑和宽松的变化，同步检查有没有其他 box 类整体组件没有响应宽松变化的」*。

**先做了系统核对**（而不是逐个眼睛看）：

1. 把两个密度块的令牌集合对了一遍 → 抓到**两个变量只写在紧凑块里**：
   `--dialog-pad`（弹窗内边距）与 `--selected-max-h`（已选目录高度上限）——
   **宽松档下它们是空值** ✗：弹窗会一点内边距都没有、已选目录的高度上限失效。
   修法：挪进**不带属性**的公共 `:root`（它们本来就跟密度无关）。
   （第一版我把它们放进 dark 主题块了 —— 同类错误换了个维度，被新写的测试当场拦住。）
2. 核对「定义了但组件完全没用到」的尺寸令牌 → `--btn-pad-x/y` 没人用，
   因为我上次修「按钮文字上移」时把高度写死成 `h-6/h-7` —— **两档一模一样**。
   修法：新增 `--btn-h-sm/md`（24/28 与 28/34），按钮高度与横向内边距都走令牌。
3. **卡片**：内部间距改走 `--pad-x` / `--gap`（6↔12、3↔6），高度本来就取 `--card-h`（52/60）。

**新增 `src/styles/tokens.test.ts`** 三条结构性检查（这类错在紧凑档下完全看不出来）：
两档令牌集合必须一致；该随密度变的必须**真的不同**（列了「故意同值」的白名单：
圆角、开关、勾选框、移除按钮、滚动条、面板宽 —— 都有各自理由）；
与主题/密度无关的令牌必须定义在不带属性的 `:root` 里。

**冒烟实测**（直接在浏览器里量）：切密度前后库卡片高度 `52px → 60px` ✓。
这条断言从此盯着「卡片不跟密度走」这个回归。

## 三、基础看图（纯前端，不含胶片带）

人类原话：*「双击/回车等放大查看图片的功能，先做一版基础的出来（不带胶片带版本），
这块不涉及 rust 原生，只用前端技术做，做的时候为后续的功能要考虑到扩展性，
同时注意执行效率，避免卡顿」*。

* **状态与视图分离**（为扩展性）：`viewer/store.ts` 只管「看哪张、缩放多少、平移多少」，
  `viewer/Viewer.tsx` 只管画。日后加胶片带 / 对比 / 评级是**往 store 加状态**；
  M2-W3 换 wgpu 渲染层时**换视图、不换状态**。
* **交互**：双击或选中后回车进入；`Esc` / 左上角返回按钮退出；双击在**适配 ↔ 100%** 之间切换；
  滚轮**以鼠标位置为锚**缩放；拖动平移；`←/→` 翻页（到头停住，不循环）；`+/-/0/1`。
* **执行效率**：变换只走 `translate3d + scale`（合成器干活，不触发重排）；
  滚轮**按帧合并**（高精度触控板能到 100+ Hz，不合并就是每帧重算多次）；
  大图**按需**取：先上网格小图秒显，再换屏幕档大图 —— 换图时按原图尺寸比例换算缩放，
  **画面不跳**。
* **新增缩略图尺度 `screen`**（长边 1920，`AGENTS.md` §6.5 的 SCREEN 档）：
  原先只有 `grid`(384) 与 `strip`(192)，看图会糊。枚举契约测试正确地红了，已同步。
* **测试抓到一个真 bug**：换大图时缩放倍率我写成了**乘**比例，应当是**除**
  （屏幕大小 = 原图尺寸 × 倍率，尺寸变大倍率就要变小）—— 不修的话大图上来画面会突然放大 5 倍。
  另有一条是我自己期望值算错（`clampPan` 的上界）。
* **分层纪律**：`photo-grid → viewer` 被 `lint:arch` 拦下（feature 之间不许直接 import）→
  把看图**归到 `photo-grid` 模块内部**（`features/photo-grid/viewer/`）：
  它本来就是「网格里放大一张」，触发点与显示位置都在网格内；
  出口注释里写明了「日后要做独立模块时，在 `workspaces/` 组合层接线再整体搬出去」。
* **冒烟实测**：打开 → 图片真的加载（`naturalWidth = 1600`）→ 双击 **26% → 100%** →
  再双击回到 **26%** → 滚轮 **26% → 37%**（transform 里能看到平移量随之变化 = 锚点生效）→ `Esc` 关闭。
* `FUTURE.md` 的 G16 已更新：DOM 基础版**已落地**，后续方向（胶片带 / 对比 / wgpu）登记在案。
