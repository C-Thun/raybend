# 补规则：0% 的层点开关打开，强度直接给回 100%

2026-11-01 00:59:36 CST 完成。

## 背景与澄清

上一轮我把规则理解反了：崔总要的不是「0% 的层点开关后得到一个开着但 0% 的层」，
而是**根本不允许「开关开着但强度 0%」这种状态存在**。规则是对称的两条：

| 方向 | 行为 |
| --- | --- |
| 强度拖到 0% 松手 | 自动**关掉该层**（已有，上轮之前就在） |
| 关着的层点开关打开、且强度是 0% | 强度**直接给回 100%**（本次补上） |

两条合起来：开关「开」⇒ 强度一定 > 0。用户不会拿到一个「开着却什么都没发生」的层。

## 改动

- `src/features/editor/store.ts::setLutLayerEnabled`：打开开关时若 `strength <= 0`，
  同一次 `commitChain` 里把强度置 1（一个撤销节点，不是两次写）。
  非 0% 的层完全不变：开关只改 `enabled`。
- `src/features/editor/store.test.ts`：上一轮那条断言写反的用例改正为
  「0% 关掉之后点开关：强度直接给回 100%」，并补「非 0% 的层开关不改强度」。
- `design/editor.md` §3.1.3 与 `specs/editor-lut-chain.md`：把「不允许开着但 0%」写成明文规则；
  上一份实施记录里写反的断言加了更正指引。

## 与上一轮修复的关系

上一轮的两处修改**保留**，它们与这条规则不冲突：

1. **「松手」只认真实手势**（`lib/slider-gesture.ts`）：Zag 的 `onValueChangeEnd` 在外部回灌时
   也会派发，旧接法等于每拖一格都提交一次（拖到 0% 那一格就关层、每格还落一次库）。
   现在只在真正松手（指针松开 / 键盘收尾）时判定 —— 与「一次手势一个撤销节点」一致。
2. **非有限强度不再猜成 100%**：`NaN` / `undefined` 一律忽略，避免任何回灌把强度抬满。

## 验证

- `pnpm test`：**1377 passed / 0 failed**（含改正后的「点开关 0% → 100%」与
  「非 0% 的层开关不改强度」两条断言）。
- `pnpm typecheck`、`pnpm build`、`lint:colors` / `lint:arch` / `lint:i18n`：全绿。

## 遗留

- 外部数据里仍可能带进「enabled=true + strength=0」的层（旧 issue / 预设 / XMP `rb:profileJson`）。
  渲染侧把它当「无效果」跳过（`LutChain::new` 过滤 strength ≤ 0），不会出错；
  界面不会主动制造这种状态，但**打开这条外部数据时不会自动改成 100%** —— 是否需要归一化，
  等真机上遇到再说（会改动已存的编辑栈，不宜默认做）。
- 未经真机验证：点开关后强度跳到 100% 的观感（滑杆是否会给出一个突兀的位移）。
