# 浏览列表实时化 + tile 角标锚外框

完成时间：2026-09-22 16:08:41 CST

两个来自人类的 bug 报告（M3 开工前的收口）：

1. **浏览列表被缓存**：先进 browse、再去导入，新导入的照片不出现在列表里，得重启程序才看得到；
2. **tile 的 `RAW` 角标跟着照片走**：极端比例（1:3 长条）下照片只占外框中间一条，
   角标贴着照片的右下角 → 同一行里比例不同的两张会一个贴外边、一个缩在中间；
   以后左下角还要放编辑 / issue 数标签，几个角各自贴不同的面就收不住了。

## 关键决策

1. **刷新用「无脑重读」，不建第二套真相**（人类 2026-09-22 问过这笔账）。
   先量了成本（`cargo run --release -p raybend --example query-bench`，10 万张挤一个目录）：
   取页 P50 0.46ms + 时间线 P50 100.6/P95 141.7ms + 分面 P50 61.4/P95 79.5ms ——
   即「再付一次进目录首屏的钱」，而真实浏览范围是**一个日期目录**（亚毫秒级）。
   相比之下，`updated_at` / 版本号那类「库变了吗」判定一旦漏埋一处，就变成
   「偶尔不更新」这种最难查的 bug。**所以：每次进浏览都重读，不猜。**
2. **`refresh` 与 `reload` 分开**（不是优化，是语义）：查询变了用 `reload`（清空、选择作废）；
   查询没变但数据可能变了用 `refresh`（保留内容与选择）。否则每次浏览↔导入往返都会
   静默丢掉用户的选择 —— 那是比原 bug 更烦人的回归。
3. **第一页之外的格一律作废**：新照片会把后面的下标整体推移，留着旧页会在滚动时
   显示错人；它们在用户滚到时按需重取（进浏览那一刻滚动条在顶部）。
   第一版做的是「把滚过的页逐页重取」，属于过度精细，已拆掉（多 12 行 + 一串串行 IPC）。
4. **残留（人类 2026-09-22 追问后确认：基本不可达）**：导入在后台收尾时浏览不会当场刷新，
   下次进浏览才更新。要踩中它得带着一个还在跑的批次离开导入流 —— 而导入进行中
   进度弹窗是**真模态**（Ark `Dialog` + 全屏遮罩；且 `App.tsx` 的分发器在
   「DOM 里有 `[role="dialog"]`」时一律不接快捷键），鼠标与 `Mod+1..4` 都切不走；
   唯一的口子是**错误态**（前后端失联）时 footer 才出现的「关闭」。
   所以**刻意不加**根层事件订阅：收益几乎为零，多一份监听要养。
5. **角标锚外框，判据是结构不是几何**：人类指出「已经跟图无关了，哪怕图只有一个像素也不影响，
   代码层就能判断」—— 所以冒烟量的是「在角落层里」+「**不在照片盒里**」，
   而不是拿极端比例的照片去比边距（那版夹具已拆）。
6. **保留老行为**（人类重申）：角标与信息条**二选一** —— 选中 / 指向 / 键盘聚焦 /
   `marks-name` 档强制文件名条时角标退场；信息条盖在角标之上；左下预留位与右下角标镜像。
7. **命令体系接入评估（`AGENTS.md` §2.15）**：本次没有新增用户可触发的功能 ——
   重读是自动的（进浏览），角标是显示规则，因此**不适合**登记进命令注册表；
   也没有新增硬编码快捷键。

## 验证（Agent 侧：冒烟 + 单测）

- `pnpm typecheck`、`pnpm test`（含新增 7 条）、`pnpm lint:colors` / `lint:arch` / `lint:i18n`、`pnpm build`：全绿。
- `pnpm smoke:ui`：全绿。角标量到 4:3 与 3:2 两张样例
  `inCorners: true / inPhotoBox: false / 到外框右·下边缘 8px`，
  左下预留位 `left: 8 / bottom: 8`（镜像对应）；选中后角标 `display: none`、文件名条 opacity 1。
- `pnpm check:browse`：全绿。新增那条按用户路径走了一遍：
  改假后端的库（等价于导入落新照片）→ 切到导入 → 切回浏览 → 状态条计数 `6 张 → 7 张`。
  **该检查做过反面验证**：临时注掉 `BrowseWorkspace` 的 `onMount(store.refresh)`，
  它立刻报「切回浏览后没有重读库（browse_page 9→9）+ 列表没变（6 张→6 张）」，随后已恢复。
- 排查中被工装坑过一次（记下来）：假后端的 fixture 原先写在 `invoke` **函数体内部**，
  每次调用都重建 → 测试对它的改动立刻被抹掉，表现为「产品没刷新」的假红。
  现在 fixture 只建一次并挂在 `window.__FIXTURES` 上。
