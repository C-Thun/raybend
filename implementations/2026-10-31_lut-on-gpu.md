# 创意 LUT 搬进 GPU（着色器）

2026-10-31 03:28:37 CST 完成。

## 背景与范围

崔总 2026-10-31 定的前置任务：多层 LUT 界面改造之前，先把 **LUT 计算搬进 GPU**，
方式必须是 **WGSL shader（wgpu）**，不是 CUDA（CUDA 绑死 NVIDIA，桌面产品不能这么绑）。
名义上只动 LUT 计算；顺手把挡在前面的结构（快速路判据、绑定组形状）一起收口。

改之前的事实（不是猜的，是读代码 + 已有实施记录对上的）：

- `develop/pipeline.rs:997` 与 `develop/working.rs:372` 里，LUT 都是**串行逐像素**循环；
- `render/working_preview.rs:103` 的 `fast` 判据里有 `lut.is_none()` —— **只要选了 LUT，
  拖任何滑杆都会掉回 CPU 全分辨率重渲**（每帧数十到数百毫秒），这才是用户感觉「LUT 贵」的真正来源；
- `spike.wgsl` 里只有显示 CLUT 与影调表，没有创意 LUT。

## 关键决策

1. **LUT 挂在 `group 0`（图像绑定组）的 binding 4..7，不新开 `group(4)`。**
   第一次跑离屏就撞上：WebGPU 的 `max_bind_groups` 默认是 4，
   `create_shader_module` 直接报 `group index 4 that exceeds the max_bind_groups limit of 4`。
   抬这个上限等于赌所有目标显卡驱动都支持，不是本地桌面软件该赌的东西。
   挂在 group 0 反而更对：**「这张图有没有 LUT」本来就是这张图的事实** ——
   参照帧（对比左侧）有自己的绑定组，用「关闭」那一套资源，于是「参照帧不套 LUT」
   变成结构事实，不需要任何运行时开关，也不可能出现「主图换了 LUT、参照帧跟着变」。
2. **求值域与 CPU 逐条对齐**：LUT 在**显示参考的编码域**（signed sRGB transfer）求值，
   位置在 `display_reference` 之后、转 Rec.2020 之前 —— 与 `render_working_reference` 完全同序。
   为此把 `adjust_global` 拆成 `adjust_global`（Rec.2020 进出）+ `adjust_srgb`（sRGB 线性域内核）。
   两个阶段都关时**原样返回**，不坐一次 from/to Rec.2020 的往返（那会改动末位）。
3. **超域残差保留**（与 `Lut::eval_extended` 一致）：输入先夹到 `DOMAIN_MIN..DOMAIN_MAX`，
   夹掉的部分在查表后加回去。HDR 高光不会被 LUT 吞掉。
4. **strength 字段先留口**：uniform 里 `.high.w = strength`，当前恒为 1，
   语义是 `mix(输入, eval_extended(输入), s)`。多层链的每层强度直接用它，不用再改协议。
5. **`gpu_lut` 跟着「帧」走，不读「当前选中项」**：`PreparedWorkingFrame` 新增
   `gpu_lut: Option<Arc<Lut>>`。理由：显影线程与渲染线程差一拍，拿新选择配旧帧就是
   「图与参数对不上」。**慢速路（锐化/动态反差/High 降噪/几何）已经在 CPU 把 LUT 烘进像素，
   必须给 `None`**，否则会套两次。
6. **`fast` 判据去掉 `lut.is_none()`**；剩下的判据（High 降噪 / 锐化 / 动态反差 / 几何）不变。

## 验证

全部在本机（WSL / lavapipe）执行：

```
cargo test --workspace
  → 1597 passed / 0 failed / 11 ignored（另 raybend-desktop 169 + 2 + doctests 2 全绿）

cargo run -p raybend --example lut-offscreen
  全局影调关：
    关 LUT：GPU vs CPU        max=1  mean=0.05  超差=0
    cube LUT：GPU vs CPU      max=1  mean=0.06  超差=0
    shaper+cube：GPU vs CPU   max=3  mean=0.08  超差=0
    自检：开 LUT vs 关 LUT     max=38 mean=9.63  超差=4918
  全局影调开（曝光/对比/高光/饱和）：
    三条对照 max=1，自检 max=38 mean=7.53
  → 全部通过（容差 3/255）

pnpm typecheck && pnpm test        → 1346 passed
pnpm lint:colors / lint:arch / lint:i18n → 三条全绿
cargo clippy -p raybend --all-targets   → 新文件无告警（既有 too_many_arguments 等为存量）
```

判据说明：容差 3/255 覆盖 f16 表 + 硬件三线性 + sRGB 传输曲线近似；
`max=1/255` 的实际读数说明 CPU 与 GPU 已经是同一张图，不是「差不多」。
「开 vs 关」那一条保证不是悄悄跳过（差 38/255、近 5000 个通道超差）。

自检与单测：

- `develop/lut.rs::cube_samples_are_r_fastest_for_the_gpu_upload`：钉住立方表顺序
  （GPU 上传按 `x = r, y = g, z = b`，顺序错了颜色就串）。
- `render/working_preview.rs::a_creative_lut_rides_on_the_fast_path_and_the_slow_path_bakes_it`：
  快速路必须带 `gpu_lut`，慢速路必须不带（防套两次）。

**未经人类验证**：Windows 真机的观感与帧率、真实照片上的 LUT 表现（这台机器只有 lavapipe）。

## 遗留与下一步

- 多层 LUT（链）的渲染侧已留好形状：uniform 的 `strength`、`CreativeLut` 的字段布局、
  `gpu_lut` 随帧走。真正上多层时，着色器里把 `apply_creative_lut` 换成按层的循环 +
  每层一张 3D 纹理（或 `texture_3d` 数组）即可，**不要再开新绑定组**。
- 仍然掉出 GPU 快速路的：锐化、动态反差、几何（裁切/旋转）、High 降噪。
  建议顺序与理由见 `memory/EDIT-GPU.md` §4。
- 导出、缩略图、1920 预览仍在 CPU（崔总明确接受）；它们的 LUT 语义仍是 `eval`（clamp），
  与编辑器的 `eval_extended`（保残差）不同 —— 这是既有的有意差异，本次未改。
- `spike.wgsl` 的 `image_config.y` 仍是「这一帧要不要套全局影调」的开关；LUT 已改为看
  自己的 uniform（`lut.low.w`）。两者独立，参照帧因此同时关掉影调与 LUT。
