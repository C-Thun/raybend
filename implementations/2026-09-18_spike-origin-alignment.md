# spike 坐标错位：把「输入原点」这件事量出来（顺带把窗口改成无边框）

完成时间：2026-09-18 15:02:44 CST

范围：`src-tauri/src/spike_viewport.rs`、`src/dev/SpikeViewport.tsx`、`src/api/spike.ts`
状态：测量与前提改动已就位；**待人类跑一次看「输入偏移」那一行**

---

## 一、人类给的两条判据

1. 缩小态（`zoom 0.0974 / pan 33.8,44.0`）截图：图像**正正好好居中在洞口里**、四角红绿蓝黄齐全
   → **绘制侧是对的**（用截图坐标反推，落点与 `rect_center + pan` 的预测一致）。
2. 1:1 态截图：把鼠标挪到读数 `3001.1, 2000.3` 的位置，那个位置**不在**画出来的十字上
   （人类用红叉标出），"移到十字上一缩放还是会歪" → **输入侧与绘制侧差一个常量**。

`洞口(物理) = (375, 46, 655, 884)` vs `洞口(CSS) = (300, 37, 524, 707)`：
**恰好 × 1.25** → 单位没问题，排除「漏乘 dpr」。

## 二、为什么之前查不下去

我用**截图目测像素**的两轮核对，精度约 ±30~40px —— 而可疑偏移（标题栏）也正好是
这个量级。**同量级的误差量同量级的偏移，等于没量**。左栏那句「往返偏差 0.000000」
也帮不上忙：它比的是 `physical_to_image` 与 `image_to_physical` 这一对**自洽**的函数，
而错位发生在「CSS 坐标的原点是谁」这层，不在数学里。

## 三、这次的改法：把原点量出来 + 消掉边框

1. **三个原点都报出来**（物理屏幕像素）：
   - `窗口原点` = `outer_position()`（含边框）
   - `客户区原点` = `inner_position()`（主线程取，安全）
   - `webview 原点` = 前端 `window.screenX/screenY × dpr`（新命令 `WebviewOrigin`）
   → 并推导出 **`输入偏移` = webview 原点 − 客户区原点**。
   这一行非零，就说明输入的 `clientX/clientY` 与 wgpu 表面不在同一坐标系，
   差多少就补多少 —— **这是本次要的那一个数**。
2. **spike 窗口改无边框**（`decorations(false)`，与产品一致）：带边框时三者可能各差一个
   标题栏；无边框后它们必然重合，输入与绘制天然同一套坐标系。
   顶栏挂 `data-tauri-drag-region`，所以仍然能拖（多显示器 / DPI 那几项要用）。

## 五、下一轮怎么走（按读数分两条路）

- **输入偏移 = 0,0 且读数对上** → 收工，1.3 继续往下走。
- **输入偏移 = 0,0 但读数仍偏** → 那不是原点问题，回头查 `resize()` 之后
  `viewport.dpr` / `viewport_size` 的更新时机（洞口是 CSS 量、物理值是 ×dpr 得来的，
  dpr 变过而洞口没重报就会错位）。
- **输入偏移非零** → 无边框没消掉它（说明偏移不在窗口边框上，而在更里层的
  webview 容器），再按这个数把 `pointer_to_image` 的入参平移掉。
