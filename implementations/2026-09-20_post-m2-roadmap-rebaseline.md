## 改动范围

根据 `implementations/` 中 M1 至 `2026-09-20_m2-w3-command-palette-shortcuts-menus.md` 的实际交付，
重新调整 `PLAN.md` 的 M2 收尾与 M3–M6 节奏，并同步修正 `FUTURE.md` 中已被排期或已经失效的表述。

涉及文件：

- `FUTURE.md`：库与磁盘一致性提升到 M3-W1，H1/H4/H6/H8/H10 指向新的 M4 波次，
  DOM 查看器 / 原生视口与 RAW 出图的旧时间点修正。

## 关键决策与理由

1. **M3 改为「实时一致性 + 导出」**：原路线把完整组织检索放在导出前，会让地图、相似图等增强能力
   挡住「导入 → 浏览 → 评片 → 导出」首个闭环；本地应用又必须优先保证程序外文件变化能及时反映，
   所以先做目录重读/监听编排，再做导出。
2. **原 M3 与 XMP 合并为新 M4**：平面标签、FTS、查询/分面、timeline 数据已在 M1/M2 提前落地，
   后续只补完整的产品层；XMP 与标签/集合/搜索放在同一阶段更利于迁移与互操作。
3. **M5 从 5 波压缩为 3 波**：frecency GC、迁移快照与恢复演练、持久化 jobs、RAW worker 隔离都已完成，
   M5 不重复实现底层，而是收成多仓体验、缓存/任务中心、备份/诊断三个用户能力。
4. **显式防止“地基即完成”的误判**：计划中逐项写明平面标签、FTS、timeline、GC、备份演练、worker
   分别还缺哪些产品闭环。
5. **发现视图不再阻塞首个可试用版本**：地图/时间线/相似图保留在 M4-W5；地图若需大型依赖，
   必须按项目纪律单独讨论，并允许拆出而不污染已完成工作。
6. **导出不提前吞掉显影系统**：M3 先把位图 / RAW / SOOC 的来源契约定清，并为未来 `issue_id`
   留稳定入口；不会为了导出首版把 issue、显影栈和原生编辑视口一起拉进当前里程碑。
