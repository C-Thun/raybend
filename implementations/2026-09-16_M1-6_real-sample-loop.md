# M1-6：真实照片的导入闭环（在真磁盘上跑一遍）

完成时间：2026-09-16 11:48:36 CST

## 为什么要有这一步

单测用的是**内存假实现**（快、可重复、`cargo test` 秒级），但它们证明不了
「照片真的按模版落在磁盘上、库里真的有那几行」。这中间隔着 9p/Windows 的路径语义、
真实 EXIF、真实的 `fs::copy`、以及真 SQLite 的事务 —— 这一步就是把那道缝补上。

产物是可重复执行的：`crates/raybend/examples/import-smoke.rs`

```bash
cargo run -p raybend --example import-smoke -- <库根> <源目录> [模版]
```

## 这次跑的是什么

  根下 3 组 `JPG+RW2` 配对、`日本/Kyoto/` 下 2 组配对（考透传与嵌套 `_RAW/`）、
  根下 2 张单飞 JPG、一个只含文档的目录、以及一个空的父目录层级。

## 顺手修掉的一个 harness 缺陷

第一版例子里 `read_summary` 用了 `std::mem::take(&mut check)` —— 读库那几条断言
记在一个被丢弃的临时对象上：**通过数不对，失败会被静默吞掉**。
写成「冒烟脚本会吞失败的断言」比没有冒烟更危险，已改成传 `&mut Checks`，
重跑后显示「14 项断言」全过。
