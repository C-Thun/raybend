## 需求原文（verbatim）

> 我计划将lut面板分为上下两部分（下面的总览部分不算在内），即上半部分是应用的lut，下半部分才是多分类的lut列表，统一在一个滚屏div内没问题其实跟现在一样。现在当选中某个lut时，其实会遇到一个问题，选中就是应用，然后要取消或是要找到应用了哪个lut其实是找不到的，如果lut够多，你要翻很多才能找到那个勾。同时也明确不支持多个lut应用。
>
> 现在修改后，`应用LUT`和下面的lut分类/列表中间会插一层lut应用层，一开始这层是空的不存在，与现在的界面无异。在下面点中lut后，选中哪个lut（即应用了），这里就会插上一行lut，显示你应用了哪些lut
>
> 直接点击下面分类/列表中的lut，不会实现多lut应用功能，其效果是，切换最底层那个lut，这样当没有多lut应用时，其行为与现在没有区别，应用了多lut后，也不会因为点了某个lut而毁掉整个多层lut。
>
> 怎么设置多层lut呢。现在鼠标指向lut时，右上角的圆圈就会出现，鼠标点击那个圆圈就可以实现多选，多选的lut在应用lut下方的使用列表中插在列表下方，处理的时候是从上往下逐层处理。
>
> 取消lut，可以反选lut右上角的圆圈里的勾。
>
> 应用lut列表中的每一条lut的样式与操作:
> - 分上下两层，左边有lut缩略图占满两层，右边上层是lut名称和lut独立开关，右边下层是调节条组件（样式与调曝光反差等一样，默认值是100%拉杆那个点在最右，往左拖可以控制lut强度，双击还原默认值）和删除图标，注意删除图标是鼠标指向才显示。
> - 需要可以拖动，调整顺序，同时每行应用的lut
>
> 顶部的`应用lut`保留作为总开关
>
> 要注意实现多层lut后，对应的issue/xmp/preset/撤销重做等功能全部要进行架构适配，这里一定要非常注重架构层级的准确抽象与表达。

以及本轮同一次口述里关于前置任务与画稿纪律的部分：

> 做这个计划的前置任务，即把lut计算搬进gpu，同时我感觉现在很多调节都没有跑在gpu上，后续都要往里改。
> 这一步我们名义上只动lut计算，但是如果改的时候遇到关联在一起的，可以一并改掉，为后面的铺路。
> 你可以在做的过程中记录一个memory文件，专门用来记忆编辑计算gpu化的进程，大约还有多少应该gpu化没有gpu化。
> 导出过程中cpu我可以接受，当然能gpu化最好。
> 之前没有gpu化之一原因好像有说gpu化没说写shader，而说要写cuda，这我就不能接受了，cuda绑定显卡，这肯定不是我们这种软件的路子，写shader还是可以的。

> 这个改动实施前要先在pencil上修改原来的界面，审核过后再正式开工。

## 我读到的语义（先按这个理解，待崔总拍板）

1. **列表点击 = 换掉链的第 1 层（基底）**；只有「圈选」才是往链里加层。
2. **圈选 = 加/减一层**；已勾选再点圆圈 = 从链里移除该层。
3. 应用层列表自上而下 = 运算顺序；第 1 行是列表点选出来的基底。
4. `应用LUT` 顶部总开关 = 整条链的旁路；关掉不清空链。
5. 每层：`lut_id` + `enabled`（单层旁路）+ `strength`（0–100，默认 100）。
6. 同一支 LUT 是否允许出现在链里两次 —— **未定**（见待定项 Q3）。

## 审阅：会碰到的问题（按风险排序）

### A. 语义/交互

- **A1 两条视觉通道会并存**：同一行既可能「是基底」（点选高亮）又「在链里」（圆圈勾）。
  现在的列表只有一套选中态（`selected`）。改造后要同时表达两件事，需要设计稿明确：
  基底行用主色底？链内成员用圆圈勾？两者重叠时的样式？
- **A2 删除基底行 ≠ 关闭总开关**：删掉第 1 行时，是把第 2 行顶上来当基底，还是整条链清空？
  （若链是 `Vec`，删第 0 项就自然由下一层顶上；要写进规格。）
- **A3 空链时区域不存在**（崔总已定）——注意「应用LUT」标题与下方列表之间的布局跳动，
  以及滚屏内高度变化时滚动位置的处理。
- **A4 圈选热区只在 hover 出现**：触控板/触屏难点；且点中圆圈与点中行的误触要处理
  （圆圈命中区独立、行点击不冒泡）。
- **A5 拖动排序**：列表在滚屏 div 内，拖到边缘要自动滚（preset 面板已有同样的能力，直接复用）。
  拖动做成「松手即 confirm」，不要每移动一格就落库。
- **A6 强度拉杆的「双击还原」**：`Slider` 现有双击回到参数默认值的机制可直接用，
  但这里是「强度」而非曝光类参数，要确认默认值就是 100（不反转、不改成 0–1 内部值）。
- **A7 单层开关全关 + 总开关开**：此时渲染应等于无 LUT；UI 上要不要提示？（倾向：不提示，等同空链。）

### B. 数据结构与架构抽象

- **B1 `DevelopStack.lut_id: Option<String>` 必须变成有序层**：
  建议 `lut_chain: Vec<LutLayer>`，`LutLayer { lut_id: String, enabled: bool, strength: f64 }`。
  - 必须**顺序敏感**地进 `profile hash`（否则重排不失效缓存 → 串图）。
  - 需要 `PROFILE_SCHEMA_VERSION` 升级 + 旧栈迁移成单层（`strength=1.0`, `enabled=lut_enabled`）。
  - `lut_enabled` 保留为总开关，不要并进层里（语义不同）。
- **B2 撤销/重做**：链的增、删、重排、调强度、单层开关、基底替换 —— 每个都是操作节点，
  全部要进 `EditorWorkspace.confirmEdit` 的节点清单（`AGENTS.md` §2.21）。
  拖拽的 confirm 是「松手」，拉杆是「松手」，圈选/点选是「点击」。
- **B3 issue（定稿）**：issue 快照要存整条链；issue 的缓存签名同样要含链（顺序+强度+开关）。
  旧 issue 读取走同一个迁移函数，不要两套解析。
- **B4 XMP**：`rb:profileJson` 存完整 `DevelopStack`，链路自动跟着走（形状变了要更新
  `specs/issue-xmp-contract.md`）；`crs:` 侧 LUT 本来就在 `NOT_MAPPED`（`xmp/mapping.rs`），
  不新增映射；`specs/xmp-sidecar.md` §5.1 要写明「多层的表达与旧版读回」。
- **B5 preset**：预设存整条链；旧的单 LUT 预设读进来要做同样的升级；
  「不包括基础曲线」等既有口径不变。
- **B6 渲染侧**：`DevelopStages.lut: Option<&Lut>` 要变成多条（或一个链对象）。
  CPU 路径逐层 `apply_rgb`（导出可接受），GPU 路径同一趟 pass 内串联多层采样
  （每层一次 3D 纹理采样，避免 N 次全画幅内存往返）。
- **B7 缺文件降级**：链里某层 LUT 文件丢失时，跳过该层并给出可见提示，
  不要整条链失败（现在单支是「引用不可用就报错」，多层要更宽容）。

### C. 待定问题（需要崔总拍板，开工前问）

- **Q1** 基底行被替换时，新基底的 `strength` 与 `enabled` 继承旧的还是重置为默认（100/开）？
  （倾向：重置为默认，避免「换了支 LUT 却只有 30% 强度」的困惑。）
- **Q2** 删除基底行：下一层顶上，还是清空整条链？（倾向前者。）
- **Q3** 同一支 LUT 允许重复出现在链里吗？（倾向：允许，但列表里只显示一个勾；
  链里再出现同一支时 UI 需要区分两行。）
- **Q4** 链长度上限？（倾向：8 层，超过后按钮禁用并提示；GPU 每层一次采样，8 层仍可实时。）
- **Q5** 应用层每行的缩略图尺寸（设计稿定），连带行高与滚动区高度。
- **Q6** 多层 LUT 是否影响「定稿(issue) 的命名/封面」：目前封面是「样片套 LUT」，多层要用整条链套。

## 验收要点（将来写进 specs 的验收清单）

- 无链时行为与现在**逐位一致**（单支 LUT 的像素输出不变）。
- 链顺序改变 → 画面改变（证明顺序真的生效）；单层开关/强度生效且可撤销。
- 重排/改强度后缓存必须失效（profile hash 覆盖链）。
- issue/preset/XMP 三条路都能保存并读回整条链；旧数据（单支）读回等价。
- 导出与编辑器画面一致（同一链、同一强度）。
